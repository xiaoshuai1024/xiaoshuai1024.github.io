装完 Claude Code 先别急着聊：这 5 条提示词，决定你做出来的是玩具还是产品

同一个需求，我听过两种结局。一句「给这个接口加个缓存」扔给 Claude Code，拿回来一套带配置层、适配器、多级策略的缓存体系，账单翻倍，这是许愿式问法。后来同一个需求换了个问法，第一轮就被四个问题问没了：这个接口写多读少，缓存攒不住热度，需求当场作废，半小时对话省掉几天的实现加无止境的维护。两次都是同一支 Claude Code，模型没换，提示词的文采也没变好。

差的不是第一句，是第一句之后还有什么。前一种问法，第一秒之后就没人管了，AI 自己决定方向、自己宣布完成；后一种问法，后面跟着一套东西接管全程。vibe coding 做出来的是玩具还是产品，分界线就画在这里。

我有个粗暴的判据：把你的会话记录翻到中间任意一轮，如果那一轮没有任何验收动作，产出大概率是玩具。中间轮次暴露的正是没人看着的时候 AI 在干什么。这篇把一次交付拆成五个阶段，每个阶段配一张提示词卡，卡和卡之间由人和门禁接力。单条提示词的深拆我写过三个提示词的事，工程资产的全景在五根工程柱子，这篇讲它们中间缺的那层：一次会话里，提示词怎么按阶段轮换。

一、玩具的特征：全程只有许愿一个动作

先看玩具是怎么造出来的。

一次交付实际是条流水线：理解需求、定方案、执行、验收、把教训攒下来。许愿式提示词只在第一站出现，一句「帮我优化一下性能」「参考某某产品做个类似的」，然后人就退场了。后面四站全部由 AI 自理，它按最隆重的方式做你没说的决定，按自己的标准宣布完成，教训哪也不去。翻车复盘我在裸聊四种姿势里摆过：不懂规矩、拿聊天记录当需求文档、看起来对就合入、一把梭没边界，四种姿势对应流水线上四个没人值守的工位。

很多人这时候的反应是换更长的提示词，把角色、要求、格式全塞进第一条。方向偏了。第一条提示词再长，管的还是第一秒；玩具感不是第一秒产生的，是第二秒到收工之间没有交接班产生的。生产级的做法不是打磨一句一步到位的话术，是给流水线的五个工位各派一个监工，每个监工就是一张卡。

所以这 5 张卡不长，也不用收藏——它们不是用来拜的，是用来换的。

二、开工卡：把许愿换成开工单

第一张卡在会话开头打出去。

这个需求先不动手。第一步，把相关代码读完，用你的话复述现状；
第二步，列出准备改哪些文件、每步干什么、明确不做什么；
第三步，列出需要我拍板的问题。我确认后再动手。

它把「帮我把这事办了」改成「先告诉我你打算怎么办」。一字之差，身份变了：我从许愿的变成验收的。开头那个加缓存的需求就是被第三步救掉的：四问一出（缓存粒度、失效策略、穿透处理、单机还是多实例），「加个缓存」从愿望变成带边界的技术决策，而且第一轮就发现这题不用做。完整的故事在计划怎么把需求问掉里。

这张卡的单条深拆版本我写过，这里补一个用了一年的细节：确认计划时不要回「可以」，至少划掉一项。计划里总有做多了的或者顺序不对的地方，你划掉一项再放行，它收到的信号是这个老板真的看计划，之后每一轮的计划质量都会往上走。次次秒批，不出三次计划就开始水。

三、契约卡：把口述升格成 WHEN/THEN

计划确认了，需求还停在聊天记录里。第二张卡在动手前打，把口述意图变成可执行的契约：

把这份需求写成 spec：每个行为一条 WHEN/THEN，边界条件单独列，
涉及钱、权限、数据删除的场景必须覆盖失败路径。
信息不够的地方标 [待确认] 列出来问我，不许猜。

聊天话术的每个词都留了解释空间，AI 会选一个解释继续干，选错的成本由账单支付。WHEN/THEN 是我把口述升格成契约的格式。实现之前它是指令，实现之后它是试卷，同一份文本用两次。拿我们踩过的佣金事故说：部分退款改造绕过了佣金结算，月底对账才炸。如果先有契约卡，这两个 WHEN 在写 spec 时就得回答：

WHEN 部分退款金额大于已支付金额
THEN 拒绝请求，返回 REFUND_EXCEEDS_PAID
THEN 不触发佣金重算，不写退款流水

「不许猜」那半句和开工卡的第三步是一对：一个在计划层问掉歧义，一个在契约层堵死歧义。什么时候值得上这张卡，判据三条：改动跨文件、有外部副作用、需要决策留痕，命中一条就写 spec；单文件小修直接聊，流程开销超过动作本身就不划算。spec 流水线的完整用法我固化在 OpenSpec 六步里，中等改动走完全程约小半天，换来返工轮次明显下降。

四、止损卡：给 AI 体面的停机权

执行阶段最容易忽略的一张卡。它不指挥 AI 干什么，只规定它什么时候必须停：

执行期间三条纪律：
1. 确认不了的事实，停下来问我，「无法确认」是合法结论，别编；
2. 同一个错误失败两次，停止重试，把报错原文贴出来；
3. 删除或改写超过 50 行的代码，先单独列出清单等我确认。

第一条是被账单教出来的。AI 没有心虚的概念，被逼着给答案时它一定给一个：编出来的配置项、猜出来的 API、虚构的日志，语气还特别自信。给它停机权比逼它硬编便宜得多，这条在我们仓库已经写进 AGENTS.md，对所有会话默认生效。

第二条防的是雪球。我见过夜里挂的自动重试把同一个错误重试了两百遍，每一遍都在烧上下文；也见过一条会话 54 轮累计 952 万 token，输入输出比 144:1，单轮消耗从两万滚到二十二万，一个会话翻了 11 倍。失败立即停，就是那类账单的闸。第三条是大改动的申报制度，为什么值钱，下一张卡连着那个事故一起讲。

五、验收卡：说完不算，跑出来算

第五张卡是最反直觉的一张，因为它管的不是 AI 的行为，管它的汇报格式：

完成后：跑构建、跑测试、跑 lint，把三条命令的输出贴给我。
任何一条红了，自己修；修不动就把报错贴出来问我。
不许改测试、不许删测试来让测试通过。

它说出口的「完成了」是主观题，这张卡把它改成判断题。为什么必须这么较真，我在那次幽灵删除里交过最贵的一笔学费：270 行并发守卫代码被一次「搜索优化」静默删掉，提交时编译是绿的，潜伏四天，大促订单超卖，又花四天排查。编译器只认语法契约，不认行为存在。你不在汇报格式里要证据，它就拿「搞定了」三个字交差，而这三个字的含金量是零。

后半句「不许改测试」是血泪条款。让红灯变绿的捷径有两条，修代码是一条，把测试改了是另一条，后者快得多也坏得多。给它「修不动就问」的出口，同时堵死作弊的路，两边得同时做。

这张卡还有个进阶形态：审查换会话。改完的代码丢给一个只读的新会话去挑毛病，明确告诉它「允许说无法确认」。自己改自己审等于没审，同一个会话既是被告又是法官，它对自己方案的盲点一无所知。审查会话拿不到写权限，自然只能挑错不能美化。三层测试怎么配、反向断言怎么写，细节在测试纪律。

六、收尾卡：把会话尾巴变成资产

最后一张卡在一段工作验收完之后打，干两件事：

这段工作到此为止。请输出：
1. 本次确认过的结论，压缩成 5 条以内，作为下个会话的交接；
2. 本次踩的坑里，哪条值得写进 AGENTS.md 或固化成检查规则，给出建议条目。

第一件管账单。会话上下文每轮全量重发，拖着整段历史聊下去，就是那条 952 万 token 会话的走法。正确姿势是一段一验收、验收完新开会话，交接只带压缩过的结论，比拖着一整段历史便宜一个量级。顺手三条纪律：稳定内容放前、易变内容放后；会话中途不动 AGENTS.md（我改过一次，缓存命中率从 92% 以上跌到 46%，实付差 5.5 倍）；并行任务各自开目录，别在一个会话里搅。

第二件管记忆。修完 bug 不算完，把「别再犯」固化成手册里的一条规则或者一道检查，才算修完。三个月后没人看复盘文档，但每一轮请求都会读手册。这条回写纪律怎么做，我写在事故固化成规则。收尾卡打完，一次交付到这里才算收口：结论带走了，教训入库了，会话可以安心关掉。

七、换卡点比卡本身重要

5 张卡逐个看都不惊艳，它们的效力来自换卡的时机：上一张卡的产出被验收的那一刻，就是换下一张卡的信号。开工卡的计划被划掉一项并确认，换契约卡；契约卡的真实场景全部回答完，换止损卡进执行；验收绿了，换收尾卡。谁不验收谁就卡在原地，会话停在错误的方向上越久，返工越贵。

也不是所有活都值得上全卡组。判断就一岔口：

单文件小修、改错字、调样式，直接聊加一条绿灯汇报就够。反过来，四张卡再齐全也救不了三种典型翻车：一次塞三个需求，AI 交付的优先级和你想的永远不一样，一个会话一个目标是铁律；「你懂我意思」，你不说的决定它全替你做，且按最隆重的做；会话从早滚到晚不收尾，账单和遗忘同步增长。这三种翻车的共同点是把卡组当摆设：卡在收藏夹里和提示词在收藏夹里，是同一种病。

卡组的尽头也不是天天换卡。哪张卡打得最勤，就把它写进 AGENTS.md 变成默认纪律，再往上是固化成命令和门禁：止损卡的纪律进了手册，验收卡进了 CI，开工卡进了 plan-first 流程。提示词的最高归宿和三个提示词那篇说的一样：变成不再需要打字提示词的系统。

玩具和产品的分界线在会话中间

回头看开头那两种结局。许愿式问法不是输在第一句的质量，是输在第一句之后整个流水线无人值守：方向自己定，事实自己编，完成自己宣布，教训哪里都不去。卡组做的事只有一件：把验收动作铺到每个阶段，让「人在场」从开场三分钟变成分布在五个工位上的五个瞬间。

这 5 张卡没有一句玄妙话术，朴素得不像值得收藏的东西。但 vibe coding 的生产级从来不是靠一句神级提示词达成的，是靠把「谁验收、拿什么验收、验收完去哪」这件事制度化。模型每升一级，纪律的复利和裸聊的账单会同步放大，差距只会越拉越开。下次会话翻车，别急着换模型换提示词，翻到会话中间那几轮看看：哪个工位没人值守，哪张卡就该补上了。
