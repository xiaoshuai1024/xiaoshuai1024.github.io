装好 Codex 要多久？从下载安装包到浏览器里看到 25:00 的倒计时，我在这台 Windows 机器上实测用了不到二十分钟。但多数人卡住的地方不是写代码，是开头五分钟——安装和登录。网上教程一抓一大把，功能章节讲得都很全，唯独「装好、登进去」这一步默认你会，多少人倒在这道门槛前。这篇文章把我这台机器上的 Codex 桌面端从头到尾跑了一遍，每步都有真机截图，专门解决开头那五分钟，再往下走完整个实操闭环。

读完你能做到：装好 ChatGPT 桌面应用，登录进 Codex，认清楚界面和两种工作模式，用一句中文让 Codex 从零做一个番茄钟网页，验证它真的能跑，最后把模型供应商切到 DeepSeek，月成本掉一个量级。

适用人群与前提

这篇教程写给两类人：完全没装过 Codex、想用自然语言做东西的新手；装了但卡在登录或不会用的半新手。

前提四样：

  • 系统：Windows 10 / 11。本文实测 Windows 10，macOS 桌面端流程一致，安装包格式不同
  • ChatGPT 账号：登录用。没有账号或不想注册的，看第六步，跳过官方登录直接接 DeepSeek
  • 网络：能访问 openai.com 和 GitHub。工具自备，本文不展开
  • 版本：ChatGPT 桌面应用（含 Codex 模式）build 26.x、Codex CLI 0.140.0（本文验证环境）、CcSwitch v3.20.0、DeepSeek V4 Flash

有个背景先交代：Codex 桌面端底层就是开源的 Codex CLI（Apache 2.0），官方把它包进了 ChatGPT 桌面应用。桌面端的好处是零命令行，文件操作、diff 审查、图片生成都有图形界面，适合不碰终端的用户；CLI 自由度更高，适合脚本化和远程场景。这篇走桌面端。

两条路选哪条，我的判断看你的使用场景：只在编辑器旁边干活、想要可视化 diff 和图形界面，桌面端够用且零学习成本；要批量跑任务、要接进自己的自动化脚本、要在服务器上干活，CLI 才是正路。多数人从桌面端入门，用到一定深度自然知道什么时候该切 CLI——两个是同一个 Codex，配置、会话、模型选择完全互通，切换没有迁移成本。

顺便回答常被问到的问题：Codex 和「豆包」「文心一言」这类聊天助手有什么区别？区别在于它是智能体，能直接读写你电脑上的文件、执行命令、改完自己验证。聊天助手给你贴一段代码让你自己搬，Codex 自己把活干完再让你验收。这个区别贯穿后面所有步骤，看实操部分就明白了。

整体思路

五步主线，一条省钱支线：

  1. 安装：下载 ChatGPT 桌面应用安装包，装上
  2. 登录：ChatGPT 账号登录，进入 Codex
  3. 认界面：功能区、工作区、两种模式、权限三档
  4. 实操：用一句中文发任务，全程看它干活
  5. 成品：审查 diff，确认文件落盘，浏览器打开验证

走完五步之后，如果你想省订阅费，第六步用 CcSwitch 把模型切到 DeepSeek——这正是本文区别于网上大多数教程的地方：不止教你怎么用，还教你怎么把成本打下来。

步骤 1：安装 ChatGPT 桌面应用

打开 openai.com/codex，点页面里的 Download for Windows，下载 MSIX 安装包（约 740MB，需要能访问 openai.com）。

拿到安装包后用 PowerShell 安装：

Add-AppxPackage .\OpenAI.Codex_x64.msix

安装完开始菜单会出现 ChatGPT（或 Codex）图标。首次双击打开，Windows 可能弹 SmartScreen「不受信任的应用」提示，MSIX 签名包首装的正常现象，选「仍要运行」。MSIX 安装不需要管理员权限，卸载直接开始菜单右键，不留残留。

两个容易卡住的点提前说。第一，下载页面可能跳转到 ChatGPT 官网而不是直接给安装包，认准 Codex 页面的 Download for Windows 按钮，别在别的页面转圈。第二，安装包接近 1GB，网络不稳定会下载失败，失败就重下，没有断点续传的变通办法，别在旧版上死磕。

预期输出：桌面应用打开，停在登录页或主界面。

步骤 2：登录，卡住最多人的一步

网上问得最多的「登录过不去」，拆开就三种情况：登录按钮点了没反应、登录成功但跳不回来、登录完要求订阅。

第一种，登录按钮点了没反应：多半是应用没更新到最新版，回官网重新下载覆盖安装。第二种，登录成功但跳不回来：浏览器授权页完成后等应用自己切回来，别手动关应用。第三种，登录完要求订阅：Codex 模式需要 ChatGPT 账号，免费账号能用但额度受限；不想订阅的跳过这一步，直接看第六步用 API key 走 DeepSeek。

登录成功的标志：应用左上角显示你的账号，左下角模型选择器能看到模型列表。

我的验证环境里，这台机器主界面左侧是项目列表（博客源码仓库直接挂在里面），中间是对话区，底部是输入框，左下角账号徽章显示的是 @deepseek——这台机器已经切到了 DeepSeek，后面第六步就是讲怎么做到的。

预期输出：进入主界面，点「新对话」能看到空的对话窗口。

步骤 3：认界面——工作区、功能区、模式、权限

Codex 桌面端的界面分两大块。

工作区就是中间那块对话的地方。你输入自然语言，它回话、贴代码、展示改动。每次改动文件之前，它先给你看 diff——左边旧代码右边新代码，你审完同意它才落盘。这是它和「贴一段代码让你自己搬」的工具最大的区别：每一步都过你的手。

功能区负责配置。左上角按钮切换 Codex 和普通对话模式，侧边栏有项目、插件、已安排的任务入口。输入框里敲斜杠能拉命令菜单，切模型、开新会话都在里面。

两种模式：计划模式 vs 代理模式

模式是新手最该先搞懂的概念，它决定 Codex 的工作方式。

计划模式：只读代码、出方案，不动手改。适合「有个想法但没想清楚怎么做」的场景。你拿它当顾问：聊方案、看它分析项目结构、反复确认，满意了再切回执行模式。相当于先画图纸再动工。

代理模式：目标明确后放开跑。它会连续干活：建文件、写代码、跑命令、自己看报错修，一口气干到底，只在需要审批时停下来等你。

我的用法：新项目、不熟的项目先计划模式过一遍方案；熟摊子、需求明确直接代理模式放它跑。切换在界面上一两秒的事，两个模式是同一份对话上下文，中途切没有成本。

持久记忆：它记得你的规矩

Codex 有记忆系统，可以把你定的规矩存成本地文件，下次干活照办。两种用法：手动记忆，直接告诉它「以后所有新项目都用 4 空格缩进、注释写中文」，它记下来；自动记忆，它从你纠正它的过程中自己沉淀规则。

这个能力对零基础用户的价值：你不需要每次把偏好重复说一遍，也不用担心它「忘记上次说好的事」。规矩写一次，长期生效，这在连续干多个项目时特别省心。想查看或清理记忆，在设置里能找到记忆管理入口，随时删。

权限三档

权限管的是它能背着你干多少事：

  • 只读：只能看文件，不能改。让它读代码、找 bug 的时候用
  • 自动审查：改文件和跑命令之前先问你。默认推荐，安全和效率的平衡点
  • 完全访问：自己读写文件、跑命令不再逐条问。练手项目可以用，正经项目慎用

我的建议比网上「推荐完全访问」的说法保守一点：练手项目可以全开，正经项目老老实实用自动审查。AI 犯错不会先打招呼，权限就是安全带。

命令行能力

桌面端虽然不用你敲命令，但 Codex 自己在后台大量用命令行：装依赖、跑测试、检查语法、启动服务。你可以把它理解成内置了一个会自己用终端的程序员。这个能力是它区别于「生成代码片段的聊天机器人」的根本——它能验证自己写的代码能不能跑。

实操里我见过它做的事：node --check 检查 JS 语法、列目录确认文件、起本地预览服务器让我在浏览器里直接看效果。这些动作它自己完成、自己汇报结果，你只需要看它干得对不对。

自然语言的用法技巧

自然语言就是 Codex 的全部操作方式，但「会说」和「说清楚」差距很大。三条技巧，都是我实际用下来最值钱的：

  • 把验收标准写进需求：「能暂停、能重置、统计当天完成数」是验收标准；「做一个番茄钟」不是。标准写清楚了，它就不给你自由发挥的余地
  • 一次说完，别挤牙膏：想到什么补一句，想到什么再补一句，它每轮都要重新理解上下文，费 token 还容易跑偏。先在备忘录里打草稿，满意了整段粘进去
  • 绝对路径写死：文件存哪、目录叫什么，直接写绝对路径，别让它猜。猜错的代价是文件散落各处，你找半天

这三条看着简单，它们决定了你是在「指挥一个程序员」还是在「给一个模糊需求添乱」。

预期输出：能说出界面哪块是工作区、哪块是功能区，能说出两种模式的适用场景，能说出当前对话的权限档位。

步骤 4：用一句中文，让 Codex 做出番茄钟

实操环节，跟着做。我的任务写在备忘录里再粘进去（先想清楚再发，省得挤牙膏式补话）：

帮我做一个番茄钟网页：25分钟倒计时、可暂停可重置、每完成一个番茄记录一次并统计当天完成数量。界面简洁美观，用中文界面。所有文件保存到 D:/codes/codex-demo-tomato/ 目录，保存完成后告诉我如何打开。

任务文案设计有三个讲究。第一，把「完成标准」写进需求——倒计时、暂停重置、完成统计，功能点列全，它就不会漏。第二，把「保存位置」写死——不写的话它会存到当前打开的项目目录里，你回头找不到；写了绝对路径，它就照做。第三，一次说清楚，比挤牙膏式补话省一半时间和 token，效果还好。

发送之后它先复述计划，然后开始干活：建目录、写文件、跑命令检查。你可以看到它每一步在做什么，遇到要写文件的地方停下来等你审。

这一轮它自动验证了产物：列出目录文件检查完整性，检查 JavaScript 语法，最后用无头浏览器打开页面截图确认界面正常显示，通过才回复「做好了」。它自己检查自己写的代码，这是桌面端 agent 和聊天机器人的分水岭——它真的在干活，不是只出嘴。

预期输出：D:/codes/codex-demo-tomato/ 下出现 index.html、style.css、script.js 加一个 app.js，对话里能点开每个文件的 diff。

步骤 5：验证成品——真的能跑，才算做完

Codex 说「做好了」不算数，浏览器打开才算。双击 index.html，番茄钟页面渲染出来，倒计时 25:00 停在屏幕上。

再验证两件事：点暂停/重置，倒计时有响应；完成一次倒计时，统计数字加一。功能全对，这个任务才算闭环。

增量修改：改现有项目才是日常

新建项目只是入门，日常最高频的场景是改现有项目。接着刚才的番茄钟，追加一个需求：

加一个深色模式，右上角放一个切换按钮，切换后整个页面配色变深。

注意观察它怎么干：它不会把整个项目重写一遍，而是先读现有代码，找到样式和页面结构，只动该动的部分，再给你 diff 让你审。这个「只动该动的」能力，是 agent 类工具最值钱的细节——改老项目最怕的就是 AI 顺手把你别的逻辑弄坏，diff 审查 + 最小改动原则，是它的两道保险。

到这里，零基础主线走完了：装、登录、认界面、发任务、验成品、改需求。接下来这条支线解决钱的问题——官方订阅费对国内用户不便宜，这也是新手问得最多的问题之一。

步骤 6：用 CcSwitch 切 DeepSeek，成本掉一个量级

CcSwitch（GitHub 仓库 farion1231/cc-switch，12.9 万 star）是开源的供应商切换器，管 Claude Code 和 Codex 两套配置。它做的事本质上是替你改配置文件：点一下，把 DeepSeek 的接入参数写进 Codex 的配置，不用手改 TOML。

到 GitHub Releases 下载 Windows 版（MSI 安装版或 Portable 免安装版都行），打开就是供应商列表界面。

为什么省得多，看 DeepSeek 官方定价页就明白：官方模型按每百万 token 计价是美元级，DeepSeek V4 Flash 缓存命中后是分钱级，差约两个数量级。

我自己的成本账：官方订阅月费固定花销，加上超额用量，重度使用一个月上百美元很正常；切到 DeepSeek 后按量付费，个人写代码一个月几块钱到十几块，日常任务的模型质量差距在感知边缘。省的是不是 99% 取决于你的用量，但数量级的差距是确定的。

切完的配置长这样（~/.codex/config.toml，key 已打码）：

model_provider = "custom"
model = "deepseek-v4-flash"

[model_providers.custom]
name = "deepseek"
base_url = "https://api.deepseek.com"
wire_api = "responses"
requires_openai_auth = true

关键在 wire_api = "responses"——DeepSeek 原生支持 OpenAI 的 Responses 协议，所以 Codex 直连 api.deepseek.com 就能跑，不需要本地代理转换格式。这是整个方案能零代理跑起来的原因。

切换后重启 Codex，左下角账号徽章变成 @deepseek，模型选择器里能选 deepseek-v4-flash。完整的配置步骤、跳过登录的细节和报错排查，我在这篇里写全了，这里不重复。

预期输出：重启 Codex 后模型跑在 DeepSeek 上，发任务正常响应，DeepSeek 开放平台能看到 token 消耗。

第一次打开项目文件夹的注意事项

新手做完新项目后，接下来大概率要把 Codex 指向一个已有的项目文件夹（比如你的博客源码、公司代码仓库）。这时候有两件事会拦住你。

第一，首次打开文件夹，Codex 会请求访问权限。桌面端对文件访问是逐文件夹授权的，弹窗里点允许才能读写里面的文件。这个弹窗第一次见有点吓人，其实只是它的安全机制：不授权，它只能看不能改。

第二，打开别人的大仓库时，建议第一句就问「先告诉我这个项目的结构，再等我指令」，而不是直接派任务。让它在计划模式下游览一遍代码，你确认它理解对了再动手。大仓库里跑偏的代价远高于多花一分钟确认。

进阶：插件、Skill、MCP，这套框架能走多远

做完第一个项目，你大概会问：除了写网页，它还能干什么？答案藏在 Codex 的框架能力里，简单认识一下，以后按需深入。

插件：把外部平台、工具和服务接进来。邮箱、日历、Excel、浏览器，都能变成 Codex 能调用的能力。相当于给它装外设。

Skill：把一套可复用的方法、流程、工具组合打包成技能。比如「每周自动生成周报」可以沉淀成一个 Skill，以后一句话调用。它的本质是把你跑通过的流程固化下来，不让它每次重新摸索。

MCP：标准化的外部连接协议。数据库、知识库、设计稿，凡是支持 MCP 的工具都能接。插件和 MCP 的区别一句话：插件是官方/生态做好的成品，MCP 是你按标准自己接的任意服务。

持久记忆：Codex 可以把规则和偏好存成本地文件，下次对话还记得。你的编码习惯、常用命令、项目约定，写一次，以后每次干活都遵守。这个能力在桌面端体现为手动记忆（你明确告诉它记下来）和自动记忆（它自己沉淀）。

这几块是 Codex 从「会写代码的工具」到「个人 AI 工作流」的跨度所在。我仓库里有一系列源码深读专门拆这些机制，文章末尾有入口。零基础阶段不用急着全学，先把主线跑通，知道有这些能力存在，需要时再回头。

常见报错与排查

登录按钮点了没反应。应用版本太旧，回官网重新下载 MSIX 覆盖安装，别在旧版上折腾。

登录成功但应用不跳转。浏览器授权完成后等应用自己切回来，别手动关应用进程；还不行就彻底退出应用（任务管理器结束 ChatGPT/Codex 进程）再开。

登录完提示要订阅。Codex 模式需要付费账号的完整额度；免费账号受限。不想订阅的走第六步，API key 认证完全绕开登录墙。

发消息后一直转圈。到模型服务器的网络不通。先测连通性：Test-NetConnection api.deepseek.com -Port 443，返回 TcpTestSucceeded : True 说明网络通，问题在别处；不通就调代理规则让域名直连。

文件写错地方了。Codex 默认在打开的项目目录里干活。想写到哪里，就在任务里把绝对路径写清楚（我上面的任务里明确指定了 D:/codes/codex-demo-tomato/），它照做。

切了 DeepSeek 不生效。Codex 不像 Claude Code 支持热重载，切换后必须完全退出重启。重启还不行，检查 config.toml 里 model_provider = "custom" 是否真的在，auth.json 里的 key 是不是 sk- 开头。

代理模式越跑越偏。任务太模糊时它可能自由发挥过头。回到对话里补一句「先不要写代码，先告诉我方案」切到计划模式拉回来，或者直接说「停，改成这样做」。

它改了我没让改的文件。权限设成自动审查就是为了防这个。发现 diff 里有你没点头的改动，直接在对话里说「这个文件不用动，撤销对它的修改」，它会改回去。这也是为什么我建议正经项目别开完全访问——出了这种事，有审查环节就还有后悔药。

成品在浏览器里样式乱了。多半是本地预览服务器没启动，或文件路径带中文/空格。用 Codex 起本地预览（它常用 python -m http.server 这类命令），再用它给的地址访问，别直接双击本地文件。

完整产物

番茄钟项目四个文件，零依赖，双击 index.html 就能跑：

  • index.html：页面结构，倒计时环和按钮
  • style.css：样式，简洁深色界面
  • script.js：交互逻辑——暂停重置、完成记录与当天统计
  • app.js：倒计时核心——状态管理、环形进度、本地存储（Codex 自己验证过语法）

这套四件套是 Codex 写前端小工具的典型产物：单页 HTML + 原生 CSS/JS，不用框架，不用构建。项目不涉及账号数据，可以直接拿我的任务文案复现。

下一步

主线走完，你有两个方向可以深入。

一个是把模型层玩明白：DeepSeek 是国产模型里第一个被官方点名支持 Codex 的，协议、模型边界和真实表现我拆解过；同一套 CcSwitch 用在 Claude Code 上的完整流程在另一篇里。另一篇Codex 接 DeepSeek 的完整教程里，还有跳过登录、协议错误的排查。

另一个是往纵深走：Codex 的权限门控机制、Skill 与 MCP 的加载机制、多会话调度，我在源码深读系列里逐篇拆过。等你用自然语言做出第一个项目，回头看这些，就知道框架能力有多值钱。

回到开头那句「装好 Codex 要多久」。卡住大多数人的不是功能，是开头五分钟的安装和登录——这关其实不难，难的是没人把每一步截图给你看。这篇文章之后，从下载安装到浏览器里看到 25:00 的倒计时，应该用不了二十分钟。剩下的，就是你想让它做什么的问题了——Codex 不会嫌你说的人话不够技术，它只在意你说清楚没有。
