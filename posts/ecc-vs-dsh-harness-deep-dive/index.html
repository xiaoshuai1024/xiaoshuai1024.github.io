26 万星 ECC 没引擎，23 万星 DSH 是真内核：两份源码读完的选装结论

ECC 拿了 26 万星，读到源码级别才发现：里面没有一行引擎代码，本体是两千五百多个 Markdown 文件加六百多个脚本。DSH 只有 23 万星，反而是个带内核、带四端、带论文的完整框架。两个 GitHub 最热的 agent 框架，我把两份源码都读到了文件级，结论先放在这里：它们不在一个维度上，比不出谁强，只能分开装。

这篇给你三样能带走的东西：一张 ECC 和 DSH 的机制速查表（可截图收藏）、一套「谁该叠装、谁该换装」的选装结论、三条对应你自己现状的判断。所有数字核对于 2026-09-20 20:30:00（UTC+8），来源是 GitHub API 与两份仓库源码，性能类数字单独标口径。

星数接近，起点完全不同

先把档案摆在一起。DSH 是 DeepSeek 官方出品，2026-08-13 创建，TypeScript 编写，五周多一点冲到 23 万星。ECC 是个人开发者仓库，2026-01-18 创建，JavaScript 编写，八个月攒到 26.3 万星，当前版本 v2.2.2，最近一次提交 2026-09-19，更新极勤。

星数打平，星速差了六倍以上。这本身就是信息：2026 年下半年的 agent 赛道，背靠大厂发布渠道的框架，增长曲线和社区项目不在一个量级。两家官方描述的第一句也早就分了岔：DSH 写着 Everything is a Plugin，一切皆插件；ECC 写着 agent harness 性能优化系统。一个说自己是什么，一个说自己能优化什么。

DSH：一切皆插件的内核

DSH 构建在 Cordis 框架上，架构主张就一条：内核不认识任何具体能力。所有能力以插件形态外挂，连主循环都没有特权——循环本身也是一个插件。内核越薄，能外挂的东西越多，这个机制的源码细节我单独写过一篇插件系统走读。

产品形态随之确定：apps 目录下 cli、web、desktop、desktop-host 四个端跑同一套内核；插件装完十二秒生效；会话设计成类似 git 的结构，改炸了能回滚，细节见会话即 git 那篇。代价是初期生态要自己种，官方用插件市场和 dsh-plugin 话题标签聚拢第三方。README 里明确写着开发者预览期将有破坏性变更。大厂敢这么写，赌的是生态速度，五周 23 万星说明赌注暂时是赢的。

ECC：26 万星，没有引擎

现在看 ECC，回收开头的判断。我把仓库按文件类型统计了一遍：Markdown 两千五百三十个，JavaScript 六百一十一个，Python 一百四十六个。package.json 里的名字叫 ecc-universal，命令行入口指向一个安装器，跟运行时没有关系。

它的插件清单自己写着：六十八个 agent、二百九十二个 skill、九十四条旧命令兼容壳，主体是带 YAML 头部的 Markdown 配置，由宿主按描述自动匹配加载。运行方式是往宿主的生命周期上挂五十五个钩子脚本，工具调用前后、会话启停、上下文压缩前后，每个动作都被它插一杠子。仓库里还有二十多个针对不同宿主的适配目录，Claude Code、Cursor、OpenCode 都有接线。

所以 ECC 的本体，是一套给现成框架调校的配置层。它优化的是你手里已有的那个 agent。这个定位解释了星数：全世界的 Claude Code 用户基数太大，任何能插进这个宿主的东西，天花板都极高。

真家伙：instinct 四步

配置层不稀奇，稀奇的是配置里长了机制。最值钱的一件叫 instinct，直觉机制，过程分四步：钩子盯着每一次工具调用默默观察；后台生成候选直觉，三十天没人转正就自动过期；置信度过零点七的写进项目档案；下次会话启动，挑最相关的六条注入上下文。

排序有个细节写在 instinct-relevance.js 的注释里：项目级直觉加零点二五的域匹配权重，技术栈匹配再加零点二以上。一个项目级零点七的直觉，加权后零点九五，能排到无关的全局零点九前面。翻译成人话：在这个项目里，本地经验比全局权威值钱。零人工维护，用得越久越准，三十天过期又压住了噪声。

其余三件快速过。GateGuard 是编辑门禁，规则很硬。AI 改代码前口头说确认过没有用，必须列出三样事实：谁引用了这段代码、公开接口长什么样、数据结构长什么样，列不全不放行，把「我觉得」挡在编辑器外面。上下文监视器设三组硬阈值，剩余上下文两成五告警，花费五美元、十美元、五十美元三档提醒，连续五次调用同一工具判循环。记忆库走保守路线：Markdown 文件存储，只进不改，默认未经审查，人工复核才升级信任，把人留在环里。

两家正面对撞有三组，先给速查表，再看解释。

设计型确定，生长型惊喜；一个防运行时越权，一个防配置里藏刀，正好互补；前者开放，后者可控。没有对错，看你更怕意外还是更怕维护。

性能账要算两遍

ECC 的 README 里有一段性能账，原文口径：主力模型从 opus 降到 sonnet 省约六成成本，扛住八成以上编码任务；思考 token 上限从三万二压到一万，隐含成本降约七成；自动压缩触发线从九成五调到五成。全部是官方自述，没有第三方复测，引用请带口径。

方向可以用独立数据交叉验证：伯克利 Sky Lab 和 LMArena 做过叫 harness 税的测量，同一个模型换壳，成功率只在小数点晃，成本最大差五倍，见壳税实测那篇。壳影响成本有硬数据，ECC 做的正是壳这一层，所以方向可信、幅度自测。壳的税和模型的价还能交叉组合，DeepSeek 官方提供 Anthropic 兼容端点，Claude Code 的壳可以直接指向 DeepSeek 的模型价，这套算法在姊妹篇模型没换，账单差20倍里逐行算过。

三条选型判断

第一，手里已经有 Claude Code、Codex 这类宿主，短期不换，选 ECC：调校层装上就生效，instinct 越用越准，GateGuard 值回票价。第二，要独立框架、押插件生态和官方迭代速度，选 DSH：接受预览期的破坏性变更，先在非生产项目试。第三，两边都在快速变化，ECC 自己用 Rust 写了一万两千多行的控制台项目补引擎课，从寄生走向独立是它能力边界的下一次证明，值得放进观察清单。

写在最后

读完两个仓库，我最大的收获是看清了星数这个指标的边界。ECC 用二十六万星证明了一个判断：配置和机制本身就是生产力，不一定非要引擎。DSH 用五周二十三万星证明了另一个判断：一个主张够彻底的内核，能靠生态速度追平八个月的积累。

两个都对，两条路线的方向也确实相反。真正的问题从来与星数无关：你手里已经有什么、愿意迁移多少、更怕失控还是更怕麻烦。答完这三个问题，答案自然浮出来。源码不会骗人，前提是有人把它读到深处。我持续读源码、写出来，就是这个原因。你现在手里的是哪个？留言说说你的组合，叠装派和换底座派各有各的道理。
