秋招面试官：AI Agent 能脱离大模型独立运行吗？90% 的人答不到点上

「AI Agent 能脱离大模型独立运行吗？」这道题在 2026 年的面试里出现频率高得反常，而 90% 的回答停在「不能，Agent 需要大模型提供智能」这一句，然后就开始聊应用场景。答到这一句只能算及格，因为面试官真正想听的是下一句：为什么不能，壳里到底有什么，模型到底负责什么。这两个问题答不上来，说明你用过 Agent 但没拆过 Agent。

我把 Claude Code 和 Codex 的主循环源码摆开对照过，还留着一份 952 万 token 的真实会话记录。三样东西放在一起，这道题的答案可以讲到机制层：Agent 壳里没有智能，它是一个以模型输出为驱动条件的循环调度器。模型给工具调用，循环就转；模型不给，循环就停；模型不在场，循环空转。这篇文章把这句话拆成三层证据，最后一节给可以直接背走的面试答案结构。

一、壳的四件套：循环、请求、分发、回填

先看 Agent 壳的真实结构。Claude Code 的主循环（v1.0.88 源码）是一个自递归 async generator，还原成可读代码，骨架是五步：

async function* agentLoop({ messages, ... }) {
  let msgs = await microcompact(messages)   // 1. 入口压缩检查
  await autoCompact(msgs)
  for await (let event of streamRequest(msgs)) { ... }  // 2. 请求模型
  let toolCalls = assistantMessages.flatMap(  // 3. 提取全部 tool_use
    (m) => m.message.content.filter((c) => c.type === "tool_use"))
  for await (let r of runTools(toolCalls)) results.push(r)  // 4. 执行工具
  yield* agentLoop({ messages: [...messages, ...assistantMessages,
                          ...results] })      // 5. 带新历史进下一轮
}

这段伪代码不是示意，是源码结构的忠实还原：一个函数收历史、发请求、提工具调用、执行、再把自己递归进下一轮。一个自递归 generator，讲完了这家公司旗舰 Agent 产品的全部调度逻辑。

Codex 那边形态不同，血统相同。入口是开源仓里 turn.rs 的 run_turn，三层嵌套：最外层 turn 做压缩和依赖解析，中间层 step loop 每轮取用户插话、构造请求、判断要不要继续，最内层流式消费模型输出，function call 一到就推进 in_flight 队列并行执行。Rust 写的，类型化取消，结构化程度高很多，但逐层读下去，它做的事情没有超出上面那五步。

两家对照之后可以给 Agent 壳下一个不客气的定义：循环、流式请求、工具分发、结果回填，四件套齐了就是一个 Agent 壳，剩下的全是加固。这个判断我有实证。自己复刻过一个最小 Agent 循环，四件套两百行以内就能跑起来一个能读文件、能改代码、能跑测试的 Agent，复刻记录在多任务编排实践里。壳的概念复杂度就这么高，一个下午能读完。

这里有个值得停十秒的观察：四件套里没有一件是「思考」。壳不生成任何内容，不判断任何方案，不做任何决策。它像一个交接班台账，把历史递给模型，把模型的工单递给工具，把工具的回执再递回模型。全部价值流动都经过模型，壳自己不生产价值。把模型的线拔掉，循环会落到什么下场，答案在驱动条件里，下一节看。

二、驱动条件：模型不点头，循环不转

「Agent 能不能独立运行」翻译成源码问题就一个：循环的继续条件写的是什么。如果继续条件是壳自己算出来的东西，那 Agent 有独立性；如果继续条件依赖模型输出，那独立性是错觉。两家的答案一致得干脆。

Claude Code 的循环出口条件是「没有 tool_use」。模型这一轮只回了文字、没调工具，循环就走收尾分支跑 Stop hook 然后 return。整个 Agent 的「停下来」不是什么状态机变迁，就是一次普通的函数返回。反过来，只要模型还在给工具调用，VE 就带着新历史递归下一轮。循环的油门和刹车都焊在模型的输出上。

Codex 把这件事写得更显式。step loop 的继续条件是一个三条件或运算：

needs_follow_up = model_needs_follow_up
               || has_pending_input
               || token_limit_reached

第一个条件是模型自己声明「我还没干完」，第二个是用户插了话，第三个是 token 到顶。三个条件里两个半依赖模型侧的输出。我拆完两个主循环后写过一句总结：前者以工具为中心，后者以意图为中心。无论哪种中心，中心都不在壳这边。全文对照在主循环源码对比那篇。

有个细节值得单独说：用户插话在 Codex 里和「模型还要继续」是同级的调度输入。session/input_queue.rs 是一个显式队列，step loop 每轮开头调 get_pending_input，取到的用户输入和模型输出一起参与继续判断。这个设计叫 steering，人在回路里。Claude Code 也支持，靠的是 generator 递归前消息队列里自然带上新输入，没有专门构件。两边实现不同，结论一样：除了模型，另一个能让循环继续的输入是人类，循环自己没有任何「想继续」的来源。

现在正面回答「拔掉模型线会怎样」。断网那一刻，四件套里的第二件（流式请求）抛出网络异常，两家都进重试。Claude Code 的退避公式是 min(base * 2^(n-1), 32000) + jitter，指数退避封顶 32 秒加随机抖动；Codex 用 ResponsesStreamRetryState 状态机数着重试次数，stream_max_retries 可配置。重试耗尽之后，整条循环以异常终止，没有 Plan B。壳对「模型不在场」的全部预案就是反复敲门，它没有能力自己产生下一步。你在产品里看到的「Agent 卡住了」，源码层就是循环在等一个永远不会来的响应。

错误处理更能说明智能的归属。工具参数校验失败，Claude Code 不抛异常，工具分发器把错误包成 <tool_use_error> 作为 tool_result 回给模型，让模型下一轮自己修参数重试。所谓 Agent 的「自我修复」，拆开看是模型修复，壳只负责把错误递回去。这个设计我第一次读到时愣了一下，因为它诚实得近乎坦白：连修 bug 这件事，壳都认定自己没戏，必须交回模型。

拿一个具体任务在两个循环里各走一遍，结构会变成直觉。任务是「读 A、B 两个文件，对比后写报告」。Codex 这边，流里第一个读文件的 function call 一到就执行，第二个到达时也推进，两个读并行，模型拿到两份内容后输出报告，继续条件不成立，turn 结束，全程一个 step。

Claude Code 这边，整轮流完提取出两个读调用，判定并发安全进并行池，结果回填后 generator 递归进下一轮，模型输出报告，没有 tool_use，出口。两条路径形状不同，驱动结构相同：每一步「接下来干什么」都由模型在下一轮输出里给出。

思想实验做到这里，「Agent 断网还能跑多久」也有了精确答案：跑到当前这轮流式请求超时为止，一秒都多不出来。壳的自主性上限就是当前这轮已到达的输出，输出消费完，循环就进入等待，等待耗尽就异常终止。没有缓存里的「下一步」，没有本地的小模型接棒，没有任何形式的余粮。

三、连记忆都不在壳里：952 万 token 的实测数据

「不能独立运行」还有第二层证据，比驱动条件更釜底抽薪：Agent 的记忆也不在壳里，在每一次请求的行李里。模型是无状态的，它对你这个项目的全部记忆，就是这一轮请求里塞进去的内容。所以循环每转一圈，历史原文重发一遍。

我拿自己的一条真实会话记录做过解剖。2026-08-20 16:45:36 起的一条 Codex 会话：54 次模型调用，总输入 9,529,727 token，输出只有 6.6 万。两个数字一除，144 比 1。你付的钱里，九成九不在「模型写了多少」，在「模型每轮重新读了多少遍聊天记录」。

单轮输入从第一轮的 20,611 一路涨到最后一轮的 226,262，涨了 11 倍，中间没有任何人来按住它。逐轮解剖的完整过程在952 万 token 那篇里，每个数字都能照着复现。

这个复利结构值得拆一层。每一轮的重发量等于历史交互的全部体积：你写过的每条需求、它吐过的每段代码、跑过的每份报错，全在下一轮的行李里。所以会话越长，单轮成本越高，涨的还是加速的。第十轮你才隐约觉得不对劲，第二十轮它已经涨了 11 倍。

这个数字结构对「独立运行」问题是直接否定。假如 Agent 壳真有独立智能，它为什么要每轮把全部历史重新发一遍，一个有自己记忆的系统不需要这样做事。事实是循环每轮都在重复同一套动作：把「我是谁、干到哪了、刚拿到什么结果」的完整档案重新递给一个失忆的专家，请它基于档案做下一个决定。144 比 1 的形状不是浪费，是这套架构的存在方式：状态不在壳里持久化，状态在请求里反复重建。

DeepSeek Harness 的源码把这层关系做得最直白，也提供了一个极端佐证。它的架构文档第一页写着：产品的每一部分都是插件，包括会话日志本身。会话是一条仅追加的事件日志，模型每轮看到的消息历史都是这条日志当场投影出来的，机制全文在会话即日志那篇。

连「记忆容器」都不是 Agent 壳的固有器官，只是可以替换的插件。壳对记忆的全部职责是搬运，不是持有。

顺带把成本的实操一面说了，这也是面试加分位。因为每轮重发，缓存命中决定成本。DeepSeek v4-flash 的输入价两档，缓存命中每百万 0.05 元、未命中 1.5 元，同一个字两种价钱，30 倍。同一个问题问两遍，token 数一模一样，实付差 30 倍。

我还做过一组受控实验：同一份代码、同一个任务，两个目录各跑一遍，仅有的区别是一个文档胖、一个文档瘦。胖文档那次缓存命中率 46%，计费 21,984；瘦文档那次命中率 98%，计费 3,989。

同样的活，实付差 5.5 倍。胖的那个没有多干活，它只是每轮把多余的指令区内容也念了一遍。

理解了「状态在请求里重建」，你就理解了为什么改一行全局配置会让那个月的成本整体上一档：前缀一变，缓存整体作废，下一轮全体按原价重来。

四、那 43 万行代码在干嘛：加固件的错觉

「Agent 有独立性」的错觉有明确来源：Agent 产品的复杂度被误认成了 Agent 概念的复杂度。Claude Code 的发布产物有 43 万行之巨，但主循环骨架 160 行讲完，剩下的都是加固件：两级上下文压缩（microcompact 和 auto-compact）、挂在循环出口的 Stop hook、捕获异常后整轮换备选模型重跑的 fallback、按并发安全性拆池的并行工具分发（池上限写死 10）、封顶 32 秒的指数退避。Codex 同构：pre-turn compaction、MCP 依赖解析、全链取消、保序回填。

这些加固件解决的都是「循环怎么转得更稳」，没有一个解决「循环怎么自己转」。它们的存在恰好反证了依赖关系的方向：正因为一切智能供给都在模型那头，断供的代价才大到需要 43 万行来防御。类比一下，电网的稳压设备越精密，越说明用电设备的命脉在电厂，不在自家机房。

复刻经验也站在这个结论一边。我做最小 Agent 时抄的就是 VE 的结构：一个循环、一个流式请求、一个工具分发、一个结果回填，四样齐了就能跑。跑起来之后再加压缩、加 hook、加重试，每加一件都在做同一类工作：让「等模型」等得更舒服。没有一个加固件曾让循环获得过一丁点自主性。工具调用的工程桥接我在另一篇里写过完整方案，贯穿的原则是调度交给模型、工具实现交给业务。当时是当架构原则写的，现在回头看，它就是「壳无智能」在工程侧的投影。

subagent 是这套判断的极端样本。Claude Code 派 subagent 不开新进程，启动器构造一个精简上下文，砍掉 MCP 连接、思考预算归零，然后直接复用同一个主循环 generator。所谓「派一个子智能体」，源码层是同一个循环第二次入场，没有新员工，只有同一个循环换了身份 ID 再跑一轮。工具描述里官方自己写着「Each agent invocation is stateless」，每次调用无状态，不指望它记住上次任何东西。Codex 的路线重一些，每个 subagent 是独立 thread，配信号量限流和 agent 树持久化，重启后整棵树从磁盘恢复。拆开看还是同一个公式的加大号：循环、请求、分发、回填，只是多了一层调度。连「多 agent 系统」都没有逃出四件套，单一 agent 的独立性就更没有藏身之处了。subagent 的完整调度对比在那篇源码文里。

四点五、一个诚实的边界：壳有工程决策，没有任务决策

写到这必须主动拆一个潜在反驳，因为面试官可能追问：壳里真的没有任何决策吗。有的，但要分清两种决策。

壳确实在做决策。Claude Code 每轮把工具调用按 isConcurrencySafe() 分块，内置只读工具标安全进并行池，MCP 工具看 server 自己声明的 readOnlyHint 元数据，这是壳在决定执行秩序。压缩时机也是壳定的，上下文逼近上限就先 microcompact 再 auto-compact。重试节奏、并发上限 10、退避封顶 32 秒，全是壳的决策。

但这些全是工程决策，回答「怎么执行得更稳」，没有一个是任务决策，即「下一步该做什么」。读哪个文件、改哪行代码、要不要认输，每一个任务级选择都来自模型的下一轮输出。类比人类组织：壳是流程和行政，模型是做判断的专家。行政可以决定文件先送谁后送谁，不能替专家决定结论。Agent 的自主性边界就画在这里，流程自主，任务不自主。这个区分在评测 Agent 产品时也用得上：吹「自主决策」的产品，值得追问一句，它自主的是哪一种。

顺带一个观察方法，看完循环形态可以再看语言生态。Claude Code 拿 JS 的 async generator 换了组合性和流式输出，Codex 拿 Rust 的 tokio 生态换了类型化取消和并发原语，两家循环各自带着各自生态的胎记。但两家换到的都是工程性质，没有哪家换来「不依赖模型输出就能继续」的能力。语言生态再强，也造不出循环自己的意愿。

这些结构判断全部可以自己验证，不需要信我。Codex 是开源的，run_turn 的循环与继续条件直接可读；Claude Code 跑一个真实任务观察行为节奏也够：请求、工具执行、结果回填循环出现，模型不再给工具调用时循环立即收尾，断网时反复重试后异常终止。三条行为对上，四件套的判断就立住了。面试里把「我验证过」讲出来，比背十个 Agent 框架名字都有说服力。

五、面试答案卡：面试官真正想听的 3 个点

秋招季这道题的区分度就在这：背答案的人答「不能」，面试官在等的是你能不能拆出「为什么」。评分式拆法是三个点，答出一个及格，答出三个就是候选人堆里能被记住的那类。先给一句结论定调：不能独立运行，但值得把「为什么」拆成三层说。

第一层说驱动。Agent 壳是循环调度器，循环的继续条件依赖模型输出。Claude Code 看「本轮有没有 tool_use」，Codex 看「模型是否声明还要继续」。模型不点头，循环就停在原地。这一层证明壳没有自主性。

第二层说状态。模型无状态，Agent 的记忆不在壳里持久化，而在每次请求里全量重建，每轮把完整历史重发一遍。这一层证明壳连记忆都没有，可以带 144 比 1 的输入输出比做数字背书。有真实数据的人在这一层就能和背答案的人拉开差距。

第三层说修复。工具调用失败不抛异常，错误包成 tool_result 回喂模型，下一轮由模型自己修参数。所谓 Agent 自我修复，修复主体是模型。这一层证明壳连纠错都外包。

三个点折成一张速查卡，面试前五分钟过一遍：

点位说的是什么源码证据证明什么
一 驱动循环继续条件依赖模型输出CC 出口=有无 tool_use；Codex=needs_follow_up 三条件壳没有自主性
二 状态记忆在请求行李里全量重建54 轮 952 万输入、144:1、单轮涨 11 倍壳没有记忆
三 修复错误回喂，模型下轮自修<tool_use_error> 作为 tool_result 返回壳没有纠错能力
加分位 a两家哲学差异工具中心（generator 递归）vs 意图中心（step loop）读过实现
加分位 b架构连成本缓存两档价 0.05/1.5 元每百万，价差 30 倍覆盖到别人不到的位置

这张卡是「秋招大模型面试六题」系列的 ep1。六题速查目录先挂在这，后面每篇发一篇补一篇，收藏这篇就能顺着追完：

  1. Agent 能脱离大模型独立运行吗（本篇）
  2. 为什么大模型记不住上一次的对话？
  3. token 到底是什么，为什么中文更贵？
  4. 为什么模型会一本正经地胡说八道？
  5. DeepSeek 为什么又便宜又快？
  6. 为什么 9.11 比 9.9 大？模型真不会比大小？

加分位放两个。第一个：两家实现的哲学差异，Claude Code 以工具为中心，generator 自递归，收齐整轮 tool_use 统一执行；Codex 以意图为中心，step loop，function call 流内即执行。能说出这个差异说明你真读过实现。第二个：把 Agent 架构和成本结构连起来讲。正因为状态在请求里重建，缓存命中率决定成本结构，两档价差 30 倍，这是绝大多数候选人覆盖不到的位置。

答完主问题，面试官通常会顺着追问，这里把三条高频追问的答案提前备好。追问 MCP：工具协议改变了工具接入的协议层，MCP server 自己声明 readOnlyHint 这类元数据，壳拿它做并发安全判定，但「调不调这个工具」的决策权仍在模型下一轮输出里，协议没有动摇结构。追问本地小模型路由：壳确实可以换模型，fallback 机制整轮换备选模型重跑就是证据，但「换哪个模型」的路由决策要么是写死的规则，要么来自上层模型输出，规则路由属于工程决策，还是不构成任务自主。

追问 agent 互操作（A2A 这类）：多个 agent 互相调用，每个节点内部仍是四件套，协议做的只是把循环里的「工具」换成「另一个 agent」，依赖关系的方向没有变化。三条追问的答案收拢成一句：往下钻每一层技术，都会重新撞见同一个结构。

这张卡的价值不止面试。判断一个 Agent 产品的能力上限，看模型；判断它的工程上限，看壳。把评测火力全部打在壳上、对模型选型漫不经心的团队，是把 43 万行的防御工事修在了不设防的方向。反过来，选型时先问「这个 Agent 允许接什么模型、切换成本多大」，比问「它有多少功能」更接近要害。功能是加固件，模型才是发动机。

结论收在最初那道题上。「AI Agent 能脱离大模型独立运行吗」，背答案的人答不能，拆过源码的人答：Agent 是一个循环，驱动全靠模型，记忆也全在模型那头的请求行李里，壳的全部工程量都花在让这个依赖关系跑得更稳上。驱动条件在模型输出里，历史在请求行李里，修复在下一轮生成里，三样东西拿走任何一样，循环剩下的就是一个空转的 while。这道题我后来常拿来当试金石。它表面考概念，实际考一个人有没有把用过的东西拆开看过。能答到驱动、状态、修复三层的人，后面聊架构基本不用再兜圈子。
