一个前端朋友发我一篇 AI 教程，说看不懂。我点开一看，满屏的大模型、Agent、RAG、MCP、Harness，标题写着「零基础入门」。他把原文念给我听，我笑不出来。我刚碰 AI 开发那会儿，也是这个表情。

那之后我把 Claude Code、Cursor、OpenCode 用进了每天的工作流，博客的写作、发布、配图全部交给 AI 跑。现在回头看，这些词没有一个是孤立的。这篇把我用下来的理解讲一遍，你会发现 AI 黑话就一条主线，串起来之后，教程里的每个词都有了落点。

主线：AI 从「只会回答」到「越来越能自己干活」

AI 圈的词看着多，实际就一条线：AI 从只会回答，到越来越能自己干活。

每个黑话都是这条线上的一站。站在起点，后面每个词都在回答同一个问题：AI 能多独立地把活干完？

大模型决定它聪不聪明。提示词决定它听不听得懂。Agent 让它自己动手。Skill 让它按你的流程干活。MCP 让它够得着你的工具。Harness 让它进得了大项目。

这张图是全文的地图。下面每一节讲一站，从最底层开始往上叠。每节我都会先用人话讲它是什么，再讲它解决什么问题，然后说我实际怎么用，最后拆一个常见误解。

六层不是六个并列的选项，是叠加的关系。底下几层是地基，上面几层是增量：没有模型，一切免谈；有了模型不会问，白搭；会问了还得一层层指挥，累；指挥明白了，还想让它记住你的规矩。一路叠上去，才是一个能独立干活的 AI。

这条线不是画死的，它还在往前长。多模态让 AI 看得见图和声音，记忆让 AI 跨会话记住你，这些都是主线上的新站点。以后看到新词，先别慌着学，拿主线对一下它补的是哪一层，就明白它为什么会出现。

举个完整的例子。我让 AI「把这篇新文章发布到公众号」：

底层模型负责理解我的意图。提示词告诉它「走 wechat 发布流程」。Agent 接单后自己拆步骤。Skill 提供发布流水线（封面、高亮、内链）。MCP 让它真实登录公众号后台、上传素材。如果这个项目代码量大，Harness 保证它按规矩来。你看，一句话的指令，六层全都参与了。

大模型：AI 的智商底座

它是什么

大模型（LLM）是 AI 的大脑。GPT、DeepSeek、Claude、豆包、Kimi，这些都是大模型。它们本质上是同一个东西：用海量文本训练出来的神经网络，擅长的是「预测下一个词」。你现在读到的这些文字，如果是 AI 写的，也是这么一句句「猜」出来的。

区别只在脑子好不好使。模型的能力上限，决定了 AI 干活的天花板。后面所有黑话，都建立在这个底座上：模型不行，提示词写得再好也白搭。

聊大模型时还会碰到两个词，一起讲掉。一个是上下文窗口，指 AI 一次能记住多少内容。窗口小的模型，你跟它聊长了它就忘了开头；窗口大的，几十万字的代码库它能一次读完。另一个是推理能力，指 AI 处理复杂逻辑的能力。简单问答用不着推理，改业务代码、写复杂 SQL，推理能力的差距就出来了。

它解决什么问题

AI 圈聊「换模型」，本质是换大脑。DeepSeek 出来那阵，很多人把代码从 GPT 换到 DeepSeek，体验是「便宜了但变笨了」；后来又换回 Claude，发现「贵但真能干活」。这不是工具差异，是智商差异。

我用一个场景演示给你看。想象你雇了个员工，让他把桌子擦干净：

你（演老板）：把桌子擦一下。

员工 A（演一个笨模型）：好的。（原地不动，开始幻想自己已经擦完了）

员工 B（演一个聪明模型）：好的。（拿起抹布，把桌面、桌角、桌腿全擦了一遍）

同样一句话，A 和 B 干出来的活完全不一样。笨模型的问题不是不听话，是理解不了「擦桌子」里隐含的「要真的动手、要擦干净」这些默认动作。

我实际怎么用

我现在的主力是 Claude 系模型，处理复杂任务，比如让 AI 重构一段业务代码、设计一个数据模型。简单任务，比如翻译、润色、写个正则，用国产模型就行。把任务分给匹配的模型，比用同一个模型硬扛所有任务划算得多。

常见误解

「大模型就是高级搜索引擎。」不是。搜索引擎从现成网页里找答案，大模型是现场推理生成答案。问它「我这段 SQL 为什么慢」，搜索引擎只能给你别人的文章，大模型能对着你的 SQL 分析。

选模型还会遇到开源和闭源的选择。闭源模型（GPT、Claude、豆包）省心，开箱即用；开源模型（Qwen、Llama）可以私有部署，数据不出内网。我的判断：个人用和常规业务用，闭源模型足够，省下的时间值钱；有数据合规要求或者要深度定制，再上开源模型。别为了开源而开源。

提示词：把需求说清楚

它是什么

Prompt（提示词）是人跟大模型说话的方式。同一个模型，会不会问，结果天差地别。

它解决什么问题

大模型再聪明，也不知道你脑子里想要什么。提示词解决的就是「把需求翻译成人话给 AI 听」的问题。

还是那个场景。你想喝杯东西：

你：来杯喝的。

员工：好的。（端来一杯滚烫的黑咖啡）

你：冰的、甜的、别太贵。

员工：好的。（端来一杯冰可乐）

你看，模型没变，需求说清楚了，结果立刻不一样。我天天跟 Claude Code 打交道，最深的体会是：提示词不是咒语，是需求文档。模型定下限，提示词定上限。

我实际怎么用

写提示词我有三个固定动作。第一，给角色和背景，让 AI 知道它在替谁干活、项目是什么样。第二，给要求，说清边界和禁忌，比如「不要动测试文件」「输出保持简洁」。第三，给格式，让它按什么结构回答，代码、表格还是清单。

一个反面例子：很多人写「帮我优化这段代码」，AI 就会泛泛给建议。改成「这段代码在双十一高峰会打满 CPU，帮我找出热点并给出修改方案，不改业务逻辑」，AI 立刻知道该往哪使劲。

真实世界的提示词长这样：

你是这个项目的维护者，熟悉 Spring Boot + MySQL 技术栈。
背景：订单查询接口在高峰期 P99 从 50ms 涨到 2s。
要求：分析可能的热点，给出修改方案；只改查询相关代码，不动表结构。
输出：按「原因分析 / 修改方案 / 验证步骤」三段输出。

四行信息，把角色、背景、要求、格式全给了。AI 拿到的是一份能干活的需求文档，而不是一句模糊的请求。

常见误解

「提示词越长越好。」不是。提示词的核心是信息密度，不是长度。往提示词里堆「请务必、非常重要、认真一点」这类情绪词，一点用没有。真正有用的信息是：背景、约束、示例、输出格式。

「提示词技巧会过时。」一半对。具体技巧会变，比如各家模型对格式的偏好不一样，流行的写法过一阵可能就不灵。但原则不变：说清背景、给足约束、给出示例、定好格式。我每次换新模型，只调提示词的细节，骨架从来不动。

Agent：会自己干活的下属

它是什么

大模型加提示词，你还得一步一步指挥。Agent（智能体）的意思是：把目标交给它，它自己拆步骤、调工具、干完回来汇报。

它解决什么问题

普通大模型是「你说一步，它做一步」；Agent 是「你给目标，它自己走完流程」。它解决的是「指挥成本」问题：AI 能干的活越多，你越不能每一步都盯着。

再演一遍。你想让员工找一本书：

你（演老板）：去帮我找《深入理解计算机系统》。

员工（演 Agent）：收到。（自己走到书架前，一本本扫过去）

员工：老板，找到了，在第三排。

你：这版太旧了，我要第二版。

员工：收到。（重新翻找，找到后递给你）

你：以后找书就按这个标准来。

员工：明白，我已经记下来了。

看到区别没有？普通大模型是执行器，Agent 是有目标的执行者。它记住你的偏好，下次自动按标准来，这就是 Agent 和聊天工具的分界线。

Agent 内部其实是个循环：接目标、拆计划、调工具、看结果、不满意就调整再来。这个循环转起来，Agent 才真正「会干活」。它拆计划用的还是大模型，调工具走的就是后面要讲的 MCP，所以 Agent 不是凭空冒出来的，是前面几层叠出来的。

我实际怎么用

我把 Agent 用在两个地方。一是多步任务，比如「调研三个国内模型的价格和限制，整理成对比表」，Agent 会自己分几步做完。二是多 Agent 并行，让一个 Agent 写后端、一个写前端、一个做测试，最后我来合并，效率直接翻倍。工具调用、任务拆解这些进阶玩法，我在《还在说「agent 就是调一次 LLM」？你理解的方向就是错的》里拆过。

常见误解

「Agent 就是高级点的聊天框。」不是。ChatGPT 是聊天框，Agent 是给你干活的下属。区别在于：Agent 会调工具（读文件、跑命令、查数据库）、会循环（干完不满意自己重来）、会记住上下文（你的项目规矩、你的偏好）。判断一个产品是不是真 Agent，就看它能不能自己闭环一个任务。

用 Agent 也有坑，我踩过两个。第一个是任务拆太粗，把「重构整个系统」丢给 Agent，它直接迷路，产出没法看。正确做法是把大任务切成一个个能闭环的小目标。第二个是循环失控，Agent 反复重试同一个失败步骤，白烧钱。现在我会给 Agent 的循环设上限，失败两次就停下来问我，而不是无限重试。

Skill：把工作流封装成技能

它是什么

同一个活干多了，就该把流程固化下来。Skill（技能）就是把「怎么干一件事」写成包：步骤、话术、检查点都在里面。AI 一调用，就按这套流程走，不跑偏。

它解决什么问题

AI 每次干活都是「裸奔」的：今天这么干，明天那么干，质量全靠运气。Skill 解决的就是「稳定性」问题：把老师傅的套路沉淀下来，让 AI 每次都用同一套标准干活。

我实际怎么用

这是我自己用得最狠的一层。我的博客写作不是靠灵感，是靠一条固定流水线：选题自检、定类型、搭骨架、写正文、配图、去 AI 味、验证字数。我把这套流程写成了一个 blog-writing 技能，每次说一句「写篇文章」，AI 就自己按九步流程走完，每一步该读哪份规范、该跑哪个脚本，它都清楚。

发公众号也是一样。wechat-publishing 技能把「博客同步到公众号」做成了流水线：封面生成、代码高亮、内链替换、原文链接注入，一次跑完。

这些技能的价值在于，AI 每次干活都是同一套标准，不会今天一个样明天一个样。我积累到现在的技能体系，思路都在这篇《把「用 AI」做成工程体系，靠的是 28 个命令和一条回路》里。

常见误解

「Skill 不就是提示词模板吗？」比模板重得多。提示词模板是一段话，Skill 是一个完整的包：除了指令，还有配套脚本、参考文档、检查清单。我的 blog-writing 技能除了说明文件，还带着五份规范文档和一套字数验证脚本。模板告诉 AI 怎么做，Skill 给 AI 全套工具。

一个 Skill 的目录结构长这样：

blog-writing/
├── SKILL.md            # 主说明：九步流程 + 每一步读哪份规范
└── references/         # 规范文档
    ├── style-guide.md      # 写作风格
    ├── post-types-guide.md # 六类文章结构
    └── polishing-and-seo.md # 润色与 SEO

AI 加载这个技能时，先读主说明知道全貌，用到哪一步再翻对应规范。这就是 Skill 和提示词模板的差别：模板是一页纸，Skill 是一套文档体系。

写自己的第一个 Skill，从最常干的活开始。你每周都做的事，就是最好的技能候选：每周报表明细、上线检查、代码审查。先把流程写下来，再让 AI 按流程跑一遍，跑不顺的地方就是技能要补的步骤。技能不是一次写成的，是跑出来的。

MCP：接上外部世界的手

它是什么

模型再聪明，也碰不到你的数据库、GitHub、浏览器。MCP（模型上下文协议）就是那个统一接口，让 AI 通过它读写外部工具。

它解决什么问题

AI 工具链最大的问题是「每家一个接口」：GitHub 插件、数据库插件、浏览器插件，各说各话。MCP 统一了协议：工具方按一套标准暴露能力，AI 按同一套标准调用。装一个数据库 MCP，AI 就能查你的表、看你的索引；装一个 GitHub MCP，AI 就能读你的仓库、提 PR。

MCP 的标准里有三样东西：工具（Tool），AI 能调用的动作，比如查表、发请求；资源（Resource），AI 能读取的数据，比如某个配置文件；提示（Prompt），工具方预置好的常用指令。工具、资源、提示，就是 MCP 的三件套，几乎所有工具都能装进这个框架。

我实际怎么用

我现在的 Claude Code 配了一组 MCP：一个管项目文件，一个管浏览器，一个管监控数据。写代码时 AI 需要查某个接口的线上表现，自己就去了，不用我贴日志给它。等于给 AI 接上了手。

常见误解

「MCP 就是插件换个名字。」方向对，但差距在标准化。传统插件是每个工具一套私有接口，AI 学一个插件就要学一套协议。MCP 是一套公开标准，工具接入一次，所有支持 MCP 的 AI 都能用。它解决的是生态问题，不只是接口问题。

给 AI 配 MCP 的正确顺序，我也说下。先配最常用的两三个，比如文件系统和浏览器，用顺手了再加。别一口气装十几个，AI 的上下文窗口有限，工具越多，它越容易在选工具上犯迷糊。工具是给 AI 用的，不是给你收藏的。

Harness：让 AI 进得了大项目

它是什么

最后一站，Harness（开发环境）。模型、Agent、Skill、MCP 都有了，AI 还是进不了大型代码库。

它解决什么问题

原因很直接：大项目不是让模型硬读全部代码，而是要给 AI 搭一套环境，让它知道项目怎么组织、规矩是什么、该问谁。

这套环境就是 Harness：项目说明文档（CLAUDE.md）、钩子、技能、插件、子代理、代码地图。小项目里 AI 硬读代码就能干活，大项目里没有 Harness，AI 就是无头苍蝇：不知道哪些代码是核心、哪些是历史遗留、改哪里会炸。

小项目和大项目的差别，一句话讲清楚。小项目是一张桌子，AI 一眼看到全貌，直接动手。大项目是一栋楼，AI 推门进去只会迷路。Harness 就是这栋楼的导览：哪层是核心业务、哪层是公共设施、哪些房间不能乱进，全部标好。没有导览，模型再聪明也白搭。

一个基础 Harness 至少包含四样东西：项目说明文档，讲清架构、规范、技术栈；行为准则，写死 AI 的边界，比如改代码前先跑测试；常用技能，把重复工作流程化；自动检查钩子，AI 每次改完自动验证。搭好这四样，大项目里的 AI 才真正可控。

我实际怎么用

我处理大项目时的做法，是先把这套环境搭好，再让 AI 进去。项目根目录放一份说明，讲清架构分层、命名规范、测试要求；把重复性工作封装成技能；把验证脚本挂上钩子，AI 改完代码自动跑检查。这也是「AI 编程不是换更强模型，而是搭一套可复用的工程化工作流」这句话的出处。想看我在这条线上的完整实践，可以读《同样的 Claude Code，三个月把你甩开三倍的是这群人》。

常见误解

「Harness 就是给 AI 写个 README。」不止。README 是给人看的，Harness 是给 AI 建的运行环境。它包含规矩（CLAUDE.md 里写死的行为准则）、工具（技能和脚本）、护栏（钩子里的自动检查）。人看 README 理解项目，AI 靠 Harness 干活。

进阶黑话：从 Token 到 A2A，按难度排

主线六层讲完了，但教程里还有一批词没落位。这批词不是一个方向上的站点，它们分散在 AI 的各个层面。我按理解难度从低到高排一遍，每个词给你一句话的人话解释，再讲它解决什么问题。

Token：AI 的基本货币

Token 是模型读写的最小单位。中文里一个字大约折合一到两个 token，英文一个单词差不多一个。你问 AI 一个问题，消耗的 token 等于「读你的问题 + 写它的回答」的总量，各家 API 的计费、上下文窗口的容量，全部按 token 算。

上下文窗口：AI 的临时记忆

上下文窗口指 AI 一次对话能记住多少内容，单位也是 token。窗口大的模型，能把几十万字的代码库一次装进去；窗口小的，聊长了就忘开头。选模型时先看窗口够不够装你的项目，再比智商。窗口不够，再聪明的模型也会「失忆」。

记忆：AI 的长期存储

上下文是临时内存，关掉对话就没了；记忆是长期存储，下次打开还记得。现在 AI 的记忆实现很朴素：把重要信息写进文件，下次对话让 AI 先读。我的项目说明、技能文档、常用规范，本质都是 AI 的记忆。想让 AI 记得住，就给它一个能写能读的「笔记本」。

RAG：先查资料再回答

RAG（检索增强生成）解决两个大问题：模型的知识停在训练那一刻，以及它有时会一本正经地编。做法是把你的文档切块、向量化、存进数据库，提问时先检索相关内容，再连同问题一起喂给模型。我查项目文档、查历史决策时都在用这套。它不改变模型的脑子，只保证它回答问题前先翻资料。

多模态：看得见图，听得见声音

多模态指模型能同时处理文字、图片、音频。纯文字模型的「看」是别人描述的，多模态模型是真能看截图、听录音。实际价值很直接：给 AI 截一张报错图，它自己读；发一段会议录音，它自己转写总结。

微调：把知识刻进模型

RAG 是临场翻资料，微调是把知识直接刻进模型的参数里。代价也摆在明面上：要准备标注数据、要花算力、要养一套训练流程。我的判断很直接：个人和小团队基本用不上微调，先靠 RAG 和技能文档把活干了。等业务场景真到了「模型必须内化某个领域」的程度，再考虑。

A2A：Agent 之间互相派活

A2A（Agent-to-Agent）是 AI 圈最新的词之一，解决的是 Agent 数量上来之后的问题：多个 Agent 怎么协作。MCP 是 AI 接工具的手，A2A 是 Agent 和 Agent 之间的协议，一个 Agent 能把自己的任务派给另一个，还能互相传结果。看到这个词，说明「AI 干活」已经从单兵作战进入团队协作阶段。

这七个词不用一次全记住。我的建议是先用好 Token、上下文窗口、记忆这三个和日常最相关的，RAG 在遇到「AI 总编答案」时再补，多模态看产品需求，微调和 A2A 知道是干什么的就够。黑话的学习顺序，永远是够用为先。

黑话什么时候会骗人

先回答一个你可能已经想到的问题：这些词为什么扎堆出现？因为 AI 工具演进太快，术语的诞生速度跟不上。Agent 起初还只是学术词汇，现在已经是招聘 JD 的标配。黑话密集的地方，往往是变化最快的地方，这本身是好事，但骗子也混在其中。

主线之外，黑话还有一堆坑，主要四种。

第一种是概念通胀。厂商把 Agent、Skill、OS 这些词往产品名里塞，一个「AI 搜索」也要叫「Agent 平台」。看到新词先别慌，拿主线对一下：它让 AI 多干了一步什么？答不上来，大概率是营销词。

第二种是定义漂移。同一个词，各家说法不一样。OpenAI 的 Agent 和开源社区的 Agent，内涵差着一截。看教程时先确认作者用的是哪个定义，不然会越看越懵。

第三种是跳级速成。网上大量「三分钟搞懂 Agent」的教程，直接跳过模型和提示词讲 Agent，读者跟着学完，只知道名词不知道原理。主线顺序别跳，一层层往上叠，才是能用的理解。

第四种是伪需求。有些教程把「把 AI 接入工作流」包装成必须上全套 Agent 体系，其实你只需要一个提示词模板。判断标准还是那条主线：我的场景里，AI 差的是哪一层？差沟通就补提示词，差流程就补 Skill，别为了用 Agent 而用 Agent。

所以看教程也有方法。先扫一遍它讲了哪几个词，拿主线排个序，看顺序是不是从底层往上走的。再找它有没有讲清楚「每个词解决什么问题」，只解释名词不解释问题的，直接跳过。最后看有没有真实案例，纯概念堆砌的教程，看完也是忘。

最后：黑话是地图，不是门槛

回到开头那个朋友。我把这条主线讲给他之后，他再看那篇教程，第一反应是「原来大模型、Agent、Skill 是这么串起来的」，而不是「我又看不懂了」。

AI 黑话真正的门槛不在名词，在没有地图。有了「AI 从只会回答到越来越能自己干活」这条线，每个词都有了位置：大模型是底座，提示词是沟通，Agent 是动手，Skill 是流程，MCP 是工具，Harness 是环境。下次再看到新词，拿主线对一下，它让 AI 多干了一步什么，你就知道它值不值得学。

这也是我一路走下来的经验：工具会换代，模型会升级，这条主线不会变。把它记在脑子里，AI 圈的教程对你就不再是天书。

如果你现在还在黑话里打转，我的建议是从第一站开始动手：选一个模型，把你要干的第一个任务写清楚，让 AI 干一遍。干完不满意，就回到提示词那层调；干得顺手了，再往 Agent、Skill 那层走。黑话不是背会的，是用会的。先跑起来，主线会帮你把每个词安放到它该在的位置。
