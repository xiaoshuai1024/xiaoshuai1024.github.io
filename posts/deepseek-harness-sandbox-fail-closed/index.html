万一 AI 想删库？DeepSeek Harness 沙箱的 fail-closed 底线

给 Agent 授权是最拧巴的事：权限给小了活干不成，给大了心里发毛。模型哪天抽风输出一条 rm -rf 类的命令，谁来拦？

DeepSeek Harness（dsh）在沙箱这件事上的答案短得像句口号：拦不住，就不跑。这篇把这句话背后的机制拆开：沙箱是一个能力接缝、四条平台实现链、三档按次携带的策略，外加上周刚刚补掉的一个真逃逸。全部内容对着 packages/sandbox 源码讲。

一、底线只有一条：失败即关闭

安全领域有个词叫 fail-closed，失败即关闭：防护组件自己出问题时，系统的反应是拒绝服务，防线绝不撤掉。dsh 把这条原则写进了类型定义。

packages/sandbox/sandbox/src/index.ts 的第 119 行附近定义了一个专用错误码，语义是「请求了受限模式但找不到可用的沙箱后端」。这个错误会作为 tool/result 返回给调用方，让人分得清两种完全不同的情况：命令没跑（缺沙箱）和 命令跑了但失败了（执行错误）。注释里专门强调区分二者，因为混淆它们意味着一种静默降级：后端缺失时悄悄裸跑命令，用户还以为一切正常。

裸跑这条路在 dsh 里被堵死了：探测不到可用后端，就报错，任务失败。宁可这一单干不成，不开一道没有护栏的门。

二、一个动作：confine 包一层

沙箱能力暴露为一个极小的接口：SandboxProvider.confine(argv, policy)。输入是你原本要执行的命令和一个策略对象，输出在第 91 行注释里写得直白：「the argv to spawn in place of」——替换原命令的包装版参数。

也就是说沙箱不拦截、不代理、不监控，它只干一个活：把你的命令包进一层受约束的外壳再交还给你。隔离由这层外壳完成。接口简单到只有签名本身，这正是接缝架构的风格：能力用最小接口声明，实现随便换。

返回值也不止一层 argv。ConfinedArgv 还携带两样配套事实：所选后端的强制执行完整度，以及这家后端自己的否决方言。同一类文件拒绝在不同方言里拼写不同，bwrap 报 EROFS，Landlock 报 EACCES，Seatbelt 报 EPERM；消费方按自家后端的方言匹配，不拿跨后端并集去猜（docs/subsystems/sandbox.zh.md）。

三、平台链：不造轮子

包装用什么材料？packages/sandbox/sandbox-local/src/index.ts 开头几行列出了全部家底：

Linux:   bwrap → Landlock（内核级，原生 launcher）
macOS:   Seatbelt（sbcl）
Windows: ACL restricted-token runner

选择顺序按平台来：Linux 上先用 bubblewrap 容器化封装，不行就落到内核级的 Landlock LSM；macOS 用系统自带的 Seatbelt 沙箱描述文件；Windows 走 ACL 受限令牌。启动时还会对每条链做功能探测（probe），探测结果决定这次会话实际用的是哪条。注意这里同样适用第一节的原则，探测不到就明说，不带病运行。

四条平台链对应的都是各操作系统打磨了十年以上的官方隔离机制。dsh 自己写的只是适配层，不是第四种沙箱。

探测的仲裁规则也有讲究：功能探测只在多候选链之间做裁判，唯一候选可以跳过探测，它自己的拒绝就是失败关闭的终点（docs/subsystems/sandbox.zh.md 对 ctx.sandbox 的描述）。链条上多一道备胎，运行时就多一次择优的机会；只剩一道时，失败照旧如实上报。

四、三档权限，按次携带

策略对象的粒度比想象中细。index.ts 第 24 到 26 行定义了文件效果策略：read-only 只许读加少量临时区写入，danger-full-access 直接绕过隔离，中间还有工作区可写档。

第 62 行的注释值得停下来看一下：策略以 PER CALL（每次调用携带）的方式生效，provider 本身不持有任何固定策略。同一个瞬间，bash 可以带着只读策略跑，一个受限子代理可以同时带着工作区可写策略干活，文档原话说两个消费方可以「at the same instant」各用各的策略。

这意味着权限细到每一次调用：每笔任务都附带一份单独签订的审批合同。「以最小权限干活」在这里不是口号，是结构支持的能力。

把策略对象拆开看有四样器官（docs/subsystems/sandbox.zh.md）。mode 是文件效果档位；workspaceRoot 是绝对的可写边界，连不消费它的档位也一并携带，消费方因此可以只解析一次再决定走哪条执法路径；sessionId 是调用会话的品牌标识，Windows ACL 后端靠它为每对「会话、工作区」分配随机的私有临时目录和 SID；解析优先级也有定规：批准的显式模式压过会话日志里最近一次 sandbox/mode 事件，再压过部署默认档。

还有一条容易漏看的分流规则：只有受约束的两档会到达提供方，danger-full-access 的消费方直接 spawn 原始 argv，整个 ctx.sandbox 被绕开。全权执行在类型层面就与沙箱链路分了家，不存在「带着全权标记还过一遍包装」的灰色路径。

后端还要报告强制执行的完整度。full 表示该模式承诺的文件效果全部被管控；partial 表示活跃后端或较旧的内核 ABI 只管住其中一个子集，现役的部分情形包括较老的 Landlock ABI 与 Windows ACL 的 Everyone 和硬链接边界。要求绝对边界的消费方必须拒绝 partial 或向上暴露这一区别，文档把这写成了返回事实的一部分。

按次携带再细，也有管辖范围的诚实声明。官方复盘 0002 记录过一个教训：权限预设在运行时更新 bash 沙箱与审批状态，却挂载不了文件系统栈，受限默认组合始终拿不到意外的 fs 访问。复盘留下的纪律是权限控制只应描述其实际管辖的能力，策略粒度的边界由此画清。

五、提权重试也有一架窄梯子

沙箱挡住的合法需求有一条正门。packages/sandbox/sandbox/src/escalation.ts 定义了严格加宽表 WIDER_MODES：read-only 可以升到 workspace-write 或 danger-full-access，workspace-write 只能升到 danger-full-access，往下没有梯级。允许发布的目标集合同样是封闭枚举 ESCALATION_TARGETS。

有个设计决定值得停下看：加宽检查放在执行时刻做，工具 schema 里发布的只是这个封闭目标枚举。源码注释给出的理由是 schema 面向注册表全局，而会话的实际档位按次变化；把动态真值烤进静态枚举，会让低档会话拿着够不着的目标空转。

发起提权的参数配对也校验得严：sandbox_permissions 与 justification 必须同时出现，理由必须是非空句子，缺任何一边都抛 invalid escalation。防的是两种畸形请求：没有缘由的审批弹窗，和只有姿态不驱动任何动作的理由。

approveEscalation 把风险点收进一条固定顺序：先查严格加宽，非加宽请求直接拒绝且不打扰人；再看审批通道是否组装、有无 agent 可路由，任一缺席即失败关闭；然后才走 ctx.approval 弹窗。allowed-once、rejected、cancelled、unavailable 四种结果各有逐字错误文案，任何失败路径下命令都没有被执行过。

被拒时模型看到统一话术。bash 与文件系统两个执法家族共享同一套拒答标记 [sandbox: file access denied under <mode> mode]，附带一条同轮重试提示：用刚好够宽的模式加理由原样重试一次。模型认词靠固定词汇，不用猜，提示就贴在否决点的旁边。

依赖方向也做了隔离。审批通道是一个最小结构函数形状，没有直接引用审批服务的类型；工具层闭包住 ctx.approval.request 再传下来，escalation.ts 因此不必依赖 approval 或 agent 包。防越权的设计顺带防住了包间耦合。

六、可写根目录只有一个来源

workspace-write 到底能写哪里，答案收敛在 packages/sandbox/sandbox/src/roots.ts。模块注释自报家门：这里就是该含义的唯一住所（the meaning’s one home）。Seatbelt profile 与进程内文件系统围栏都从这里推导白名单，「write 工具写不了 /tmp 而 bash 能」这类不对称被结构性排除。

推导逻辑本身几十行：read-only 的允许列表为空；workspace-write 给出工作区根、宿主 /tmp 与 os.tmpdir() 三个路径，各自规范化后去重。规范化选的是 realpathSync.native，注释解释了挑选原因：原生实现按文件系统逐组件查找，行为与 chdir、spawn 以及各执法层保持一致。

失败方向同样保守：根目录不存在或不可读时返回原拼写，缺失的根匹配不到任何路径，效果接近没有授权；注释明说发明回退路径等于授予调用方从未点名的位置。bwrap 与 Landlock 方言保留各自的授予写法，跨方言一致性由测试钉住。

收进一个模块还有第二层用意：Seatbelt profile 与进程内围栏每次开工都向同一个函数取白名单，两边没有各自维护路径清单的机会。授权语义调整一次，两条执法链同时跟上，「不同步」这个状态在这段代码里找不到容身之处。

七、谁在盯着两套执法不说两家话

共享不止发生在 roots 层。ctx.invariants 是包自有运行时不变式的注册表服务（docs/subsystems/invariants.zh.md），每个工作区包发布一个 ./invariant 配套插件，用自己的 npm 包名登记检查；注册表负责选择规则、名称保留、子 fiber 生命周期和归因到包的失败上报。

检查内容的约定很具体：可以断言权威事件流或可变数据的性质，绝不允许断言服务或方法是否存在。能力接缝本来就允许换实现，拿「某服务在不在」当正确性判据会把替换通道焊死；不变式盯数据契约，这才是与接缝架构相容的守夜方式。

沙箱世界照此受益的例子写在 capability-seams 服务表里：ctx.sandboxPolicy 统一保管部署默认档和工作区根，bash 执行器与 fs 围栏两类强制组件都读同一个服务，因此两边不会限制到不同的根目录。策略单源加上包级不变式，双通道始终说同一种方言；无论底层换成哪家执行器，读数的来源都只有一个。

八、一条无害通知怎么骗过分类器

平台链的长尾行为有个完整样本。官方复盘 0004（docs/postmortem/0004-landlock-partial-notice-misclassified-child-failures.zh.md）记录：Landlock ABI 较旧的内核上，launcher 每次执行子进程前打印一行无害通知 landlock-run: partial enforcement (older Landlock ABI)，随后照常放行子进程。

当时的 harness 把这个前缀与任意非零退出组合判定为 launcher 失败。于是 ripgrep 无匹配时的退出码 1 被误报成 SANDBOX_UNAVAILABLE，结构化的沙箱错误还被文件系统搜索的通用 SEARCH_FAILED 二次遮蔽。误伤集中在可用性与诊断完整性：约束没有被削弱，命令也没有裸奔。

修复把证据门槛立了起来。RunnerFailureRule 现在携带可选的允许退出码、大小写不敏感的逐行致命签名，以及按整行精确匹配剔除的信息性行；Landlock 被映射成退出码 125 加一行非通知诊断。复盘结论值得抄进任何系统：进程归因需要多项独立证据同时成立，一个共享前缀证明不了任何事。

九、逃逸实录与收紧

沙箱不是铁板。8 月 21 日的 v0.1.1-rc.1 更新日志里有一条修复格外显眼：

Prevents sandbox escapes — confined processes could bypass Bubblewrap restrictions “through /proc/<pid>/root”.

被限制的进程能借 /proc/<pid>/root 这条符号链接路径绕出 bwrap 的 confinement。社区也有人做过四个安全漏洞的完整披露。这些案例放在第一节的原则下看会很清楚：发现逃逸之后的修法是把洞焊死，没有任何一处因为「修起来麻烦」而放宽约束。版本历史往前翻，rc.1 同一批更新还在改进缓存命中率的显示精度——安全和性能两条线并行推进，谁也不给谁让路。

十、落到你身上：敢开哪一档

机制的答案说完，说说选择。我的做法是让默认档保持在工作区可写，需要全盘读的任务临时提到 read-only 加显式路径白名单，danger-full-access 只留给一次性的、我盯着屏幕的任务。理由来自上面第二节：policy 是按次带的，收紧的成本接近零，先紧后松永远比先松后补便宜。

删库的恐惧不会消失，但可以被结构消化。当「拦不住就不跑」内建为系统能力、运维纪律退居二线时，放心把命令交给 Agent 才第一次有了工程基础。
