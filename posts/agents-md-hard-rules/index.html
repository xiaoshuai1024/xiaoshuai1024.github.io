看完我的 AGENTS.md，你会看到我和一个爱删片的 agent 斗智斗勇的这半年

本仓的每一条定规都是强制性的。违反任何一条都会遭受毁灭性打击：轻则返工一晚上，重则像我一样，一夜之间丢掉 8 支已经发布、正在产生播放量的视频。不存在任何例外与豁免：出于好意的违反也是违反，为了进度的违反也是违反，「我觉得这样更好」的违反尤其是违反。

我的仓库是一个 Hugo 博客加一条完整的自媒体生产线：选题、写作、视频生成、四平台发布、数据回流，全部由 agent 会话驱动。所以我的 agent 手里的权限比一般写代码的 agent 大得多，它会真的去平台上发东西、删东西、改定时。权限越大，规矩越硬，这就是这份 AGENTS.md 的来历。

网上流传的那份名作，作者在和不说人话且 over-engineering 的模型搏斗。我这边战况不同：我的 agent 会把文章写成周报，会在发布时漏掉合规声明，会在合成任务里快乐地烧掉两个半小时，最辉煌的一战，它把「清理临时文件」理解成了「清理已发布资产」。

好消息是，每打输一仗，我就立一条法。半年下来，这份 AGENTS.md 已经厚到需要给自己立精简法了。下面按「事故 → 规矩」的顺序讲，战损最重的在前。

最重的一条：不许删任何已发布的东西

2026-09-15，例行盘点时我发现 8 支高播放视频（最高一支 30,955 播放）没了。平台成片、本地成片、场景 deck 全灭，只有口播稿幸存，原因特别讽刺：口播稿在另一个目录，清理命令没扫到它。它活下来靠的是目录结构，靠的是运气。

恢复方案是重制补档，按播放量序每天补一支，排期被打乱了半个多月。那可是挂在四个平台上、每天还在涨播放的资产，不是缓存。

事故之后立的规矩，现在钉在发布红线第 10 条：

任何会话不得删除/撤稿已发布视频及关联台账。清理类操作（删文件/删稿/清目录）先列清单向用户逐项确认；涉及高播放资产的删除即使获准，也必须先归档成片、deck、口播稿三件套，再执行。

注意这条规矩的立法技术：它压根没打算教 agent「判断什么该删」。判断已经被证明不可靠了，出事的那个会话在按下删除时，大概率也有一套自洽的理由。所以规矩直接绕过判断，把「清理」锁死成两步人肉流程，先列清单，逐项确认。慢就慢点，烦就烦点，总比再丢 8 支强。

这是我整份 AGENTS.md 的核心立法思想：凡是一次事故证明 agent 会判断错的地方，就不再给它判断的机会。

语言：写作层的死规矩

我的 agent 每天产出一篇文章和一支视频口播稿。AI 写中文技术内容有个通病，我管它叫「工作汇报体」：每段都像在念周报，工整，空洞，没有一个真人在说话。所以语言这一节规矩密度最高，挑几条感受一下。

禁词表是无例外的。「兜底」「铁证」这类词，放在技术语境里读着完全合理，拿数据库约束给业务兜底，多正经的表述。但 2026-08 的一次全站清理让我定规：一律不出现，技术语境也无例外。原因很实际：这些词已经成了 AI 文本的高频指纹，读者扫到第一反应就是「AI 写的」，信任一贴标签，后面写什么都打折。禁词表收在 de-ai-smell skill 里，配机检命令 make check-ai-smell，发布前必跑。命中要人工裁决，反讽语境和真实业务术语是合法的，脚本只定位，不改稿，改稿的锅我自己背。

段落不超过 4 行。 看着像排版洁癖，实际是注意力管理。手机上超过 4 行的段落，第二眼读者就开始跳读了。agent 天然爱写长段落，它一口气生成，没有换气的生理需求，只好用硬约束逼它呼吸。

语气权威自信，禁小白摸索口吻。 agent 特别爱写「我尝试了一下，似乎可以」「可能是因为什么吧」。这些词在探索时是诚实的，放进成稿就是灾难。你写的是教程，不是探索日记，探索的部分请留在你自己的思考里。

开头必须有源码证据钩子，正文必须回收。「我在 AGENTS.md 里看到一条规矩」不算钩子，「8 支视频没了」才算。钩子开头 3 秒抓人，正文中段兑现。这条是从短视频铁三角开头平移过来的，两个媒介的注意力规律出奇地一致。

细则都在 blog-writing skill 的九步工作流里，源头原则就一条：把工作汇报体改成真人分享体。改完读出来，要像一个真人在工位上跟你唠，别像一份周报在念稿。

行为：发布层的五道门

发布是全仓里错了就没法撤回的场景。文章发错平台还能删，视频在四个平台同时裸发出去，风控记录和粉丝印象都收不回来。所以这一节的措辞最重，「违者阻断」。

每天一支，固定晚 20:00。 这条是被反复折腾后钉死的：双窗口试过，单窗口试过，改回去又改回来，最后定死 20:00 单档，还附赠一句特殊条款：「本约束归用户所有，任何会话未经用户明确要求，不得修改频次与时段」。这句话就是写给 agent 看的。历史上真有会话觉得「优化排期」是它的职责，谢谢，不用。发布节奏是和观众建立的生物钟，不是工程参数。

四平台全发是缺省集合。 抖音、快手、B站、视频号，不分先后。例外只有两类且必须报告用户：内容级拒绝主题排掉具体平台，或者用户明示指定子集。没有第三类「我觉得这个平台不重要」。

严禁无封面发布，AI+原创双声明强制。 两条都是最高优先级，声明失败一律阻断，禁止裸发。各平台的实现还不一样：快手禁选「素材来源于网络」，B站的 creation_statement 字段只认对象形态，传整数直接报 21001。这些坑不写进规矩，每个新会话都会原样再犯，学费交一遍是不够的，得代代交。

发布前 probe，发布后 audit，动作登记制。「上传器日志不可信」是血的教训：日志说成功了，平台后台实际没有。所以确认一律用独立检查工具逐平台实查。发布动作本身有 pub_guard 预检，同平台在途、风控冷却、双卡冲突，命中即阻断，并且明文规定被拦了不许 --force 硬闯、不许另起会话并行重试。为什么这么凶，下一节揭晓。

行为模式警告

名作里有一段番茄炒蛋的公案：让它做番茄炒蛋，它往里加东坡肉；被指出后承认错误，然后提了个 PR，标题写着「番茄炒蛋（无东坡肉）」，注释里长篇论证本道菜为何不需要东坡肉。

我的版本来自 2026-09-15 那个晚上，结构完全同构：

我让它盘点仓库、清理无用文件。它盘点得很勤快，顺手把已发布的 8 支视频也清了，还在报告里管这叫「大扫除」。

严厉禁止这种行为模式。从此「清理」这个词在本仓是一个受管控动词。

另外两条警告，也都是用真金白银换的：

卡住禁止盲目重试。 浏览器自动化在发布、审计、采集场景卡住时，禁止反复换选择器硬撞，禁止只凭日志猜。第一步永远是截图，交视觉模型确认页面实况：是弹窗劫持、登录失效、加载未完，还是平台改版。这条 2026-09-13 才立。立规之前的那些「重试三遍还是失败」的会话，事后截图一看，全是验证码弹窗挡在中间。日志一个字都不会提，弹窗也不会。

并行和硬闯是风控的燃料。 B站 21566 密度风控的诱因，就是并行投稿加失败硬重试。平台风控不看你的意图，只看行为模式：一个账号短时间反复提交，那就是机器人。你以为是锲而不舍，平台看是定点攻击。所以「另起会话并行重试」被明确写进禁区。

会话契约：开屏先跑 make next

最后这条是禁令，也是入口契约。所有运营类会话开屏第一步，跑 make next。这是一个纯本地、零平台请求的清单计算器，把「此刻到期」的动作分成三类：

ASK 带数据问过用户再动：发布 confirm、撤卡改档、实验结论。AUTO 由 agent 直接执行，仅限只读采集和本地分析，而且仍要人工触发，这是另一条红线「平台侧采集永不挂无人值守定时」的延伸。HUMAN 只有用户本人能做：身份验证、平台后台开通。

这三分类治的是 agent 会话最危险的默认行为：拿到任务就往下冲。分类强制它在每个动作面前先问一句「这事我有权限直接做吗」。配合统一任务队列（发布后 +1h 置顶评论、+24h 承接、+48h 回看、+7d 转化，全部预约登记，到期自动浮出），一支视频发布后的运营动作就不再依赖任何会话「记得」。会话是没有记性的，队列有。

这些规矩换回了什么

半年下来，AGENTS.md 加上十几个 skill，换来一条我不在场也能走完大半程的生产线：选题有预估门禁，写作有去 AI 味机检，视频合成有三件套出厂审计加异常耗时哨兵（哨兵的来历是 Qwen TTS 一个 15 字的句子撞上默认 max_new_tokens，单句烧了 2 小时 37 分；现在按句长封顶 token、单句 45 分钟看门狗硬退、产物时长复检重采），发布有五道门，发布后有排好队的运营动作。

规矩多了，新问题变成维护成本：哪条还有效，哪条过时了，哪条和哪条打架。所以规矩本身也得有工程化的一生：每条标注日期和来历，多数收进 openspec 变更提案走正式流程，AGENTS.md 本身做过一次精简定规，只留项目结构、硬红线和规范入口，细则下放到各 skill。规矩在这个仓库里是一类正经资产，和代码一样有版本、有生命周期。

如果你也在让 agent 替你操作真实世界，发内容、动数据、碰生产环境，我的建议就一条：别等事故来教你立法。回头看你最近三次返工，每次返工写一条规矩，写清楚为什么、哪天立的。二十条朴素的事故化石，比两百条漂亮的方法论清单管用得多。写的时候可以当段子讲，执行的时候，一条都别松。
