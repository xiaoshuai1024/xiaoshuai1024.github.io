Windows 用户的 DeepSeek Harness：一条刚铺好正变稳的路

网上的 Agent CLI 教程几乎都有一个隐藏前提：你在用 mac 或 Linux。而 dsh 最新一版更新日志的白纸黑字是 persistent PowerShell sessions on Windows PTY，发布方亲手把 Windows 写进了一线名单。

这篇沿三条线展开：Windows 在这个项目里的真实地位，只在 Windows 平台冒头的一小簇坑，再给一套用最少动作绕开它们的用法。标题里那句「刚铺好正变稳」，每一节都会给出对应的证据。

一、Windows 已经是官方一线平台

证据是版本日志原文：rc.8 的 changelog 里出现了 persistent PowerShell sessions on Windows PTY。持久 PowerShell 会话从这一版起进入 PTY 支持序列，与跨平台功能同批交付，排位就是核心迭代的正席。

「一线平台」这个词平时听得多，这次的分量由代码结构给出。终端子系统把 PTY 后端定义成按类型注册、可整体替换的一层，Windows 的 PowerShell 就是往同一张注册表里补的一种后端类型。文档同时写明：会话在后端或工具插件重载期间保持存活，PTY 状态与原始字节始终留在进程内。拿到这种结构性的座位，才算一线。发布、清理、关闭这些生命周期环节，由同一个服务统一接管，三条平台的会话在管理面上没有主客之分。

同一个版本里还有一条必须看清的提醒：SQLite 存储格式发生 breaking change，升级前要按说明处理已有数据文件。功能推进和数据迁移同时出现在一个 rc 版本里，说明这个项目的迭代节奏快得不容你跳版本升级。

对 Windows 用户的意义很直接：你可以名正言顺地把它当本机工具用，不用再绕 WSL 或者虚拟机。

二、Windows 版沙箱走的是哪条链

沙箱篇列过四条平台链，这里只取 Windows 那一行：

Linux:   bwrap → Landlock
macOS:   Seatbelt (sbcl)
Windows: ACL restricted-token runner

Windows 不用 bwrap 或 Landlock，也不借用 macOS 的 Seatbelt，走的是 NT 权限模型自带的 ACL 受限令牌：创建进程时剥掉不需要的权限，让它带着一张打了折的令牌运行。隔离材料和另外两家不同，能力接缝完全相同，confine 接口换成哪条实现都不影响上层调用。选原生机制还省下一层依赖负担：隔离随系统自带的安全组件走，不往机器里再引进独立的第三方运行器。

这套接缝在源码层面的形态值得看清：ctx.sandbox.confine(argv, policy) 接过消费方交出的确切 argv，返回一份包装后的 ConfinedArgv，策略按每一次能力调用携带；工作区根目录从会话 cwd 推导，先规范化再使用。命令跑完后你还能拿回一份沙箱事实，模式、是否发生拒绝、强制执行完整度各自独立报告，退出码与沙箱结论互不混写。danger-full-access 这一档另有一套路径，消费方直接 spawn 原始 argv，整条约束链都不进入。

错误语义同样经过设计。找不到可用后端时抛出错误码为 SANDBOX_UNAVAILABLE 的专用异常，调用方拿这个码就能把缺沙箱环境和命令自身失败分开归因。文档还把话说死：受限策略下静默的无隔离透传永远不合法。这两条合在一起，意味着沙箱缺位会被显式报告，不会伪装成一次普通的命令失败。

策略还有一层统一性值得知道：bash 类工具与文件类工具读到的是同一份沙箱策略服务，部署默认模式加上工作区根目录归一处保管，命令和文件操作不会被限进两个不同的根。想让某次命令拿到更宽的权限，走的是一次性、必须附带理由说明的重试通道，而且要先经过审批接缝对这次确切调用的放行。拒绝的分类口径整体偏保守，宁可多报也不会漏掉一次拦截。边界外的东西在架构里另有座位：容器、microVM 和远程执行作为完整能力接缝的同级实现存在，职责在于搬走整个运行时，平台内的进程隔离才归这条链管。

强制执行完整度则是另一个维度的诚实：full 表示后端管控了该模式承诺的全部文件效果，partial 表示只管住了其中一个子集。文档点名的 partial 情形目前有两个，较老的 Landlock ABI，加上 Windows ACL runner 的 Everyone 组与硬链接边界。需要绝对保证的消费方被要求自行拒绝运行，或把这个区别如实暴露给上层。read-only 模式下，Windows runner 连一个显式可写根目录都不授予，语义照样站得住。

成熟度差距也要摆上桌面：bwrap 和 Landlock 各有十年以上的实战年限，ACL 受限令牌是系统原生机制但在这个项目里历史短得多。能力等价是起点，打磨时间是另一回事，这也正是下一节 issue 清单存在的原因。

三、角落里的三个坑，个个有名有号

公开 issue 区里，Windows 相关的讨论形成了清晰的一小簇。#425 是编辑写入类问题：文件写入频繁撞上 ReplaceFileW 的 EIO 与共享冲突，目前没有重试机制，表现为保存时报错。#4689 出在原子写入层：写者锁泄漏，影响设置持久化，症状是配置改了却没存住。#4713 最重：强杀一个子进程可能拖崩整个 harness。

三个问题指向同一层：都在 Windows 的文件语义与进程语义边界上，属于换到新平台必然要补缴的学费。架构本身没有出问题，出问题的是新地基上还没磨平的接缝。跑这套东西之前建立这样的心理预期——偶发的写入报错先怀疑平台链，不用急着推翻自己的配置——能省掉大部分排查情绪。

值得多记一笔的是这三个问题的分布价值：没有一个落在模型调用、上下文管理这类核心链路上，全部集中在文件写入与进程终止两处。也就是说日常风险有明确的边界，知道边界在哪，比知道有多少个 bug 更能让人安心。遇到怪错时先对照这张清单归位，排查范围就从全站搜索缩小到两个目录。

四、动手前，把这几件低成本的准备做掉

结合我自己在 Windows 上跑它的过程，有几件事值得在装任何东西之前先做掉。官方开发指南的前置条件一节把这些门槛写得明明白白，照着核对一遍，比凭感觉装完再排错省力得多。

  1. Node 版本先把关。官方下限是 22.19+ 或 24+，CI 矩阵覆盖 22.19、24 和 26 三个版本。v22.13.0 卡在下限之下直接起不来，上手篇存有完整报错现场，这一步不满足，后面全是白折腾。
  2. 终端直接用 PowerShell PTY。rc.8 已经给了持久会话支持，不要再叠加花式终端模拟层去制造变量。pwsh 工具的官方描述里有两条 Windows 口味的约定值得记牢：路径一律写 C:\... 原生形式，环境变量用 $env:NAME 读；每次调用都在新进程里执行，cwd 和变量跨调用不保留，换目录传 workdir 参数，靠不住 cd 攒状态。
  3. 写入类怪错先搜 ReplaceFileW。遇到保存失败、EIO 字样，去 issues 搜这个关键词对号入座，大概率已经有人贴过现成的规避办法。
  4. 跟着 rc 版本走。Windows 相关修复一直在密集合入，旧版本的坑可能下个版本就没了。

PowerShell 会话用起来还有一处容易误判的地方，文档专门给了解释规则：一次发送返回时，理由可能是静默或超时，此时顶层 shell 仍然活着；只有理由标成 session_exit，才代表这个 shell 本体退出，某个前台子进程结束触发不出这个标记。判断会话死活时以返回原因为准，比盯着输出流猜可靠得多。

打算从源码构建的话，官方给出的最低配置是这样三条线：

Node.js 22.19+ 或 24+
启用了 Corepack 的 pnpm（仓库固定 11.7.0）
Git 2.26+

表后面还有一个很有用的完工信号：pnpm install 之后跑一次 pnpm run typecheck，它能干净退出，整个搭建就算验收通过。环境核查从此有了终点，你可以放心地把注意力转回正文工作。

另有两类高频误读，提前记住能省掉不少冤枉路，两条都出自 pwsh 工具的官方描述原文。命令在 Windows 上被强杀时，以 [exit code: 1] 结算且不带信号标记，把它当作一次中断看待就好，命令本身往往清白。文件操作被沙箱拦下时，返回值里带 [sandbox: file access denied under <mode> mode]，这是策略生效的专用标记，见到它就停下来调整授权范围，反复换写法重试只会原地打转。

长输出与长任务也各有一条官方姿势。超长的执行结果会截断只留尾部，完整内容写进独立文件并在结果里报出路径，需要全文顺着路径取即可；预计跑得久的命令标 run_in_background，调用立刻返回 job id，之后用 job_output 收增量输出、job_kill 收尾，前台不用干等。

五、接缝设计帮你把试错成本压进可控区间

这套系统里让我最安心的一处设计在能力接缝。shell 执行器层中，bash-local、bash-sandbox、pwsh-local 共享同一个接口，消费方名单里 bash 工具、pwsh 工具和两个 hooks 桥写得清清楚楚，对实现更换毫无感知。PowerShell 执行器顶替 bash 执行器时上层一行代码都不用动，这是文档表格里写明的契约，属于架构承诺。

落到排查场景，这份契约给了你一个干净的控制变量手段：出现怪异行为又拿不准层级时，把执行器换一个实现包再跑同样的输入，变量立刻被隔离出来。会话持久化也留了同样的余地，jsonl 与 sqlite 两个后端持久化同一套 SessionEvent 词汇，应用组合时选边即可。插件篇写过挂载与重载的机制细节，源码内部篇备好了完整的分层地图，两篇都值得一并收藏。

同一条原则延伸到持久终端：每个 PTY 会话由注册表铸造专属身份，权限校验比对的是持有会话的确切 Agent 身份，靠名称相近来冒认的操作会被直接挡下。后端启动到一半资源收不干净时，会带上专用错误拒绝启动，泄漏被显式摆上台面。

受管环境变量是另一处不起眼的干净设计。DSH 这一族前缀归 harness 所有，每次执行前先丢掉从父进程继承的同名变量，再注入当次收集的可信快照；你在全局环境里攒下的杂项进不了子进程，排查环境问题只需要盯住一个来源。

能力等价出自设计，坑藏在实现与平台细节里。每个关键位置都有同构替换件，Windows 上任何一颗雷都有办法绕着走或者换条道，这份从容感是「刚铺好正变稳」最有底气的注脚。

六、三周的项目，和时间客观存在的差距

评价口径我想放平一点：一个发布三周的项目，把 Windows PTY 这种又脏又细的活排进 changelog 正文，这是姿态很好的信号，说明双平台不在画饼阶段。信号归信号，macOS 与 Linux 积累了多年的生态打磨时间，Windows 需要按月追，这个时间差压缩不掉。

好在作为使用者，你需要的东西很少：知道一线地位是真的，知道坑集中在写入与进程层，知道自己手里有版本节奏这根杠杆。路的形态已经定了，剩下的是铺路的人把每一段接缝走完，走在上面的人提前看清哪几段还湿着就够了。
