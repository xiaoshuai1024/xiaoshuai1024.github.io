模型没换，账单差20倍：三家AI编码工具价目表拆解

先看一份我自己机器上的真实记录：一个 Codex 会话，五十四次调用，输入九百五十二万 token，输出只有六万六千，输入是输出的一百四十四倍。这份账单放到 DeepSeek、Anthropic、OpenAI 三家的现行价目表上结账，同一个 token 量，应付金额从四毛二到八块五，差出二十倍。模型一个都没换，换的只是价目表。

大多数人比价的方式是看「每百万 token 多少钱」。这篇给你一套更细的算法：账单是四个因子相乘，模型单价只是其中之一。价格数据截至 2026-09-20，口径在各节标明。

账单解剖：钱花在四个因子上

AI 编码的账单和人力成本逻辑不同：人力的大头在能力，token 的大头在重复。那份九百五十二万 token 的会话里，第一轮输入两万，最后一轮滚到二十二万，涨了十一倍，没有任何东西踩刹车。你付的钱，绝大多数没变成模型写的代码，变成了它每轮重读的聊天记录。

账单的结构，是四个因子相乘：任务 token 总量、壳的首包税、模型单价、缓存折扣。任务总量由活儿决定，短期动不了；首包税由壳决定，每轮原样重发的系统提示和工具说明书；模型单价看价目表；缓存折扣看你的使用纪律。四个因子里有两个半在你手里，后文的算法全围绕它们展开。

三张价目表，三种定价哲学

DeepSeek 的表结构最特殊，我直接从官方文档页抓的现行价（api-docs.deepseek.com，2026-09-20 20:45:00 抓取）：主力 deepseek-flash，输入命中缓存每百万零点零零三到零点零零六美元，未命中零点一五到零点三美元，输出零点六到一点二美元。每组两个数是峰谷两个价，谷时为峰时的一半。命中与未命中的价差五十倍，是三家最陡的缓存斜率。旗舰 deepseek-v4-pro 全线上浮约四点四倍，未命中价也只相当于 Claude Opus 5 的四分之一左右。

Anthropic 的表，按官方公告口径（2026-06-30 生效）：Claude Sonnet 5 每百万输入两美元、输出十美元，发布期价格已转永久；Opus 5 五美元和二十五美元；顶配 Fable 5 十美元和五十美元。缓存读长期按输入价一折计费，缓存写一点二五倍。牌价最贵，但一折缓存读配高命中率，实付没有牌面那么吓人。

OpenAI 的表，按官方定价页口径（2026-07-30 生效）：GPT-5.6 Sol 四美元和二十美元，缓存输入零点四美元；Terra 两美元和十二美元；Luna 零点二美元和一点二美元。坦白说明：OpenAI 定价页对我的网络环境返回 403，这组数字来自官方发布公告与多个独立来源交叉印证，引用请以官方页实时为准。

三张表摆在一起，是三种定价哲学：DeepSeek 把缓存和时段做成显式杠杆，奖励会安排任务的人；Anthropic 把缓存做成隐性折扣，奖励上下文管理得好的人；OpenAI 居中，胜在 Codex 生态顺手。你的使用习惯落在哪种奖励区间，比哪家单价低重要得多。

同一份 token 单，三家结账

现在把那份真实的 Codex 会话放到三张表上。口径交代清楚：九百五十二万输入、六万六千输出，命中率按九成计，这是对照自家实验里瘦指令目录的实测值取的整。

价目表计算应付
OpenAI GPT-5.6 Sol857 万×$0.4 + 95 万×$4 + 6.6 万×$20≈ $8.56
Claude Sonnet 5857 万×$0.2 + 95 万×$2 + 6.6 万×$10≈ $4.28
DeepSeek-flash 峰时857 万×$0.006 + 95 万×$0.3 + 6.6 万×$1.2≈ $0.42
DeepSeek-flash 谷时全部半价≈ $0.21

Sol 除以 DeepSeek 峰时，二十点六倍，标题的数字就是这么来的，每一分都来自算式。更要紧的是命中率这个变量：从九成掉到四成六（我在 Codex 上实测的胖指令目录真实命中值），同一份单变成 Sonnet 十一点八美元、Sol 二十三点六美元、DeepSeek 一点六五美元，每家自己的账单翻四到八倍。命中冲到九成八，Sonnet 回落到二点九一美元。模型价差是二十倍的杠杆，缓存纪律是四到八倍的杠杆，后者你自己就能拧。

一个诚实的边界：这是计算口径，不是把同一个任务在三家实跑三遍。不同模型 tokenizer 不同、能力不同导致轮数不同，真实对比会有偏差。但它足以回答先动哪个因子：先看命中率，再挑表，最后才挑模型。

壳的税：模型一样，账单差五倍

价目表只是账单的一半，另一半在壳上。伯克利 Sky Lab 和 LMArena 做过叫 harness 税的测量，七个模型、三个壳、二十一组配对：同一个模型，套 Claude Code 解一题一点三三美元，套只有四件工具的极简壳 Pi 只要零点六七美元，成功率一个九十七点八、一个九十六点七。能力几乎没动，成本差一倍，二十一组最大差五倍，完整数据在壳税实测那篇。

钱花在哪？首包。每轮请求都把系统提示词和全部工具说明书原样重发。Claude Code 的初始上下文是 Pi 的十倍以上，三十七件工具说明合计一百五十多 KB，最大单件两万四千字符。十五轮任务光首包就重发六十万 token，Pi 只要六万。我还补过一个受控实验：两个目录跑同一个任务，只有 AGENTS.md 不同，胖的命中率百分之四十六，瘦的百分之九十八，实付差五点五倍。壳的税不只是首包大，它还污染缓存：指令区每改一个字，缓存前缀全体失效。

DSH 在这一项上的思路值得单独说：一切皆插件，内核不预载工具说明书，用到什么挂什么，首包天然瘦，「说明书税」从预付改成后付。不是说 DSH 一定更省，它的轮数和调用密度不同；要说的只是，壳这一层的钱是可以设计的变量。

DeepSeek 的深算：峰谷与兼容端点

DeepSeek 的峰谷时段官方定义为工作日 UTC 01:00-04:00 与 06:00-10:00，换算成北京时间：工作日 09:00-12:00 和 14:00-18:00 收峰价，晚上、清晨、周末、法定节假日全部谷价半价。对个人的含义很直白：下班后让 agent 批量跑不急的活，自动省一半。把「什么时候跑」从习惯问题变成价目问题，这是三家里仅有的合法作弊码。

第三张牌最少人知道：DeepSeek 官方提供 Anthropic 兼容端点（api.deepseek.com/anthropic，官方文档明示），Claude Code 的壳可以直接指向 DeepSeek 的模型价。壳税和模型价两个杠杆交叉组合，玩法存在，边界也要说清：工具调用兼容度、长上下文表现、编码能力差异都会反映在轮数上，价目表便宜不等于账单便宜，换接后拿真实任务跑三天再下结论。

四条对账纪律

第一条，任务切换立刻开新会话，二十几万 token 的尾巴别让它陪跑。第二条，给指令区减负，仓库规则进项目文件、通用规则进全局，三点五千字的指令区每轮多收九百三十一 token 还拖垮命中率。第三条，守住缓存前缀，AGENTS.md 这类每轮都发的文件别频繁改，改一次等于缓存清零重来。第四条，批量任务排谷时，DeepSeek 谷价是官方半价，这一个动作比换模型省得多。

顺序别搞反：先知道钱花在哪个因子，再决定动哪个因子。顺序反了，就会出现「换了更便宜的模型，账单没变」的怪事，因为你的钱根本没花在模型单价上。

写在最后

把三张价目表放在一起，我的结论是：AI 编码的成本优化，第一杠杆是缓存纪律，第二杠杆是壳的选择，第三杠杆才是模型。大多数人从第三步开始省钱，方向用反了。

先把自己的会话流水拉出来，算一遍输入输出比和命中率，再决定动哪个因子，这一步成本十分钟，收益按倍数计。你的输入输出比是多少？留言报个数，超过一百的，今天就该对账了。想看这两家框架本体怎么选，移步姊妹篇26 万星 ECC 没引擎，23 万星 DSH 是真内核。
