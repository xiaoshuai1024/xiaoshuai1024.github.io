Codex 用法分 5 级：90% 的人卡在第 2 级，你在哪级

xiaoshuai1024 included in AI
About 200 words One minute 
Contents

  • L2 喂上下文：让 Codex 读你的规矩
  • L3 拆任务：从「帮我做」到「帮我做这一步」
  • L4 建管线：把重复动作固化成工具

  • 自测表：你现在在哪级

刷到一条视频：18 天跑 400 个任务，总结出 Codex 的 5 级用法。框架我认，数字我怀疑——不是怀疑他吹，是怀疑那个用法层级对普通开发者太远。我把这条视频的分级框架拿来，用我自己这一年的全仓实测重新填了一遍血肉：每一级的坑、每一级的升级判据，都是我真实翻过车的地方。

先给结论：90% 的人卡在 2 级。不是能力问题，是没人告诉你 2 级往上还有明确的台阶，以及每级台阶的判据长什么样。这篇就是那份判据清单。

L1 会提问：把 Codex 当问答机

第一级的特征就一条：打开就问，问完就关。「这段代码什么意思」「这个报错怎么修」，一轮对话解决一个小问题，不超过五行改动。

这级没有问题，人人都从这来。坑在于停在这级的原因：你只把模型当更快的搜索。同样一个报错，L1 的问法是「这个错怎么修」，拿到答案就走；更好的问法是「这个错的根因是什么，同类还有哪些」——多问半句，一次交互变一次学习。

升级判据很好测：你最近的 10 次对话里，有没有超过 3 次是连续追问同一个问题。全是「一问一答就散」，你还在 L1；开始连续追问，你已经往 L2 走了。

L2 喂上下文：让 Codex 读你的规矩

第二级开始有工程味：你会主动给上下文了。项目背景、代码规范、技术栈约束，写进对话开头或者项目根的 AGENTS.md，让模型带着你的世界观数活。

本仓就是活例子。仓库根有一份 AGENTS.md，写死的都是边界类条目：Hugo 锁 0.124.1 勿升级、源码仓和 Pages 仓是分离架构别混淆、画图一律 draw.io 禁 mermaid、部署走 deploy.sh 四步流程别自创。任何 agent 进来干活，第一眼读的就是它。效果直接：没有这份文件时，让 agent 改构建配置，它十有八九建议升级 Hugo 到最新版（升了主题就崩）；有了这份文件，「勿升级到更高版本」六个字省掉一轮来回纠正。

这份文件现在三千多字，但它不是一次写成的。第一版只有两百字，写着写着发现 agent 反复在三个地方翻车，就把这三处的边界补进去；后来又翻两次，再补两轮——所谓「改过三轮才站稳」，就是这个循环：跑，翻车，把翻车原因写成禁令，再跑。规则文件不是文档，是事故记录本。

L2 的坑是喂错方向。多数人拼命往上下文里塞业务背景，塞了三千字，模型改代码还是我行我素。模型缺的往往不是背景，是边界：哪些不许动、哪些必须保持、改完要过什么检查。三百字的禁令清单，比三千字的项目介绍更改变行为。

升级判据：你的项目里有没有一份 agent 每次都会读的规则文件。没有，你是 L2 的门外汉；有了，并且改过至少三轮（第一版一定不够用），L2 站稳了。

L3 拆任务：从「帮我做」到「帮我做这一步」

第三级开始拉开差距。特征：你不再把一个完整需求丢给模型，而是拆成有序的小步，每步有明确的完成标准和验收方式。

那条视频说 18 天 400 个任务，平均一天 22 个。我的实测账更糙也更有参照性：这个仓库目前 97 篇文章、全套发布管线，每一篇从选题到发布平均要过 9 个阶段——选题分析、骨架、正文、配图、验证、构建、发布、回填、复盘。一个「写文章」的模糊指令，agent 做出来的是四不像；拆成 9 个带门禁的步骤，每步确认再进，产出才稳定可控。其中两道门禁是硬的：文章草稿必须经我确认才准发布，视频的口播稿和分镜必须完整过目才准渲染——就是这套流程，多次拦下「内容跑偏但表面完工」的半成品。任务数量不重要，任务有没有「完成判据」才重要：400 个没判据的任务，不如 40 个有判据的。

L3 的坑是拆得太碎。拆到「改这一行」的粒度，你成了人肉编译器，agent 沦为打字员，效率反而低于自己写。健康的粒度是一步能独立验收：改得对不对，看输出就知道，不用读全部代码。

升级判据：接到大需求时，你动手前会不会先列任务清单（哪怕只在脑子里）。会列、每条能说出「怎么算做完」，L3 到手。

L4 建管线：把重复动作固化成工具

第四级，你开始把自己的工作流做成 agent 能直接执行的形态：skill、命令、检查脚本——同一个流程，第二次绝不该再手工讲一遍。

本仓的 blog-writing skill 是最典型的一个：选题自检、定类型、起标题、搭骨架、写正文、配图、收尾、润色、验证，九步工作流连同翻车记录全部写成了 skill 文件。写新文章时一句「按 blog-writing 走」，agent 拿到的不是提示词，是这一年的全部方法论。它的内部结构也值得抄：主文件只有五百行工作流骨架，风格规范、分类型模板、选题方法这些大块内容拆成五个按需加载的参考文件——agent 走到哪步读哪份，不用一次吞下全部。这招就是 L2 的升级版：上下文不再是一坨，是分层喂的。类似的还有发布管线、视频管线、选题分析管线——每条管线背后都是「这件事我手工做过 N 遍，第 N+1 遍必须自动化」的愤怒。

L4 的坑是过早固化。流程只跑过一次就做成管线，固化的是错误。我的习惯是手工跑三遍：第一遍摸索，第二遍修正，第三遍确认流程稳定，第四遍才值得写成工具。管线是重复的奖赏，不是规划的产物。

升级判据：数一数你有多少个固化下来的流程（模板、脚本、skill 都算）。少于三个，你在 L3 和 L4 之间；五个以上且每个都还在用，L4 实锤。

L5 全自治：管线自己跑，你只看结果

第五级是管线加上时间表：定时任务把「跑管线」这件事也从你手里拿走，你的角色从执行者变成验收者。

这个仓库现在的日常就是 L5 的样子：视频渲染挂后台，完成后自动走定时发布，晚上 8 点平台侧自动出片；发布后 1 小时置顶评论、24 小时回复、48 小时数据回看，全部是流程里的既定动作；选题分析从待办清单拉取、三维评分、出报告、写回，一条命令。我不盯过程，只看两样东西：门禁的红绿灯，和最终数据。

L5 的坑最隐蔽：自治系统出错时，代价也是自治的。我曾经让管线自动跑，结果一个参数没对上，半成品差点直接发了。所以到 L5，课题从「自动化做多深」变成了「门禁做得多硬」。本仓现在每条视频出片前要过四道机器验收：hugo 构建无报错、去 AI 味扫描零命中、封面像素签名 PASS、metadata 文案 lint 零 FAIL——任何一盏红灯，流程自动停线等人，不带病出片。自治的程度，永远不能超过门禁的硬度。

升级判据：你有没有「睡一觉起来，工作已经做完且结果可信任」的流程。有一个，够到 L5 的边；有三条以上互不依赖的自治管线，L5 你算站稳了。

自测表：你现在在哪级

对着下面五条，从上往下找第一条做不到的，那就是你当前的台阶：

  • 我的对话里全是单轮问答（→ 你在 L1）
  • 项目里有一份改过三轮的 agent 规则文件（→ L2 稳）
  • 大需求动手前先拆步骤、每步有完成判据（→ L3 稳）
  • 有五个以上还在用的固化流程/脚本/skill（→ L4 稳）
  • 有三条以上带硬门禁的自治管线（→ L5）

要说明的是，这五级不是鄙视链。L1 用得好照样解决真问题，L5 用得差照样炸现场。分级唯一的作用是给「下一步练什么」一个明确答案——卡在 L2 的人去练 L3 的拆任务，比去研究什么新模型有用得多。

那条 18 天 400 个任务的视频，框架是对的，我的实测只是把每级台阶的判据说得更具体。工具的等级撑不起用法，用法的等级才决定产出——同一个 Codex，在 L1 手里是高级搜索，在 L5 手里是一支不下班的工程队。差距不在模型，在台阶。
