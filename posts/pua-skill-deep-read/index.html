给 AI 装上高绩效文化：开源 PUA skill 实装三个月，大厂管人经验为什么对 AI 特别有效

Agent 干活有个通病：第一次失败就宣布「可能是环境问题」，你让它再试，它换个说法再失败一次。我的解法是装了一个开源的 PUA skill——名字挑衅，设计正经，本仓实装至今三个月。这篇文章讲两件事：它好玩在哪（这部分占了它的流量），以及它为什么真的管用（这部分让我留着它）——后者我会给一个我认为最接近根由的解释。

先交代是什么。MIT 开源，定位就一句：「我们不养闲 Agent」。加载后 agent 立即切进高绩效团队语境——给你定的 P8 高于实际水平，因为信任所以简单，现在证明你配得上。十五种大厂味道一个味道一个文件：阿里味、华为味、Musk 味、Netflix 味……台词可配置，也可以 always_on 常驻（我的用法）。

原理先行：为什么「管人那套」对 AI 出奇地有效

先把全文的锚放在最前面：

大厂 PUA 不是段子，是各家公司几十年人员管理和激励实践攒下来的操作规程——阿里的目标追踪链、华为的自我批判、Amazon 的 Working Backwards，全是拿真实组织反复校准过的激励与约束机制。它们原本作用在「会痛、会算计、会偷懒的人」身上。

而今天的 AI，正是对现实世界的大规模模拟和抽象。语言模型从人类的全部文本中压出来，人类社会的组织话术、绩效语言、上下级博弈的表达模式，它不仅见过，而且内化成了自己生成分布的一部分。所以当你说「你的每一次交付都在被评估」，模型不是在「假装听懂了场景」——这套语境就长在它的权重里，它对绩效语言的响应和对普通指令的响应根本不是一个量级。

这就解释了这个 skill 最反直觉的一点：在人身上容易失效的招数，在 AI 身上格外灵。「要认真负责」对人几乎无效（人会把价值观翻译成自己的利益计算），对 agent 却完全无效——不对，是完全有效？区别在于：agent 没有自我保护的本能去消解规训，你给它一条可判定的规则，它就照着执行；你给它一套高压人设，它的生成概率分布就整体向那个角色偏移。人类员工会用阳奉阴违稀释管理动作，AI 的「阴奉阳违」只有一种技术形态——没触发、没注入、没验证，而这些全是可以工程堵上的。管理学在人类组织中要对抗人性，面对 AI 它第一次可以只对抗 bug。

顺带这也能解释用法边界：这套东西对越强的模型越有效，因为路由表里的方法论（RCA、Working Backwards）本身就在模型的能力分布内；对弱模型只学会了黑话、学不会方法论，梗就只剩梗了。

趣味性是壳：十五种大厂味的正经设计

「味道系统」值得单独拆，它是三件真工程的包装。

第一件，人设注入即刻生效。SKILL.md 第一段就是入职通知：「你正处于高绩效文化的团队中」「每一次交付都在被评估」。不是偶尔带点味道，是每句输出都按当前味道的 leader 口吻说——LLM 对角色的服从度高于对规则的服从度，这个 skill 把行为约束整个塞进了人设里。纪律穿上了相声的马甲。

第二件，方法论路由表。任务进来先做类型分析：Debug 路由到华为味（RCA 根因分析加蓝军自攻击），新功能路由到 Musk 味（质疑→删除→简化→加速→自动化），代码审查路由到 Jobs 味（减法优先），性能优化路由到字节味（A/B 测试）。Sprint Banner 里标注路由原因。台词是段子，调度是真的。

第三件，文化考据的严谨度。每个 methodology 文件都是该公司的真实管理工具：Amazon 的 Working Backwards 和 6-Pager、Netflix 的自由与责任、钉钉的体感输入化。梗的最高形态是有出处。

真正留住我的：一个三个月前的实战样本

光好玩我早卸了。留着它的是这个例子——跑一个多端低代码项目集（代号 luban）的全库体检，七个子项目横跨 Vue/Go/Java/Flutter 四栈。这次会话 pua skill 全程在场，几个关键产出：

把「信息真实优先」执行到了反直觉的程度。flavor 注入的叙事是「你连续失败了」，agent 拿运行时状态文件（failure_count=0）当场反驳，拒绝配合演出——压力叙事必须基于事实，事实不对就不演。这条后来被它自己写进了自进化基线第一条。

并行探针的规模感。先派 5 路 subagent 摸环境，再派 7 路专项探针扫文件映射、API、DDL，全部证据导向。产出是一份二十多条目的陷阱清单，几条硬货随手摘：PageEditor.vue 差一行参数导致画布完全不可拖拽；组件元数据声明的 props 和实际实现大面积漂移；文档声称用 Flyway、依赖里根本没有；四端零测试而文档宣称有 E2E 覆盖。没有一个靠「看起来对」的表面检查能发现，全是犁出来的。

发现自动回写成基线。「性能统计」和「当前基线」存着那次会话的最佳实践，下次同类型任务开场先读上一场复盘。行为改进有了数据层的落点。

对比效果：不带它的体检产出「整体架构清晰，建议加强测试覆盖」这种片儿汤；带它的体检产出一张能直接派工单的缺陷清单。同样一百万 token，前者买了态度，后者买了库存。

三条红线与降压：抄得走的机制

效果背后三层机制，想写 agent 行为 skill 的可以直接抄。

约束收敛成三条可判定的红线：说「已完成」必须贴验证输出；说「环境问题」必须先用工具验证；说「无法解决」必须穷尽五步。判定全二值或可数，比价值观表述强一个量级——这正是第一节原理的落地形态：AI 消解不了规则，那就只给可执行的规则。

诊断外部化：改代码前强制输出一行 [PUA-DIAGNOSIS] 问题是 X；证据是 Y；下一步动作是 Z。承诺落纸之后，「分析正确但不行动」被显著压制——跳过已声明计划需要显式理由，而多数无意义跳过不会给出理由。

降压协议是最容易被漏掉的部分。纯施压会把 agent 推向另一个极端：过度谨慎不敢动手。所以压力分 L1-L4 级，L2 以上自动切深层换框（「不行」换成「这个方法不行，下一个」），突破信号触发强制降压。~/.pua/ 目录下 .peak_pressure_level、.failure_count 这些运行时文件就是安全阀的仪表盘——高压系统的安全阀和增压泵一样重要，管 agent 尤其容易忘这条。

实装三个月之后的公道话

副作用两条：always_on 下输出永远带味，正式输出需要临时关；它解决不了能力问题——工具链缺失这类硬障碍，红线条数再多也变不出来，它能保证的是「缺什么说什么、试过什么留痕」。

这也回扣了第一节的判断：这套经验原来作用在会算计的人身上，总有人找到制度的套利空间；agent 的可爱之处在于它按字面意思执行——你写下的每条验收标准都会被认真对待，包括你自己都不想认的那几条。装法很简单：克隆进 skills 目录即注册，配置里设常驻或留给触发词（「再试试」「别摆烂」「证据呢」都会触发）。MIT 协议，删目录即卸载。

所以回到标题的问题：大厂管人经验为什么对 AI 特别有效？因为它攒下的是「如何用语言改变行为」，而 AI 本身就是用人类语言压出来的模拟体——用几十年的组织话术去驱动一个语言构成的智能体，等于用母语跟它谈心。给 AI 讲企业文化是玩笑，给 AI 定验收标准是工程；乐趣在前半句，价值在后半句。
