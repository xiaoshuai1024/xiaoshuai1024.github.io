10 万星 Caveman 领衔：四个省 token 的开源 skill，从输出砍 65% 到上下文换血

xiaoshuai1024 included in AI
About 400 words 2 minutes

2026-08-26 我分析过一个会话吃掉 952 万 token 的 Codex 账单，结论比账单扎心：大头不是写代码花掉的，是重复读入的文件、来回贴的背景和 agent 的碎嘴。当时给自己立了家规，纪律管住人；剩下的浪费得靠工具管，社区已经把工具做成了小生态。

我按「治哪一段浪费」把 GitHub 上的省 token skill 盘了一遍，只收高星和知名度经过社区验证的仓，四个全是万星级。先建判断框架：agent 的 token 浪费发生在四个环节，说得多（回复十行有效三行）、记性差（同样的背景贴到第三遍）、喂得陈（整本过期文档塞进上下文）、返工贵（做错了推倒重来，同一份活烧两遍 token）。开自己的会话记录对号入座，浪费在哪一环就装哪一味药。别四个全装，skill 加载的每一行都从你的上下文里扣。

Caveman：输出砍 65% 的祖师爷（103,664★）

如果只装一个，装这个。口号语法就是错的：「why use many token when few token do trick」。它让 agent 用穴居人腔说话，代码、命令、报错原样保留，纯聊天输出砍 65%（官方实测口径）。效果拿同一个意思的两种说法对比就懂：「我已完成对配置文件的修改，接下来运行测试验证」变成「Config 修好。跑 test 验证」，信息没少，字数去了六成。

值得抄的是 README 里那套压缩纪律：不造自创缩写（tokenizer 切得更碎，一个不省）、否定词一个不丢（丢了意思反转，修复误解比省的贵）。

10 万星后它攒成了全家桶：caveman shrink 压命令输出（字节级可还原）、proxy 层在 Claude Code 实测省 33.2% 输入 token（官方 54 轮基准）、pixel mode 把 SKILL.md 渲染成 PNG 让模型看图读，税基从文本换成图片。

比口号更重要的是常驻机制。在 system prompt 里写「请精简回答」，十几轮后服从衰减，啰嗦回潮；skill 的持久化让压缩规则挂在每一次响应上，第 1 轮和第 40 轮一个口径。

怎么用：装完敲 /caveman 挂档常驻，日常 full 档够用；写文档和邮件前记得 off，语气在「人读」场景里是有价值的 token。覆盖 30+ agent，MIT 加 BSL 双协议。

安装（Claude Code 插件市场）：

claude plugin marketplace add JuliusBrussee/caveman
claude plugin install caveman@caveman-skills

planning-with-files：工作记忆搬到磁盘（26,635★）

「你的 context 会死，计划不会。」它把工作记忆分成三个文件放上磁盘：task_plan.md 管目标分解，findings.md 管已确认的事实，progress.md 管进度游标，每回合由 hook 把最小快照重新注入 context。/clear、会话崩溃、compaction 都杀不死这三块石头板。

省钱逻辑在这里：上下文丢了就得重喂背景，重喂是最贵的浪费。作者内部基准，带三文件的新会话平均 5.0 回合恢复现场，裸跑要 13.3 回合。

差出来的 8.3 回合干的都是重贴背景，消耗的恰是账单里最贵的重复输入。数字是自测，没有第三方复核，方向和我的体感一致。

它和 CLAUDE.md 分工明确：CLAUDE.md 存几周不改的长期规范，三文件存每小时都在变的任务态。分开住，每回合注入的快照才够小，注入本身才不变成新的浪费。60+ agent 可装，npm、Claude Code 插件市场、npx skills 三条路。

怎么用：开工时让 agent 把任务分解进 task_plan.md，确认过的结论随手写进 findings.md，每完成一步更新 progress.md 的游标，hook 会在下个回合把这三样接回上下文。习惯养成之后，/clear 不再是心理负担，是随手可用的清空键。

安装：

npx skills add https://github.com/OthmanAdi/planning-with-files

Context7：文档按需拉，别整本喂（约 6 万★）

给 LLM 提供实时、当前版本的代码文档的 MCP server，2026 年这条赛道的默认答案。agent 写代码时拉到当前版本的库文档，参数名、方法签名、废弃标记全是真的，不靠「记忆」里可能过时甚至编造的 API。

省 token 的角度容易漏掉它，其实它治的是「喂得陈」这一环：把一份几百页的参考文档贴进上下文，是输入侧最粗的管子之一，而且贴的还是过期版本。Context7 反过来，按问题拉当前版本里需要的那几页，其余的不进上下文。用新版本库的项目几乎是刚需，编造 API 一次返工的代价远超省下的那点文档 token。

怎么用：装好后在 prompt 里加一句 use context7，agent 查 API 时自动拉真实文档；也可当 MCP server 常驻。免费额度够个人用，context7.com/dashboard 申请 key 拿更高限额。需要 Node.js 18+。

安装（一条命令走 OAuth 认证、生成 key、自动装好 skill）：

npx ctx7 setup

可用 --claude / --cursor / --opencode 指定目标 agent。

OpenSpec：返工是最贵的浪费（约 6.3 万★）

Spec 驱动开发工具，把 AI 编程从「对话式临场发挥」变成「先写 spec、再按 spec 实现」的工程化流程。需求落成可读、可追踪的 spec（proposal、design、specs、tasks），agent 按 spec 一步步实现，每步都能回溯到规格。

它在省 token 榜单里的位置靠一条朴素的道理：做错重来的返工，是全链路最贵的浪费。一次「AI 一顿操作、结果不对」的返工，等于同一份活烧两遍 token，还搭进去排查时间。spec 前置把「做什么」先约定清楚，一次做对，账单直接砍掉返工那一段。这也是我在用的主力工具，插件榜里专门写过它的方法论位。

怎么用：项目里 openspec init 初始化，新需求先出 proposal，确认后落成 specs 和 tasks，agent 按任务清单逐步实现，每步可验证。需要 Node.js 20.19.0+。

安装：

npm install -g @fission-ai/openspec@latest

怎么选：一张对号表加一笔真账

浪费环节对症 skill药方
说得多Caveman穴居人腔常驻，输出砍 65%
记性差planning-with-files三文件石头板，5 回合恢复现场
喂得陈Context7文档按需拉当前版本
返工贵OpenSpecspec 前置，一次做对

两个战场的分工见下图：一头治「模型说出来的」，一头治「喂进去的」，会话里输入远大于输出，两头一起掐才见效；OpenSpec 管的是更前面一步，别让活白干。

两周路线当参考：第 1 天装 Caveman 挂 full 档，记下当日 token 基线；第 3 天装 planning-with-files 治当周最长的会话；第 7 天回翻会话日志，文档贴得最多的加 Context7，返工最多的加 OpenSpec；第 14 天复盘，留下省得动的，卸载没用的。

真账收尾：我本机常驻一套命令输出压缩管线 rtk，2026-09-05 查累计数，4279 条命令输入 4.7M token，省下 4.1M，87.9%，大头是 rtk read 砍掉 2.9M 和 rtk grep 砍掉 1.1M。它和四个 skill 不同层，rtk 压工具输出，skill 管 agent 语言，两层叠起来才是完整省法，完整用法我另写过一篇。口径提醒：caveman 的 65% 是输出口径，proxy 的 33.2% 是输入口径，别拿 65% 直接套总账单预期。
