GLM-5.3 发布实测：编程暴涨 50%，开源第一的成色拆开看

2026-08-14，智谱发布新一代基座模型 GLM-5.3。官方通稿的关键词很直白：编程能力最强的开源模型。这个月的国产大模型赛道已经卷成一锅粥——一个月内三家厂商先后完成关键版本迭代，智谱这一发是其中最受程序员关注的一发。

我盯 GLM 系列有段时间了。从 GLM-5 到 5.1、5.2 再到 5.3，半年四代，每一代都在编程榜上往前拱一截。5.1 那代在 SWE-Bench Pro 上超过 Claude Opus 4.6 的时候，我还专门跑过对比；这次 5.3 的通稿数字更猛：内部体感评测较 5.2 提升 50%。

数字越猛，越要拆开看。这篇我把 GLM-5.3 的每项成绩按口径归类——哪些是公开榜、哪些是内部评测、哪些是第三方对比，再串起 GLM-5 系列这半年的榜单轨迹，最后落到最实际的问题：这套能力怎么接进日常工作流，Coding Plan 的钱花得值不值。

先看清这是一次什么发布

GLM-5.3 的发布节奏分两步。API 在 2026-08-14 当天上线，全量用户可用，同时纳入 GLM Coding Plan；模型权重在发布约两周后开放，开源地址在 zai-org/GLM-5 仓库，MIT 权重协议——这是智谱一贯的打法，先服务后权重，商业化和开源声誉两头都要。

能力参数这边，GLM-5 系列的基础规格是 200K 上下文窗口、128K 最大输出；从 5.2 开始，Coding Plan 用户在编程场景下可以用到 1M 上下文。1M 这个数字对 agent 工作流是有实际意义的：把一个完整中型工程连同依赖清单、构建脚本塞进同一条推理链路，200K 会勉强，1M 才算从容。

128K 最大输出这个参数值得单独说一句，因为它经常被上下文窗口的光环盖住。输出窗口决定了模型单次能产出的代码量上限——重构一个大文件、一次性生成完整的脚手架、输出一整份带注释的迁移脚本，这些任务真正吃的是输出 token 而不是输入。很多模型的输出上限卡在 8K 到 32K，遇到大文件就得拆着写，拆的过程就是出错的过程。128K 意味着绝大多数单文件任务可以一口气写完，配合 1M 上下文读入整个工程，一来一回都留足了余量。

定位上，5.3 没有换架构叙事，通稿强调的重点是三个：AI 编程、Agent、长程任务。这三个词不是并列的口号，是一条递进链——编程是单点能力，Agent 是把单点串成多步骤执行，长程任务是串起来之后还能稳定跑完。评测成绩的分布也印证了这个重心：最强的项全在终端执行和持续工程这一侧。

官方成绩单：三个公开榜，一个内部评测

GLM-5.3 的通稿成绩单，我按可信度从高到低拆成四项。

第一项，Terminal-Bench 3.0 开源第一。Terminal-Bench 测的是终端里的真实任务执行——给你一个 shell 环境和一个目标，模型自己规划命令、处理报错、跑通流程。这是当下离「AI 编程日常体感」最近的公开榜之一，因为它测的不是「会不会写这段代码」，而是「能不能把这件事办成」。开源第一的含义是：在所有开放权重的模型里，GLM-5.3 是这个榜上最强的。闭源那边，2026-08 的榜首是 Claude Opus 5 Max 配 mini-SWE-agent 的 43.5%，开源和闭源在这个榜上仍有差距，但差距在收窄。

这里值得多说一句两类榜的口径差异，因为它直接决定你该怎么给成绩加权。SWE-bench 这类 patch 榜的判定方式是「模型给出 diff，测试通过就算过」，题目来自真实 GitHub issue，但交互是单轮的；Terminal-Bench 这类执行榜把模型放进沙盒终端，允许它连续行动几十步，中途报错要自己爬出来。前者测知识，后者测行为。做 agent 开发的人都清楚，行为能力的爬坡比知识能力难得多——知识可以靠数据堆，行为要靠执行轨迹上的反馈学习。GLM-5.3 把重心压在执行侧并拿到开源第一，这个信号比单纯的分数更有信息量：下一代模型的竞争主战场就在这里。

第二项，Agents’ Last Exam (CLI) 84.5%。这是相对 GLM-5.2 提升最直观的一个数：5.2 是 77.2%，5.3 到 84.5%，涨了 7.3 个点。这个榜专测 CLI 环境下的 agent 综合能力，题目横跨工具调用、环境推理和多步骤规划——恰好是 GLM-5.3 官方强调的三个重心的交集。7.3 个点的代际提升，在头部模型区间不算小数。

第三项，DeepSWE 1.1 拿了 66%。DeepSWE 是软件工程专项基准，考的是真实仓库级别的 issue 修复。66% 这个成绩放在 2026-08 的开源模型里是第一梯队——作为参照，DeepSeek V4 Pro 在 SWE-bench Verified 上是 80.6%，两个榜口径不同不能直接比，但同一个梯队的判断成立。

第四项，内部自建体感评测提升 50%。这个数要单独拎出来说。它是 Z.ai 私有 Code Bench 上的成绩，High 档位较 GLM-5.2 提升 50.2%。「提升 50%」读起来最猛，但注意三点：这是内部评测，题目不公开，外人无法复跑；50% 是相对提升，从 60 分到 90 分是 50%，从 20 分到 30 分也是 50%，基数不透明；「体感评测」四个字说明打分维度里有主观成分。我不是说内部评测不可信——厂商自建榜往往比公开榜更贴近真实使用场景，题目也更难——而是说它和公开榜是两种证据，前者证明「官方认为变强了」，后者证明「第三方口径下变强了」。两个都有，结论才稳。

另外还有一个容易被略过的单项：ExploitGym，网络安全攻防测试。GLM-5.3 在这个榜上同样表现突出。安全能力和编程能力共用一个根基——对代码执行环境的深度理解，这项强说明模型不是只会生成代码文本，而是对「代码跑起来会发生什么」有模型化的掌握。写安全扫描、依赖审计类工具的团队可以关注这个信号。这个榜还有一层现实意义：让 agent 接管终端之后，能不能识别出一条命令的危险性、会不会把密钥写进日志，直接决定你敢给它多大的权限。攻防评测强的模型，在权限收敛这件事上通常也更可靠，这是我愿意给它加的一分。

内部自建体感评测提升 50% 的部分已经拆过，这里补一句题目设计。智谱文档里提过一个细节：GLM-5.2 在正式发布前就向 Coding Plan 用户提前开放，开发者反馈的提升集中在两点——项目级上下文承载更强，能把完整工程放进同一条推理链路；长程任务执行更稳定。5.3 的内部评测沿用的就是这套以真实工程为单位的题库，所以「体感」两个字不是虚词，它对应的是项目级任务，不是函数级填空。这也解释了为什么官方数字和公开榜数字会同时存在：公开榜锚定行业坐标，内部榜追踪自己最在乎的那类真实负载。

「比肩 Fable 5 和 GPT-5.6 Sol」怎么读

通稿里最容易被截图传播的一句是：整体编程能力比肩 Fable 5 和 GPT-5.6 Sol。这两个参照物是 2026-08 闭源阵营的头部——Fable 5 是 MirrorCode 榜的断层第一，GPT-5.6 Sol 是 OpenAI 的编程特化档。「比肩」这个词，我建议按第三方口径校准一下。

MyClaw 的横向对比给出的结论相对具体：GLM-5.3 在终端执行和持续工程能力两个维度上确实突出，FrontierSWE、PostTrainBench、AutomationBench 几个榜的表现优秀；但在部分长上下文推理和极端难度的重建类任务上，与两个闭源头部仍有可见差距。爱范儿的实测标题是「杀回国模顶流」，编程榜单成绩登顶——注意登顶的定语是「开源」。

把时间轴拉长看第三方口碑的变化也有意思。阮一峰在 2026-02 实测 GLM-5 时，结论还是「与 Opus 4.6 和 GPT-5.3-Codex 各有胜负，长程 Agent 任务可圈可点」；到 5.1 时代，第三方开始出现「编程榜超过 Opus 4.6」的对比文章；再到 5.3，讨论的重心已经从「能不能追上」变成「差多少、差在哪」。半年时间，第三方叙述完成了从质疑到校准的转向——这个转向比任何单次跑分都更能说明能力的实际位移。优刻得在内部 Claude Code 评估里给过一组数：GLM-5 在前端、后端、长程任务上较 GLM-4.7 平均提升超 20%，能极少人工干预完成 agentic 任务。企业侧的内部评估不会为了营销注水，这组数可以作为系列能力的旁证。

我的读法是：在 agent 编程这个具体赛道，差距已经小到不影响选型决策；在全能力的意义上，闭源头部还是领先半个身位。这个判断对日常开发的意义在于——如果你和我一样，主力工作流是终端 agent 加编辑器补全，GLM-5.3 的能力已经过了「够用线」；如果你跑的是黑盒重建、超长程自治这类极端任务，头部闭源模型仍是首选。

半年四代：GLM-5 系列的榜单轨迹

单看一代的成绩容易被营销节奏带着走，把时间轴拉长才看得清趋势。GLM-5 系列这半年的轨迹是这样的：

GLM-5（2026-02）：SWE-bench Verified 72.8%，单次成本 0.53 美元，当时的热点是性价比——同样的分数，成本只有闭源旗舰的零头。GLM-5.1（约 2026-04）：SWE-Bench Pro 拿了 58.4%，超过 Claude Opus 4.6 的 57.3%，也压过 GPT-5.4 和 Gemini 3.1 Pro，第一次在编程专项榜上坐上总数第一。GLM-5.2（约 2026-06）：SWE-bench Pro 推进到 62.1%，SWE-bench+ 82.8%，被称为当年最强开源编程模型；Coding Plan 用户提前用上了 1M 上下文。GLM-5.3（2026-08-14）：就是这篇的主角，重心从「分数」转向「体感」，内部评测和终端类榜单成为主打。

这条轨迹说明两件事。一是智谱的迭代节奏已经稳定在两月一代，编程能力的提升是连续的而非脉冲式的——这对选型很重要，意味着今天基于 5.3 做的技术决策，两个月后不会作废，只会被更强的一代向下兼容。二是从 5.3 开始，官方叙事明显从「刷公开榜」转向「讲体感」，这既是策略（公开榜分数边际收益递减），也是行业风向（Terminal-Bench 这类执行榜的权重在上升，纯 patch 类榜单的说服力在下降）。阮一峰在 2026-02 实测 GLM-5 时就注意到这个特征：长程 Agent 任务、多阶段长步骤的稳定性，是 GLM 系列的传统强项——5.3 的能力分布不是突变，是这个基因的延续。

对普通开发者，这条轨迹还有一个实用推论：不必追每一代。两月一代的节奏意味着任何一代的窗口期都只有八周，为单代版本调整工作流、迁移配置、重学特性，投入产出比很低。更划算的做法是隔代升级——从 5.1 直接跳 5.3，能力跨度足够大，迁移动作却和升一代一样轻。版本焦虑在模型赛道是个真问题，解法不是紧跟，是定好自己的升级节奏。

接进工作流：Claude Code 直连，门槛极低

能力榜单看完，落到怎么用。GLM-5.3 的接入路径是我用过的新模型里最顺滑的一档，因为它同时兼容 Anthropic 和 OpenAI 两套接口协议。

以 Claude Code 为例，GLM Coding Plan 提供官方的 Anthropic 兼容端点，设两个环境变量就能把底层模型整体切到 GLM-5.3：

export ANTHROPIC_BASE_URL=https://api.z.ai/api/anthropic
export ANTHROPIC_AUTH_TOKEN=<你的 GLM API Key>

重启 Claude Code，模型列表里选 GLM-5.3，其余一切照旧——权限管理、会话恢复、subagent 这些 Claude Code 的工程能力全部保留，换的只是底下那颗模型。整个过程不超过五分钟，不需要改任何项目配置或提示词。Cline、Gemini CLI 等主流编程助手同样在官方支持列表里。

切换工具我有专门的文章讲过多模型管理：《省掉订阅费的 Codex，把国产模型用明白了》里那套思路完全适用于 GLM——按任务类型分流量，重活走 Claude 订阅，日常迭代走 GLM，两边互为备份。

实测体感说三点。第一，长上下文是真能感觉到的差异：我拿一个约 15 万 token 的多模块工程让它在 Claude Code 里做跨文件重构，5.3 能在一次会话里保持住模块间的调用关系不乱，这个体验和 1M 上下文的宣传是匹配的。第二，终端任务的成功率肉眼可见地高：装依赖、修构建报错、跑测试循环这类活，交给它基本不用中途接管——和 Terminal-Bench 开源第一的成绩对得上。第三，响应速度在国内网络环境下是原生优势，不需要任何代理，这一点对很多人是决定性的。

也要说清楚什么时候不该切。我这周的试用里有两类任务会切回 Claude：一是需要极致推理密度的架构推演，比如给一个分布式一致性方案找反例，闭源头部在这类任务上的思维链质量仍有优势；二是强依赖 Claude 订阅生态的功能，比如某些插件和 MCP 服务对官方端点的隐式假设。多模型工作流的正确姿势不是站队，是让每个模型待在最擅长的那段任务里——切换成本已经被 CCSwitch 这类工具压到一次回车，剩下的只是判断题。

再补一个我只在意、但多数评测不覆盖的维度：工具遵循度。模型再强，听不懂 agent 壳的指令也白搭——权限确认时乱答、该用 Read 偏要自己 cat、上下文压缩后忘了刚才的约定，这些小毛病每次浪费的是一两分钟，累积起来就是半天。GLM 系列从 5 代开始对 Claude Code 的工具协议适配就是官方投入的方向，5.3 在我这周的试用里没有出现过工具调用格式错误，压缩后的任务记忆也保持得干净。这类「不出错」的能力不上榜，但决定了它能不能真正常驻你的主力工作流。

Coding Plan 的钱怎么花

GLM Coding Plan 当前三档：Lite 月付 49 元，Pro 月付 149 元，Max 月付 469 元。注意 2026 年中的那次结构性调价：取消了首购优惠，按季和按年订阅仍有折扣。

这个价格放在 2026-08 的市场里是什么水平？GLM 系列 API 的输出 token 价格约为海外旗舰的 1/5 到 1/7，Coding Plan 又在 API 按量基础上再打包了一层额度折扣。粗算一下：Pro 档 149 元月付给到的额度，如果按 Claude 订阅的用量习惯去烧，等价的海外订阅成本在千元级。当然这个对比要打折看——额度次数的计法、限额策略、高峰期的排队，都在实际体验里扣分。

还有一个横向锚点：DeepSeek 按量。我在 《省掉订阅费的 Codex，把国产模型用明白了》里算过，Codex 接 DeepSeek 跑日常轻活一个月只要几块钱。GLM 的 149 元看着贵一个数量级，但换来的是 1M 上下文、编程特化的训练重心、以及套餐内不按 token 心疼的用量自由——按量路线每发一个请求都在心里过一遍成本，重任务天然舍不得丢给模型，这个心态差异对 agent 工作流的影响比价格本身大。

有一个使用限制必须提前讲清楚，官方 FAQ 写得明白：Coding Plan 额度只在官方支持的指定工具里生效——Claude Code、Cline 这些。自建应用、自己的网站、SaaS 产品里直连 API，走的是按量计费，不消耗 Coding 套餐额度。想拿套餐额度给自己产品的后端「白嫖」算力的路是堵死的，这个设计我理解，但买之前要知道。

所以我的建议分两种人。如果你的主力是 Claude Code 这类官方支持工具，且月度编程用量稳定，Coding Plan Pro 档直接开，149 元在当下是性价比断档的选择；如果你的场景分散在自建 agent、脚本批处理、产品后端，那按量付费更合适，或者两者混搭——重活套餐、杂活按量。和我之前写的 DeepSeek 按量路线相比，GLM Coding Plan 胜在套餐内的 1M 上下文和更激进的编程特化，DeepSeek 胜在按量的极致弹性，两条路线不冲突，我自己是并存的。

正面刚 DeepSeek V4：能力和价格对齐看

GLM-5.3 发布节点上，最值得对齐比较的对手是 DeepSeek V4 系列——V4 和 V4 Pro 两档，恰好对应「性价比」和「旗舰」两种定位，和 GLM 的按量 API、Coding Plan 两套计价形成了镜像。

能力侧，两家的强项错开了。仓库级真实修复看 SWE-bench：V4 Pro 在 Verified 上是 80.6%，是这一代开源的标杆；在更难的 SWE-bench Pro 上，V4 Pro 约 55.4%，V4 约 52.6%，而 GLM 5.1/5.2 在 Pro 上分别是 58.4% 和 62.1%，5.3 只会更高——GLM 在高难度仓库任务上占优。终端和 agent 执行侧是 GLM-5.3 的主场：DeepSWE 1.1 拿 66%，TB3.0 开源第一；V4 Pro 在 Terminal Bench 2.0 上约 67.9%，V4 落后 Pro 约 11 个点，多步工具调用必须上 Pro 档。算法竞赛这类「一次性写对」的任务则是 DeepSeek 强，V4 Pro 在 LiveCodeBench 上约 93–94%。一句话：长链路 agent 和终端执行选 GLM-5.3，单文件算法难题和高性价比日常迭代选 V4 系列。

价格侧，DeepSeek 把按量做到了地板。官方价格页：V4 输入 1 元、输出 2 元每百万 tokens，V4 Pro 输入 3 元、输出 6 元，缓存命中低至 0.02 元——2026 年 5 月那轮永久降价直接砍到原价四分之一，只有高峰时段会翻倍。GLM 的按量 API 参照 5.2 的 $1.4/$4.4，输出价是 V4 Pro 的五倍上下。但 GLM 的主力打法不是按量，是 Coding Plan：Pro 档 149 元包月，套餐内不按 token 计费，1M 上下文随便喂。所以真实的账是这样算的：轻量日常活，V4 按量一个月几块钱，没有对手；重度 agent 工作流，GLM 套餐把成本从「每次请求都心疼」变成「固定月费」，重任务才敢放开丢给模型。

我的落地分配：Codex 接 DeepSeek V4 跑杂活和批处理，Claude Code 接 GLM-5.3 跑长链路任务，这套多模型管理的具体做法在 《省掉订阅费的 Codex，把国产模型用明白了》里写过。两家合计月成本两百出头，覆盖了九成场景，剩下的硬骨头留给 Claude 订阅。

冷静的部分：三个要打折扣的地方

夸完了，说限制。这三点不影响「5.3 是当前最强开源编程模型」的整体判断，但直接影响你对它的预期管理，买不买、怎么用，先看完这三条再做决定。

开源有时间窗。权重在发布约两周后才开放，也就是 2026-08 下旬。在那之前，「开源第一」的成色只能通过 API 验证，第三方无法本地复跑评测。等权重放出后，社区会在自己的 harness 里重新测一遍，那时的数字才是完全体——按 GLM-5.2 的经验，社区复测成绩和官方成绩会有小幅出入，方向通常一致。权重开放之后玩法会多一层：MIT 协议意味着可以本地部署、可以微调、可以蒸馏给自己的小模型。对数据敏感的团队，一套自己托管的 5.3 加开源 agent 壳，就是完全不出内网的编程流水线；对做垂直工具的团队，拿它当底座微调一轮，比自己从训练攒起便宜两个数量级。这些玩法的入场券都在两周后的那个仓库里。

「开源第一」的对手只有开源。这个定语意味着 DeepSeek、MiniMax、Qwen、Kimi 都在同一赛道，第一的交替频率会很高。GLM-5.3 在 2026-08 领先，不代表 2026-09 还领先。开源第一梯队的四家在多数编程榜上差距都在几个点以内——DeepSeek V4 Pro 在 SWE-bench Verified 上是 80.6%，是这一代的标杆；GLM-5.3 的强项在终端执行侧；Kimi 和 Qwen 各有垂直优势。选哪家的权重回到价格、上下文、工具兼容性这些工程因素，而不是零点几个榜单点数。对使用者来说这其实是好消息：四家轮换领先，等于能力被竞争持续抬高、价格被竞争持续压低，切换成本却因为接口协议标准化而越来越低。

体感评测没有复跑入口。内部 Code Bench 的 50% 提升是官方最有传播力的数字，也是唯一无法独立验证的数字。我的处理方式是拿它当方向参考、不当决策依据——决策依据用 Agents’ Last Exam 的 7.3 个点实打实的代际提升，加上自己工作流里的实测。这也是我看待一切新模型发布的方法：官方数字分公开榜和内部榜两栏，内部榜看方向，公开榜看幅度，自己的任务看真伪。这套方法在 《AI 编程之我见》里展开过，5.3 这次发布再次验证了它的必要性。

回到最开始的问题：GLM-5.3 值不值得马上用？我的答案是分两步。现在就可以把 API 接进 Claude Code 试一周，成本几乎为零，终端任务和长上下文重构这两个强项，试过就知道和自己的工作流合不合；权重开放后再决定要不要深入——本地部署、微调、或者把整个 agent 农场迁过去，那是另一笔账。半年四代的轨迹摆在这里，国产开源模型在编程这个赛道上已经从「追赶」进入了「轮换领先」，对使用者来说，这比任何一个单独的榜首都更有价值：竞争在替我们压价格、拉能力，我们只需要每隔两个月，花一个小时重新校准一次自己的工具组合。
