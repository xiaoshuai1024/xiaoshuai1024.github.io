字节把 Trae 一分为二：写代码的归 Code，干活的归 TraeWork

先看两条数据。抖音上「trae」关键词按点赞排序，半年内最高的两条视频：一条 2.5 万赞，英雄哪里出来的《TRAE SOLO 新版本发布，AI 跑通产品研发全流程》，265 秒，演示的是在 IDE 里用 AI 从零写出一个 3D 跑酷游戏；另一条 1.7 万赞，极物君的 AI 营地的《Trae Work 保姆级教程》，465 秒，演示的是让 AI 整理一家咖啡店的报表、发票和数据仪表盘。前一条的观众是程序员，后一条的观众是想让电脑替自己干活的普通人。

两条视频，两个没有交集的受众群体，恰好就是字节这步棋要分开的人群。Trae 官方文档最近挂出一行更新，标题只有一句：TraeWork is available。配合定价页和两条爆款视频的逐字稿，可以确认：SOLO 时代「不止编程」的那条线，已经从 IDE 里独立出来，成了单独的产品。

先把结论放在这：**写代码的 Agent 和干活的 Agent，从此是两个物种，选型逻辑不能混用。**这刀为什么这么切、你怎么选，往下看。

这篇拆四块：TraeWork 到底是什么、字节为什么把这刀切在这里、它和 Claude Code 这类编程 Agent 为什么不是一类工具、免费额度背后打的是什么主意。

TraeWork 是什么：一个能动手的聊天窗

先把产品说清楚。TraeWork 打开之后长得像豆包或者 DeepSeek 的聊天界面：中间一个输入框，可以打字也可以语音。区别在能力清单：聊天窗只能给你答案，TraeWork 能直接操作你的电脑。极物君在视频里演示的能力有四样：读取文件、移动文件、修改文件内容、创建新文件。这四样叠起来，就是「整理文件夹、把乱七八糟的表格提取成一份 Excel、做一个经营仪表盘、写日报」这类活的全集。

界面左侧有一个侧边栏，放的是豆包没有的两样东西：技能和自动化工作流。技能是预设好的任务模板，自动化工作流是可以重复触发的固定流程。这两样是把用过的活攒下来、下次一键重跑的容器，面向的是要反复做的固定任务，不是一次性问答。

复杂任务有一条单独的路径：Plan 模式。直接执行模式下，TraeWork 拿到任务就动手；Plan 模式下它先停下来，产出一份执行清单，把不确定的地方变成问题向你确认，你答完它才继续。极物君让他基于一份咖啡店销售汇总表做可视化仪表盘，用的就是 Plan 模式：它中途停下来问了两个数据口径的问题，确认之后才开工，最后交付了一个可交互的网页仪表盘，还附了一段「建议关注」的阅读提示。

这个设计值得单独说一句，因为它暴露了字节对这类产品的定位。写代码的 Agent 最大的风险是把代码改坏，所以要 diff 审查、要沙箱；干活的 Agent 最大的风险是理解错任务白干一场，所以它要先弄清任务再动手。同样是 Agent，风险模型不一样，交互设计就发展成了两个样子。

这刀为什么切在这里：从 SOLO 到分家

字节的这条产品线，过去二十个月的演化路径值得摊开看，每一步都在为最后的分家做铺垫。

2025 年 1 月，Trae 国际版发布，基于 VSCode 内核，卖点是在 IDE 里免费用 GPT-4o 和 Claude；3 月国内版跟进，配豆包模型，可切 DeepSeek。这个阶段的 Trae 是「免费 AI IDE」，打的是 Cursor 的价格锚点。

2025 年 7 月，SOLO 模式发布，字节给它起的定位是「业内第一个 Context Engineer」：你给需求，它自己感知上下文、拆任务、交付结果，从「辅助写代码」往「独立交付软件」走。2026 年这轮更新里，SOLO 内部先分出了两个模式：Code 和 MTC。英雄哪里出来在视频里解释得很直白：Code 模式就是以前的 SOLO，面向程序员；MTC 是 More Than Coding，面向「策划、程序、美术、测试、运营、市场」所有互联网岗位。

再往后就是现在这一步：MTC 那条线不再住在 IDE 里，独立成了 TraeWork，而且一口气铺了网页、桌面、移动三个端。IDE 版的 Trae 继续演 Code 这条线。至此，当初一个产品里的两条基因正式分家：写代码的留在 IDE，干活的搬进工作台。

为什么非要分？看两条爆款视频的受众就明白了。程序员要的是 IDE 里的 Agent：懂工程结构、能跑测试、可以审 diff，这些能力对不写代码的人是负担。而想让 AI 整理报表的人，根本不需要打开一个 IDE，给他一个 VSCode 界面反而是劝退。极物君那条 465 秒的教程，从头到尾没出现过一行代码，弹幕和评论区的高频词是「保姆级」「小白」。IDE 是程序员的母语，聊天窗是所有人的母语，两个受众用两套界面，分开是产品必然，不是版本管理。

收费结构也跟着人群切开了。Trae 定价页现在的口径是所有 AI 请求按 token 用量计费，折算成 Dollar Usage 从每月额度里扣；Pro 档大约 10 美元一个月，基础档免费。干活的场景是高频小额请求（读文件、改表格、生成报表），编程场景是低频大请求（整个任务上下文动辄几万 token），一个额度池养两种消耗模式必然打架，分开计价才算得清。

和 Claude Code 不是一类工具：别用一套选型逻辑

本号的读者大多是 Claude Code、Codex 这类编程 Agent 的重度用户，最容易犯的错误是拿同一把尺子去量 TraeWork。量完的结论会错得很离谱，因为它们从输入到风险模型就不是一类东西。

我在拆 harness 税时写过：编程 Agent 的价值是把整个工程上下文塞进首包，让模型「入职」你的代码库，Claude Code 的工具说明书一场对话要重复支付将近 4 万 token。TraeWork 恰好反过来，它不要求你懂工程结构，它要求的是把日常文件流交给它：文件夹是乱的、表格是散的、日报是重复劳动。这些任务的共同点是不需要读代码。

两边的分工可以这样划：

  • 交给编程 Agent 的：改代码、跑测试、审 diff、重构、排查线上问题。判断标准是这件事出错要回滚代码。
  • 交给 TraeWork 的：整理文件、汇总表格、做仪表盘、写例行日报、批改作业这类文档流。判断标准是这件事出错浪费的是时间，不是代码库。

有一个重叠地带值得点名：小工具。极物君演示过让 TraeWork 直接做一个网页仪表盘，英雄哪里出来用 Code 模式做游戏，两边都在「生成一个能用的东西」。区别在后续：仪表盘要改主题，你在聊天窗里说一句「换成苹果风」就行；游戏要加碰撞判定，你得进 IDE 看代码。交付物是一次性的，TraeWork 顺手；交付物要长期维护，回到 Code。

风险模型也不同。编程 Agent 的安全事故是删库、是静默改错 270 行，所以权限要层层设卡。TraeWork 的安全事故是把你孩子的作业批错了、把报表算错了。发现成本低，重跑就行。这就是为什么它可以放心地把入口铺到移动端，而 Claude Code 到今天还主要活在终端里。

免费额度背后：获客、依赖和一次前车之鉴

最后说免费额度。TraeWork 对新手免费额度「完全够用」，这是极物君视频里的原话，也是字节的获客策略：用 token 额度把「第一次让 AI 干活」的门槛降到零。这和 2025 年初 Trae IDE 免费送 GPT-4o、Claude 的打法一脉相承：先让人用起来，等任务流长在产品上，额度自然不够，Pro 档 10 美元一个月的水到渠成。

这套打法有一个绕不开的前车之鉴，就发生在 Trae 自己身上。2025 年 11 月，Trae 因故下线了 Claude 模型，付费用户被迫迁移到字节自研的 SOLO 模型，社区当时的讨论相当激烈。这件事的教训不在字节，在用户：当你的日常工作流长在一家厂的 Agent 服务上，模型供给本身是单点依赖。免费额度是获客手段，不是承诺；今天送你 Claude，明天可以收回。

所以我的使用建议是按数据归属性分工：文件整理、报表这类数据在你自己电脑上的任务，放心的交给 TraeWork，锁死的只是工具不是数据；反过来，任务产物存进对方账号体系的（云端项目、自动化工作流的配置），想清楚迁移成本再深度使用。工具可以换，数据格式和任务习惯才是真的迁移成本。

结尾

回到开头那两条爆款视频。2.5 万赞的那条里，英雄哪里出来说了句大实话：有时候 AI 的上限完全取决于人的上限。1.7 万赞的那条里，极物君对着镜头问：总分十分的话，你会给这个仪表盘打几分？

两条视频没有一条弹幕在争论模型跑分，观众关心的都是「我的活它能不能干」。字节把这刀切下去，等于官方承认：AI 编程工具的下一步增长，不在把程序员的一天从 8 小时压缩到 4 小时，而在那几亿个不写代码、但每天和表格文件夹打交道的人。Code 和 Work 从此是两个物种，选型的时候先问自己一句：这件事出错，我损失的是代码，还是时间？

至于程序员该不该装 TraeWork：装。把生活里的文档流交给它，代码留给终端里那个老伙计。
