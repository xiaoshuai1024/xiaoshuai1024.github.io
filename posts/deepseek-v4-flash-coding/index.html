DeepSeek 便宜到骨折还拿了世界第二,但我劝你先别切

xiaoshuai1024 included in AI编程
About 300 words 2 minutes

做 AI 开发，选模型是每周都在做的决策。7 月 31 日 DeepSeek 上线 V4 Flash 正式版 API，我第一时间翻的是榜单——Terminal-Bench 2.1 拿了 82.7 分，超过 GLM-5.2，只比 Opus 4.8 低 2.3 分。

这个数字本身很漂亮，但漂亮得不等于该立刻切过去。一个模型值不值得换，要看三件事：能力是真的强还是测出来的强、强在哪、代价是多少。这篇就把 V4 Flash 这三件事拆开讲。

结论是：这是国产模型第一次在编程榜上摸到第一梯队的边，成本结构更是碾压级。但榜单数字带着官方测试的水分，真实生产表现还得等第三方验证。 该试的可以试，该等的别急。

82.7 分的含金量：真的进了第一梯队

Terminal-Bench 2.1 测的是 AI 在真实命令行环境里，能不能独立完成端到端的复杂任务——不是写一段函数，是从拿到需求到跑通结果的全流程。这个榜比单纯写代码难，也更接近 Agent 的真实工作。

V4 Flash 的 82.7 分，排在它前面的只有 Opus 4.8 的 85.0。后面是 GLM-5.2 的 81.0、自家 V4-Pro 预览版的 72.1、V4 Flash 预览版的 61.8。

2.3 分的差距意味着什么？在这种百分制的综合评测里，2-3 分经常落在测量误差和抽样波动的范围内。换句话说，V4 Flash 和 Opus 4.8 在这个榜上的差距，已经小到不能说"明显落后"了。这是一个质变——之前国产模型在这个层级总是差一档，现在站到了同一条线上。

但要注意一个细节：Opus 是 Anthropic 的闭源旗舰，价格不便宜；V4 Flash 是 DeepSeek 的速度成本优先版本。一个堆料旗舰和一个性价比型号打到了一起，这本身就是 V4 Flash 成本结构的胜利。

跃升幅度：后训练的真实价值

光看绝对分数不够，看进步幅度更能说明问题。V4 Flash 正式版相比预览版，几个关键基准都是暴涨：

  • Terminal-Bench 2.1：61.8 → 82.7
  • CyberGym：38.7 → 76.7
  • DeepSWE：7.3 → 54.4

DeepSWE 涨了快 6 倍，这个幅度在模型迭代里很少见。

更关键的是这次更新的方式：没有改模型结构和尺寸，总参数还是 2840 亿、激活参数 130 亿（MoE 架构），只是在预览版基础上重新做了一遍后训练。

这件事的信号比分数本身重要。它说明在不动底层架构的前提下，靠后训练数据和方法论的优化，还能榨出这么大的提升空间。换句话说，DeepSeek 的后训练管线在 Agent 和编程方向上的调优能力，已经到了一个相当成熟的程度。这对后续 V4 Pro 正式版是个好兆头——同样的训练方法用到更大的模型上，天花板只会更高。

不只是编程：综合能力逼近最强

如果只是编程一个榜强，还能说是专项优化。但 V4 Flash 在综合测评上也逼近了第一梯队。

AII 智能指数拿到 50 分，只比 GPT-5.6 Luna 低 1 分。比自家旧版 V4 Flash 高 10 分，比 V4 Pro 还高 6 分。前端代码专项更是 1586 分，刷新了这个赛道的记录。

工具使用任务上，Toolathlon-Verified 70.3 分，接近 Opus 4.8 的 76.2。这些不是编程榜，是模型综合理解和执行能力的体现。一个速度成本优先的版本，在综合能力上能和闭源旗舰打这么近，说明 V4 Flash 的强不是偏科。

成本结构：真正的护城河

能力到了第一梯队，价格却完全是另一个段位。

官方数据是 1.64 亿 Token 只要 8.9 元人民币，API 调用 1249 次。换算下来单任务成本比降价 80% 之后的 GPT-5.6 Luna 还要低约 60%。自有 API 还提供约 98% 的缓存命中折扣——业内大多数厂商给的是 90%。

这才是 V4 Flash 真正的杀手锏。编程榜第一梯队，国产模型迟早能摸到；但把第一梯队的能力，卖到白菜价，是 DeepSeek 一直在建立的差异化。对做 Agent 的开发者来说，Agent 一个任务要调几十上百次模型，单价差一个数量级，项目能不能跑通完全不一样。

V4 Flash 原生支持 Responses API，并且针对 Codex 做了优化，可以直接当 Codex 的后端模型用。这意味着你不需要等一个专门的编程版，现在就能把它接到现有的编程 Agent 工作流里。我自己主力是 Claude Code，但 Codex 用户这次是直接受益的——后端换成 V4 Flash，成本能压下来一大截。

要冷静的地方：榜单不等于生产

说完好的，必须说清醒的。这套成绩来自 DeepSeek 在指定 harness 和参数下完成的官方测试，实际表现还有待第三方评测和生产任务验证。这一句不是我加的免责声明，是承认这套数字的边界。

官方测试和真实生产的差距，在这行见得太多了。指定 harness 意味着测试环境、提示词、工具调用方式都是对模型最有利的配置。换到你的真实代码库、真实的脏数据、真实的边界场景，分数掉两成很正常。所以82.7 分是"上限参考"，不是"你用了也能拿到"的保证。

其次，V4 Flash 这个版本没有多模态能力，用不了 computer use 这类视觉交互功能。V4 系列后续会支持多模态，但 Flash 正式版这一版是纯文本。如果你的 Agent 场景需要看图、看界面，这版不适用。

第三，V4 Pro 正式版还没发。Flash 是速度成本优先的版本，Pro 才是堆料旗舰。官方说 8 月初发布。如果你等的是 DeepSeek 的最强能力，现在不是上车点，再等两周看 Pro。

第四，缓存 98% 折扣是有条件的，命中率高才划算。如果你的任务模式命中不了缓存，这个优势打折。

什么场景该切，什么场景该等

判断该不该用 V4 Flash，看你的场景落在哪：

该切的场景：成本敏感的批量 Agent 任务（一个流程要调几十上百次模型）、命令行端的自动化、Codex 后端替换、纯文本的代码生成和重构。这些场景里，V4 Flash 的能力够用、成本碾压，ROI 立竿见影。

该等的场景：需要多模态的 Agent、需要视觉理解的任务、对模型能力天花板有要求（等 V4 Pro）、需要第三方评测交叉验证再决策的团队。这些场景现在切，要么功能不全，要么踩坑风险高。

还有一类是该试但不该 all-in：把 V4 Flash 当 Codex 后端或命令行 Agent 接进去跑真实任务，用你自己的代码库做 A/B 对比。官方榜单看个趋势，自己的真实任务才是最终的真相源——这道理和我之前写视觉验收时讲的一样，别人的测试报告是线索，你自己跑出来的才是结论。

一个判断

很多人讨论新模型，注意力都在"分数超过谁"。但 V4 Flash 这次真正值得关注的不是某个榜单的第几名，是两件事：

一是国产模型第一次在编程综合能力上，和闭源旗舰站到了同一条起跑线。差距从"明显落后一档"压缩到"测量误差边缘"，这是质变。二是它把这种能力卖到了一个让对手很难跟的价格。能力追上是迟早的事，成本结构才是 DeepSeek 持续在建立的护城河。

但别被榜单带偏了节奏。官方测试的上限数字，和你在真实生产里能拿到的表现，中间永远有一段距离。该试的现在就接进去跑真实任务，该等的就等 V4 Pro 和第三方评测。 最该避免的，是看到 82.7 分就全量切换，然后在生产环境里发现它在你的场景下根本不是这么回事——那不是模型的问题，是决策的问题。

模型选型从来不是看一张榜单拍板的事。看能力、看成本、看边界，然后用你自己的真实任务做最终判断。
