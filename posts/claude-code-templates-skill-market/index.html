893个 Claude Code skill 挑不过来？三判据砍到先装两个

上周整理自己的 skill 库时，我干了个笨活：把 GitHub 上最大的 Claude Code 模板市场逐个分类数了一遍。davila7/claude-code-templates，32,216 星（2026-09-30 复核），skills 目录下 31 个分类、893 个 skill，三天涨了两百多颗星。数字之外还有个更值得说的发现：装 skill 的快路径，不在官方那个 179,099 星的仓库。

这篇文章回答三个问题：这个市场装进去的到底是什么；skill 凭什么比把 prompt 贴进系统提示强；893 个里面怎么挑。第三问给三条判据，配套两支我读过原文的推荐。

一、官方仓库立标准，市场才是货架

17.9 万和 3.2 万这两个星数不是竞争关系。官方 anthropics/skills 仓库定义了 Agent Skills 这个形态：一个文件夹加一份 SKILL.md，写明这个 skill 管什么、什么时候用、怎么用。它是标准和样本库，回答的是「skill 应该长什么样」。

claude-code-templates 干的活不同：分发。Claude Code 的扩展点全在项目或全局的 .claude/ 目录里，agents、commands、hooks、skills 各占一层。装一个 skill 的传统路径是找到文件、建目录、拷进去；这个市场把 893 个组件做成索引，README 给的用法是一条命令：

npx claude-code-templates@latest

按仓库的说法，命令跑起来是终端里的交互货架，按分类浏览、选中落盘，网页端 aitmpl.com 是同一个货架的浏览版。我没跑过这条命令，你自己敲一遍就有判断，这是验证成本最低的一步。

边界说在前头：它装的是别人写的 prompt 和脚本，不是官方功能，Claude Code 本身没有任何变化。我的规矩是装之前逐个过目，毕竟进的是能影响代码行为的目录。

二、skill 凭什么比常驻 prompt 强

答案在上下文的经济账里。官方把这个机制叫渐进披露（progressive disclosure）：skill 常驻上下文的只有开头一句描述，命中了工作场景，全文才加载进来。把几千字的 prompt 贴进系统提示则相反，每一轮对话都在场、都在烧 token，塞得越多，注意力越散。

这不是理论。我自己仓库里二十六个自研 skill 就按这个机制组织，写作、画图、四平台发布各管一段，只在命中时上场。用下来唯一的约束是：开头那句描述写得不准，它大概率永远不被触发，装了约等于没装。

所以 skill 不是越多越好。我日常高频在跑的也就一把，五六个高频的，比几十个全装强。

三、893 个怎么挑：三条判据

组件这一级没有星数可看，三万颗星是整个库的，分不到单个 skill 头上。挑法只剩三条判据。

判据一，公司挂名优先。skills 目录里有一排公司名分类：doordash 下 5 个、sentry 下 6 个、railway 下 12 个。目录结构是我 2026-09-27 用 GitHub API 实查的，提交者身份没逐个核过，但大概率是公司自己开源的内部流程，比个人随手上传的多一重维护保底。

判据二，分类厚度。development 一个分类就有 230 个，是最厚的一档，说明这个领域的需求最集中，淘到好货的机会大；scientific 和 ai-research 各一百三十多个，紧随其后。

判据三，工作流对号。写代码的看安全和排障，写东西的看文风类，做媒体的看转写下载，做自动化的看 n8n 那一族。这条判据最终由你的活决定，我的清单替代不了。

三条合起来是一张速查表，直接抄：

判据看什么本次实查（2026-09-27/30）
一 · 公司挂名分类名是公司名，维护多一重保底doordash 5 / sentry 6 / railway 12
二 · 分类厚度需求集中度，厚分类好货概率大development 230 最厚
三 · 工作流对号按你的活选分类安全排障 / 文风 / 转写下载

按这三条，我自己挑了两支先装，原文都读过。security-audit（security 分类），仓库描述写的是 Web 与 API 安全测试、渗透测试、漏洞扫描、安全加固，一套全管。systematic-debugging（development 分类），描述只有一句：遇到任何 bug、测试失败或意外行为，先找根因再提修法；文件里第一条规矩更狠，没完成根因调查，不许提出修复。第二支对症的正是 AI 改代码不看证据的毛病。

还有两支我点了名但没装过：humanizer 和 avoid ai writing，都标着去 AI 味。效果不打包票，验证办法也简单：同一篇稿，装与不装各跑一遍，摆在一起看。

四、一条命令，一条规矩

收个尾。skill 这个形态在官方仓库拿了 17.9 万星之后，已经是行业标准，值不值得用不用再论证。竞争发生在另一层：谁挑得准，装得对。

市场把「装」的成本打到一条命令，判据把「挑」的范围砍到先装两个试一周，渐进披露解释了为什么五六个高频就够。装进来的每个文件都值得过目一眼，这是唯一的规矩。893 这个数字下周只会更大，清单会过期，判据不会。
