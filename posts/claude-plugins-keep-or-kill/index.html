照榜单装了 12 个开源 Claude Code 插件，实测一个月我删了一半

Claude Code 的插件和 skill 榜单网上已经不少了，我之前也整理过一版。但榜单有个共同问题：只管推荐，不管售后。装的时候每个都写着「必装」，装完之后哪些真在干活、哪些在吃灰，没人告诉你。

这次我把话说完：照榜单装了 12 个开源插件，用一个月真实任务逐个实测，删了一半，留下 6 个。留下来的每个都附 GitHub 实拍、实测体验和照抄能用的安装命令；删掉的 6 个，也讲清楚为什么删，这部分可能比推荐更值钱。

先看结果

淘汰标准就一条：这一个月里，它有没有被我真实触发过。不是「我觉得它有用」，是有据可查的使用记录。插件和 npm 依赖一个道理：装 800 个包，入口就那几个，区别只是白白多出上下文开销和选择干扰。

留下的 6 个

1. Superpowers · 留

仓库：github.com/obra/superpowers

它是什么：一整套 agentic skills 框架 + 软件开发方法论。brainstorm、设计、TDD、代码审查、调试、执行计划，每个环节一个 skill，从想法到交付全链路覆盖。

实测体验：装完后第一个月我只用到了它的 brainstorming 和 executing-plans，第二个月开始 debugging、grill-me 也被自然带起来了：它们挂在开发流程的固定环节上，写到「设计完就该 TDD」的节点就会触发。这是它能留下的关键：它的工作流和写代码的流程天然重合，不用你记着去用。

安装（Claude Code）：

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

2. ECC · 留

仓库：github.com/affaan-m/ECC

它是什么：agent 性能优化系统，打包了 skills、instincts（直觉规则）、memory（记忆）、security（安全）、research-first development 五个维度，管的是 agent「怎么跑任务」本身。

实测体验：它的 memory 和 research-first 两个模块在长任务上肉眼可见地稳：agent 动手前先调研、跨会话记得上下文，长任务稳不稳就看这两件事。选 minimal profile 装，full 版会把一堆你用不到的模块也塞进来，那正是我要在别人机器上删的东西。

安装（Claude Code，minimal profile）：

npx ecc-install --profile minimal --target claude

3. OpenSpec · 留（这个月用得最狠）

仓库：github.com/Fission-AI/OpenSpec

它是什么：Spec-Driven Development（规格驱动开发）工具。把 AI 编程从「对话式临场发挥」变成「先写 spec、再按 spec 实现」，需求落成可读可追踪的 proposal / design / specs / tasks，AI 照规格一步步做，每步可回溯。需要 Node.js 20.19.0+。

实测体验：AI 编程的大坑不在写不出代码，在写出来的对不对没法验证。OpenSpec 是这 12 个里我触发得最多的：凡是超过半小时的改动，我都先 openspec proposal 开个变更提案再动手，一个月下来攒了小几十条变更记录，每条都对应一次真实使用。用台账说话，这是它能留下的全部理由。

安装：

npm install -g @fission-ai/openspec@latest
cd your-project
openspec init

4. Context7 · 留

仓库：github.com/upstash/context7

它是什么：给 LLM 拉取实时库文档的 MCP server。Claude Code 写代码时读当前版本的官方文档，避开模型记忆里可能过时或编造的 API。需要 Node.js 18+，建议去 context7.com/dashboard 申请免费 API key 提限额。

实测体验：模型幻觉有一大类是「编造 API」：参数名错的、方法不存在的、已废弃接口硬上的。只要项目里有一个版本更新比较勤的库，它就在持续救命。这个月实测里它救命的一个案例是新版路由库的 breaking change，模型记忆里的写法整个是旧版。

安装：

npx ctx7 setup

这条命令走 OAuth 认证、生成 API key、自动装好 skill，可用 --claude / --cursor / --opencode 指定目标 agent。

5. caveman · 留（顺手，但真省 token）

仓库：github.com/JuliusBrussee/caveman

它是什么：一个 token 压缩 skill，原话「why use many token when few token do trick」：用穴居人式简短说话砍掉约 65% 的 token。支持一键安装脚本（自动发现机器上所有 agent）和 Claude Code 插件两种装法。

实测体验：看着是乐子，账是真的。上下文快爆的长会话里让它接管输出，一轮对话省下来的 token 够再跑两轮。会话短的场景用不上它，所以我把它归在「按需点名」那一档，但按需也轮得到它，这就够留下的资格了。

安装（Claude Code 插件）：

claude plugin marketplace add JuliusBrussee/caveman
claude plugin install caveman@caveman

6. pua · 留（同上，按需点名）

仓库：github.com/tanweai/pua

它是什么：反向激励型输出风格 skill，和 caveman 一个赛道的乐子产物，走的是「刺激型」话风。

实测体验：卡壳的时候点名调一下换个脑子，真用得上。它和 caveman 的存活逻辑一样：有明确的触发场景（点名），不靠躺在技能列表里等运气。顺带一句真心话：这两个装了就好，别指望它们改变生产力，它们改变的是心情，而心情偶尔也值钱。

安装：

claude plugin marketplace add tanweai/pua
claude plugin install pua@pua-skills

删掉的 6 个，和为什么

karpathy-skills（github.com/multica-ai/andrej-karpathy-skills）：Karpathy 总结的 LLM 写代码反模式，就一个文件，写进 CLAUDE.md 给 agent 装避坑直觉。东西是好的，但内容太薄，一个 markdown 的信息量，读完抄进自己的项目规范就够了，没必要以插件形态常驻。读完即毕业型。

mattpocock/skills 和 anthropics/skills：两个官方/半官方 skill 集合，质量都在线，问题出在和 Superpowers 大面积重叠。同一个环节挂两个相似 skill，agent 选错一个，输出格式就不对。重复不是冗余，是干扰，留一个就行，我留了覆盖面更宽的 Superpowers。

graphify（github.com/Graphify-Labs/graphify）：代码图谱分析，把代码库结构建成图给 agent 查。在超大型陌生代码库上应该很强，但我的日常项目它做完索引用不上几次，跑图谱的时间比省下的还多。工具没输，场景没对上。

claude-hud（github.com/jarrodwatts/claude-hud）：终端里的 Claude Code 状态仪表盘，显示 token 消耗、会话状态。好看，第一周天天看，第二周忘了。信息价值撑不起常驻，需要的时候 ccusage 这类一次性命令也够。新鲜感驱动的装机，新鲜感过了就该卸。

compound-engineering-plugin（github.com/EveryInc/compound-engineering-plugin）：复合工程方法论插件。理念先进，但它预设的是「团队协作 + 多 agent 并行」的工作形态，单人单机用不上里面七成的能力。为用不上的能力付上下文税，不划算。

装之前先问自己三句

这一个月实测下来，我总结成一个极简判断法，下次再看到「必装榜单」先过一遍：

  1. 场景问：我的日常工作里，有没有它挂靠的那个环节？（没有环节，就没有触发；没有触发，装了等于没装。）
  2. 重叠问：已有装备里有没有功能相似的？（有，二选一，别都留。）
  3. 回手问：假如现在卸掉它，一周内我会不会装回来？（不会，就是装饰品。）

榜单的价值是帮你完成「从 0 到 10」的冷启动，这个判断法管的是「从 10 往后」。插件这东西，装的那一刻不产生任何生产力，被触发的那一刻才产生。照着别人的榜单堆装备，不如照着自己的流程做减法。留下的 6 个在客观上未必排头名，只是恰好长在我的工作流上；你的工作流长什么样，只有你自己知道。
