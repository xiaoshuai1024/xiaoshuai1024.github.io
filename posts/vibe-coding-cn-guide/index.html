Claude Code vibe coding 入门：先看卡在第几层，再决定学什么

这两天技术公众号在转同一个 GitHub 仓库：tradecatlabs/vibe-coding-cn，一套中文的 vibe coding 教程，16.3k 星（2026-10-01 复核），MIT 协议。转发配文出奇一致：终于有人把 vibe coding 讲明白了。

星数证明热度，证明不了适不适合你。我把它的主干文档读了一遍，这篇是提炼版：先用五层方法定位你卡在哪，再决定补什么，附带三条铁律和从哪个分支上手。原文从需求分析讲到部署复盘，你在电梯里读不完，这里 5 分钟读完。

一、先把 vibe coding 这个词掰正

Karpathy 在 2025 年 2 月造出这个词时，场景说得很窄：周末小工具、自己玩的东西，可以用「忘掉代码的存在」这种方式干活。传到中文圈，语境被裁掉了，变成「闭眼让 AI 写，能跑就行」。教程开篇就先纠这个偏：vibe coding 是人机协作的编程形态，人要留在环里，负责定目标、分任务、验收产出。

这套教程的骨架概括成四个字：道法术器。器是模型和算力，术是 Claude Code、Codex、Cursor、Gemini CLI 这些工具，法是结构化的开发流程，道是识别问题边界、分解目标的能力。教程主打 Codex 讲解，方法本身工具无关，我用 Claude Code 跑同样的流程没有障碍。

四层里有个扎心的对照：新手把预算全砸在器上，订阅最强的模型、追每一次版本更新；老手在法上花功夫，流程和验收搭好之后，中等模型也交付得了产品。工具半年一换，流程攒下来全是自己的。

二、五层方法，先定位你卡在第几层

教程的主体是一套五层递进的方法，从最轻的 Prompt 一路到最重的 Quality Gate。它的价值不在教你某一句神级提示词，在于给了一张地图：每层解决一个具体问题，卡住了能定位自己在几楼。

第 1 层，Prompt。 一句「给这个接口加个缓存」就是许愿，AI 只能靠猜。教程把一条合格的 prompt 分成六个要素：意图、上下文、模板、参数、反馈、迭代。写全了，猜的部分就没了。怎么写好这五张卡，我之前专门写过一篇《装完 Claude Code 先别急着聊》，模板可以直接抄。

第 2 层，Skill。 好用的 prompt 不该每次重敲，固化成可复用的原子能力，场景命中才加载全文。这一层怎么挑现成的、怎么写自己的，见《893个 Claude Code skill 挑不过来？》。

第 3 层，工程流程。 教程给每个项目定了三个交付物：需求文档、执行记录、验证报告。作用很直接：让「做了什么、验了什么」留下痕迹，AI 换了一个会话，接手的人还能续上。

第 4 层，Context。 上下文是消耗品，喂多了贵，喂错了污染判断。同一个会话从第一个任务聊到第十个，单轮消耗能翻 11 倍，这个数字我实测过，见《Claude Code 裸聊会翻车》。

第 5 层，Quality Gate。 测试先行，加质量门禁，这是五层的顶。前四层决定 AI 干得快不快，第五层决定你敢不敢把产出部署上线。

对照这张图自查：如果你还在纠结「哪句提示词更灵」，你在 1 层；如果项目已经因为没有验收翻过车，直接去补 5 层，收益最快。

三、三条铁律，条条有血泪背书

五层方法是地图，教程里还有几条铁律是红线，我挑最值钱的三条。

AI 的产出只是候选答案。 教程把这条叫隔离审查：模型生成的代码、方案、结论，默认状态是「候选」，人做终审过滤器。关键动作是新开会话复审，因为生成代码的那个会话对自己的产出有立场，自己写的自己查，查不出问题。这条和我自己的习惯完全对上了，验收必须换会话，更多动作细节见《vibe coding 技巧 12 招》。

造轮子之前先搜轮子。 教程的血泪教训里排第一位。AI 写代码太快，造一个轮子的时间成本被压到几分钟，人就容易上头，什么都让 AI 现写。成本没有消失，只是后移到了维护和修 bug 的阶段。成熟方案被踩过的坑，你自造的轮子要一个一个重新踩。我的补充判据：让 AI 先搜现成方案，搜不到或者搜到的依赖太重，再动手写。

AI 是放大镜。 工程习惯好，效率放大十倍；习惯烂，烂代码和坏决策也放大十倍。教程把测试和质量门禁放在最高层，就是给放大镜装上保险。我付出过学费：AI 改并发逻辑时静默删掉 270 行防御代码，编译全绿，四天才发现。没有门禁，AI 越快你翻车越快。

四、从哪个分支开始

仓库用六个分支组织内容，一个分支对应一种起点，按需取用：

分支定位什么时候进
hello-python半小时跑通环境和工具链第一次接触，先验证地基
hello-mcp让 AI 调用外部工具和数据想接真实服务再深入
hello-cursorCursor 用户的等价讲解主力工具是 Cursor
hello-code-style定制 AI 的编码风格AI 写的代码总不合口味
hello-dev-diary开发日记，记录协作过程想留痕迹做复盘
hello-professional需求、选型、架构、编码、测试、部署全流程有真实项目要做，直接进

对中文用户友好的细节也做了：术语配了中英热词表，部署方案考虑了免翻墙的环境。这在国内同类教程里不多见。

回到最初的问题：1.6 万星值不值得进。工具会换代，Codex、Claude Code、Cursor 半年后都可能换了模样，星数会过时，这套教程里跟着时间贬值的只有器那一层。法层的东西不贬值：把产出当候选、造轮子前先搜、测试先行，这三条在纯手工编程的年代就成立，到了 AI 代写的年代，从加分项变成了生死线。要我说，进仓库先看 hello-professional 一个分支就够了，剩下的按缺什么补什么。
