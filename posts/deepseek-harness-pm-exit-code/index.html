一个退出码 1 的误诊：DeepSeek Harness 沙箱故障乌龙复盘

一次什么都没搜到的 ripgrep 查询，能让整台机器拉响沙箱故障的警报。名单上的嫌疑人有 Landlock、有 runner、有整套文件系统搜索，实际上全员无辜。这桩冤案的卷宗就躺在 DeepSeek Harness（下称 dsh）仓库的 postmortem 目录里。

翻开它的过程挺有意思：故障不是环境坏了，两套各自合理的设计撞在一起，撞出了一个谁都没想到的结论，合法的非零退出会被当成基础设施塌方上报。这种误诊比漏报更伤人，因为它消耗的是你对告警本身的信任。

一、ripgrep 空结果引发的全家桶报错

现场长这样。在 Landlock ABI 较旧的内核上，glob 和 grep 返回的合法结果会被 harness 标成 SANDBOX_UNAVAILABLE，用户看到的是一整套基础设施级的报错。环境没有坏，文件也没少，报警已经响成一片。

源头藏在 ripgrep 的一个约定里：退出码 1 表示搜索成功执行但没有任何匹配项。目录里没有东西满足 pattern，它正常结束并返回 1。也就是说，非零退出在这个工具的世界里可以代表好消息，而 harness 侧的分类规则恰好没把这层含义接住。

蒙冤的还不止这一个退出码。分类口径放宽到「任意非零退出加这条子串」之后，false 直接以非零收场、无效 pattern 时 ripgrep 以退出码 2 结束、甚至子进程自己挑了个退出码 125 收尾，这些发生在约束与执行全部成功前提下的普通结局，都可能被登记成沙箱基础设施故障。最讽刺的冲突在最后一个数字上：launcher 真失败的约定退出码恰好也是 125，子进程完全可以从容选走同一个号码。

这篇复盘的内容全部出自仓库 docs/postmortem 目录的 0004 号文档，下面按原文展开。

二、一行子串匹配的两类人

误诊的机制集中在一条 stderr 判定规则上。原生 launcher 往标准错误里写的行有两种身份：一种叫部分强制执行通知，内容形如 landlock-run: partial enforcement (older Landlock ABI)，打印之后 launcher 继续正常执行子进程；另一种是真失败，此时打印诊断信息并以退出码 125 终止，子进程根本不会被执行。麻烦在于两种行共用同一个前缀。

harness 的判定用的却是不区分大小写的 landlock-run: 子串匹配，两类情况在这把尺子底下长得一模一样。消费方接着接力：看到非零退出码加上这个子串，就把整次调用登记为 runner 失败。于是每一次返回空结果的 rg 全都蒙了冤，iglob、grep 一个都没跑掉。

换个角度描述会更准：这是表达力不足的问题。公开的沙箱结果类型只能表达一组子字符串，于是有三件事它根本装不下：Landlock 失败必须使用退出码 125 这条事实装不下，致命证据必须集中在一行诊断之内装不下，同一前缀下有一行固定文本属于信息性通知这件事更是无从谈起。消费方的布尔判定只好用手里仅有的材料定罪，把来自不同进程、互不相干的两个事实拼成了因果。

细节的呈现还叠了一个小动作：报告错误详情时固定取 stderr 第一行。哪怕致命证据实际写在后面的行里，操作者看到的永远是开头那行。归因已经错了，展示还要再糊一层。

三、简化是在哪一步发生的？

复盘时间线值得按步重放，因为缺陷正是被其中某一步悄悄换掉的。第一步，原生 launcher 定下约定：launcher 自身失败以退出码 125 收场，每次失败都印一行致命的 landlock-run: 诊断；内核只能部分强制执行时，则打印措辞精确的通知，随后照常执行子进程。约定本身边界清晰，两类局面从文本到状态都区分得开。

第二步发生换血。沙箱提供方把这套约定封装成一条签名列表：runnerFailureSignatures 里只剩 landlock-run: 一个前缀。退出码门控没了，逐行结构没了，通知与致命的诊断差别没了，留下的是一个谁都能撞上的字符串。第三步，bash 消费方拿着这个前缀与任意非零退出做组合判定，并顺手把 stderr 第一行当作详情上报。第四步，测试矩阵顺着表示方式一起变矮。

第四步多解释两句。单元测试覆盖了三种剧本：没有诊断的成功、带诊断的拒绝、含致命前缀的失败；唯独没人构造过「通知之后跟上一个由子进程控制非零退出」的组合。真实 runner 测试在没有对应内核的主机上自行跳过，而完整 ABI 的机器又演练不出降级通知，长尾状态两头落空。

模拟提供方的剧本形状也照着数据表示画：要么不输出 runner 行，要么只给含义明确的致命前缀，从不在子进程的非零退出之前先递上一条无害通知。数据表示缺了哪个角，测试矩阵就缺同一个角。直到有人写下一个最小 POSIX 包装脚本，先打印那条通知再 exec 实际负载，拿 false 和 ripgrep 空匹配两种输入各喂一次，误判当场现形。

复盘的教训清单里由此多了一条通用守则：平台差异要在原生边界上放一个确定性的模拟实现，再覆盖一条组装后的产品路径；会自行跳过的真实内核测试，单独扛不住这类回归。

四、第二层遮蔽更隐蔽

分类器认错人还不算完，错误上报通道又叠了一层转换。当时的文件系统搜索由 runRipgrep 函数承担，它架在 bash 之上跑 ripgrep，捕获除中止之外的所有错误，然后统一替换成一套 cwd 与 shell 启动相关的 SEARCH_FAILED 话术。

结构化的 SANDBOX_UNAVAILABLE 就这样被第二层吸收掉了。后果比第一次误诊更重：就算真发生了沙箱故障，操作者拿到的也是那段通用启动文案，里面不含任何可定位的细节；调用方原本能靠 SANDBOX_UNAVAILABLE 错误码做程序化分支处理的希望也一并落空。假警报淹没真故障，诊断通道整体失明，两层设计单独看都算自洽，叠在一起连现场细节都传不出来。

五、修法是收紧签名

四处修改里有两处直接落在判定规则上。判定前先精确排除信息性行，剩下的情况才进入失败评估；致命证据必须带退出状态门控，光凭那条子串不再构成定罪依据，partial enforcement 通知从此只被当作通知处理。

现在的判定规则长什么样，子系统文档写得明白：RunnerFailureRule 携带可选的允许退出码门控、一组不区分大小写的逐行致命签名，以及按整行精确匹配排除的信息性行；消费方先把排除项剥掉再做致命匹配，单独一条无害通知从此提供不了失败证明。Landlock 后端同步改了约定实现：映射为退出码 125 加一行非通知式的诊断；bwrap、Seatbelt 和自定义 runner 则继续只依各自的签名行事。

另外几处改动各自堵住一层翻译损失。dsh-bash-sandbox 改为直接 spawn 提供方的 argv，启动之前就遭拒的情形走 spawn 错误通道上报，不再翻译成本地化的 shell 诊断；前台与后台执行共用一套返回证据的分类器，致命证据的优先级高于拒绝证据，前台错误上报匹配到的那条致命行，同时保持捕获到的 stderr 原封不动。同一座代码库里的 shell 执行层早有同款直觉：超时、中止、信号与退出码各自独立成字段，哪个维度出事就报哪个维度，互不代言。

文件系统搜索整体搬上 subprocess seam，直接执行打包好的 ripgrep，不再借道沙箱化的 bash，少一层包裹就少一层错误翻译的机会，seam 设计我在能力接缝那篇里展开过。守卫还配了两层回归：原生边界的 partial-landlock.spec.ts 覆盖信息性通知、致命证据与前／后台三类局面；组装后的产品路径另有 partial-landlock 快照组合固定下来，独立于文件系统搜索的实现选择存在。

安全边界也必须说清：这个缺陷从头到尾没有削弱任何强制约束，也没有让命令越过沙箱裸奔，受影响的面集中在可用性与诊断完整性上。dsh 沙箱整体为什么采用 fail-closed 取舍，见沙箱专题。

六、宁窄勿宽，先把例子摆实

把经验推成通用清单之前，先拿卷宗里的现成素材过一遍筛子。三条原则的每一个推演步骤都能落在这份事故记录上，不需要引入任何外部案例。

第一条，退出码要进合取。rg 空搜索返回 1 属于正常业务结局，新规则要求致命证据配上特定的门控退出码，Landlock 这一族只认 125，1 在第一道条件处就被洗清嫌疑。旧签名对数字毫无概念，所以 1 被照单全收，这就是反面教材本身。

第二条，信息行的排除要走整行精确比对。partial enforcement 通知全文措辞固定，具备列入白名单的条件，摘除动作发生在致命匹配之前，通知单独出现时判定因证据不足自然终止。对从未登记过的陌生致命行则反向处理：保持失败关闭，宁可多花一次人工确认。共用一个前缀的两类行，由其余部分的精确程度各断各的案。

第三条是个纯反例：详情不许固定取首行。设想致命诊断印在第三行、前两行被子进程自身输出占用的场景，首行策略交出去的解释材料将与故障毫不相干。修复后的分类器上报匹配到的致命行，原始 stderr 保持完整，现场随时可供复核。

三条其实指向同一个姿态：签名的职责是收窄怀疑范围，把「长得像」升级成「由多份相互独立的证据共同指向」。宽签名省下的只是几个字符的定义成本，产出的则是源源不断的新冤案。

七、带内通道的天花板在哪？

还有一个诚实的边界要交代。stderr 归根到底是一条带内通道，归因所依赖的全部线索都在受限进程看得见的同一个流里。理论上，一个受限子进程可以刻意复刻那条受了门控的致命诊断行，再凑出约定的退出码，主动制造一次误归因；合取条件拦得住无心的事故，验不出书写者的身份。

复盘据此把这个方向划成独立课题：带外状态协议属于后续加固工作，本次修复的范围限定在沙箱可用性与诊断完整性，同样不涉及任何形式的绕过。分层划界的好处在于责任清楚，一次修复只需要兑现一份承诺。

八、你仓库里有没有一个这样的分类器

误诊和漏报都要付出代价，我的看法是前者更贵。漏报是少知道了一条信息，误诊则是往信心里掺假，它同时污染两条线：可用功能被判成故障的直接损失，加上以后每次见到同类告警都不敢立刻相信的信任损耗。

签名规则的取舍因此明确起来，宁可窄而准，宽而省事的规则每天都在生产新冤案。测试侧的道理相同：老内核的降级通知属于长尾真实状态，常规测试环境永远不会撞上它，只能靠针对这种状态的专项回归来守住。现在回头翻翻手里的项目吧，找一个把 warnings 当 errors 的分类器并不难，难的是赶在下一桩冤案之前，替它补上有退出码门控的那半行条件。
