3 份拷贝看懂 QKV：Transformer 1750 亿参数拆到矩阵这一层

把 Transformer 整张网络摊开看，里面没有循环、没有卷积，没有任何称得上「结构」的东西——矩阵乘法、加法、softmax，三种运算翻来覆去叠几十层，就是 GPT 这类模型的全部。一个能写代码、改 Bug、陪你聊到深夜的程序，骨架朴素到让人愣神。

QKV 是另一处被讲玄学的地方。评论区一半人卡在「QKV 到底是什么」，我当年也卡过，卡住的原因只有一个：总想把它当成高深概念去背。把话说白就通了——QKV 不是概念，是同一个矩阵乘了三个权重矩阵得到的三份拷贝。

这篇我把一个 token 从输入到输出的完整旅程走一遍，每一步都落到矩阵形状上。看完你不光能在脑子里徒手推演整张网络，还能拿到开头那个反差的答案：奇迹不在运算本身，在运算的堆法和次数。

一、先看全景：数据在 Transformer 里走一趟

设一段输入有 n 个 token，每个 token 被表示成 d 维向量（GPT-3 小版本里 d 取 12288，教学场景常取 512）。整句话就是一个 n×d 的矩阵，从现在起你只需要盯着这个矩阵的形状变化。

它先过嵌入层拿到初始值，加上位置编码，然后进入编码器堆叠的 N 层结构。每层做三件事：自注意力（token 之间互相看一眼）、残差连接加归一化（把结果稳定地传下去）、前馈网络（每个 token 自己再深挖一次）。三层做完进下一层，N 层之后从顶端取输出。

走到嵌入层之前还有一步：分词。模型不认识字，只认识 token id。主流方案是 BPE（字节对编码）：从单个字符开始，统计语料里最常出现的相邻对，反复合并成新词元，直到词表达到目标规模。中文一个常用字多半是独立 token，英文一个长单词可能拆成两三段，数字、代码、标点各有各的拆法。「unbelievable」可能是 un+believ+able 三块，每块查嵌入表得到一个向量。分词质量直接影响一切：同样的文本，分词差劲的模型等于戴着一副度数不对的眼镜读书，而且没有「词汇必须成词」的硬约束，模型对拼写错误、混排中英的容忍度反而更高。GPT 系列词表约五万，LLaMA 系列十几万（多语言更友好），这个数字在第七节算参数量时还会回来。

一张图记住形状就够了：任何时刻数据都是 n×d，变的只是内容。注意力层让 token 之间交换信息，FFN 层让每个 token 独自消化信息，两者交替，这就是 Transformer 的全部节奏。

训练和推理时这张图的走法不一样。训练是「整句并行」：n 个 token 一次性送进去，掩码保证第 t 个位置只能看见前 t-1 个，然后每个位置同时算一遍「下一个词预测的对错」，效率极高。推理是「逐字串行」：生成一个词，把它拼回输入再算一遍，你在对话框里看到模型一个字一个字往外蹦，就是这一轮轮矩阵乘法在跑。同样生成 100 个 token，训练时一遍前向就处理完的上百个位置，推理要重复一百次前向——这就是为什么推理贵，也是后面 KV cache 这类优化存在的理由。

还有个谱系问题容易混。2017 年原始论文是编码器加解码器的双塔结构，为翻译设计。BERT 拿走了编码器（只读，擅长理解），GPT 拿走了解码器（带掩码，擅长生成），后来大模型时代彻底是 GPT 路线赢了。今天你用到的所有主流对话模型，骨架都是「解码器堆 + 下一个词预测」，所以这篇第七节之后我把重点放在解码器侧。

二、位置编码：注意力天生不知道顺序

第一个要补的洞是顺序。「我打你」和「你打我」三个词完全一样，如果模型不知道谁在前谁在后，这两句话没有区别。而自注意力机制打分时只看内容相似度，天生是个「词袋」——这是它相对 RNN 最大的短板，必须靠位置编码补。

原始论文的方案很优雅：给每个位置 pos 造一个 d 维向量，用不同频率的 sin 和 cos 波形填充。第 i 个维度用的频率是 1/10000^(2i/d)，维度越低频率越高，波长越短。

为什么选三角函数？两个性质。第一，任何固定偏移 k，PE(pos+k) 都能表示成 PE(pos) 的线性组合——相当于每个位置自带一把「相对位移的尺子」，模型想学相对位置关系，线性层就能算出来。第二，不同位置的内积呈现随距离衰减的趋势，离得近的 token 天然更容易互相注意。

拿真实数字感受一下。d=512 时，第 0 维的频率是 1/10000^0=1，波长 2π≈6 个位置，几个 token 之内波形就转完一圈，专门分辨「隔壁邻居」；第 511 维的频率是 1/10000^(510/512)≈1/9550，波长约六万个位置，整篇文章都在一个波形里缓慢爬升，负责「段落级远距离」。512 个维度就是 256 把不同刻度的尺子，从相邻两个字到全文结构全覆盖。位置向量直接加到词向量上，两者维度相同，模型在后续层里自己学会从混合信号里把「词义」和「位置」拆开用。

后来的模型大多换了方案：GPT 系列直接用一个可学习的位置向量表（简单粗暴，效果也好），RoPE 把位置信息旋进注意力计算里（现在主流大模型的标配）。RoPE 的思路值得多说一句：它不改输入向量，而是在算注意力打分时，把 q 和 k 向量的每两个维度当成复平面上的一个点，按位置旋转一个角度。两个位置的内积只依赖角度差，位置差多少、注意力分数就怎么衰减，相对位置信息在打分那一刻天然嵌入，而且外推到训练时没见过的长度也比加法编码稳。但「必须额外告诉模型顺序」这个洞，是注意力机制与生俱来的，谁也绕不开。

三、自注意力：三个矩阵的三份拷贝

现在到主角了。忘掉「Query 是查询、Key 是键、Value 是值」这种翻译腔解释，直接看矩阵怎么来的。

每个 token 的输入向量 x 是 1×d。准备三个可学习的权重矩阵 W_Q、W_K、W_V，形状都是 d×d_k（教学场景 d_k=64）。用 x 分别右乘它们：

q = x · W_Q    # 这个 token 想找什么信息
k = x · W_K    # 这个 token 能提供什么信息
v = x · W_V    # 这个 token 实际携带的内容

这 n 个 token 拼成 n×d 矩阵 X，三份拷贝就是 X·W_Q、X·W_K、X·W_V，各自 n×d_k。所谓 QKV，就是同一个 X 在三个不同权重下的三次投影——同一个词，站在三种立场上的三种说法。

接下来四步算完一层注意力：

scores = Q · K^T          # n×n，每对 token 的相关度打分
scores = scores / √d_k    # 缩放，防止方差过大
weights = softmax(scores) # 每行归一化成注意力权重
output = weights · V      # n×d_k，按权重混合各 token 的内容

除以 √d_k 这步最容易被略过，但它有硬理由：q 和 k 的每个分量都是独立分布，点积的方差约等于 d_k 倍。d_k=64 时不缩放，打分动辄几十，softmax 会退化成 one-hot——所有注意力砸在一个 token 上，梯度消失。乘个 √d_k 把方差拉回 1，softmax 才能保持「柔和地多方关注」。

不信手算一个微缩版。设 d_k=2，两个 token：「猫追」的 q=[1,0]，两个 k 分别是 [1,1]（「猫」）和 [0,1]（「追」）。点积得 1 和 0，除以 √2 得 0.71 和 0，softmax 后约 0.67 和 0.33——「追」这个位置三分之二的注意力在看「猫」，三分之一留给自己。如果 d_k=512 又不缩放，同样模式的打分可能放大到 20 比 0，softmax 直接变成 1.0 和 0.0，其余 token 全部出局。一次缩放，决定注意力是「分配」还是「独占」。把推导再推一层：q·k 是 d_k 项求和，每项独立同分布、方差约 1，求和后方差就是 d_k、标准差 √d_k——打分天然放大 √d_k 倍，指数函数对这种量级敏感，梯度归零。除以 √d_k 恰好把方差拉回 1。面试问「为什么除以 √d_k」，答案就一句：控方差、保梯度，这是数值稳定问题，不是设计美学。

多头注意力是把上面这套并行跑 h 次。d=512 破成 8 个头，每头 d_k=64，各自有自己的 W 矩阵，各自算一遍注意力，最后把 8 份 n×64 拼回 n×512，再乘一个输出投影矩阵 W_O（512×512）融合。动机很直接：一个头只能学一种关联模式——有的头盯句法依赖，有的头盯指代，有的头干脆盯相邻位置。八个小空间各学各的，比一个大空间什么都挤在一起学，效果好得多。实测里确实能观察到分工明确的专业化头，这是 Transformer 少数「设计预期被验证」的案例。

顺带算一下注意力的计算量。打分矩阵 Q·Kᵀ 是 n×n 的，n 个 token 两两打分，复杂度 O(n²·d_k)。序列翻十倍，注意力计算翻一百倍——这是 Transformer 最贵的部分，也是各种长文本优化（稀疏注意力、FlashAttention、滑动窗口）发力的地方。FlashAttention 聪明在不算 n×n 矩阵显式存下来，分块在显存里增量算 softmax，数学结果不变，读写显存的次数大减，长序列训练直接提速几倍。

回到「小猫追球，它跑得很快」这个例子走一遍全流程：「它」的 q 和全句每个 token 的 k 打分，训练好的模型里对「小猫」的权重显著最高，softmax 之后 output 里「它」的向量就混入了大量「小猫」的 v——指代消解在矩阵乘法里发生，没有任何规则代码。多头再各干各的：句法头把「追」和「球」连上，位置头确认「它」紧跟宾语从句，最后 W_O 把八个头的结论叠回一个向量。

四、残差和 LayerNorm：注意力只是打工仔

注意力算完，数据并没有直接交给下一层。先走一轮 Add & Norm：

x = LayerNorm(x + Attention(x))
x = LayerNorm(x + FFN(x))

残差连接 x + F(x) 的价值在深层网络里被反复验证：梯度可以沿着加法支路无损回传，网络再深也不会训崩。你可以把每一层理解成「在已有表示上做增量修订」——注意力层交上来的是修订建议，加上原文才是修订稿。这也解释了为什么 Transformer 能堆到几十上百层：每层只需要学「改什么」，不用重学「全部内容」。

LayerNorm 对每个 token 自己的 d 维向量做标准化（均值 0 方差 1，再乘可学习的缩放加偏置）。它压的是数值分布，防止层数多了之后有的维度数值越滚越大、有的越滚越小，softmax 和激活函数对数值范围极其敏感，不归一化几层之后就废了。你可能会问为什么不用 NLP 里更常见的 BatchNorm——因为序列长度不一，一个 batch 里各句同一位置的字毫无共同点，跨样本统计量没有意义；LayerNorm 只看单个 token 内部，跟 batch 和长度都无关，天生适合文本。

残差和 Norm 的摆放顺序还有讲究。原始论文是后归一化（post-LN）：先算注意力再加残差再归一化。后来 GPT-2 之后主流改成前归一化（pre-LN）：归一化放在子层输入上，残差通路上不再插 Norm。区别在梯度流：post-LN 的残差通路被 Norm 打断，层数一深训练就不稳，要配学习率预热小心翼翼地训；pre-LN 让残差通路完全干净，梯度直通每一层，几十上百层的堆叠才变得平淡无奇。看一篇模型结构的实现，先看它 Norm 放哪，基本能判断出身和年代。

深度堆起来之后，各层有没有分工？有，而且能用探针实验测出来：在每层顶端挂一个小分类器，看那一层的表示能不能回答「这个词的词性是什么」「这个词指代谁」这类问题。结论相当一致——浅层偏句法和表面特征，中层开始出现短语和语义角色，深层贴近任务目标和你最终读到的「理解」。残差通路把各层输出一路累加，顶层向量实际上是「浅层细节 + 中层结构 + 深层语义」的总和，删掉任何一段都有损失。这解释了为什么同样结构下，深的就是比浅的强：不是玄学涌现，是一层一层往上叠抽象级别。

顺带说清一个常见误解：注意力并不是 Transformer 里最重要的部件。消融实验里把注意力换成平均池化，模型性能下降但没崩；把残差连接砍掉，直接训不动。骨架是残差通路，注意力是挂在骨架上的器官——器官可以换，骨架不能断。

五、FFN：参数量的大头藏在每个位置里

每层注意力之后还有一个前馈网络，结构简单到过分：两个线性层夹一个激活函数，对每个 token 独立施同样的变换。

FFN(x) = max(0, x·W1 + b1)·W2 + b2    # d→4d→d

注意两点。第一，中间层扩到 4d 是原始论文的默认配置，d=512 时 W1 是 512×2048——一层 FFN 的参数约 210 万，而一层注意力的参数约 63 万（下节细算），FFN 是注意力的三倍多。学界目前的共识是：注意力负责「路由信息」（哪个 token 该看哪个），FFN 负责「存储和加工知识」（大量事实记忆被认为存在 W1/W2 的键值对结构里）。模型答不答得上知识题，很大程度看 FFN 够不够大。

第二，各 token 之间在 FFN 里完全不交流，它只沿着 d 维度独自深挖。所以一层之内「横向交流一次（注意力）+ 纵向深挖一次（FFN）」是固定节拍，谁也不能替谁。

顺序反过来行不行——先 FFN 再注意力？数学上搭得起来，效果上吃亏。FFN 加工的是单个 token 的表示，如果它先跑，加工依据只有这个词自己的词向量和位置，上下文一点没进来，等于闭卷做题；先注意力再 FFN，每个 token 的向量已经混过了全句信息，FFN 是带着语境开卷深挖。一字之差的编排，换来的是每层深挖的质量，堆几十层后差距被逐层放大。

激活函数这些年也在换代。原始论文用 ReLU，后来 GPT 系列换 GELU（平滑版 ReLU），现在主流大模型多用 SwiGLU 门控线性单元：两条支路一条过激活当「阀门」，一条保持线性当「内容」，相乘输出。SwiGLU 通常配一个不太规整的中间维度（比如 11008，不走整 4d），实测同样参数量下损失更低，现在基本是 LLaMA 系之后的事实标准。再往后是 MoE（混合专家）：把一个大 FFN 拆成若干个「专家」FFN，每个 token 过一个路由网络只激活其中一两个。总参数量巨大、单 token 实际计算量小，GPT-4 传闻、DeepSeek-V3、Mixtral 都走这条路——「知识存得多，但每次只查相关的几页」。

六、解码器多了什么

原始 Transformer 是编码器+解码器的翻译结构，现在的 GPT 类模型只保留了解码器。解码器每层比编码器多两样东西：

掩码自注意力：生成第 t 个 token 时只准看前 t-1 个，未来的 token 全部加一个负无穷掩码再 softmax，权重直接归零。没有这个掩码，训练时模型能「偷看答案」，学不到逐词预测。

交叉注意力：Q 来自解码器，K 和 V 来自编码器的输出——翻译时用当前生成的词（Q）去原文里找相关词（K/V）。GPT 这种纯生成模型没有原文可查，这项就砍掉了；翻译、语音识别这类「有输入序列」的任务，交叉注意力依然是标配。

解码器推理还有一个绕不开的工程话题：KV cache。逐字生成时，第 t 轮要把前 t-1 个 token 全部重算一遍注意力——但前 t-1 个 token 的 K 和 V 根本没变，每轮都重算是纯浪费。于是把每层的 K、V 缓存下来，新 token 只需算自己的 q k v，再和缓存打分。显存账可以当场算：缓存大小 ≈ 2（K 和 V 两份）× 层数 × 序列长度 × d × 每参数字节数，fp16 下 96 层、d=12288、序列 2048，一轮对话缓存就要约 9.7GB——还没算模型本体。所以各种推理优化都在给这块减负：GQA 让八组头共享一份 K/V，缓存直接砍到约八分之一；再往下还有量化 KV 和滑动窗口。对话模型越聊越长不降速，靠的就是这套机制。

七、手算一层的参数量

空说无凭，手算一遍。取 d=512、h=8、d_k=64、FFN 中间层 2048：

  • 注意力 QKV 三组权重：3 × (512×512) ≈ 78.6 万，输出投影 512×512 ≈ 26.2 万，合计约 105 万
  • FFN：512×2048 + 2048×512 ≈ 209.7 万
  • 单层合计约 315 万，加上 LayerNorm 的缩放偏置可忽略

还有个面试速算值得单独记：一次注意力有 Q、K、V、O 四个权重矩阵，参数 4d²；FFN 两层共 8d²；一层合计 12d²，LN 的缩放偏置忽略不计。拿 GPT-3 验证：96 层 × 12288² × 12 ≈ 1750 亿，口算直接对上论文数字。记住 4d²、8d²、12d² 这三个数，参数量题基本秒答。 FFN 占了三分之二。把层数乘到 GPT-2 的 48 层、d 拉到 1600，参数量就到了 15 亿量级；GPT-3 的 96 层、d=12288 则是 1750 亿。大模型的「大」，每层里的大头都是 FFN，注意力反而只占小头——这和大多数人「Transformer 就是注意力」的直觉正好相反。

除了层内参数，还有两块常被漏算。嵌入矩阵（词表 × d，GPT-3 是 50257×12288，约 6 亿参数）和输出层——而 GPT 系列这两块是同一个矩阵的两种用法：输入时用它把 token id 变向量（查表），输出时用它把顶层向量变回词表概率（乘转置），权重共享省了一亿多参数，这招叫 weight tying。所以严格说 GPT-3 的 1750 亿里，「骨架」约 1740 亿，「词表接口」约 6 亿。

训练目标拆开看很朴素：整个模型所有层所有参数，做的事情只有一个——给定前 t-1 个 token，预测第 t 个 token 的概率分布，拿交叉熵和真实答案比对，梯度回传。没有语法教材，没有知识库，语料喂进去下一词预测跑几十遍，语法和事实就长在了注意力和 FFN 的权重里。简单目标加上足够大的容量和语料，涌现出你看到的一切能力，这是 Transformer 故事里最让人不释手的部分。

这套「下一词预测」只是第一站。原始预训练出来的模型只会接龙，你问它问题它可能接着编更多问题。所以要跟人对话，还得两道工序：监督微调（SFT）——拿几万条「问-答」示范数据继续训练，把接龙机器掰成问答机器；人类反馈强化学习（RLHF），或者更轻的偏好优化（DPO）——同一个问题生成多个回答，让人标注哪个更好，用这些偏好信号调整模型，让它的口味贴近人类。这三步没有一个改 Transformer 的结构，改的只是权重里的内容。结构是 2017 年那篇论文定的，能力是数据加偏好信号喂出来的。

最后看一遍那个 token 的完整旅程：查词表变成向量，加上波形位置码，进第一层——被投影成 q k v 三份拷贝，和所有 token 互相打分，按权重混合，残差修订，归一化，FFN 深挖，再进下一层。十几层之后，这个向量已经混入了全句的语境信息，顶端接一个线性层加 softmax，下一个词的概率就出来了。理解到这一层之后，「为什么大模型需要那么多算力」也有了具体答案：每个 token 过每层都是实打实的几次大矩阵乘法，n 个 token、N 层、训练时整个语料库重复几十遍。矩阵乘法朴素，架不住次数恐怖。

结论

Transformer 的设计哲学是「用最通用的计算单元（矩阵乘法）换最灵活的信息通路（注意力）」。它把 RNN 的顺序依赖换成了全连接的打分矩阵，代价是失去位置感，于是用位置编码补；打分太尖锐，于是用 √d_k 缩放和多头分治；深层难训，于是用残差当骨架。每一个组件都是在给注意力的天然短板打补丁，而 FFN 悄悄占了参数量的大头。

现在回答开头的反差：只会乘法、加法和 softmax 的程序怎么会写代码？答案是「简单运算 × 恐怖次数 × 正确堆法」。注意力提供通路，FFN 提供容量，残差提供深度，1750 亿个参数在几万亿 token 上把下一词预测做了一遍又一遍——每一遍都只是乘法，但乘法的组合空间里装得下语法、事实和推理模式。运算确实朴素，架不住堆法精妙、次数恐怖。

网上教程喜欢把 QKV 讲成玄学，我的建议是永远回到矩阵形状：任何一步你说不清输入输出各是几行几列，就还没真懂；说得清，剩下的只是乘法。下次再有人拿「注意力机制」唬人，你就让他把 Q 的形状说出来，多半就露馅了。
