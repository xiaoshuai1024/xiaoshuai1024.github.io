Claude Code 又被封号？CcSwitch 切国产模型，省 99%

做 AI 开发，主力客户端我用 Claude Code。Skills、MCP、subagents 这套框架能力，目前没有对手。但官方账号绕不开一个问题：我的号就封过。

Anthropic 不向中国地区提供服务，注册只能借其他地区的通道。中国地区封号极频繁，Claude Code 源码里直接写了地区判断，识别到国内环境就视为违规。个人号如此，团队共享 key 风险更大。被封那天，我一点都不慌。

后来我换了一条路。Claude Code 客户端本身是开源的，模型供应商可以换。用 CcSwitch 把 DeepSeek、Qwen、Kimi、GLM 这些国产模型接进同一个客户端。封号之后，我全量切到国产模型，切一次就不回官方。

读完后你能做到：一套 Claude Code 客户端全量跑国产模型；月账单从官方 $100+ 掉到几美元；账号也不再随时面临封号风险。

Claude Code 强在哪，官方号为什么容易封

为什么离不开 Claude Code，答案在框架层。它和「填提示词的工具」是两代产品，差别在下面四样能力：

  • Skills：把常用工作流封装成可复用的技能，一个命令执行整套流程
  • MCP：接任意外部工具，数据库、浏览器、设计稿都能连
  • subagents：按角色派多个子代理并行干活，主会话只做收敛
  • 多会话编排：一个任务拆成多个会话并行跑，最后合流

这套能力属于客户端的框架层，不是某个大模型的独有能力。模型是发动机，客户端是底盘。底盘好用，换个发动机照样开。

问题出在根本上：Anthropic 根本不向中国地区提供服务。想用官方号，只能借非中国地区的通道注册。

账号一回到中国地区网络，封号就成了高频事件，源码里就有地区判断，识别到国内环境就视为违规。封号和你的使用模式无关，是你所在的地区本身就不在服务范围内。对重度用户来说，这等于脖子上一直悬着一把刀。

适用人群与前提

这篇文章适合两类人：

  • 重度用 Claude Code / Codex，但官方号被风控或快被风控的人
  • 想用 Codex 但接不上官方模型、想换国产模型的人

前提不多，三样东西：

  • 已装 Claude Code 或 Codex CLI
  • 一个国产模型平台的 API key（DeepSeek / Qwen / Kimi / GLM 任选）
  • 一个桌面小工具，macOS 或 Windows 都行

版本我用的：Claude Code 最新稳定版、CcSwitch v3.16.5+。DeepSeek 侧是 V4 Flash 正式版 API（2026 年 7 月底公测）。

CcSwitch 是什么：一个管所有客户端配置的开关

CcSwitch 是 farion1231 开源免费的桌面应用（MIT 协议，Tauri + Rust 写的），干一件事：在多个 AI 客户端之间切换模型供应商。

它内置 50 多家供应商预设，DeepSeek、Qwen、Kimi、GLM、MiniMax、硅基流动、火山引擎、百炼都在里面。你只填一个 API key，剩下交给它。

切换的底层动作很简单：把 provider 配置原子写入各客户端的 live 配置文件。Claude Code 读 ~/.claude/settings.json 的 env 段，Codex 读 ~/.codex/auth.json 加 config.toml。

CcSwitch 就是那个替你改配置文件的人。点一下，配置落盘：Claude Code 即时生效（热重载），Codex 重启终端后生效。

这套机制的优势在可逆。切错了、某个模型不给力，换一个国产 provider 就恢复原状，不用手动改一堆 JSON。配置本身存在本地（~/.cc-switch/ 目录），不用注册、不传云端。

为什么是本地文件而不是云端账号？因为切换的本质就是改一份纯文本配置，不依赖任何厂商的登录态，不经过第三方服务器，改坏了一键还原。

配置来源可审计，换机器拷走 ~/.cc-switch/ 整个目录就能恢复整套配置。

整体四步配置 + 最后一步全量国产：装 CcSwitch → 添加国产 provider → 切 Claude Code 验证 → 接 Codex → 封号后全量跑国产。每一步的具体动作和预期输出在下面步骤里。

成本账：官方模型和国产模型差一个数量级

先看官方定价（2026 年 7 月，单位 美元/百万 token）：

模型输入输出
Claude Fable 5$10$50
Claude Opus 5$5$25
Claude Sonnet 5$3（促销期 $2）$15（促销期 $10）
Claude Haiku 4.5$1$5
DeepSeek V4 Flash缓存命中约 $0.028输出同样便宜一个量级

最显眼的是 DeepSeek V4 Flash：输入价格约为 Opus 的 1/178。按每天几百万 token 的重度用量粗算，官方账单每月上百美元；切到 V4 Flash 缓存命中后是个位数美元，省 99%。

而且 DeepSeek 的缓存命中折扣给到 98%，业内大多数厂商只有 90%。批量任务命中缓存，成本还要再降一个量级。

还有一个关键点：DeepSeek V4 Flash 官方适配了 Codex。从 7 月 31 日发布的新版起，当前 Flash 模型正式支持 Codex，它原生支持 OpenAI 的 Responses API，DeepSeek 官方文档的「接入 Agent 工具」明确列了 Codex。

这是国产模型里第一个被官方点名的 Codex 后端。其他国产模型接 Codex 通常要本地代理把协议转一下，CcSwitch 内置了这种本地路由。

V4 Flash 的榜单数字和真实边界，我在这篇拆解里讲过，82.7 分是官方测试上限，生产表现要看自己的任务。

步骤 1：去 GitHub Releases 下载 CcSwitch

到 CcSwitch GitHub Releases 下载并安装桌面应用。它是所有切换操作的总入口，官方下载渠道就一个：GitHub Releases，官网 ccswitch.io 的下载按钮也指向那里。

# macOS：Homebrew 一行装好
brew tap farion1231/ccswitch && brew install --cask cc-switch

# Windows：https://github.com/farion1231/cc-switch/releases → 下载 .msi（安装版）或 Portable ZIP（免安装，解压即用）

Linux 用户下载 .deb 或 .AppImage。认准仓库作者 farion1231，别下错同名项目。

预期输出：打开应用，能看到 Provider 列表页和管理页。

步骤 2：添加国产模型供应商

按官方手册（仓库 docs/user-manual）的流程，添加 DeepSeek，填入 API key。这一步的细节经常被忽略：应用切换器没选对、预设没选，就会卡在「添加后不生效」。照着官方文档走最稳。

配置流程五步：

  • 顶部应用切换器确认选的是 Claude Code（不是 Claude Desktop，两者配置路径不同）
  • 点右上角的 + 打开「添加供应商」面板
  • 「预设」下拉选 DeepSeek，名称和端点会自动填充，不用手填
  • 粘贴 API key，点「添加」
  • 可选：点模型输入框旁的 Fetch Models，自动拉取可用模型列表

预期输出：DeepSeek 卡片出现在列表里，状态可切换。Qwen、Kimi、GLM 等其他国产平台同理会操作，各加一张卡片，后面切换就是点一下的事。

步骤 3：一键切换并验证 Claude Code

选中 DeepSeek 卡片，点「启用」。CcSwitch 会把 ANTHROPIC_BASE_URL、ANTHROPIC_AUTH_TOKEN 写进 ~/.claude/settings.json 的 env 段。DeepSeek 提供 Anthropic 兼容端点（https://api.deepseek.com/anthropic），Claude Code 不用改一行代码。

切换后 settings.json 长这样：

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.deepseek.com/anthropic",
    "ANTHROPIC_AUTH_TOKEN": "sk-..."
  }
}

预期输出：Claude Code 支持热重载，切换后即时生效，/status 里显示的模型从官方 Opus 变成 DeepSeek V4 Flash。

步骤 4：Codex 接 DeepSeek V4 Flash

在 CcSwitch 里配 Codex 客户端，选中 DeepSeek，切换。V4 Flash 原生支持 Responses API，CcSwitch 会把 ~/.codex/auth.json 和 config.toml 一起写好。

预期输出：codex 会话跑在 V4 Flash 上。注意 Codex 不像 Claude Code 那样支持热重载，切换后要重启终端再验证。它在 Terminal-Bench 2.1 有 82.7 分，做命令行 Agent 够用。

步骤 5：封号之后，全量国产

换到国产模型之后，我的做法是切一次，就不再回官方。

官方号已经封了，没有「切回去」这回事。我把所有场景都放在国产模型上跑：Claude Code 和 Codex 两个客户端，都走 DeepSeek V4 Flash。重活、轻活、日常任务，全在这一个模型上。

不是「重的用官方、批量用国产」，那是封号前才有的配置。封号后全量国产才是常态。

不同的国产模型之间，能力有强有弱，但切换也是可选的，不是必需的。我的主力是 V4 Flash，需要更强的推理能力时，换成国产阵营里更强的那个（Qwen3-Coder 或 Kimi），这些都要在步骤 2 里先配好卡片，到时点一下就是几秒钟的事。

但这跟「回官方」是两回事，国产阵营内部怎么选都行，官方号一旦封了就不碰了。

常见报错与排查

401 认证失败。原因是 API key 填错，或 env 没写进配置文件。检查 ~/.claude/settings.json，确认 ANTHROPIC_AUTH_TOKEN 指向的 key 在平台后台有效。

切换后没生效。先确认是哪个客户端：Claude Code 支持热重载，切换后即时生效；Codex 需要重启终端再验证。都试过还不行，检查 ~/.claude/settings.json 的 env 段是不是被别的工具改回去了。

首次启动提示登录 / 初始化引导。Claude Code 没识别到新配置，先弹登录流程。到 CcSwitch「设置 → 通用」打开「跳过 Claude Code 初次安装确认」，再重启 Claude Code，它会把 skipIntroduction 写进 settings.json。

Codex 接入报协议错误。部分国产模型只有 Chat Completions 端点，Codex 要的是 Responses 格式。用 CcSwitch 的本地路由转协议，或者直接换原生支持 Responses 的模型（V4 Flash、MiMo、豆包、Qwen3-Coder 这批）。

国产模型工具调用不稳 / 不支持 Extended Thinking。V4 Flash 的 Tool Use 是部分兼容，深度思考类任务偶尔抽风。这类活在国产阵营里换更强的模型（Qwen3-Coder、Kimi 这批），别硬扛在 V4 Flash 上。

别指望一个国产模型吃下所有场景。国产模型便宜是便宜，能力天花板和稳定性有高有低。深思考、长链路这种重活，换成国产阵营里更强的旗舰，别全都压在 V4 Flash 上。但整体还是全量国产，阵营内部怎么选都行，官方号不碰了。

完整产物与关键文件

整套方案跑起来后，真正参与工作的文件就三个：

  • ~/.claude/settings.json：Claude Code 的配置，CcSwitch 切换时原子写入 env 段
  • ~/.codex/auth.json 加 config.toml：Codex 的认证与模型配置，同一处切换
  • ~/.cc-switch/：本机目录，所有 provider 配置的源头

换机器时把 ~/.cc-switch/ 整个目录拷过去，重新装一次 CcSwitch 导入即可，不用手动重建每个供应商。

CcSwitch 源码在 GitHub（farion1231/cc-switch），MIT 协议。配置切换是本地文件操作，没有云端同步，介意数据出网的场景也能用。

长期用下来的判断

我从换方案到现在，客户端一直是 Claude Code，必装插件和重度用法里写的那套 Skills、MCP、subagents 能力一个没少，因为框架在客户端里，不在模型里。换了发动机，底盘还是那套底盘。

成本这关最直观。官方价 $5/M 的输入，V4 Flash 缓存命中约 $0.028/M，差 178 倍。这不是省一点，是把 token 从计价单位变成了不心疼的资源，批量任务敢放开跑，这是贵模型时代不敢做的。

至于封号：国产模型 API 走的是平台 key，不存在违反服务条款的问题。

我的号被封之后，这套方案让我把「想用 Claude Code 的框架」和「不想担封号风险」两件事同时解决了。这也是我对所有重度用户的建议：封号后全量切到国产模型，切一次就不再回官方。用 CcSwitch 把配置管在同一处，需要更强能力就在国产阵营内部选旗舰，别再把官方号当靠山。
