Claude Code 裸装，是个能干的终端 agent；装对插件和 skills，才是把它的能力放大的那个乘数。

同一个 Claude Code，装了 spec 驱动、浏览器自动化、实时文档、token 压缩、代码图谱这些之后，能干的事是完全不同的量级。这篇把我验证过、值得分享的开源插件和 skills 按 GitHub Star 排了一下，每个的安装命令都从对应仓库的 README 抓的真实写法，照着复制就能装。Star 数截至 2026 年 8 月，来自 GitHub，每天在涨，仅作量级参考。

先看排行

下面按 Star 从高到低逐个讲。

1. Superpowers · 约 26 万 stars

仓库：github.com/obra/superpowers

它是什么：一套 agentic skills 框架 + 软件开发方法论。不是单个插件，是一整套"怎么用 AI 做软件"的技能包——brainstorm、设计、TDD、代码审查、调试、执行计划，每个环节都有对应 skill。跨 11 个 agent 平台（Claude Code、Codex、Cursor、Antigravity、Gemini CLI、OpenCode 等），是这套生态里 star 最高的。

为什么值得装：它把"高手怎么用 AI 编程"沉淀成可复用技能，而不是让你每次从零写提示词。executing-plans（每步验证门）、grill-me（拷问方案）、brainstorming（创意前置）这些 skill，覆盖了从想到做的完整链路。

安装（Claude Code）：

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

2. ECC · 约 23.7 万 stars

仓库：github.com/affaan-m/ECC

它是什么：全称 The agent harness performance optimization system，一个 agent 性能优化系统。打包了 skills、instincts（直觉规则）、memory（记忆）、security（安全）、research-first development（研究优先开发）五个维度，给 Claude Code、Codex、OpenCode、Cursor 用。提供 minimal / full 两种 profile，按需选。

为什么值得装：它管的是 agent"怎么跑任务"本身——记忆怎么留、安全怎么守、动手前先调研。这层能力是大多数人调 Claude Code 时忽略的，但恰恰决定 agent 长任务稳不稳。觉得自己的 agent “跑着跑着就飘了”，先看这个。

安装（Claude Code，minimal profile）：

npx ecc-install --profile minimal --target claude

或手动：

/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc

3. karpathy-skills · 约 19.8 万 stars

仓库：github.com/multica-ai/andrej-karpathy-skills

它是什么：一个 CLAUDE.md 文件，改善 Claude Code 的行为，源自 Andrej Karpathy 对 LLM 编程陷阱的观察。提供两种装法：作为 Claude Code 插件（跨项目生效），或合并进单个项目的 CLAUDE.md。

为什么值得装：这份清单里最轻的一个，就一个文件。但 Karpathy 对"LLM 写代码常踩哪些坑"的观察非常准，把这些反模式直接写进 CLAUDE.md，等于给 agent 装了个避坑直觉。零成本、收益直接，适合任何新项目的起手式。

安装（插件方式，推荐）：

/plugin marketplace add forrestchang/andrej-karpathy-skills
/plugin install andrej-karpathy-skills@karpathy-skills

4. graphify · 约 10 万 stars

仓库：github.com/Graphify-Labs/graphify

它是什么：把任意代码库（文档、SQL schema、配置、PDF）转成可查询的知识图谱。一个 /graphify skill，本地确定性 AST 解析，每条边都可解释，不依赖向量库。支持 Claude Code、Cursor、Codex、Gemini CLI。注意 PyPI 包名是 graphifyy（双 y），CLI 命令才是 graphify。

为什么值得装：大型 codebase 是 AI 编程的最大障碍——上下文塞不下，agent 看不全就乱改。graphify 把代码库结构化成图谱，agent 查关系、追调用、定位改动点都有了准头。项目越大越值钱，且本地解析、确定性、不调云。

安装：

uv tool install graphifyy      # 装 CLI（或 pipx install graphifyy）
graphify install               # 把 skill 注册到你的 AI 助手

5. caveman · 约 9.5 万 stars

仓库：github.com/JuliusBrussee/caveman

它是什么：一个 token 压缩 skill。原话：“why use many token when few token do trick”——用"穴居人"式的简短说话方式，砍掉约 65% 的 token。提供一键安装脚本（自动发现机器上所有 agent）和 Claude Code 插件两种装法。

为什么值得装：context 预算是 AI 编程的硬约束，烧光了就得清上下文、丢历史。caveman 用极简措辞输出，把同样的信息塞进更少 token，等于变相扩了上下文窗口。长任务、长对话场景下，省下来的 token 就是省下来的钱和连贯性。

安装（Claude Code 插件）：

claude plugin marketplace add JuliusBrussee/caveman
claude plugin install caveman@caveman

或一键脚本（macOS/Linux/WSL）：

curl -fsSL https://raw.githubusercontent.com/JuliusBrussee/caveman/main/install.sh | bash

6. OpenSpec · 约 6.3 万 stars

仓库：github.com/Fission-AI/OpenSpec

它是什么：Spec-Driven Development（规格驱动开发）工具。让 AI 编程从"对话式临场发挥"变成"先写 spec、再按 spec 实现"的工程化流程。需求落成可读、可追踪的 spec（proposal / design / specs / tasks），AI 按 spec 一步步实现，每步都能回溯到规格。需要 Node.js 20.19.0+。

为什么值得装：AI 编程最大的坑不是写不出代码，是写出来的代码对不对没法验证。OpenSpec 直接解决"AI 一顿操作，结果不对"的根本问题——先约定清楚要做什么，再让 AI 照着做，每步可验证。这是我每天在用的核心工具。

安装：

npm install -g @fission-ai/openspec@latest
cd your-project
openspec init

7. Context7 · 约 6 万 stars

仓库：github.com/upstash/context7

它是什么：给 LLM 提供实时、最新代码文档的 MCP server。让 Claude Code 写代码时拉到当前版本的库文档，而不是靠"记忆"里可能过时甚至编造的 API。提供 CLI + Skills 和 MCP 两种模式，需要 Node.js 18+。建议在 context7.com/dashboard 申请免费 API key 拿更高限额。

为什么值得装：模型幻觉里有一大类是"编造 API"——参数名错了、方法不存在、用了已废弃接口。Context7 直接堵这个口子，问它某个 API 怎么用，它拉真实文档而不是猜。用新版本库的项目几乎是刚需。

安装：

npx ctx7 setup

这条命令走 OAuth 认证、生成 API key、自动装好 skill。可用 --claude / --cursor / --opencode 指定目标 agent。

8. Playwright MCP · 约 3.6 万 stars

仓库：github.com/microsoft/playwright-mcp

它是什么：微软官方的 Playwright MCP server。让 AI 驱动真实浏览器——点击、填表、截图、跑 E2E、抓页面内容。微软官方维护，跟进速度和质量有保证。

为什么值得装：只要活儿和浏览器沾边（前端调试、E2E 测试、爬数据、验证 UI），这个就是必备。比让 AI 凭空"想象"页面靠谱太多。

安装（在 Claude Code 的 MCP 配置里加）：

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

9. claude-hud · 约 2.7 万 stars

仓库：github.com/jarrodwatts/claude-hud

它是什么：实时显示 Claude Code 在干什么——上下文用量、当前活动、token 消耗。给那个"黑盒跑在终端里"的 agent 一个可视化面板。

为什么值得装：AI 编程最大的失控来源是"不知道它现在占了多少上下文、在哪个环节烧 token"。claude-hud 把这些摆出来，你才知道什么时候该清上下文、什么时候该停下来重新对齐。属于可观测性插件，没有它是在盲开。

安装：

/plugin marketplace add jarrodwatts/claude-hud

然后按提示 install。（Linux 老版本 Claude Code 若报 EXDEV，先升级 Claude Code。）

10. compound-engineering-plugin · 约 2.4 万 stars

仓库：github.com/EveryInc/compound-engineering-plugin

它是什么：EveryInc 出的 Compound Engineering 工作流插件。把"规划-执行-验证"这套复合工程方法论固化成 Claude Code 的工作流。

为什么值得装：和 OpenSpec 的 spec 驱动是同一类思路的不同实现——把工程纪律嵌进 AI 编程。如果不适应 OpenSpec 那套术语，可以试这个，找个顺手的。方法论类插件，关键是用得进去。

安装：

/plugin marketplace add EveryInc/compound-engineering-plugin
/plugin install compound-engineering

11. claude-skills · 约 2.4 万 stars

仓库：github.com/alirezarezvani/claude-skills

它是什么：345 个 Claude Code skills 按域分组的合集——engineering（24 核心 + 25 进阶）、product（12）、marketing（43）、regulatory/quality（12）、project management（6）、C-level advisory（28，全套 C-suite）、business/growth（4）、finance 等。

为什么值得装：量大管饱，当"技能超市"用——需要什么先来这里翻，翻不到再自己写。适合想拿个大全集打底的人。注意按域挑着装，别全装。

安装（按域，示例装工程类）：

/plugin install engineering-skills@claude-code-skills          # 24 核心工程
/plugin install engineering-advanced-skills@claude-code-skills  # 25 进阶

12. pua · 约 1.9 万 stars

仓库：github.com/tanweai/pua

它是什么：一个提高 agent 积极性的 skill——用企业高绩效文化的话术，逼 agent 拿结果、拿证据、做闭环。MIT 许可。方法论是智能路由：Debug 走根因分析、构建新功能走"质疑→删除→简化"的极简链路、架构决策走 Working Backwards。

为什么值得装：它治的是 AI 编程最普遍的毛病——自报完成但没验证。pua 触发于"又错了"“换方法"“为什么还不行"这类不满信号，一旦触发就强制证据优先：没跑验证别说完成，贴输出才算 done。这条纪律比任何花哨功能都实用。

安装：

claude plugin marketplace add tanweai/pua
claude plugin install pua@pua-skills

更新时先 claude plugin marketplace update 再 claude plugin update pua@pua-skills，否则可能装到旧缓存版本。

怎么选，别照单全收

十二个看下来，容易犯一个错：全装上。插件和 skills 不是越多越好，装多了反而互相冲突、拖慢上下文、让 AI 不知道听谁的。

选型就三条原则：

按场景缺什么补什么。 写新功能多 → OpenSpec 走 spec 驱动；要碰浏览器 → Playwright MCP；文档老变 → Context7；项目太大 agent 看不全 → graphify；context 总不够 → caveman；agent 老自报完成 → pua。不是 star 高就装，是缺这个能力才装。

方法论类只选一套。 Superpowers、ECC、OpenSpec、compound-engineering、pua、karpathy-skills 都带行为约束或方法论，别同时全开，选一套吃透。可以 karpathy-skills 当起手式（一个文件零成本），再选一个主方法论（OpenSpec 或 Superpowers），pua 留作 agent 偷懒时触发的纪律。

可观测性和 token 不能省。 claude-hud 这种监控、caveman 这种省 token，看着不起眼，但是"让你能持续跑下去"的底座。AI 编程要工程化，可观测和预算控制是前提。

一个判断

很多人把 Claude Code 当成一个更聪明的命令行工具，装完就开干。但它的真正价值要在插件和 skills 生态里才释放出来——裸装的 Claude Code 是发动机，插件和 skills 是变速箱和方向盘，没有后者你只能在原地轰油门。

如果只留三个，我会留 OpenSpec（保证做的是对的事）、Playwright MCP（让 AI 能碰真实世界）、Context7（保证用的知识是对的）。这三个分别管"方向、执行、知识”，是工程化 AI 编程的最低配。

剩下按场景加。但记住一条：每装一个，想清楚它补的是哪个能力缺口；补不上的，star 再高也别装。 工具的价值在于被用对，不在于被装上。
