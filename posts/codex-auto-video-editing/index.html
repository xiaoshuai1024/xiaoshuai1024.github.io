Codex 自动剪视频实操：串起 DeepSeek 和开源 Skill，6 条素材变 30 条

让 Codex 自动剪视频，最难的不是让它看懂视频。我跑通这条管线之后回头看，真正决定成败的只有一条纪律：每一步只吃上一步的产物。镜头切分吃 FFmpeg 的帧差输出，配音吃镜头表，成片吃配音时间轴——任何一步越过上游直接碰原始素材，整条管线就开始猜，猜错一次，后面全部返工。

这条管线现在一天能出 30 条，单条配音成本 4-8 毛，产量是手动剪辑的 5 倍。下面是完整搭建过程，从装 Codex 到剪映草稿自动落盘。

前置：装 Codex，权限放到最后一档

Codex 桌面版从官网下载（chatgpt.com/codex/get-started），安装时权限有三档：请求批准、替我审查、完全访问。

自动剪辑要读写素材文件、跑 FFmpeg 和 TTS 脚本，前两档每一步都要人点确认，管线会卡成手动档。完全访问只给盯过的自动化流程，这是它能自动跑的关键，也是别随便给其他会话开的原因。

把模型切到 DeepSeek V4 Flash

剪视频是高频调用场景，默认模型按量计费不划算。~/.codex/config.toml 几行切到 DeepSeek V4 Flash：

model = "deepseek-v4-flash"
model_provider = "deepseek"

[model_providers.deepseek]
base_url = "https://api.deepseek.com"
wire_api = "responses"

[model_providers.deepseek.models]
deepseek-v4-flash = { name = "deepseek-v4-flash" }

切完别停在欢迎页：让它跑一个真实小任务，比如列出当前目录并统计文件数，确认回复真的来自 DeepSeek。配置文件写对和请求真的通了，是两件事——下面这样带模型头信息的回复才算验证过：

进入剪辑：/video-generation 调 Skill，@ 引素材

工作方式是在对话框输入 /video-generation 调出视频生成 Skill，@ 引用素材文件或目录。剪辑规范、脚本、画面模板都封装在 Skill 里，对话里只给素材和意图：「把这 6 条素材按参考片的节奏混剪」。

Skill 接管后会自动建项目目录：assets 放素材、work 放中间产物、final 放成片。把这套目录约定写进项目的 AGENTS.md，下次续跑不用重新交代，一句「继续上次的剪辑」直接接着干。

幕后：四步流水线

Skill 在背后跑四步，每步的输入严格等于上一步的输出：

  1. FFmpeg 帧差拆镜头：按画面变化率切片，recipe.json 记录每条镜头的起止时间；
  2. 视觉特征匹配：对镜头提特征，按参考片的风格挑选与排序；
  3. TTS 逐镜头配音：每条镜头独立配音，时间戳与镜头起止一一对应；
  4. 成片输出：remix 主片 + srt 字幕 + 剪映草稿，一次产出三种格式。

三个硬约束，比选什么模型更重要

这三个约束是成片质量的下限，来自踩过的坑：

约束判据违反后果
置信度门槛匹配置信度 <0.6 的镜头直接丢弃，不硬凑凑数镜头出现明显跳切
三镜头不同源连续三条镜头不得来自同一素材画面重复感
剪映三 ID 一致草稿内素材 ID、时间轴 ID、导出 ID 三处一致剪映打开报错或素材丢失

状态门禁先过再发：每步产物落盘后做一次存在性和完整性检查，不过门禁不进下一步。先跑通一条完整片，再回头封装自动化——顺序反了，你封装的只是 bug。

成本账

配音走本地合成，单条 4-8 毛；一天 30 条的产能下，产量从一天 6 条到 30 条，瓶颈从「剪不完」变成了「选题不够」。

这是好问题。剪辑从手艺变成管线之后，可复跑、可度量，省下来的判断力可以全部花回选题上。这条管线已经封装成开源 Skill（github.com/xiaoshuai1024/skills），四种模式全本地零收费，拿走就能跑。
