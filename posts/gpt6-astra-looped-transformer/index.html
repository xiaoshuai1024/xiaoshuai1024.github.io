这台模型为什么在实际任务上体感提升有限，可以看我之前写的能力分层分析；本文只聊架构争议本身。

GPT-6 Astra 发布前的两天，The Information 援引内部消息扔出一颗雷：Astra 用了一种叫 recurrent depth（循环深度）的设计，也就是 looped transformer（循环 Transformer），而它「会让模型的部分乃至全部推理过程变得不可见」。模型上线后争议越滚越大，逼得 OpenAI 首席科学家 Jakub Pachocki 亲自出面，说他想避免「一场由混乱的报道引发的、奔向不可监控性的竞赛」，并强调当前前沿模型的计算图深度与 GPT-4 的差距仍在两倍以内。

这句话信息量不小，但被各家转述得语焉不详。Sebastian Raschka（《Build a Large Language Model (From Scratch)》的作者）随后写了一篇长文，把技术细节摊开讲了一遍。这篇是我读完他的原文和相关论文后的复述与整理。结论先给出来：循环 Transformer 大概率不是思维链变短的元凶，更合理的解释是模型变强了，不需要那么长的草稿纸。

循环 Transformer 到底是什么

循环 Transformer 的定义可以这样给：让中间表示两遍或多遍地通过同一批 Transformer 块（常规架构只过一遍），每一遍复用同一套权重。

拿今年 7 月发布的开放权重模型 Nanbeige4.2-3B 做例子最直观。它的架构看起来就是个常规 Transformer：输入经过 token 化和嵌入之后，穿过 22 个 Transformer 块，每块有自己的权重（块内部是什么，可以看QKV 矩阵级拆解，这篇不展开）。区别在于多了一条绕回栈开头的路径：第一遍走完后，隐藏状态被送回这同样的 22 个块再来一遍。

把计算过程展开看，相当于 44 次块应用。但和真正拥有 44 个独立块的模型不同，第 23 次块应用用的是块 1 的权重，第 24 次用的是块 2 的权重，依此类推。有效深度从 22 提到 44，参数量却不用翻倍，这就是全部诀窍。

这个思路不新。2018 年的 Universal Transformer 论文就在做类似的事，只不过它反复应用的是单个 Transformer 块，没有用一整个栈。

这笔成本账要算清楚

循环不是白拿的，Raschka 把账算得很细，这也是理解整个争议的基础。

省的是参数和内存。22 个块用两次的模型，Transformer 块参数量约为 44 独立块模型的一半。附带一提，嵌入层和输出层通常占总参数相当比例（Nanbeige 3B 里约 25%，两层共享权重可降到 12.5%），这部分不在比较范围内。

不省计算。前向传播时中间输入照样要走完 44 次块应用；训练时梯度要反向流经两轮重复。实际计算开销和 44 个独立块差不多，区别只是优化器要更新的独立参数更少。

KV 缓存也省不下。这是容易想当然的地方。虽然两轮共用权重，但第二轮进入某个块的中间状态和第一轮不同，产生的键值也不同，所以每一轮都得单独保留缓存条目。被复用的 22 块栈，其 KV 缓存需求和 44 独立块的常规 Transformer 一样。Nanbeige 团队试过在两轮之间共享 KV 缓存，体积确实减半，但模型表现明显不如独立缓存的版本。

另外两条经验来自他们的技术报告：从头训练循环架构效果好于把预训练好的模型 upcycling 改造；循环轮数从 2 加到 3 还有收益，但开销不划算，所以定在 2。

循环次数谁来定

Nanbeige 把循环次数焊死在 2，但这个数字完全可以是活的，不同研究给出了三种决策方式。

自适应停止（Universal Transformer）：模型内置一个小的可学习函数，每一步为每个位置输出停止概率，跨循环累加，超过阈值就停，另设最大轮数封顶。这让模型把算力分给真正需要额外计算的 token。

退出门（字节跳动 Ouro）：Ouro-Thinking 2.6B 把同一组 48 个块应用四次，共 192 次块应用，只需存 48 份权重，比 Nanbeige 更激进。一个学习得到的退出门给不同退出点分配概率，用累计概率阈值决定由哪一轮提供输出。（一个实际注意点：官方 Hugging Face 实现会先算完所有配置的轮次再选输出，循环数实际上被硬编码成了 4。）

可学习路由器（2025 年的 Mixture-of-Recursions）：和混合专家模型的思路类似，一个小型路由器作用在 token 的隐藏表示上，决定共享栈对每个 token 应用几次。路由器看的是隐藏表示，其中包含上下文信息，所以同一个词出现在不同位置，分到的遍历次数可以不同。论文探索了两种形态：专家选择路由（每个递归步骤自己挑要处理哪些 token，退出的不再参与）和 token 选择路由（路由器一开始就把每个 token 分配到 1 次、2 次或 3 次的路径上）。

效果如何？Mixture-of-Recursions 的实验里，最小规模（135M）上常规 Transformer 反而最好；模型变大后循环方案追上来，训练预算紧张时优势尤其明显；最大预算下几条曲线很接近。也就是说，模型足够大时，循环 Transformer 能在固定算力预算下提升质量。顺带还有一个细节：跳过部分计算意味着同预算能处理更多训练 token。

顺带说个容易混淆的类比。这套「循环」和 1990 年代的 RNN 确实神似，都在复用权重，但方向不同：RNN 是跨时间步复用，隐藏状态从一个 token 传给下一个；循环 Transformer 的循环发生在架构深度方向上，token 之间仍靠注意力传信息。更简单的理解是把循环 Transformer 看成「权重共享版的把模型做深」。

Astra 用没用，贡献有多大

先泼冷水：这至今只是未经证实的爆料，闭源权重模型没法自行核实。

但 Raschka 判断「很可能用了」，理由有三：报道本身；这项技术在已有研究里确实显示出潜力；以及 Pachocki 那句「计算图深度与 GPT-4 差距在两倍以内」。虽然这句话也可能只意味着用了两倍数量的常规块，并不明确证实循环架构。

更值得说的是他对贡献度的判断：Astra 的成功主要来自更好的训练配方和训练数据，循环架构这个改动或许有些帮助，但 The Information 高估了它的贡献。

那几万台 Mac 和计算机操作是什么关系

Raschka 用 Astra 的观察里，最突出的是计算机操作能力（computer use）：模型通过 Codex/ChatGPT 应用直接操作你本地电脑上的软件（哪个工具该排到哪个模型上，看三件套排班）。3D 渲染和图形任务上 Astra 好得不成比例：几乎在所有类别上甩开 GPT-5.6，但图形类演示的领先格外明显，从用 Blender 渲染纽约市到虚拟看房，社交平台上这类例子一抓一大把。

这和另一条报道对上了：OpenAI 采购了数万台 Mac Mini 和 Mac Studio 用于强化学习。这些 Mac 不是拿来训练模型的（那还是 GPU 的活，据英伟达 CEO 说法 Astra 在约 10 万块 Grace Blackwell 上训练），而是充当模型训练时可以交互的 macOS 环境：

  1. 给模型一个任务提示，比如「打开某应用并完成某事」；
  2. 框架把 macOS 界面截图喂给模型；
  3. 模型预测鼠标/键盘动作（点击、按键、滚动）；
  4. 框架在 Mac 上执行这些动作；
  5. 把执行后的新截图再喂回去；
  6. 循环 2-5 直到任务成败，把信号交给验证器打分，作为后训练阶段强化学习的奖励，和常规的可验证奖励强化学习（RLVR）同一套思路。

Raschka 有个类比很准：这像当下的人形机器人：在流水线这种已有专用机器的场景里人形不是效率最高的选择，但胜在通用。很多软件暂时没有 CLI，与其等谁把接口设计出来，不如直接提升模型操作图形界面的能力。他预计接下来几个月到几年，计算机会成为 LLM 和智能体框架两个层面持续打磨的重点。

（他顺带提了个反直觉的实战建议，值得单独记下：新一代模型理解提示词的效率已经高了，把你现有的一部分 AGENTS.md 和 SKILL.md 删掉或归档，也许并不是坏事，旧的手把手指导反而可能束缚新模型，逼它走更差的方案。）

隐藏思维链：元凶不是循环架构

终于到房间里的大象：循环 Transformer 会不会遮蔽推理轨迹？

先摆一个前提：OpenAI 从 o1 起就一直对用户隐藏大部分推理轨迹，对终端用户来说没有新增的差别，可解释性担忧主要是模型开发者视角的。

然后是推理模型的工作方式。模型在给出最终答案前会生成中间步骤，用的是普通文本 token，也就是思维链。这些步骤是草稿纸：模型仍是一次生成一个 token，中间步骤的作用是在出答案前增加计算量。草稿纸上会有回溯：模型发现错误，退回之前的某个选择换思路重来。

争议的逻辑链是这样的：推理轨迹的多 token 带来计算，循环也在块内部增加计算，那带循环的模型是不是「内部算够了，外部草稿纸就不需要了」，于是思维链变短、监控失效？

Raschka 的回答是：token 变少不构成可解释性担忧，因为它更可能只是模型变强的副产品。

证据就在 GPT-5.6 家族内部。同样达到相近任务表现，Luna 比 Sol 多用了 80% 的 token，没有人因此说 Sol 的可解释性比 Luna 差。更合理的解释是能力更强的模型（更大、训练更充分）解决问题更高效，高效的外在表现就是 token 更少。

Astra 的情况类似：各 effort 档位上它整体不一定比 GPT-5.6 Sol 用更少 token，但在准确率固定的条件下确实用得更少。Astra 系统卡承认推理轨迹的可监控性相对 Sol 有退步，主要与轨迹更短、信息量更少有关，但这无法证明循环是根本原因，轨迹整体变短同样能解释（就像 Luna 和 Sol 的例子）。

还有一个常被忽略的事实：推理轨迹本来就不保证如实描述模型内部发生的一切。Raschka 认为唯一站得住脚的担忧是循环架构会不会更频繁地生成「假的」推理轨迹刻意误导用户，但目前没有任何有力证据表明这种情况正在发生。

几小时后 Pachocki 的澄清也印证了这个方向：「我们自最早的推理模型起就一直在保留并利用思维链监控……它确实很脆弱，而且不幸的是正朝着不好的方向发展，原因与架构变化无关。」所谓「混乱的报道」，指的多半就是 The Information 那段话。

四篇值得知道的新研究

Raschka 文末介绍了几项循环 Transformer 的新进展，挑重点说。

潜在推理（2025，《Scaling up Test-Time Compute with Latent Reasoning》）：在 8000 亿 token 上训练 3.5B 模型，把 4 个块组成的共享栈夹在 2 个起始块和 2 个末尾块之间，每轮循环开始时共享栈同时接收上一轮隐藏状态和起始块输出（拼接后过线性投影）。训练时循环次数随机采样，推理时人选定预算（8/32/64 轮），另有基于相邻两轮下一 token 分布 KL 散度的自适应停止。收益取决于任务：HellaSwag 约 8 轮后趋平，GSM8K 和 HumanEval 能持续受益。注意模型仍可生成文本思维链，循环只是在每个 token 输出前给它更多计算。

记忆不等于推理（2025，《Beyond Parameters: Exploring Virtual Logic Depth for Scaling Laws》）：分别测记忆和推理，发现参数量固定时循环几乎不改变模型存储的信息量（循环是计算机制不是存储机制），但复用块能在不加参数的情况下提升多步数学题表现。也就是说，即使没有更多地方存知识，额外的计算也能帮模型解决问题。

算力等同下的公平比较（2026 年 9 月，SMELT）：在每 token 计算量、非嵌入参数量、KV 缓存需求都相同的条件下比较循环与常规 Transformer。做法是用 MoE 架构，中间一半块应用两次，收窄隐藏维度抵消计算开销，再增加专家数量补回参数量。规模做到 540 亿非嵌入参数，拟合扩展曲线后估计：达到同样验证损失，循环方案省约 6.8% 到 18% 的训练算力。这回答了「循环值不值」：值。

全带宽 Transformer（2026 年 8 月）：研究跨 token 位置的循环：每步解码用可学习门控，把上一个 token 的最终隐藏状态和新采样 token 的嵌入结合，作为下次前向传播的输入。1B 基座模型上，这种潜在反馈在 MATH500 上输出更短轨迹且保持准确率，但指令微调后缩短效应消失了。这项研究直接呼应「循环是否带来更短轨迹」的讨论，但也留下了缺口：没测常规增大模型是否会产生类似影响，也没确认更短的轨迹是否忠实度更低。

我的结论

把整场争议拆完，三个判断。

第一，循环 Transformer 是个工程上讲得通的选择：固定算力预算下换来更好的模型（SMELT 给了量化证据），省参数、不省计算、不省 KV 缓存，它改变的是计算的分配方式，不是模型的透明程度。

第二，「循环架构隐藏思维链」这个指控目前证据链是断的。思维链变短在同代不同规模的模型间一直在发生（Luna 对 Sol），轨迹本来也不保证忠实，系统卡承认的可监控性退步更可能来自轨迹整体变短。Pachocki 自己都说原因与架构变化无关。

第三，真正该盯的不是架构，是这件事本身：推理监控确实在变脆、朝不好的方向走。Raschka 的类比放在这里正合适：大学现场数学考试里，聪明且准备充分的学生大概率更少用草稿纸、更少回头重来。草稿纸变少不代表思考被藏起来了，但对我们这些只能看草稿纸的人来说，能看到的确实越来越少。这是能力提升的代价，也是 OpenAI 说要强化监控技术的理由，跟他们用不用循环 Transformer 无关。

补充一句给关心 AI 安全的读者：Astra 的计算机操作能力（配合那数万台 Mac 的训练环境）比架构传言更值得放进你的关注清单。Raschka 的态度也是这个：在把主力电脑的访问权限交出去之前，能先审计一下框架是件好事，这正是开源在这件事上的价值。

这篇把循环 Transformer 的原理、成本账和四篇新研究都拆在了明处，下次哪个模型再被爆「新架构隐藏推理」，你可以照这套方法自己验一遍，值得点个收藏备用。GPT-6 系列我会随开放进度持续写，关注后新篇第一时间能看到。你更担心推理不可见，还是计算机操作权限交出去这件事？评论区聊聊。
