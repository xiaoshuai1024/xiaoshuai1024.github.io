DESIGN.md：Google 开源的格式，让 AI 复刻 73 家官网风格不跑偏

让 Claude 写过页面的人，多半见过这一幕：第一轮极简白，你说「再高级一点」，第二轮紫色渐变就来了。需求它全听懂了，长相每次都不一样。

GitHub 上有个项目声称治这个病：VoltAgent 的 awesome-design-md，2026-10-01 我查是 119,000 颗星、13,300 次 fork。它的全部内容，是 73 份 Markdown 文件。我把其中 Linear 那份从头到尾读了一遍：23 个色值、13 级字号、8 档圆角，外加一组不许违反的禁令。

这篇文章讲清楚三件事：这文件是什么，为什么一份文本锁得住风格，边界在哪。

一、一个 Markdown，两步接入

用法在 README 里就两步：把某站点的 DESIGN.md 复制到项目根目录，然后对 AI 说一句「按这份规范写界面」。不装插件，不导设计稿，复制粘贴就完事。

这个格式是 Google 实验室提出来的。他们做了个 AI 界面设计工具叫 Stitch，DESIGN.md 就是它用来承载设计规范的格式，2026-04-21 Google 把规范草案开源，Apache-2.0 协议，放在 google-labs-code/design.md。你在 AGENTS.md 的语境里理解它会很快：AGENTS.md 告诉 agent 项目怎么构建，DESIGN.md 告诉 agent 界面长什么样。我自己仓库里躺着一份写了半年的 /posts/agents-md-hard-rules/，管住的是 agent 的行为；现在设计这半边也有对应的文本了。

规范定义了 8 个章节：概览、颜色、字体、布局、层次、形状、组件、注意事项，可以省略但顺序不能乱。文件是双层的：开头一段 YAML 配置放机器可读的设计数值，下面用 Markdown 写人类可读的设计理念。Google 还配了工具链，一条命令能检查规范写得对不对，连颜色对比度够不够都替你查，还能直接导出成 Tailwind 配置。

Google 为什么把格式白送？格式这种东西，谁开放谁定标准。agent 生态里被所有工具都认的格式，就站在了入口上。

二、Linear 那份里写了什么

Linear 是硅谷出了名讲究设计的公司，它那份 DESIGN.md 有 548 行。开头一段配置长这样，全是写死的数值：

colors:
  primary: "#5e6ad2"   # 薰衣草蓝，全站的彩色强调就它一个
  canvas: "#010102"    # 近黑背景，只带一点冷调
  surface-1: "#0f1011" # 卡片底色
  hairline: "#23252a"  # 描边
typography:
  display-xl:
    fontFamily: Linear Display
    fontSize: 80px
    fontWeight: 600
    letterSpacing: -3.0px

光颜色就有 23 个：4 级深浅不同的卡片底、3 级描边、语义色各占其位。字号整整 13 级，从 80px 的首页大标题到 12px 的注释小字，每一级的字号、粗细和字距全部写死。

光有数值还不够，正文里还有护栏。写明薰衣草蓝只准出现在四个地方：品牌标、主按钮、焦点环、链接，多一处都算违规。大标题字重 600 封顶，原文说 Linear 抗拒 700 以上的展示字重。这些条目把「Linear 的味道」从设计师的感觉，翻译成了 agent 可执行的规矩。

三、为什么一份文本锁得住风格

风格漂移的根源不是模型笨，是规范缺位。你跟 AI 说「高级感」，这四个字在不同轮次激活的候选完全不同，它每轮都在猜。你给它 23 个色值加一组禁令，它每轮都在同一套数值里做选择。判卷方式不一样：人看界面看感觉，模型出界面只认字面。

这也解释了为什么载体是 Markdown，不用 Figma 导出文件：大模型读纯文本几乎不用转换，README 的原话是「Markdown is the format LLMs read best」。前端行业做了十年的设计 token，那些命名好的颜色字号变量，第一次以 agent 能直接消费的格式落了地。

四、三条边界，一条正确用法

第一条，73 份规范不是大厂官方给的。社区从各家公开的样式代码里一份份提取，仓库自己声明「不主张任何站点的视觉所有权」。这是风格近似，不是官方认证。想要没被收录的站点，可以去 getdesign.md 提需求，还有只交付给你本人的私密通道。

第二条，「像素级复刻」是营销说法。它做到的是风格高度一致，不是拿着放大镜逐像素比对。复刻效果我也没跑过，验证就两步五分钟：复制文件，对 Claude 说一句，等界面出来。营销号的话别全信，我的话也只信一半，你自己跑一遍最有说服力。

第三条，商用风险自己掂量。拿特斯拉的规范直接做商用网站，侵权责任跑不掉。正确用法是学它的结构，写你自己的规范。给你一个五条起步的最小模板：

# DESIGN.md（最小版）
主色：#______（只用于主按钮和链接）
背景：#______（页面）/ #______（卡片）
字号：标题 __px、正文 __px，字重最大 __
圆角：卡片 __px、按钮 __px
禁令：强调色不得用于正文文字

写完可以用官方工具验一下结构和对比度：

npx @google/design.md lint DESIGN.md

五、前端的价值换了个位置

「不再需要前端写页面了」这类标题，只说对了一半。写页面的活确实在变少，但 DESIGN.md 本身就是前端的新活：色值、字阶、间距、护栏，每一条都是设计系统的工程化表达，写得出来这些的，还是懂设计和懂工程的人。交付物从页面换成规范加验收，数值是人定的，审美是人选的，判断和责任都在人手里。

这件事的分量，在格式变成标准的势头里。AGENTS.md 管构建，DESIGN.md 管外观，agent 的世界里，人写下的规矩一块块补齐。下一块被文本化的经验是什么我不知道，但把隐性经验写成显性规范这件事，从现在起值得每个写代码的人练。
