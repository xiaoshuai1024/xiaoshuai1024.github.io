省掉订阅费的 Codex,把国产模型用明白了

xiaoshuai1024 included in AI编程

省掉订阅费,是这篇文章的出发点。OpenAI 的 Codex 桌面版是当前最能打的 AI 编程 agent 之一,但官方使用路径绕不开两件事:一个 ChatGPT 账号和一笔订阅费。我在 AI 开发这条线上已经全量跑了小半年的 agent 工作流,这次把 Codex 的模型层整个换掉——用开源的 CcSwitch 把 DeepSeek 接进 Codex,配置完直接跳过官方登录,打开就是能用的状态,模型走国产 DeepSeek,按量付费。

读完你能做到:在一台 Windows 机器上装好 Codex 桌面版,不注册 ChatGPT 账号、不交订阅费,双击图标就能聊;用真实任务验证 DeepSeek 确实在响应。

适用人群与前提

这篇教程面向会用桌面软件、能看懂终端报错的开发者。不需要懂命令行,配置全程图形界面:

  • 系统:Windows 10 / 11(本教程实测 Windows 10)。macOS 上的 Codex 桌面版同样支持,CcSwitch 配置思路一致。
  • 工具版本:Codex 桌面版(本文实测 build 26.730.8199.0)、CcSwitch 最新版、DeepSeek API。
  • CcSwitch 获取:到它的 GitHub 仓库(farion1231/cc-switch)下载最新版 Windows 安装包,装好后首次打开是空供应商列表,配置完就有东西了。
  • 科学上网:下载 Codex 桌面版安装包和后续更新需要。工具自备,这里不展开。
  • 账号准备:一个 DeepSeek 开放平台的 API key。平台充值后按量付费,个人写代码一个月几块钱。不需要 OpenAI / ChatGPT 账号。

整体思路

核心分工:Codex 客户端是壳,模型供应商是芯,CcSwitch 负责换芯。

  • Codex 桌面版是 OpenAI 官方的 AI 编程 agent 前端,底层封装了开源的 Codex CLI(Apache 2.0 协议)。它默认只认 ChatGPT 账号。
  • CcSwitch是开源的供应商切换工具,它做的事是把第三方模型供应商写进 Codex 的配置文件,你不用手改。
  • 关键一步:DeepSeek 的 API 原生支持 OpenAI 的 Responses 协议,所以 Codex 直连 api.deepseek.com 就能跑,不需要本地代理中转。
  • 结果:auth.json 里放的是 DeepSeek 的 API key,而不是 ChatGPT 的登录凭证。Codex 识别到 API key 就走 API-key 认证路径,登录环节整个跳过。

为什么不用手改 config.toml?一是格式容易错,缩进、引号一不对 Codex 直接不认;二是模型目录(cc-switch-model-catalog.json)是 Codex 模型选择器的数据源,手写容易漏。CcSwitch 把这三件事打包成一个界面,换供应商、改模型都在里面点,配错了也能一键切回官方。

下面分四步走:装 Codex 桌面版 → 用 CcSwitch 配置 DeepSeek → 打开跳过登录 → 发任务验证。

步骤 1:下载并安装 Codex 桌面版

打开 Codex 官网 openai.com/codex,点 hero 里的 Download for Windows,下载 Windows 安装包(MSIX,约 740MB)。下载和安装需要科学上网。

拿到安装包后,用 PowerShell 安装:

# Windows 用 PowerShell 安装 MSIX 包
Add-AppxPackage .\OpenAI.Codex_x64.msix

安装完成后,开始菜单会出现 “Codex” 图标。这一步先不用管登录,首次打开会停在登录页,这是正常的,配置完 CcSwitch 再看。

首次双击打开,Windows 可能弹 SmartScreen 提示「不受信任的应用」,MSIX 签名包首装的正常提示,选「仍要运行」。进去后停在登录页,右边是登录按钮,先别点。MSIX 装完不需要管理员权限,想卸载直接在开始菜单右键卸载,不留残留。

步骤 2:用 CcSwitch 配置 DeepSeek

打开 CcSwitch,左侧选 Codex 客户端,点「添加供应商」。配置全程图形界面,三步走完。CcSwitch 会把供应商参数写进 ~/.codex/ 下的三个文件:config.toml、auth.json、cc-switch-model-catalog.json。

① 新建供应商。点「添加供应商」,弹出预设列表,几十个模型厂商的卡片排好:DeepSeek、Kimi、智谱 GLM、通义千问都在这。不用手写任何参数,选现成的预设。「添加供应商」按钮在窗口右上角,窗口太小会被折叠进更多菜单,把窗口拉大一点就露出来了。

② 选中 DeepSeek。在卡片网格里找到 DeepSeek,点一下,卡片整体变蓝,参数就带进来了。预设已经写好了 DeepSeek 的接入参数(官网、接口地址、协议、默认模型),不用自己查。

③ 只填 API key。选中后右侧表单自动填好:供应商名称 DeepSeek、官网 platform.deepseek.com、接口地址 https://api.deepseek.com、协议 OpenAI Response。你唯一要手填的是自己的 API key,然后保存激活。

预期输出:CcSwitch 的供应商列表出现两条:OpenAI Official 和 DeepSeek。

验证配置是否写进去:打开 ~/.codex/config.toml,能看到这几行就对了:

model_provider = "custom"
model = "deepseek-v4-flash"

[model_providers.custom]
base_url = "https://api.deepseek.com"
wire_api = "responses"
requires_openai_auth = true

responses 是 OpenAI 给 agent 场景设计的 API 形态,Codex 走它连模型。DeepSeek 开放平台原生兼容这个协议,所以 base_url 直接填 https://api.deepseek.com 就行,不需要起本地代理去转换请求格式。这是整个方案能「零代理」跑起来的原因。选成旧的 models(Chat Completions)协议会直接失败,后面报错排查里会讲。

步骤 3:重新打开 Codex,登录直接跳过

完全退出 Codex,再双击图标打开。这次不会有登录页,直接进主界面:左侧是你的项目列表,中间是对话区,底部是输入框。

预期输出:Codex 主界面直接可用,没有登录墙。第一次打开某个文件夹,Codex 会要求授权访问权限,点允许就行。

跳过的原理在认证文件里。官方路径下,Codex 用 ChatGPT 账号登录,凭证存在 ~/.codex/auth.json;CcSwitch 激活 DeepSeek 后,把这个文件里的 OPENAI_API_KEY 换成了你的 DeepSeek key。Codex 启动时检测到这个字段就走 API-key 认证,登录环节整个跳过,所以看到的是直接进主界面,而不是登录墙。以后想切回官方账号,CcSwitch 里选回 OpenAI Official 再重启一次 Codex 就行。

步骤 4:发一个真实任务,验证 DeepSeek 在跑

输入框里写一个具体的编码任务。就用上一步主界面截图里那个销售数据任务:

写一个 Python 脚本，读取一份销售数据 CSV，去掉重复的订单号，按产品分类汇总营收，并打印每周销售趋势表。

预期输出:Codex 侧边栏底部的账号徽章变成 @deepseek,回复里是 DeepSeek 写出的完整脚本 sales_analysis.py(约 273 行)和运行结果:读入 CSV 后去掉重复订单号、按产品分类汇总营收、打印每周趋势表。

确认在用的是 DeepSeek,看三个地方:侧边栏底部徽章是 @deepseek(而不是你的 ChatGPT 邮箱);回复里的模型选的是 deepseek-v4-flash;回到 DeepSeek 开放平台的用量页面,能看到这次对话的 token 消耗和扣费。三处对上,就是真的在走国产模型,不是配置了个空壳。这套确认法也是排查的总纲,出了问题先对着这三处看,能快速定位是网络、key 还是模型的问题。

常见报错与排查

配置和验证都走通了,再说几个实际会碰到的报错和排查方法。

打开 Codex 又回到登录页。配置前打开过客户端,缓存了登录态。彻底退出进程(任务管理器里结束 Codex / ChatGPT)再开。

配置完还是要求登录。CcSwitch 里 DeepSeek 没保存或没激活。回到 CcSwitch 确认激活状态,再检查 config.toml 里 model_provider = "custom" 是否真的写进去了;同时看 auth.json 里的 OPENAI_API_KEY 是不是你的 DeepSeek key,写的是 sk- 开头、后面一串字符的才是,空值或还是旧登录态就没生效。

发消息后一直转圈。到 api.deepseek.com 的网络不通。先测连通性,PowerShell 里跑 Test-NetConnection api.deepseek.com -Port 443,返回 TcpTestSucceeded : True 说明没被代理拦住;不通就调整代理规则,让 api.deepseek.com 直连。

报 401 / 403 错误。API key 无效或账号没充值。到 DeepSeek 开放平台确认 key 状态,充值后回 CcSwitch 重新激活一次供应商,让新 key 写进 auth.json。

日志里出现 “remote control requires ChatGPT authentication”。这是 API-key 认证的限制:Codex 的远程控制功能(在别的设备上操控这台机器)必须用 ChatGPT 账号,当前用不了。它是 INFO 级提示,不影响对话和写代码。

报协议错误。供应商的 wire_api 必须选 responses(DeepSeek 原生支持),选成旧的 models 协议会直接失败。

完整配置与产物

配置由 CcSwitch 生成,不手动改也完全可以。关键文件都在这三个:

文件作用
~/.codex/config.toml供应商、模型、marketplace、插件
~/.codex/auth.jsonOPENAI_API_KEY(你的 DeepSeek key)
~/.codex/cc-switch-model-catalog.json模型目录,包含 deepseek-v4-flash

auth.json 长这样(key 脱敏):

{ "OPENAI_API_KEY": "sk-***" }

cc-switch-model-catalog.json 里是模型目录,Codex 模型选择器的下拉列表读的就是它。文件里列了 deepseek-v4-flash(轻量、快、日常够用)和 deepseek-v4-pro(重活更稳),按需在 CcSwitch 里切,不用手动改文件。

手动改过配置后,重启 Codex 生效。

下一步

同一套 CcSwitch,我也用在 Claude Code 上。两篇文章可以连着看:/posts/claude-code-ccswitch-domestic-models/ 讲的是封号场景下的迁移,这篇讲的是给 Codex 直接换芯。
