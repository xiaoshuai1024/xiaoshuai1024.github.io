程序员接 AI 办公有新路:17,844 星的 Univer 让 agent 自己做表格

GitHub 上有个安静了四年的老项目:2022-09-29 建仓,把表格、文档、幻灯片搬进浏览器自己渲染,一直不温不火。到 2026 年 9 月,趋势雷达抓到它日增 1,142 星,总星 17,844(2026-09-24 实查)。更硬的信号在官方仓库列表里:DeepSeek Harness 的 Office 插件、腾讯 WorkBuddy 的本地 Office 集成,两个今年热度领先的 AI 办公产品,官方集成建在同一个开源项目上。

它叫 Univer,dream-num 出品,Apache-2.0 协议。这篇讲清三件事:它怎么接得住 agent、生态成形到什么程度、接入前要分清什么边界。判断先给:AI 办公的竞争重心正在从「给人用的界面」挪向「给 agent 用的运行时」,Univer 是把这套定位做完整的开源项目里,眼下还没有第二家。 翻红的原因在定位换轨:前四年它把公式引擎、Canvas 渲染、统一数据模型这些难啃的部分做完了,agent 浪潮一来,手里的运行时正好是刚需。

给屏幕,还是给运行时

让 agent 用办公软件,多数团队的第一反应是给它一块屏幕:截图、找按钮、模拟点击。这条路线能跑演示,生产问题一串:界面改一版脚本全废,点错菜单没人知道,任务只能串行,跑完还得人盯屏逐格核对。活省了一点,验收一点没省。

另一条路把 Office 内容做成 agent 能直接读写的结构化数据。openpyxl 这类语言库是初版:能生成文件,没有公式重算,写出来的表常常看着对、一算就错。运行时路线保留完整的编辑器语义,公式重算、引用联动都在,再把每一步开放成 API。Univer 是这条路的完整实现:浏览器里是可编辑界面,Node.js 里同一套模型去掉界面接着跑,官方叫 Headless 模式,agent 读写数据结构,人看渲染结果,两层共用一个内核。

三个机制,正对 agent 三个短板

第一,agent 改文件容易改坏。Univer 把编辑收进结构化 API,每次修改走命令体系,可撤销、可审计,改错一步就能回来。

第二,agent 说改好了,你没法信。官方给的验证三件:内容检查管数据对不对,渲染截图管样子对不对,布局诊断管溢出遮挡。agent 交活前先自检,人复核验证结果,不用整张表从头划到尾。

第三,不该让 agent 碰正式文件。官方把 git 的 worktree 心智平移进 Office:agent 在隔离草稿里干活,人在正本上审阅,决定合不合并。写代码的人一眼认出来,这就是 pull request,内容从代码换成了表格。

要提醒一句:机器验证管住质量下限,管不住业务判断。agent 做报价单,折扣公式少乘一个量级,公式自洽、排版漂亮,三件验证全过,错的只有懂这单生意的人看得出来。验证加人审,两道闸缺一不可。

生态不是路线图

README 里挂着五个官方开源集成,挑要紧的说。univer-workspace 是可自托管的完整参考实现,agent 能直接生成表格形态的小应用,页面指标绑定单元格。dsh-univer-office 给 DeepSeek Harness 用,介绍里写的 connected content、validation、isolated worktrees,和前面三个机制逐字对应。workbuddy-univer-office 给 WorkBuddy 用,MCP 预览加草稿 review,官方标注 development preview,方向已定、实现未满。

周边还有两件:univer-mcp 把表格接进 MCP 协议,自然语言直接驱动作表;univer-sdk-skills 是官方写给 agent 看的使用说明,把 Claude Code 的 skill 玩法搬进了办公域。一家做集成叫合作,五家齐挂叫选边,办公域的 agent 生态,Univer 已经站上公共层的位置,开源侧眼下没有对手。

接入前先分清两件事

第一,开源和商业的边界。核心 SDK、公式引擎、Headless 运行时在 Apache-2.0 之下,独立可用;实时协作、xlsx 导入导出、图表透视表、服务端计算在收费的 Pro 层。Sheets 成熟度靠前,Docs 演进中,Slides 还在开发。数据要留在自己的基础设施里,开源版自托管正好;要开箱协作,要么 Pro,要么闭源方案。

第二,它有明确的不适用区,对照入座:

场景建议
只需脚本生成 xlsx 或 docxopenpyxl 等语言库,更轻
要完整办公体验快速上线闭源 SDK 或飞书、WPS 开放接口
开箱即用的实时协作Pro 层或专用协同服务
给自己产品嵌表格,agent 要读写Univer 的主场
让 agent 操控已有办公软件界面自动化,Univer 帮不上

两条风险如实讲:experimental 接口有变动可能,生产接入要锁版本、避开实验段;四年才走到转折点,押注它要有陪跑预期。

带走三句话

办公内容的下一步是成为数据结构,文件只是序列化形态;agent 要的是带验证的读写接口,屏幕是给人用的;人和 agent 的分工照抄代码仓库,agent 在草稿里干活,人在正本上批准。

Univer 的翻红是一个信号:AI 成了办公软件的主要用户之一,四十年围着人设计的编辑器必须长出第二张面孔。这张面孔今天叫 harness,明天可能换词,内核不会变:读写有接口,验证有依据,合并要人批。下次要把 AI 接进表格文档,先别写操控界面的脚本,先问一句:我的 Office 内容,有没有运行时。
