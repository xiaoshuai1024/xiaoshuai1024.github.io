Codex 增长 4 倍反杀：再凭感觉选工具，加班的是你

上个月我司工位评选出了年度事件：坐角落的那个逆袭选手，把卷王的工牌抢了。

这事要从我司的特殊性说起。别的公司工位上坐着人，我们公司工位上坐着 AI——四个，都有自己的工牌，都要干活，卷起来比真人都狠。

而上个月，行业数据把这场宫斗直接拍在了桌面上：Codex 单月增长 20.8%，Claude Code 只有 5.2%。四倍的差距。要知道今年第一季度，Claude Code 周活 420 万，Codex 还不到 100 万——去年它是应届生，今年它绩效第一。

你可能觉得这是厂商的战报，跟你的键盘没关系。但选错默认工具的代价是真实的：一个不适合你工作流的工具，每天都在让你多解释、多等待、多返工——它不加班，加班的是你。

这篇把四个我都深度用过的选手拉出来遛一圈：卷王 Claude Code、逆袭的 Codex、野路子 DeepSeek Harness（下称 DSH）、新来的 ZCode。每个都讲脾气、讲短板、讲真实使用痕迹，最后给一张决策表，两分钟对号入座。

先上结论：90 秒版本

没耐心听宫斗剧的，直接看表：

你的情况默认工具核心分工
复杂重构、多文件架构活Claude Code长链路任务最稳，深度推理强
高频日结任务、预算敏感Codex增长最猛不是没原因，性价比在追平
预算拉满都不想花、要透明可控DSH开源可读，源码我拆了 11 篇，行为可预期
想要一个能开会员、管桌面的全能选手ZCodeskill 生态 + 桌面操作，覆盖面最野

记住这张表，下面的宫斗剧可以快进。但我的建议是别快进——选型这事，别人翻过的车，你没必要再翻一次。

表是粗糙的，补三个边界反例，帮你把对号入座对得更准。

反例一：预算敏感但你做的是重构密集型工作。 这时候别硬省钱。重构里一个隐藏 bug 的排查时间，够买很多次差价——该上深度工具就上，省钱的正确位置是你那些日结杂活，不是核心任务。

反例二：公司数据敏感，对任何云端工具都放不下心。 这属于信任问题压过效率问题，决策直接退化成「源码可读性优先」，DSH 的开源属性在这里不是加分项，是入场券。

反例三：你就是喜欢折腾，四个都想要。 可以，但请遵守第三节末尾的排班规则，否则四个工具改一个仓库的场面，堪比四个部门同时改一份周报——最后你花在调和上的时间，比自己写还多。工具组合的上限不取决于工具数量，取决于你的派活制度。

卷王 Claude Code：会把周报写成小说的那种

在开发者的草原上，Claude Code 已经称霸了很久。雨季来的时候，也就是需求发布周，草原上所有生物都能感觉到它的脚步声。

它的性格非常鲜明：你让它改一个按钮，它顺手给你重构了三层楼。改完了还给你写一篇小作文，解释它为什么这么做、架构上有什么考量、顺便反思了一下项目的历史遗留问题。你只是想换个按钮颜色。

这就是卷王的职场画像。团队里总有这么一位：你让他帮忙带杯咖啡，他顺便做了一次咖啡供应链优化方案，PPT 有二十页。

该说不说，卷王的能力是真的。复杂重构、跨文件改动、需要理解整个项目脉络的活，我到现在首选还是它。深度推理这个事，不是增长数据能否定的——Codex 增长 4 倍，也没在深度这一项上反超。

但它有个职场病：边界感差。你给它一个任务，它给你交付一个部门。对小团队是惊喜，对你就意味着 review 的时间变长了——它产出的每一行代码，最后都要你的眼睛过一遍。

8 月它也有大动作：安全加固，上下文成本降了 8 倍。卷王意识到了，光加班没用，还得控制成本——这话听着像不像你们公司今年发的全员邮件。

说两个我的真实使用痕迹，你感受下它的脾性。

账号风波，我的真实经历。今年我经历过一次 Claude Code 相关的账号风控，起因是用第三方渠道切了国产模型——这事我在别的文章里写过完整的复盘。教训到今天还成立：卷王对公司忠诚度有要求，你给它喂什么模型，它背后的平台是有意见的。从此我切模型的操作收敛了很多，该走官方走官方，想野一点的活，分给后面两位。

生态是另一个观察面。我那篇按 GitHub Star 排行写的插件文，是这个号数据最好的一篇——侧面说明大家都想明白了一个理：裸装的 Claude Code 只是个能干的员工，配上插件才是配置完整的部门。这种生态厚度是两年攒出来的，短期内逆袭者追不平。

所以卷王的正确用法是：把架构级的、需要全局视野的活给它，把它的认真劲儿用在刀刃上。你让它修个错别字，它给你返工整个文档，这不是它的问题，是你的派活问题。

逆袭的 Codex：职场最惨的不是输，是被骂都像抄袭

Codex 的上半年，用一个词总结：憋屈。

OpenAI 发布 Codex CLI 的时候，整个行业的评价高度一致——长得几乎和 Claude Code 一模一样。功能像、交互像、连工作方式都像。职场里最惨的剧本不是输，是你做什么都被说成抄谁的。它被骂了整整一年。

然后剧情反转了。增长 20.8% 对 5.2%，用王者荣耀的说法，这叫逆风翻盘；用职场的说法，这叫那个被所有人看扁的同事，年底拿了绩效 A。

它做对了什么？我深度用下来的体感是三件事：快、便宜、够用。

快是交互层面的反馈速度，日结任务体感明显；便宜是成本层面，同样的活，账单厚度肉眼可见地友好（下一篇我拿同一个任务四个模型跑账单，数字摆出来会很直观）；够用是说，如果你的日常是高频小任务，不是大型架构重构，它和卷王的差距你根本感知不到。

这就是逆袭选手的职场策略：不在卷王的主场打架。你卷深度，我卷频次；你服务大项目，我服务每天的琐碎。大多数开发者的日常，就是琐碎本身。

当然它也有毛病。长链路任务跑到一半容易忘了初心，你让它修个 bug，它修着修着开始给你加功能——好家伙，职场新人热情过头，把别人的活也干了，干完还不一定对。

说个我印象最深的真实案例。有一回我开着一个长会话让它连续干活，跑完一看账单：一个会话，952 万 token。那天我对着账单研究到半夜，把每一轮对话吃掉多少 token 拆了个遍，后来专门写了篇文章验尸。从那以后我用 Codex 定了两条规矩：长任务切成短任务再派，context 喂料先压缩再投喂。规矩立完，账单薄了一半都不止。

这件事让我对它的评价多了半颗星：它的账单是透明的，透明意味着可治理。你至少知道钱花在哪了，这比含糊的包月扣费体感踏实。

另外它有个被低估的能力：并行。开几个会话同时跑不同任务，互不干扰——相当于这个新人愿意加班，还愿意同时打三份工。你只要有本事把任务切干净，产出就是乘法。至于怎么切任务才能不打架，那是你的管理水平问题，工具不替你背这个锅。

逆袭者的适用边界收个尾：日结任务为主、预算敏感、任务可切分——三条占两条，它就该在你排班表上占一行。

野路子 DSH：进门第一天先焊死沙箱

纪录片旁白响起：在开源的荒野上，有一头独来独往的猛兽。它不参加排名，不混圈子，饿了就吃issue，饱了就提交代码。

DSH（DeepSeek Harness）是我今年拆得最狠的一个项目，源码深挖系列写了 11 篇。写到第十一篇的时候，我对它的评价浓缩成一句：这是我见过把「不信任」执行得最彻底的代码库。

举一个细节你就懂了。它的沙箱是 fail-closed 的：门正常的时候放行，门坏了，两边一起锁死。注意这个设计——大多数系统的思路是「门坏了先放行别耽误事」，它的思路是「宁可耽误事，不放行」。职场翻译：这个同事不信任所有人，包括门。

还有会话当 git 管理的设计。你跟它的每一段对话都有版本、可以回滚、可以追溯——你上班摸鱼说错过的话，它都给你存档，但存档是为了让你可以反悔。这个思路说实话比很多人类的会议纪要强。

很多人对 DSH 的顾虑是国产、开源、年轻。我的体感正好相反：源码摆在那里，每一行行为都可预期。闭源工具像个黑盒同事，能力存疑但态度良好；DSH 像个把工作日志全公开的同事，你看完它的日志再决定要不要信它——这种透明在选型的时候价值千金。

它便宜。便宜到什么程度，还是那句话，下一篇账单对比里见，数字比形容词诚实。

再给两个源码系列里的真实发现，你感受下这头猛兽的性格。

一个是缓存纪律。我拆它的缓存逻辑时发现，它对「什么该进缓存、什么绝不进」的边界卡得近乎偏执——该省的一个 token 都不浪费，不该省的一步都不省。这种偏执在职场里叫什么？叫花自己钱办自己事的人才有抠门自觉。开源项目花的是社区的钱，它还这么抠，这是真把项目当自己的养。

另一个是错误码的执念。进程管理器对退出码的处理严格到较真的程度——绿色测试发布挂了这种职场灵异事件，在它的世界里是有明确责任人的，不会出现「大家都没错但就是不行」的悬案。你排查问题时最怕的就是悬案，它把悬案率压到了最低。

所以 DSH 适合谁？想知道黑盒里有什么的人。如果你选工具的标准是「出了问题我能查到为什么」，它是四个里面唯一把底牌摊在桌上的。代价是你要花时间读它——透明从来不是免费的，它是用你的阅读时间换的。

新来的 ZCode：简历写到鼠标为止

ZCode 是最近才进我工位的。简历打开，好家伙：会写代码、有自己的 skill 生态、能挂 MCP、还能直接操作我的桌面——从改配置到点按钮，全包。招聘要求里写「吃苦耐劳」，它简历上写「吃苦耐劳 inclusivity 全都有」，我逐条面完，居然没找到明显的水分。

我的第一反应不是惊喜，是警觉。职场里简历越全能的新人，你越要看看它的工位在哪——因为你的工位可能就是它的工位。

深度用下来，它的定位其实是「覆盖面」：常规代码任务之外，那些不属于 IDE 的活——批量操作系统配置、跨应用的操作流程、需要界面交互的验证——它真的能替你点。别的工具在你电脑里当程序员，它在你电脑里当远程桌面那头的同事。

短板也明显：深度推理和长链路的稳定性，跟两个头部选手还有距离。新人的成长曲线陡不陡，要看后面几个版本，我会持续观察——毕竟工牌刚发，别急着转正。

但它验证了一个趋势：AI 编程工具的战场，正在从「谁代码写得好」扩大到「谁替你干的杂活多」。这对职场人是个好消息——杂活才是班味的主要来源。

给一个我真实跑过的场景，你感受下「桌面级」和「代码级」的差别。

有一次我要验证一个本地应用的窗口行为，需要反复打开、切换、截图、比对。这活交给代码级工具，得先写个自动化脚本，起服务、配环境、调 API——工具还没用上，脚本先写了半小时。交给 ZCode，它直接替我点：开窗、切页、截图、对照，一套流程下来我要做的就是最后看一眼结果。别的工具产出代码让你去执行，它直接产出现场。

当然，把「操作电脑」当卖点的工具有个天然代价：每一步都比纯代码任务慢，而且依赖界面稳定。批量重复的高频操作，写成脚本永远比每次让它手点划算。它的正确定位是低频、跨应用、每次流程还不完全一样的活——这种活写脚本不划算，人肉干又烦，正好给它。

职场画像收个尾：它是那种啥都会一点的应届生，你要是拿它跟资深架构师比深度，是招聘启事写错了；你要是让它把部门杂活全接了，它会还你一个清爽的工位。

四牛马同槽：我的排班表怎么运转的

工具多有一个幸福的烦恼：活来了给谁。我摸索了一段时间，现在的排班规则简单到可以贴在工位上。

规则一：按任务长度分诊。 预计超过半小时的连续任务——新模块、跨文件重构、需要读遍全库的调研——派给 Claude Code。十分钟内能交代清楚的——改文案、修报错、写个小函数、补个测试——丢给 Codex。不确定长短的，按十分钟算，先派便宜的，跑偏了再升级。

规则二：按信任等级分诊。 涉及生产配置、数据库、线上数据的操作，永远给有沙箱、行为可预期的选手，DSH 这种 fail-closed 性格的在这里是加分项。纯本地、随时能回滚的实验性任务，谁顺手谁来。

规则三：按工种分诊。 纯代码活在 IDE 系里流转；跨应用的杂活——批量整理文件、操作界面、验证桌面应用行为——走 ZCode。别让架构师去搬水，也别让搬运工去做架构，两边都不舒服。

规则四：冲突要有仲裁。 四个工具改同一个仓库，冲突是必然的。我的土办法是分时段：大任务开跑后，小任务等它提交完再派；实在要并行，就给每个工具划不同的目录边界。这条最土，但省掉的所有 merge 冲突都是真金白银的时间。

规则五：上下文别来回倒。 一个任务在哪个工具开工，就尽量在它手里干完。我曾经把一个半成品任务从卷王手里倒给逆袭者，光是把背景讲清楚就花了两轮对话，对方还问出了我答不上来的问题：「之前那位改到哪了？」任务交接的成本，比工具差价贵多了。

这套排班跑顺之后的体感变化很具体：以前一个工具干所有活，排队、互相打断、上下文越堆越长；现在四个人各干各的，我唯一的活是派活和验收。有朋友问我这不就成监工了吗——对，这个岗位叫技术负责人，只是部门成员全是 AI。

选型三大反模式：坑都是标准形状的

排班表之前，我踩过三个典型的坑，形状标准到可以当反面教材。

反模式一：全押一个。 我曾经很长时间只用一个工具，理由是「切换有成本」。后来比了比成本发现，切换成本是一次性的，错配成本是每天的——把杂活交给按 token 计费的卷王，等于请架构师帮你订会议室。工具组合的价值不是加法，是各干各的乘法。

反模式二：按社区嗓门选。 增长数据出来之前，Codex 在社区里的风评是被嘲了一年。如果当时跟着嗓门走，就错过了它逆袭后的性价比窗口。数据点（增长、基准测试、账单）永远比情绪点（「都说」「我觉得」「XX 要凉」）可靠——这也是我写这四篇横评的底气来源：全是自己跑出来的体感和账单。

反模式三：为新而新，为稳而稳。 新工具一出就全量切换，和死守一个工具到天荒地老，是同一枚硬币的两面。我的折中是「试用期制度」：新工具进来先给非关键任务跑两周，好用在排班表上加一行，不行就静默退出——转正流程走完，才有资格接核心任务。ZCode 现在就处在这个阶段。

三个反模式背后的道理是同一句：选型是运营动作，站队是情绪动作。前者按季度回顾，跟着任务结构和成本走；后者只会跟着嗓门走。

成本这一块，先剧透一句

四个工具四种计费，账单差距大到什么程度？我只剧透一个数字：我曾经用一个会话跑出 952 万 token 的账单——那次账单教会我的事，够写一篇单独的文章（已经写了）。

下一篇我把同一个任务的活，按四个模型的定价分别算一次钱。有人按订阅费，有人按 token，有人免费——差价具体到倍数。这里先记住一个原则：增长数据决定行业走向，账单决定你的钱包走向，两条线要分开看。

结论：工位没换人，换的是排班

回到开头的宫斗剧。Codex 抢走的其实不是 Claude Code 的工牌——卷王还在，深度任务的王座没变。它抢走的是排班表：每天的琐碎任务、高频小活、预算敏感的批量处理，正在从卷王手里转移到逆袭者手里。

所以「谁该当默认工具」这个问题，本身就问错了一半。默认工位只有一个，任务却有好几种，正确的问法是：我的工作里，哪类任务占比最大。重构密集型，卷王继续坐镇；日结密集型，逆袭者性价比正在变高；预算敏感或者需要透明可控，野路子 DSH 值得你读完它的源码再决定；杂活密集型，全能新人 ZCode 可以给个试用期。

我自己现在的排班是：Claude Code 当主力架构师，Codex 接高频日结，DSH 跑预算敏感的批量任务，ZCode 负责桌面杂活。四个牛马，各司其职，谁也不抢谁的活——这才是多工具时代的正确姿势：不是选一个，是排一个。

最后，祝你早日找到自己的四工位配置，从此告别亲自加班。愿你派活有方、验收有据，账单越来越薄，下班越来越准——前途一片手机。
