全栈架构 × AI 研发实战

字节把 Trae 一分为二：写代码的归 Code，干活的归 TraeWork

 included in AI 开发
先看两条数据。抖音上「trae」关键词按点赞排序，半年内最高的两条视频：一条 2.5 万赞，英雄哪里出来的《TRAE SOLO 新版本发布，AI 跑通产品研发全流程》，265 秒，演示的是在 IDE 里用 AI 从零写出一个 3D 跑酷游戏；另一条 1.7 万赞，极物君的 AI 营地的《Trae Work 保姆级教程》，465 秒，演示的是让 AI 整理一家咖啡店的报表、发票和数据仪表盘。前一条的观众是程序员，后一条的观众是想让电脑替自己干活的普通人。 两条视频，两个没有交集的受众群体，恰好就是字节这步棋要分开的人群。Trae 官方文档最近挂出一行更新，标题只有一句：TraeWork is available。配合定价页和两条爆款视频的逐字稿，可以确认：SOLO 时代「不止编程」的那条线，已经从 IDE 里独立出来，成了单独的产品。 先把结论放在这：**写代码的 Agent 和干活的 Agent，从此是两个物种，选型逻辑不能混用。**这刀为什么这么切、你怎么选，往下看。 这篇拆四块：TraeWork 到底是什么、字节为什么把这刀切在这里、它和 Claude Code 这类编程 Agent 为什么不是一类工具、免费额度背后打的是什么主意。 TraeWork 是什么：一个能动手的聊天窗 先把产品说清楚。TraeWork 打开之后长得像豆包或者 DeepSeek 的聊天界面：中间一个输入框，可以打字也可以语音。区别在能力清单：聊天窗只能给你答案，TraeWork 能直接操作你的电脑。极物君在视频里演示的能力有四样：读取文件、移动文件、修改文件内容、创建新文件。这四样叠起来，就是「整理文件夹、把乱七八糟的表格提取成一份 Excel、做一个经营仪表盘、写日报」这类活的全集。 界面左侧有一个侧边栏，放的是豆包没有的两样东西：技能和自动化工作流。技能是预设好的任务模板，自动化工作流是可以重复触发的固定流程。这两样是把用过的活攒下来、下次一键重跑的容器，面向的是要反复做的固定任务，不是一次性问答。 复杂任务有一条单独的路径：Plan 模式。直接执行模式下，TraeWork 拿到任务就动手；Plan 模式下它先停下来，产出一份执行清单，把不确定的地方变成问题向你确认，你答完它才继续。极物君让他基于一份咖啡店销售汇总表做可视化仪表盘，用的就是 Plan 模式：它中途停下来问了两个数据口径的问题，确认之后才开工，最后交付了一个可交互的网页仪表盘，还附了一段「建议关注」的阅读提示。 这个设计值得单独说一句，因为它暴露了字节对这类产品的定位。写代码的 Agent 最大的风险是把代码改坏，所以要 diff 审查、要沙箱；干活的 Agent 最大的风险是理解错任务白干一场，所以它要先弄清任务再动手。同样是 Agent，风险模型不一样，交互设计就发展成了两个样子。 这刀为什么切在这里：从 SOLO 到分家 字节的这条产品线，过去二十个月的演化路径值得摊开看，每一步都在为最后的分家做铺垫。 2025 年 1 月，Trae 国际版发布，基于 VSCode 内核，卖点是在 IDE 里免费用 GPT-4o 和 Claude；3 月国内版跟进，配豆包模型，可切 DeepSeek。这个阶段的 Trae 是「免费 AI IDE」，打的是 Cursor 的价格锚点。

拆完 WorkBuddy 的 1GB 客户端,看懂了腾讯做 AI 办公的打法

 included in AI 工具
WorkBuddy 是腾讯 2026 年 3 月发布的 AI 办公工作台,上线四个月就坐上了国内 AI 办公智能体桌面端月活第一的位置:第三方榜单给它的数字是 1115 万,第二名百度搭子是 674 万。围绕这个第一,争议同样热闹:有港股报道说它月活 2000 万,知乎上有文章专门质疑这个数字的统计口径,36氪则泼了盆冷水:离腾讯想要的十亿级超级应用,还差 70 倍。 吵数据的人很多,拆产品的人很少。质疑派没拆过客户端,捧场派也拿不出机制层面的证据,争论停留在表态层面。 我把国内版 WorkBuddy 5.5.6 的 macOS 客户端完整拆了一遍:安装包、进程结构、打包代码、依赖清单,能看的地方都看了。这篇文章把拆到的东西按机制摆出来,最后回答标题里那个问题——这个第一,含金量到底怎么算。 先给一个判断框架:看懂执行型 AI,先看它的工具箱 大多数人第一次用 WorkBuddy 都有个错觉:这不就是个聊天窗口吗,和网页版大模型有什么区别? 区别在于:网页版大模型只能「说」,WorkBuddy 能「做」。你说「帮我把这个季度的数据整理成周报」,它真的会去打开文件、读内容、算数字、写文档、存到你指定的位置。这一类产品现在叫执行型 AI,或者叫 AI Agent(智能体):它和大模型聊天的部分只是入口,真正值钱的是后面那条执行链。 判断一个执行型 AI 靠不靠谱,我有个简单框架,三步: 第一步看工具箱:它能实际操作什么?是只能读写文件,还是能跨应用、能上网、能跑命令?工具箱的深度决定了它能替你干的活的上限。 第二步看连接方式:它和微信、飞书、钉钉这些办公软件是怎么对接的?接口是谁做的,权限怎么给,这条链路决定了它是在你的工作流里干活,还是只能在你眼前表演。 第三步看数据去了哪:你的文件、聊天记录、任务内容,哪些留在本机,哪些上了云?这决定了你敢把多少真实工作交给它。 下面按这三步逐层拆。结论的方向是:WorkBuddy 的工具箱和连接方式,做得比大多数人以为的认真;但它的第一,同样离不开一条别人拿不到的连接。 第一层解剖:1GB 的客户端里装了什么 动手拆之前,先交代版本和环境,所有证据都基于以下事实,你可以自己复现: 国内版:官网 workbuddy.cn,dmg 安装包 509MB,版本 5.5.6(build 38337834),应用装完后占 1.0GB 磁盘 国际版:官网 workbuddy.ai,5.5.2,dmg 490MB,com.workbuddy.workbuddy-ai——和国内版(com.tencent.workbuddy.mac)是两个完全独立的应用,连版本号都不同步 macOS 最低要求 11.0,Apple Silicon 优先 第一眼就值得说的数字:1.0GB。作为对比,我之前拆过 Claude Code 的 307MB 二进制,当时觉得已经够重了,WorkBuddy 直接是这个体积的三倍多。多出来的体积是什么?往下看。 启动后开进程列表,能看到一条很有信息量的东西:除了正常的界面进程,WorkBuddy 还跑了一个常驻守护进程,命令行是 daemon-app-server-entry.

你的 Claude 不一定需要 Claude Code：成功率只差 1%，账单差 2 倍

 included in AI 开发
先看一组我自己量出来的数。agent-autopsy 是一个专门抓包整理各家 coding agent 提示词的开源仓库，作者把 Claude Code、Codex、antigravity 这些壳运行起来，从实际发出的请求里截获系统提示词和工具定义，按模型分档存档。我把里面 Claude Code（Fable 5.1）那份下载下来量了一遍：系统提示词全文 10.4KB，六个章节；工具定义 37 个，按「单次请求实际发送一份」的口径合计 154KB，其中纯描述性文字 9.1 万字符，占六成。最大的一件是 Artifact 工具，光使用说明就 2.4 万字符，一个工具的说明书，是整个系统提示词的 4.7 倍。 也就是说，Claude Code 每次接活，模型要先读完将近 4 万 token 的「入职材料」才碰得到你的代码。这份材料不便宜：按 token 计价，它是每次请求都要重复支付的首包成本。 它买到智商了吗？2026-09-16，UC Berkeley Sky Computing Lab 和 LMArena 团队发了一项测量，名字起得很直白：HarnessTax（harness 税）。结论是：同一个模型，换个 harness，成功率只动 1 个百分点上下，账单差 2 到 5 倍。 这篇拆三件事：这笔税怎么测出来的、钱花在了哪里、什么情况下交得值。最后回到开头那份 4 万 token 的入职材料，它该不该瘦，答案在测量里。 先把账本摊开：HarnessTax 测了什么 harness 这个词，中文圈常译成「壳」或「执行框架」，指包裹在模型外面的那层工程：系统提示词、工具定义、权限控制、上下文管理、执行循环。Claude Code 是壳，Codex CLI 是壳，Pi 也是壳。模型本身只有一个，壳可以有无数个。 要回答「壳值多少钱」，得把壳和模型的组合拆开量。HarnessTax 的做法是控制变量：7 个模型 × 3 个 harness，组成 21 组配对，跑同一批任务。基准选了两个：SWE-bench Lite 每次跑 30 题、每题重复 3 次；Terminal-Bench 2.

循环Transformer会让GPT-6 Astra藏起思维链吗？把这场架构争议拆开看

 included in 大模型
这台模型为什么在实际任务上体感提升有限，可以看我之前写的能力分层分析；本文只聊架构争议本身。 GPT-6 Astra 发布前的两天，The Information 援引内部消息扔出一颗雷：Astra 用了一种叫 recurrent depth（循环深度）的设计，也就是 looped transformer（循环 Transformer），而它「会让模型的部分乃至全部推理过程变得不可见」。模型上线后争议越滚越大，逼得 OpenAI 首席科学家 Jakub Pachocki 亲自出面，说他想避免「一场由混乱的报道引发的、奔向不可监控性的竞赛」，并强调当前前沿模型的计算图深度与 GPT-4 的差距仍在两倍以内。 这句话信息量不小，但被各家转述得语焉不详。Sebastian Raschka（《Build a Large Language Model (From Scratch)》的作者）随后写了一篇长文，把技术细节摊开讲了一遍。这篇是我读完他的原文和相关论文后的复述与整理。结论先给出来：循环 Transformer 大概率不是思维链变短的元凶，更合理的解释是模型变强了，不需要那么长的草稿纸。 循环 Transformer 到底是什么 循环 Transformer 的定义可以这样给：让中间表示两遍或多遍地通过同一批 Transformer 块（常规架构只过一遍），每一遍复用同一套权重。 拿今年 7 月发布的开放权重模型 Nanbeige4.2-3B 做例子最直观。它的架构看起来就是个常规 Transformer：输入经过 token 化和嵌入之后，穿过 22 个 Transformer 块，每块有自己的权重（块内部是什么，可以看QKV 矩阵级拆解，这篇不展开）。区别在于多了一条绕回栈开头的路径：第一遍走完后，隐藏状态被送回这同样的 22 个块再来一遍。 把计算过程展开看，相当于 44 次块应用。但和真正拥有 44 个独立块的模型不同，第 23 次块应用用的是块 1 的权重，第 24 次用的是块 2 的权重，依此类推。有效深度从 22 提到 44，参数量却不用翻倍，这就是全部诀窍。 这个思路不新。2018 年的 Universal Transformer 论文就在做类似的事，只不过它反复应用的是单个 Transformer 块，没有用一整个栈。

看完我的 AGENTS.md，你会看到我和一个爱删片的 agent 斗智斗勇的这半年

 included in AI 开发
本仓的每一条定规都是强制性的。违反任何一条都会遭受毁灭性打击：轻则返工一晚上，重则像我一样，一夜之间丢掉 8 支已经发布、正在产生播放量的视频。不存在任何例外与豁免：出于好意的违反也是违反，为了进度的违反也是违反，「我觉得这样更好」的违反尤其是违反。 我的仓库是一个 Hugo 博客加一条完整的自媒体生产线：选题、写作、视频生成、四平台发布、数据回流，全部由 agent 会话驱动。所以我的 agent 手里的权限比一般写代码的 agent 大得多，它会真的去平台上发东西、删东西、改定时。权限越大，规矩越硬，这就是这份 AGENTS.md 的来历。 网上流传的那份名作，作者在和不说人话且 over-engineering 的模型搏斗。我这边战况不同：我的 agent 会把文章写成周报，会在发布时漏掉合规声明，会在合成任务里快乐地烧掉两个半小时，最辉煌的一战，它把「清理临时文件」理解成了「清理已发布资产」。 好消息是，每打输一仗，我就立一条法。半年下来，这份 AGENTS.md 已经厚到需要给自己立精简法了。下面按「事故 → 规矩」的顺序讲，战损最重的在前。 最重的一条：不许删任何已发布的东西 2026-09-15，例行盘点时我发现 8 支高播放视频（最高一支 30,955 播放）没了。平台成片、本地成片、场景 deck 全灭，只有口播稿幸存，原因特别讽刺：口播稿在另一个目录，清理命令没扫到它。它活下来靠的是目录结构，靠的是运气。 恢复方案是重制补档，按播放量序每天补一支，排期被打乱了半个多月。那可是挂在四个平台上、每天还在涨播放的资产，不是缓存。 事故之后立的规矩，现在钉在发布红线第 10 条： 任何会话不得删除/撤稿已发布视频及关联台账。清理类操作（删文件/删稿/清目录）先列清单向用户逐项确认；涉及高播放资产的删除即使获准，也必须先归档成片、deck、口播稿三件套，再执行。 注意这条规矩的立法技术：它压根没打算教 agent「判断什么该删」。判断已经被证明不可靠了，出事的那个会话在按下删除时，大概率也有一套自洽的理由。所以规矩直接绕过判断，把「清理」锁死成两步人肉流程，先列清单，逐项确认。慢就慢点，烦就烦点，总比再丢 8 支强。 这是我整份 AGENTS.md 的核心立法思想：凡是一次事故证明 agent 会判断错的地方，就不再给它判断的机会。 语言：写作层的死规矩 我的 agent 每天产出一篇文章和一支视频口播稿。AI 写中文技术内容有个通病，我管它叫「工作汇报体」：每段都像在念周报，工整，空洞，没有一个真人在说话。所以语言这一节规矩密度最高，挑几条感受一下。 禁词表是无例外的。「兜底」「铁证」这类词，放在技术语境里读着完全合理，拿数据库约束给业务兜底，多正经的表述。但 2026-08 的一次全站清理让我定规：一律不出现，技术语境也无例外。原因很实际：这些词已经成了 AI 文本的高频指纹，读者扫到第一反应就是「AI 写的」，信任一贴标签，后面写什么都打折。禁词表收在 de-ai-smell skill 里，配机检命令 make check-ai-smell，发布前必跑。命中要人工裁决，反讽语境和真实业务术语是合法的，脚本只定位，不改稿，改稿的锅我自己背。 段落不超过 4 行。 看着像排版洁癖，实际是注意力管理。手机上超过 4 行的段落，第二眼读者就开始跳读了。agent 天然爱写长段落，它一口气生成，没有换气的生理需求，只好用硬约束逼它呼吸。 语气权威自信，禁小白摸索口吻。 agent 特别爱写「我尝试了一下，似乎可以」「可能是因为什么吧」。这些词在探索时是诚实的，放进成稿就是灾难。你写的是教程，不是探索日记，探索的部分请留在你自己的思考里。

照榜单装了 12 个开源 Claude Code 插件，实测一个月我删了一半

 included in AI编程
Claude Code 的插件和 skill 榜单网上已经不少了，我之前也整理过一版。但榜单有个共同问题：只管推荐，不管售后。装的时候每个都写着「必装」，装完之后哪些真在干活、哪些在吃灰，没人告诉你。 这次我把话说完：照榜单装了 12 个开源插件，用一个月真实任务逐个实测，删了一半，留下 6 个。留下来的每个都附 GitHub 实拍、实测体验和照抄能用的安装命令；删掉的 6 个，也讲清楚为什么删，这部分可能比推荐更值钱。 先看结果 淘汰标准就一条：这一个月里，它有没有被我真实触发过。不是「我觉得它有用」，是有据可查的使用记录。插件和 npm 依赖一个道理：装 800 个包，入口就那几个，区别只是白白多出上下文开销和选择干扰。 留下的 6 个 1. Superpowers · 留 仓库：github.com/obra/superpowers 它是什么：一整套 agentic skills 框架 + 软件开发方法论。brainstorm、设计、TDD、代码审查、调试、执行计划，每个环节一个 skill，从想法到交付全链路覆盖。 实测体验：装完后第一个月我只用到了它的 brainstorming 和 executing-plans，第二个月开始 debugging、grill-me 也被自然带起来了：它们挂在开发流程的固定环节上，写到「设计完就该 TDD」的节点就会触发。这是它能留下的关键：它的工作流和写代码的流程天然重合，不用你记着去用。 安装（Claude Code）： /plugin marketplace add obra/superpowers-marketplace /plugin install superpowers@superpowers-marketplace2. ECC · 留 仓库：github.com/affaan-m/ECC 它是什么：agent 性能优化系统，打包了 skills、instincts（直觉规则）、memory（记忆）、security（安全）、research-first development 五个维度，管的是 agent「怎么跑任务」本身。 实测体验：它的 memory 和 research-first 两个模块在长任务上肉眼可见地稳：agent 动手前先调研、跨会话记得上下文，长任务稳不稳就看这两件事。选 minimal profile 装，full 版会把一堆你用不到的模块也塞进来，那正是我要在别人机器上删的东西。
