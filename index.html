装完 Claude Code 先别急着聊：这 5 条提示词，决定你做出来的是玩具还是产品

 included in AI 开发
同一个需求，我听过两种结局。一句「给这个接口加个缓存」扔给 Claude Code，拿回来一套带配置层、适配器、多级策略的缓存体系，账单翻倍，这是许愿式问法。后来同一个需求换了个问法，第一轮就被四个问题问没了：这个接口写多读少，缓存攒不住热度，需求当场作废，半小时对话省掉几天的实现加无止境的维护。两次都是同一支 Claude Code，模型没换，提示词的文采也没变好。 差的不是第一句，是第一句之后还有什么。前一种问法，第一秒之后就没人管了，AI 自己决定方向、自己宣布完成；后一种问法，后面跟着一套东西接管全程。vibe coding 做出来的是玩具还是产品，分界线就画在这里。 我有个粗暴的判据：把你的会话记录翻到中间任意一轮，如果那一轮没有任何验收动作，产出大概率是玩具。中间轮次暴露的正是没人看着的时候 AI 在干什么。这篇把一次交付拆成五个阶段，每个阶段配一张提示词卡，卡和卡之间由人和门禁接力。单条提示词的深拆我写过三个提示词的事，工程资产的全景在五根工程柱子，这篇讲它们中间缺的那层：一次会话里，提示词怎么按阶段轮换。 一、玩具的特征：全程只有许愿一个动作 先看玩具是怎么造出来的。 一次交付实际是条流水线：理解需求、定方案、执行、验收、把教训攒下来。许愿式提示词只在第一站出现，一句「帮我优化一下性能」「参考某某产品做个类似的」，然后人就退场了。后面四站全部由 AI 自理，它按最隆重的方式做你没说的决定，按自己的标准宣布完成，教训哪也不去。翻车复盘我在裸聊四种姿势里摆过：不懂规矩、拿聊天记录当需求文档、看起来对就合入、一把梭没边界，四种姿势对应流水线上四个没人值守的工位。 很多人这时候的反应是换更长的提示词，把角色、要求、格式全塞进第一条。方向偏了。第一条提示词再长，管的还是第一秒；玩具感不是第一秒产生的，是第二秒到收工之间没有交接班产生的。生产级的做法不是打磨一句一步到位的话术，是给流水线的五个工位各派一个监工，每个监工就是一张卡。 所以这 5 张卡不长，也不用收藏——它们不是用来拜的，是用来换的。 二、开工卡：把许愿换成开工单 第一张卡在会话开头打出去。 这个需求先不动手。第一步，把相关代码读完，用你的话复述现状； 第二步，列出准备改哪些文件、每步干什么、明确不做什么； 第三步，列出需要我拍板的问题。我确认后再动手。它把「帮我把这事办了」改成「先告诉我你打算怎么办」。一字之差，身份变了：我从许愿的变成验收的。开头那个加缓存的需求就是被第三步救掉的：四问一出（缓存粒度、失效策略、穿透处理、单机还是多实例），「加个缓存」从愿望变成带边界的技术决策，而且第一轮就发现这题不用做。完整的故事在计划怎么把需求问掉里。 这张卡的单条深拆版本我写过，这里补一个用了一年的细节：确认计划时不要回「可以」，至少划掉一项。计划里总有做多了的或者顺序不对的地方，你划掉一项再放行，它收到的信号是这个老板真的看计划，之后每一轮的计划质量都会往上走。次次秒批，不出三次计划就开始水。 三、契约卡：把口述升格成 WHEN/THEN 计划确认了，需求还停在聊天记录里。第二张卡在动手前打，把口述意图变成可执行的契约： 把这份需求写成 spec：每个行为一条 WHEN/THEN，边界条件单独列， 涉及钱、权限、数据删除的场景必须覆盖失败路径。 信息不够的地方标 [待确认] 列出来问我，不许猜。聊天话术的每个词都留了解释空间，AI 会选一个解释继续干，选错的成本由账单支付。WHEN/THEN 是我把口述升格成契约的格式。实现之前它是指令，实现之后它是试卷，同一份文本用两次。拿我们踩过的佣金事故说：部分退款改造绕过了佣金结算，月底对账才炸。如果先有契约卡，这两个 WHEN 在写 spec 时就得回答： WHEN 部分退款金额大于已支付金额 THEN 拒绝请求，返回 REFUND_EXCEEDS_PAID THEN 不触发佣金重算，不写退款流水「不许猜」那半句和开工卡的第三步是一对：一个在计划层问掉歧义，一个在契约层堵死歧义。什么时候值得上这张卡，判据三条：改动跨文件、有外部副作用、需要决策留痕，命中一条就写 spec；单文件小修直接聊，流程开销超过动作本身就不划算。spec 流水线的完整用法我固化在 OpenSpec 六步里，中等改动走完全程约小半天，换来返工轮次明显下降。 四、止损卡：给 AI 体面的停机权 执行阶段最容易忽略的一张卡。它不指挥 AI 干什么，只规定它什么时候必须停： 执行期间三条纪律： 1. 确认不了的事实，停下来问我，「无法确认」是合法结论，别编； 2. 同一个错误失败两次，停止重试，把报错原文贴出来； 3. 删除或改写超过 50 行的代码，先单独列出清单等我确认。第一条是被账单教出来的。AI 没有心虚的概念，被逼着给答案时它一定给一个：编出来的配置项、猜出来的 API、虚构的日志，语气还特别自信。给它停机权比逼它硬编便宜得多，这条在我们仓库已经写进 AGENTS.

年薪 75 万美金的 FDE 没人科班：我拆完 1000 份 JD，说点实话

 included in AI 开发
两个数字放在一起看，很有意思。 第一个来自财联社：国内招聘平台上，FDE 的招聘需求涨了 42 倍，头部大厂给到年薪上百万。第二个来自数据团队 Bloomberry 2026 年 1 月的报告：他们拆了 1000 多份 FDE 招聘 JD，2025 年上半年的岗位数是 2024 年同期的 12.65 倍，平均总包 173,816 美金，基础模型实验室的 FDE 平均 25 万美金一年。 FDE，Forward Deployed Engineer，前置部署工程师。顺便纠个错：财联社把它译成「前端部署工程师」，不少国内的转述文章跟着抄错了。Forward 在这里是「向前推进到前线」的 forward，跟前端没有关系。硅谷给这个岗位起了个外号：the hottest job in AI that nobody was trained for，AI 圈最火、但没人受过科班训练的岗位。 高薪、暴涨、零科班，三件事同时成立，通常说明这个岗位正在被重新定义，定义权暂时握在第一批从业者和招聘方手里，市场上的信息是混乱的。你打开招聘软件搜 FDE，会看到一半岗位在要 Python 和 Agent 开发经验，另一半在要「客户沟通」和「方案讲解」，它们看起来根本不像同一个工种。 所以这篇文章不聊概念，聊数据。我把 Bloomberry 的 1000 份 JD 拆解、Anthropic 官方招聘页的 JD 原文、Levels.fyi 和猎聘的薪资档位放在一起，回答三个问题：这个岗位到底在干什么，门槛具体卡在哪，以及什么样的开发者应该转、什么样的千万别碰。 一、说人话：带着模型住进客户公司的工程师 FDE 这个词是 Palantir 造的。2003 年这家公司成立时的核心打法，就是把自己最强的工程师派到客户现场：情报机构、金融公司的办公室里，贴着客户的真实数据和真实流程做系统。工程师从大后方（总部）被推到最前线（客户现场），forward 说的就是这个位移。 类比一下：资深的家电维修老师傅，一部分坐店等机器送上门，另一部分直接背着工具箱去客户家里，看现场的使用环境、看接线、当场改方案。FDE 就是上门的那批。模型公司在总部把模型练好，但模型在客户那里跑不起来、跑起来不好用、好用了没人敢信，这些问题没有一个能靠远程支持解决。 为什么 2025、2026 年这个岗位突然爆炸？因为 AI 公司们撞上了同一堵墙。

Claude Code 帮我拿到技术总监 offer，这套求职系统开源了

 included in AI 开发
我的求职系统里有一张表，其中一行写着：AI 应用开发工程师，月薪 20-40K，AI 工程化方向 72 分起投。 意思是，这个岗位投不投，取决于测评分数够不够 72。差几分，这份简历就先压着，把短板补上再投。分数来自 72 项技能的逐项测评，每项 0 到 5 分，做完题才算数，自我感觉在这套流程里不算证据。 这张表背后是一套跑了半年的系统：四条 Claude Code 自定义命令，接成一圈。扫岗位、测能力、补短板、练面试，各管一段，上一条的输出就是下一条的输入。这个月我把整个项目整理开源了，GitHub 上 169 个文件，MIT 协议，clone 下来改三处就能换成你自己的求职系统。 这篇文章把系统拆开讲清楚：每条命令怎么工作，72 分这条线怎么标定，它凭什么能治「学了就忘」，以及你拿去之后要改哪三处。先从古法求职的问题说起。 古法求职的三个死结 古法求职我用了 12 年，总结下来就三个死结：没有标准、没有反馈、没有复盘。每一个都不是靠努力能补的，它们缺的是结构，态度补不上结构。三个死结叠在一起还有个隐性代价：求职周期被拉长。岗位会过期，手感和状态会衰减，拖上三个月，市场上适合你的坑位换了一轮，你还在原地修感觉。 第一个死结是没有标准。「我准备好了吗」这个问题全凭感觉。觉得自己 Vue 用得挺熟，觉得微服务「差不多懂了」，觉得算法「应该够了」。面试官不认感觉，他只认你能不能把问题讲透，而感觉和讲透之间的差距，你事先量不出来。 第二个死结是学了东西没人检验。看文档、刷教程、收藏文章，整个过程没有一道题来验证你到底会不会。收藏夹越来越厚，本事原地踏步。我在上一篇文章里拆过这个现象，问题出在学习流程里没有回路，学了没检验，时间花了等于白花。 第三个，没有复盘。面完一场就扔。面试官问了什么、哪题卡住、哪句话答得虚，全靠脑子记。记不住就丢了，于是同一类问题可以在三场面试里卡你三次，你甚至不知道它们是同一类。 下面这套系统，就是针对这三个死结逐个下手的。它的起点很朴素：一次技术选型会上被一句 RAG 追问问到哑口，当天晚上我写出了第一版能力评分表。 第一步：把招聘市场变成数据源 系统的采集端是 /find-jobs。它扫八个招聘平台，BOSS直聘、猎聘、拉勾、51Job、智联这些，把岗位收进一张表。表的每行长这样（内容做了虚构处理）： 公司 岗位 薪资 核心技能 背调 某智能硬件公司 AI 应用工程师 20-30K RAG、LangChain、Spring AI 300 人规模，自研产品，非外包 一行岗位，五列信息。背调那一列是我坚持要有的：公司规模、劳务纠纷记录、外包比例，这三样决定你要不要把一场面试的机会花在这家公司上。岗位描述写得再漂亮，仲裁记录拉出长长一串的公司也要三思，这类信息手动查得翻裁判文书网，命令直接帮你汇总。这些内容散落在八个平台和几十页搜索结果里，手工整理要一个下午，命令跑完不到一分钟。 八个平台各有性格。BOSS直聘响应最快，岗位更新最勤；猎聘集中在中高端岗位；51Job 和智联覆盖更多传统企业；高校人才网和公司官网渠道则是冷门机会的藏身处，官网经常挂着没同步到平台的岗位。同一岗位多平台都挂的，系统按公司加岗位名去重，只留一行，各平台链接并进去。 岗位库还配了一个 MCP 服务端。开启之后，Claude Code 里的任何会话都能直接查这张表，按城市、薪资、技能标签过滤，统计任意时间段的新增岗位数。「青岛地区 25K 以上的 AI 岗位，过去两周新增了几个，技能要求有什么变化」这类问题，它自己发工具调用去查库，不用你翻表格。采集和使用接在一起，这张表就从存档变成了随时可问的数据源。 /scan-jobs 负责让数据保鲜。它可以按天扫新岗位、GitHub trending 和掘金热榜，发现 JD 里冒出来的新技术要求，自动对照我的能力评分表：市场在要求、我表上还没有的技能，直接加进技术学习清单。MCP 就是一个实例，去年它的岗位 JD 出现频率一路上涨，扫描抓到这个变化，学习清单跟着把它排到了前面。

月底对账,AI替你核完要多久?0.003秒,10笔差异

 included in AI
订单、账单、流水三方金额笔笔对得平,AI 却说这份对账结果有问题。最后证明 AI 是对的:一处差异值 2000 块,藏在合同条款里,不在任何一张表的数字里。 这是我这周做的一个实测:把财务每月的供应商对账,整个交给 AI 数字员工干,从派活到交付全程留证。程序化 agent 跑完 203 单核对用时 0.003 秒;把同一张工单丢给 Claude Code,它 5.3 分钟交付,中间还自己写了个对账脚本。两边对同一份验收基准,10 笔差异全部命中,零误报。 先把结果放在这,后面每一节都会兑现: 周日早上的消息轰炸 事情从一个虚构但眼熟的场面开始。财务部王姐,周日早上 9:02,消息和四份文件一起砸过来:8 月三家供应商的账单今天必须核完,老板下午 4 点要看差异汇报。 接下来的几个小时,要求持续加码:供应商换了对账系统、账单格式跟以前不一样,要你「迁就一下」;银行流水导过一版旧的,重新导了一份,文件名带着 (1);「7 月的也重新核一遍」「不对,还是全核吧,保险」;然后是催命三连:「进度怎么样了」「?」「小周?」。 这是演示用的虚构记录,但干过对账的人应该都不陌生。这类活有三个特征,凑齐了就是数字员工的第一落点: 重复:月月做,逢月必有,流程不变只有数据变。复杂:三方数据交叉(ERP 订单、供应商账单、银行流水),还要叠加合同条款推理,不是单表去重那种一眼活。可验证:对没对,拿差异清单对着原始数据一查就知道,不存在「说得对不对全凭感觉」。 反过来说,三条缺任何一条的活都不适合现在交给 AI:一次性的活不值得建管线,简单的活 Excel 公式更快,不可验证的活你没法信任它的输出。选场景这件事,比写代码重要。 派活的关键产物是工单,不是提示词 王姐最后受不了了,13:42 把这单活转给了数字员工。派活的东西不是一段咒语式的提示词,是一张工单: 王姐的原话是这么写的:「小助手,月底了,8 月的三家供应商要对了,老规矩。东西都在 data/ 目录里:erp_orders.csv 是咱们 ERP 里导出来的 8 月采购订单,supplier_invoice.csv 是三家供应商开过来的账单,bank_flow.csv 是公司账户 8 月的付款流水,contract_terms.csv 是三家的合同条款,对的时候要照着合同来。」 这张工单是纯大白话,但里面有三个不可缺少的结构。第一是业务口径:本月账期已到,应该全部开票、全部付款完毕,有不一致就是差异;ERP 里「已取消」的单子原则上不该出现在账单里;金额 1 元以内当尾差忽略。第二是数据位置:四份文件各是什么、在哪。第三是交付物定义:一份能直接给老板看的报告,有几笔问题、涉及多少钱、什么原因、怎么处理。 网上流传的「万能提示词」解决不了这三件事。口径决定 AI 怎么判定「差异」,交付物定义决定它输出什么形态,数据位置决定它从哪取数。你给同事派活也是这么派的:告诉他标准、给他文件、说清楚要什么成品。对 AI 派活没有魔法,就是好好写工单。 我把这张工单的模板放在这,照抄改口径就能用: 任务:<什么活,什么期间> 数据:<哪几张表,各自是什么,在哪> 口径 1:<怎样算正常,怎样算差异> 口径 2:<特殊情况的处理原则,如取消单/尾差/账期> 口径 3:<需要结合的规则文件,如合同条款> 交付:<报告形态,给谁看,包含什么>程序化数字员工:0.
