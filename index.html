Claude Code vibe coding 入门：先看卡在第几层，再决定学什么

 included in AI 编程
这两天技术公众号在转同一个 GitHub 仓库：tradecatlabs/vibe-coding-cn，一套中文的 vibe coding 教程，16.3k 星（2026-10-01 复核），MIT 协议。转发配文出奇一致：终于有人把 vibe coding 讲明白了。 星数证明热度，证明不了适不适合你。我把它的主干文档读了一遍，这篇是提炼版：先用五层方法定位你卡在哪，再决定补什么，附带三条铁律和从哪个分支上手。原文从需求分析讲到部署复盘，你在电梯里读不完，这里 5 分钟读完。 一、先把 vibe coding 这个词掰正 Karpathy 在 2025 年 2 月造出这个词时，场景说得很窄：周末小工具、自己玩的东西，可以用「忘掉代码的存在」这种方式干活。传到中文圈，语境被裁掉了，变成「闭眼让 AI 写，能跑就行」。教程开篇就先纠这个偏：vibe coding 是人机协作的编程形态，人要留在环里，负责定目标、分任务、验收产出。 这套教程的骨架概括成四个字：道法术器。器是模型和算力，术是 Claude Code、Codex、Cursor、Gemini CLI 这些工具，法是结构化的开发流程，道是识别问题边界、分解目标的能力。教程主打 Codex 讲解，方法本身工具无关，我用 Claude Code 跑同样的流程没有障碍。 四层里有个扎心的对照：新手把预算全砸在器上，订阅最强的模型、追每一次版本更新；老手在法上花功夫，流程和验收搭好之后，中等模型也交付得了产品。工具半年一换，流程攒下来全是自己的。 二、五层方法，先定位你卡在第几层 教程的主体是一套五层递进的方法，从最轻的 Prompt 一路到最重的 Quality Gate。它的价值不在教你某一句神级提示词，在于给了一张地图：每层解决一个具体问题，卡住了能定位自己在几楼。 第 1 层，Prompt。 一句「给这个接口加个缓存」就是许愿，AI 只能靠猜。教程把一条合格的 prompt 分成六个要素：意图、上下文、模板、参数、反馈、迭代。写全了，猜的部分就没了。怎么写好这五张卡，我之前专门写过一篇《装完 Claude Code 先别急着聊》，模板可以直接抄。 第 2 层，Skill。 好用的 prompt 不该每次重敲，固化成可复用的原子能力，场景命中才加载全文。这一层怎么挑现成的、怎么写自己的，见《893个 Claude Code skill 挑不过来？》。 第 3 层，工程流程。 教程给每个项目定了三个交付物：需求文档、执行记录、验证报告。作用很直接：让「做了什么、验了什么」留下痕迹，AI 换了一个会话，接手的人还能续上。

DESIGN.md：Google 开源的格式，让 AI 复刻 73 家官网风格不跑偏

 included in AI 开发
让 Claude 写过页面的人，多半见过这一幕：第一轮极简白，你说「再高级一点」，第二轮紫色渐变就来了。需求它全听懂了，长相每次都不一样。 GitHub 上有个项目声称治这个病：VoltAgent 的 awesome-design-md，2026-10-01 我查是 119,000 颗星、13,300 次 fork。它的全部内容，是 73 份 Markdown 文件。我把其中 Linear 那份从头到尾读了一遍：23 个色值、13 级字号、8 档圆角，外加一组不许违反的禁令。 这篇文章讲清楚三件事：这文件是什么，为什么一份文本锁得住风格，边界在哪。 一、一个 Markdown，两步接入 用法在 README 里就两步：把某站点的 DESIGN.md 复制到项目根目录，然后对 AI 说一句「按这份规范写界面」。不装插件，不导设计稿，复制粘贴就完事。 这个格式是 Google 实验室提出来的。他们做了个 AI 界面设计工具叫 Stitch，DESIGN.md 就是它用来承载设计规范的格式，2026-04-21 Google 把规范草案开源，Apache-2.0 协议，放在 google-labs-code/design.md。你在 AGENTS.md 的语境里理解它会很快：AGENTS.md 告诉 agent 项目怎么构建，DESIGN.md 告诉 agent 界面长什么样。我自己仓库里躺着一份写了半年的 /posts/agents-md-hard-rules/，管住的是 agent 的行为；现在设计这半边也有对应的文本了。 规范定义了 8 个章节：概览、颜色、字体、布局、层次、形状、组件、注意事项，可以省略但顺序不能乱。文件是双层的：开头一段 YAML 配置放机器可读的设计数值，下面用 Markdown 写人类可读的设计理念。Google 还配了工具链，一条命令能检查规范写得对不对，连颜色对比度够不够都替你查，还能直接导出成 Tailwind 配置。 Google 为什么把格式白送？格式这种东西，谁开放谁定标准。agent 生态里被所有工具都认的格式，就站在了入口上。 二、Linear 那份里写了什么 Linear 是硅谷出了名讲究设计的公司，它那份 DESIGN.

893个 Claude Code skill 挑不过来？三判据砍到先装两个

 included in AI 编程
上周整理自己的 skill 库时，我干了个笨活：把 GitHub 上最大的 Claude Code 模板市场逐个分类数了一遍。davila7/claude-code-templates，32,216 星（2026-09-30 复核），skills 目录下 31 个分类、893 个 skill，三天涨了两百多颗星。数字之外还有个更值得说的发现：装 skill 的快路径，不在官方那个 179,099 星的仓库。 这篇文章回答三个问题：这个市场装进去的到底是什么；skill 凭什么比把 prompt 贴进系统提示强；893 个里面怎么挑。第三问给三条判据，配套两支我读过原文的推荐。 一、官方仓库立标准，市场才是货架 17.9 万和 3.2 万这两个星数不是竞争关系。官方 anthropics/skills 仓库定义了 Agent Skills 这个形态：一个文件夹加一份 SKILL.md，写明这个 skill 管什么、什么时候用、怎么用。它是标准和样本库，回答的是「skill 应该长什么样」。 claude-code-templates 干的活不同：分发。Claude Code 的扩展点全在项目或全局的 .claude/ 目录里，agents、commands、hooks、skills 各占一层。装一个 skill 的传统路径是找到文件、建目录、拷进去；这个市场把 893 个组件做成索引，README 给的用法是一条命令： npx claude-code-templates@latest按仓库的说法，命令跑起来是终端里的交互货架，按分类浏览、选中落盘，网页端 aitmpl.com 是同一个货架的浏览版。我没跑过这条命令，你自己敲一遍就有判断，这是验证成本最低的一步。 边界说在前头：它装的是别人写的 prompt 和脚本，不是官方功能，Claude Code 本身没有任何变化。我的规矩是装之前逐个过目，毕竟进的是能影响代码行为的目录。 二、skill 凭什么比常驻 prompt 强 答案在上下文的经济账里。官方把这个机制叫渐进披露（progressive disclosure）：skill 常驻上下文的只有开头一句描述，命中了工作场景，全文才加载进来。把几千字的 prompt 贴进系统提示则相反，每一轮对话都在场、都在烧 token，塞得越多，注意力越散。 这不是理论。我自己仓库里二十六个自研 skill 就按这个机制组织，写作、画图、四平台发布各管一段，只在命中时上场。用下来唯一的约束是：开头那句描述写得不准，它大概率永远不被触发，装了约等于没装。

10 万星 Caveman 领衔：四个省 token 的开源 skill，从输出砍 65% 到上下文换血

 included in AI
2026-08-26 我分析过一个会话吃掉 952 万 token 的 Codex 账单，结论比账单扎心：大头不是写代码花掉的，是重复读入的文件、来回贴的背景和 agent 的碎嘴。当时给自己立了家规，纪律管住人；剩下的浪费得靠工具管，社区已经把工具做成了小生态。 我按「治哪一段浪费」把 GitHub 上的省 token skill 盘了一遍，只收高星和知名度经过社区验证的仓，四个全是万星级。先建判断框架：agent 的 token 浪费发生在四个环节，说得多（回复十行有效三行）、记性差（同样的背景贴到第三遍）、喂得陈（整本过期文档塞进上下文）、返工贵（做错了推倒重来，同一份活烧两遍 token）。开自己的会话记录对号入座，浪费在哪一环就装哪一味药。别四个全装，skill 加载的每一行都从你的上下文里扣。 Caveman：输出砍 65% 的祖师爷（103,664★） 如果只装一个，装这个。口号语法就是错的：「why use many token when few token do trick」。它让 agent 用穴居人腔说话，代码、命令、报错原样保留，纯聊天输出砍 65%（官方实测口径）。效果拿同一个意思的两种说法对比就懂：「我已完成对配置文件的修改，接下来运行测试验证」变成「Config 修好。跑 test 验证」，信息没少，字数去了六成。 值得抄的是 README 里那套压缩纪律：不造自创缩写（tokenizer 切得更碎，一个不省）、否定词一个不丢（丢了意思反转，修复误解比省的贵）。 10 万星后它攒成了全家桶：caveman shrink 压命令输出（字节级可还原）、proxy 层在 Claude Code 实测省 33.2% 输入 token（官方 54 轮基准）、pixel mode 把 SKILL.md 渲染成 PNG 让模型看图读，税基从文本换成图片。 比口号更重要的是常驻机制。在 system prompt 里写「请精简回答」，十几轮后服从衰减，啰嗦回潮；skill 的持久化让压缩规则挂在每一次响应上，第 1 轮和第 40 轮一个口径。

AI 做页面总翻车？26 万星领衔，前端 skill 按 Star 排行

 included in AI编程
同一句「做个落地页」，裸装的 agent 交回来的东西几乎一个模子：居中 hero 大图，下面三张等宽卡片，蓝紫渐变配色，圆角图标。换个 agent 再跑一次，结构照旧。多数人把这口锅扣给模型，重写 prompt、换模型、贴示例图，折腾一圈页面还是那张脸。 差距出在装备层。prompt 是每个项目都要重写的重复劳动，skill 是一次安装、长期生效的审美和流程约束，写进 skill 的设计决策从下一单开始自动生效。这篇按 GitHub Star 把前端出活用得上的 skill 排了一遍，只收高星和知名度经过社区验证的仓——skill 是要长期住进 agent 里的装备，几千星的无名小仓不进榜，出了问题都找不到人。Star 数截至 2026-09-27，来自 GitHub，每天在涨，仅作量级参考。 榜单和插件那篇有三个重合（Superpowers、karpathy、graphify），不是偷懒：这边按前端的活重新评估了一遍，每个都给前端场景的用法。 1. Superpowers · 约 26 万星 仓库：github.com/obra/superpowers 它是什么：agentic skills 框架加一整套软件开发方法论，一个环节一个 skill：brainstorm、设计、TDD、代码审查、调试、执行计划，跨 11 个 agent 平台，是整个 skill 生态里星最高的仓。 为什么值得装：前端活翻车多数不在写的那一刻，在开工前没人定方向。它的 brainstorm 和 design 两个 skill 管的就是这一段：需求先过一遍质疑和选项收敛，出一份方向清单再动手。「我想做个好看的落地页」这种只有一句的需求，经过这道工序会变成有取舍边界的设计简报，agent 拿到的输入质量完全不同。 怎么用：开工先跑 brainstorm 过需求，design 位出方向清单，确认后再进执行；其余 skill（验证门、代码审查）在写码阶段按流程自动接力。 安装（Claude Code 插件市场）： /plugin marketplace add obra/superpowers-marketplace /plugin install superpowers@superpowers-marketplace2. karpathy-skills · 约 19.8 万星 仓库：github.

Flask 作者谈 Pi 爆火：限制 Agent 的不是 AI，是系统架构

 included in AI 开发
Pi 火了之后，中文圈的解读大多停在第一层：只给模型一个 bash，上下文干净，省钱，所以赢了 Claude Code。2026-09-01，Flask 作者 Armin Ronacher 上了一期近两小时的播客访谈，把话题引向了别处。他是当事方，他所在的 Earendil 刚收购了 Pi 和它的作者 Mario Zechner。但整场访谈讲得最多的，是模型之外的事：Agent 真正卡住的地方，是三个做了几十年的老工程问题。其中一堵墙里有这么个故事，一家公司的 Agent 干了几周活，用户才发现自己的 Postgres 从来没跑起来过。 这场访谈我印象最深的一个判断：强模型这一层，换壳已经不是杠杆了。伯克利 HarnessTax 做过 21 组实测，同一个模型换不同的壳，任务成功率只动 1 个百分点上下，换到终端操作基准差异放大到 ±5%，账单则差出 2 到 5 倍，完整数据我在《你的 Claude 不一定需要 Claude Code》里分析过。注意这组基准没测的东西：不查库、不配界面、跑在现成的测试容器里。Agent 卡住的恰好是这些，3 堵墙，数据操作、界面与问责、运行环境，一堵都不需要等 AI 突破。 极简是表象，能自己长才是赢面 Pi 全部家当是 read、write、edit、bash 四件工具，系统提示词短到一屏读完。赢的原因，Armin 的解释很直接：模型非常擅长使用计算机，bash 加管道让上下文保持自由和高效，专用工具塞多了反而稀释。他举的证据就在对家门里：Codex 找文件靠的也是 bash 跑 ripgrep，不是什么专用检索工具。 工具箱塞满的代价有实测数据：Claude Code 的 37 个工具说明书合计 154KB，每轮请求都要重发一遍，缓存命中时实付能压低不少，但前缀一变，重复部分照原价走。但 Armin 不把 Pi 的胜利归给「少」。访谈里他反复强调的是可扩展：别的 Agent 厂商在往壳里塞工具，Pi 把扩展留给用户和模型自己写，模型可以现场给自己写一个扩展装上。他把这类软件叫自扩展软件，认为 Pi 踩中的是这个平衡点。Earendil 收购 Pi，目标明说就是拉人，Mario 曾被 Gmail 缔造者 Paul Buchheit 称作「没人知道的最好的程序员」。
