GPT-6 跑分逼近满分，你的任务为什么只提升一点：能力分层机制

 included in AI
GPT-6 Astra 的跑分单很吓人。FrontierMath Tier 4 拿到 98%，ARC-AGI 3 拿到 99.9%，都逼近满分。同一个模型，第一批第三方评测却给出克制结论，编程是小幅提升，不是突破。满分的榜单和无感的体感同时为真，只可能有一个解释，提升是分层的。 你感觉不到跳档，多半因为你的活不在跳档的那一层。这篇把分层拆开，再给一套不依赖任何榜单的自测方法。先看总览图。 一、两组跑分，讲了两个故事 先把四个基准的活儿性质摆清楚，数字才有意义。FrontierMath Tier 4 是竞赛级数学推理，ARC-AGI 3 是抽象图形推理，这两个属于推理侧。DeepSWE 是真实仓库级的智能体编程任务，模型要自己找文件、改代码、跑验证；Terminal-Bench 是终端里的长链路开发任务，理解需求、定位、修改、测试、按报错返工，一个任务串起十几步。后两个属于编程侧。 这批数字还各有各的口径。官方跑分出自受控环境，数字最漂亮也最理想化；第三方评测独立但任务集未必贴你；你的重放是第三种口径，样本最小，唯独它对你的决策有效。三种口径不互相打脸，各自回答各自的问题，混着看才会得出「满分和无感并存」的困惑。 推理侧是满分区。FrontierMath Tier 4 的 98%、ARC-AGI 3 的 99.9%，数字漂亮，但满分区里没有信息量。一排模型都贴着天花板，你看不出谁比谁强在哪，这叫基准失灵，区分度归零。这两个基准的难度档也是全系列里最硬的，撞线撞在最难的档上，说明推理侧的卷已经卷到头了，往后这一侧的跑分可以默认忽略。 编程侧才是有信息的地方，而且它自己就分了两档。Terminal-Bench，57.9% 对上一代的 37.3%，一步跳了 20.6 个百分点，这是跳档。DeepSWE，74.1% 对 70.8%，涨 3.3 个百分点，这是稳涨。 顺手解读一下上代那两个数字的含义。37.3% 意味着上代模型在终端任务上，接近三分之二的尝试死在链路中途，启动、定位、修改、验证这条链总有一环掉链子；70.8% 则说明仓库级智能体任务它本来就能干个七八成，提升空间只剩零头。起点不同，涨幅自然不同，这也是「看提升先看起点」的读表习惯。 同一个发布会，同一个模型，两条编程曲线的涨幅差了六倍多。接下来要回答的问题是，这条分界线画在哪，你的活落在哪一侧。 二、分界线：任务链路的长短 把跳档和稳涨的任务摆在一起，规律很清楚，分界线是任务链路的长短。 长链路任务的分数由链式通过率决定，这个数学值得算一遍。假设一个任务十步，每步成功率八成，十步全对的概率不到 11%；每步提到九成，全链路通过率跳到 35%。单步可靠性只涨了十个点，链路通过率涨了两倍多，链路越长，放大越狠。 Terminal-Bench 那二十个百分点的跳档，机制就在这里。GPT-6 的提升集中在每一步的稳定性上，十几步的链路把它逐级放大成整条曲线的抬升。 梯度可以再验一遍。同样是单步从八成到九成，五步任务的通过率从 33% 抬到 59%，涨 26 个点；十步任务从 11% 抬到 35%，涨 24 个点，看着接近，但十步任务的基数只有五步的三分之一，相对提升大得多。你的活链路越长，这次升级对你的价值越大，短链路活几乎拿不到放大红利。 短链路活拿不到这个放大器。给一段输入要一段输出的纯生成，中间没有多步推理和工具调用，模型生成本身涨多少，你就感觉到多少，一步都多不了。 断片修复是另一个省钱点，上代模型长编码跑到一半断掉，只能全价从头再来，尾部那几轮是纯损耗；官方这次专门修了断片，等于直接砍掉尾部轮次，这部分的收益全落在总开销上，和GPT-6 账单说明书里的轮次机制对得上。第三方评测说「小幅提升非突破」，测的正是纯生成层，结论没有错，只是它没覆盖跳档的那一层。 所以两派吵不起来。看跑分的人盯的是长链路层，说无感的人日常干的是短链路活，都对。分层地真，比笼统地强或弱都更接近事实。 你的活落在哪一层，不用猜，三个问题定位。这活从接需求到交付要几步自主决策，一两步是短链路，十步开外是长链路；中途要调用工具、改文件、跑验证吗，要就有链式放大；失败了能从头重跑吗，能重跑的任务对单步稳定性更敏感。三问答完，你对「这次升级我拿得到几成」基本有数了。 三、基准失灵之后，怎么自己测 满分区没有区分度，发布会没有你的任务，剩下的路只有一条，自己建评测集。 顺便把「跑分不等于任务」再拆具体一点，错位至少有三处。一处是难度分布。基准为了区分模型，题目集中在中等难度，而真实工作的难度是两头的，高频简单活和低频硬骨头，中间地带反而少，中等难度上的优势传导不到你的两头上。 第二处是上下文。基准任务都是干净的一次性输入，你的活带着历史包袱，几十轮对话的仓库上下文、上个任务残留的约定、团队自己的规范，这些基准一概不测。

GPT-6 到位后，Claude Code 和 Codex 怎么排班：三件套分工与换模三信号

 included in AI
GPT-6 Astra 发布后的这几天，后台被同一个问题刷屏。主力工具要不要换？我的答案是先把问题换掉，换不换工具是个伪问题，怎么排班才是真问题。一个模型再强，也强不到包打所有工位，就像没有一个员工适合所有岗位。 这篇给出一套可以直接抄走的排班表。依据有两个，一是我们自己仓库的真实工作流，这套三件套每天在跑；二是 GPT-6 已公开的能力与成本数据，重活位的预排全部有出处。先看总览图。 一、现役分工：三件套各守一位 先交代真实情况。按使用频率排，我们的顺序是 Claude Code、Cursor、OpenAI 的 OpenCode、Codex。主力是 Claude Code，频率上断档领先，仓库开发、文章写作、发布管线、数据回流报表都归它。 为什么主力是它不是别人。写文章和跑管线都需要长会话，几十轮对话里它对上下文的维持最稳；我们的 skill 体系和发布流程都以它为第一公民构建，工具链的粘性本身就是生产力；日常改动碎、上下文切换频繁的场景，它的响应结构最适合。 顺带回答一个反问。既然它这么能干，为什么还要养一个班子？因为单工具依赖是真实风险。定价说变就变，服务说断就断，能力再有盲区你也没得挑。排班制天然分散这些风险，一个工位出事，其余照转。 Cursor 和 OpenCode 做轻量替补。临时查看别人仓库、快速小改、主力通道排队时的分流，这类活不需要重型工具。 Codex 的位置比较特别。按频率它排最末，但它守着一块别人干不了的工位，长时自动作业。视频生产链上的批量任务交给它，六条素材自动剪成三十条成片候选，一跑几个小时不用人盯，这套实操之前写过完整拆解。频率低不等于不重要，工位制看的不是出场次数，是不可替代性。长时作业要的是稳定压倒一切，任务形态固定、失败可重跑，这正好是它的长处。 这个工位还有一层调度价值。无人值守的批量任务和有人盯的交互任务分给两个引擎，一边跑几小时的渲染，一边继续写文章改代码，互不阻塞。把批量活塞给主力引擎，等于让全天最贵的交互时间排队等后台任务，怎么排都亏。 GPT-6 进来之前，这张表已经稳定跑了很久。它进来后不挤占任何人的工位，新开一个，重活试用位。全库代码分析用得上它约 105 万 token 的上下文，超长编码和深度调试推理吃它的一次成型率。 有一个诚实的前提要说清。GPT-6 目前是有限预览，只面向部分组织和受信企业，我们自己还没上手，重活位的排定依据是公开数据而非实测。这正是排班制的第一个好处，预排不伤现役，错了改回来就行。 二、换模三信号：缺一不换 新模型能不能从试用位升到主力位，看三个信号，不看发布会。 信号一，任务集稳定胜出。把你最近十个真实需求原样重放，看一次通过率，不是看跑分。一次通过之外再记一个数，返工轮数，它同时是信号二的输入，通过率够但每单都要返工三轮，成本维度的判定就会翻过来。GPT-6 的多项跑分逼近满分，但编程提升是分层的，长链路任务跳档、普通生成只稳涨，这个分层的机制和自测方法写在跑分分层里。 这个信号灭着的样子很常见，跑分赢麻了，重放到自己任务上反而翻车。第三方评测说的「小幅提升非突破」测的就是普通生成层，你要确认自己的活不在那一层。 十个任务怎么挑有讲究。覆盖你最高频的三类日常活，加上最痛的两类硬骨头，再放两个边缘形态防止样本太纯。重放时环境要一致，同样的仓库状态、同样的提示词，顺序打乱着跑，防止模型对前序任务留有记忆。挑任务偷懒，测出来的结果就是自欺。 信号二，成本压得平。同样的活，总开销不涨。单价、token 量、轮次要一起看，GPT-6 单价贵 2.5 倍、重活总开销反降 43% 的机制拆解见GPT-6 账单说明书。重活压得平、零碎活压不平，这正是它只进重活位的原因。这个信号灭着的样子，是让 5 倍输出价的模型去干格式转换，每一单都在赔。 信号三，接入成熟。API 全面开放、常用客户端和框架接好、订阅渠道铺开。这个信号可以拆成四项逐一核对，官方 API 文档齐不齐、你在用的客户端支不支持、团队的框架和工具链有没有适配、订阅入口对你开没开。GPT-6 当前还在有限预览阶段，四项里多数是灭的，所以它现在只能是试用位。工具链没接好就硬上，省下的模型钱会加倍付给工程时间。 三个信号缺任何一个，都不换。不是保守，是每个灭掉的信号都对应一种真实的返工成本。 三、三条纪律：防止换模误伤主力 排班制要配三条纪律，缺了会出事故。 双引擎不急着裁。新旧两套并行跑一段，看起来是浪费，其实是对照组。没有对照组，你说不清新工具的胜出是真实的还是幸存者偏差，也说不清它只是恰好碰上了几类顺手的任务。并行的额外消耗要当保费记进表里，这笔钱买的是判断的可信度，比换错工具再换回来的成本低一个量级。 老工具留作基线。每次新模型进来，用同一批任务在老工具上重跑一遍，成本和通过率都有了参照。记录格式固定成一张表，任务、工具、轮次、输入输出 token、一次通过、返工次数，六列数字摆在一起，谁强谁省一目了然。我们 952 万 token 的消耗记录就是这么攒下来的，见数字员工成本实测。 新模型先进试用期，干满两周再谈转正。两周足够覆盖一周以上的真实任务波动，也足够让新鲜感褪掉。试用期内的表现只记数据不做结论，到期拿数据对三个信号，全亮转正，缺一续期或者出局。 四、时间表：分两半换 落到执行，节奏分两半。重活长活现在就排进 GPT-6 的试用队列，预览开放到你就开测，成本数据支持这个方向；日常主力位一行代码都不用动，等三个信号全亮再说。 试用队列的第一批任务建议直接用三个代表。一个全库分析，挑你最熟的中型项目，测它敢不敢一次读满；一个超长编码，挑过去断过片的那种任务，测稳定性；一个深度调试，挑一个悬了很久的 bug，测一次成型率。三个任务跑完，信号一和信号二的第一手数据就都有了。

GPT-6 账单说明书：单价贵 2.5 倍，重活总账反而便宜 43%

 included in AI
GPT-6 Astra 开放有限预览的第一天，两组数字同时摆上桌。API 定价输入每百万 token 10 美元、输出 50 美元，是上一代的 2.5 倍；同一批公开报道里，重型任务的总成本比上一代低 43%，比另一家旗舰低 86%。单价和总价反着走，这不是笔误。 结论先给一半。省出来的不是模型的钱，是你决策的钱。会把任务分对的人拿到的是折扣，分不对的人拿到的是溢价，分界线不在模型那边，在你这边。 这篇把账单结构拆开，价格怎么读、总账为什么降、任务怎么分、哪两条纪律不随模型换代作废，一次讲完。先看这张总览图，全文围绕它展开。 一、单价面：贵在哪，结构说了什么 先看贵的部分。输入 10 美元、输出 50 美元，每百万 token，这个定价里的事，不止涨了 2.5 倍。输出价是输入价的 5 倍，这个比例才是关键。 它意味着账单的大头不在你问了多少，在它写了多少。拿一个具体任务演算。提示词两万 token、输出五千 token，按这个定价，输入花 0.2 美元，输出花 0.25 美元，合计 0.45 美元。输出 token 只有输入的四分之一，钱却占了一半还多。把输出量放大十倍，总账涨到原来的六倍，读写结构比任务难度更决定价格。 由此推出两类活的价格属性。读得多写得少的活，比如全库分析里的一次定位提问，天然便宜；写得多的活，比如让模型把整个模块重写一遍，天然贵。同一个模型，同一个单价表，两种命运。 再补一个计费视角。走 API 按 token 计费，上面的演算全部成立；走订阅包月的用户，感受会滞后一拍，额度内的消耗不按单显示，贵的体感要等额度告急或者超额账单出来才显形。两类用户该做的事一样，把读写结构记下来，订阅用户只是晚一点看到代价。 2.5 倍的涨幅买到了什么，公开数据给了三样。上下文约 105 万 token，中型项目全库一次读入，不用再切片再摘要。超长编码半路断片的老毛病，官方这次专门修了。一次成型率提升，一遍过的概率变高。 前两样是能力，第三样是钱。它直接决定了下面这组反直觉的数字。 二、机制面：省的不是单价，是轮次 再看降的部分。重型任务总成本比上一代低 43%、比另一家旗舰低 86%，这两个数字的来源不是单价，是轮次。 一次成型率高，返工就少；返工少，轮次就少。总账约等于单价乘以 token 量再乘以轮次。单价涨了 2.5 倍，轮次和重复读取压到原来的四分之一，总账就降三成多；压得再狠一点，43% 的降幅就出来了。断片重跑和反复返工的活，轮次从七八轮压到两三轮并不稀奇，这个降幅属于它们。 长链路任务正是返工的重灾区。全库分析跑到一半断了重来，代码生成完了编译不过再改一轮，测试挂了回头再调一处，过去这些返工都在按单价重复付费。更狠的是每一轮返工都要把上下文重新喂一遍，轮次上涨的同时，单轮的 token 量也在膨胀，两个乘数一起变大。模型一遍成型率上去了，这些重复支出整段消失。 反过来也解释了为什么零碎活占不到便宜。格式转换、小段改写这类活本来就一轮完事，轮次没有下降空间，2.5 倍的单价涨幅会原样落进总账。43% 的降幅只属于返工大户，一遍就能干完的活，越贵的模型越亏。 所以「贵」和「便宜」是同一组数字的正反面。用对了，轮次下降摊薄单价，拿到折扣；用错了，一遍遍返工放大单价，拿到溢价。分界线落到任务分配上。 三、分配面：三类配它，零碎外派 任务怎么分，一张表说清。 三类活配它。全库代码分析，105 万 token 的上下文正好用满，这是它独占的场景，别的模型还在切片和摘要里打转；超长编码，断片修复直接受益，过去最长的活受最深的返工伤；深度调试推理，一次成型率就是收益本身，每省一轮返工，省的是单价、token 量、轮次三个乘数的乘积。

装了十几个 skill，模型却一次都不主动用？MCP 越装越多，会话越开越慢，token 消耗怎么压都压不下来？先别急着卸载插件，这两个毛病多半同源。 我在 Claude Code 里装了 30 个 skill。每次启动新会话，这 30 个 skill 的正文一行都不会进入模型的上下文，真正进来的只有 30 行介绍，每个 skill 一行，内容是名字加描述。第一反应是安装出了问题，直到把加载源码翻完，我才确认这不是缺陷，是官方文档里写明的设计，名字叫渐进式披露（progressive disclosure）。 skill 为什么沉睡、MCP 为什么拖慢会话、写 skill 时描述到底该写给谁看，这篇统一回答。文中引用的源码结论来自之前对 Claude Code 与 Codex 加载机制的源码对比，那篇有行号级证据，这篇负责把原理讲成人人能用的大白话。 先看这张总览图，全文都围绕它展开： 一、三层加载：每层只在需要时出场 一个 skill 就是磁盘上的一个目录：必备一份 SKILL.md，头部是 YAML 元数据，关键字段 name 和 description，正文写操作指引；可以再放 references/ 存详细资料、scripts/ 放脚本。关键在于这三部分进入模型视野的时机完全不同。 元数据（名字加描述）会话启动时就进入上下文，全程常驻；SKILL.md 正文只在模型判断当前任务需要时才被读取。 references/ 和 scripts/ 更靠后，连正文都只提一句，模型按指引在真正用到时才去读。「渐进式」和「披露」两个词都用得准确：信息都在磁盘上，分批出示，什么时候出示、出示给谁，机制说了算。 三层的 token 量级差得很远。元数据层每个 skill 几十 token，30 个 skill 合计千把 token，这是一次会话的固定开销；正文层单份一两千 token，但只为真正触发的技能付费，一次会话通常只触发两三个；附件层不预先加载，读到哪个算哪个。 对比一下全量注入：30 份正文全部塞进上下文，按单份 1500 到 2500 token 估算，常驻开销冲到 6 万 token，渐进式把它压到千把，只剩百分之二上下。Claude Code 2.

Claude Code 裸聊会翻车：单轮 11 倍消耗与五根工程柱子

 included in AI 开发
2026-08-20 那天我翻了一张 Codex 会话账单，越翻越不对劲。54 次调用，累计输入 952 万 token，输出只有 6.6 万，输入输出比 144:1。单轮消耗从 20,611 一路涨到 226,262，一个会话之内翻了 11 倍，干的活却没变。 再往前，还有一笔更疼的。270 行并发守卫代码被一次「搜索优化」提交静默删掉，编译照样绿，没人发现。潜伏四天，大促订单超卖，又花了四天排查才把根因挖出来，详见 那次幽灵删除的完整复盘。 这两笔消耗指向同一个病根。很多人第一反应是模型不够聪明，或者提示词写得不够好，方向全偏了。模型没问题，出问题的是我把一件工程活当成了聊天：需求靠口述，规则靠临时想起，验收靠肉眼，成本靠事后惊讶。 Karpathy 把这种状态叫做 vibe coding，全凭感觉跟 AI 对话，代码哗哗地出。这个词用来形容爽感很准，用来指导干活就危险了。爽感来自「聊」，质量来自「工程」，两件事的差距就是上面那张账单和那次超卖。 这两年带着小团队用 Claude Code 交付了近百万行的多租户 SaaS，我把踩过的坑收拢成五根工程柱子：项目记忆、skill 资产、spec 契约、测试门禁、边界与成本。五根柱子的组合逻辑也简单：前两根管 AI 知不知道，第三根管干的是什么活，第四根管干得对不对，第五根管能不能干得久。每根柱子拦住哪类事故、怎么装、装晚了会缺什么，下面逐根拆开。 一、先看裸聊翻车的四种姿势 裸聊的事故看着花样繁多，归拢之后就四种。每一种我都交过学费，先摆出来，后面五根柱子逐一对应。 **姿势一：AI 不懂你家的规矩。**每个仓库都有一堆写不进代码的隐性规则。我仓库里有三个老模块按订单状态驱动，直接改状态字段会绕过佣金结算，这条规则不存在任何代码注释里。AI 每次会话都是新人，没人告诉它，它就敢直接改。部分退款改造那次，佣金多结、积分没扣、报表虚高，月底对账才炸。 **姿势二：聊天记录当需求文档。**口述的需求散落在几十条消息里，AI 记住的永远是最后一版。我说过一句「给这个接口加个缓存」，它回敬了我一整套缓存体系：多级缓存、过期策略、预热脚本，账单翻倍，而我要的只是三行代码。聊得越多，意图被稀释得越狠，最后一轮的 AI 是拿着转述了二十遍的需求在干活。 **姿势三：「看起来对」就合入。**AI 说「搞定了」的时候，它的目标函数是让验收变绿，管绿灯是真是假。我见过 178 个测试全绿、真实环境一连就崩的交付；也见过快照测试把 bug 输出固化成标准答案，从此每次都「通过」。编译能过、页面能开、测试能绿，三样加起来证明不了行为正确。 **姿势四：一把梭，没边界也没成本概念。**一个会话从早聊到晚，上下文雪球越滚越大，账单曲线就是第一节那张 11 倍的曲线。三个会话共用一个目录并行开发，互相覆盖对方的改动，git status 里全是看不懂的冲突。夜里挂个自动重试，醒来发现它把同一个错误重试了两百遍。 四种姿势对应一个共同结构：缺了某个工程件，AI 就用最自然的方式把这个洞撞开。 它们还容易被误诊成提示词问题。姿势一怪 AI 记性差，姿势二怪它不听话，姿势三怪它吹牛，姿势四怪它烧钱，于是解法永远在换模型、换提示词模板之间打转。病根其实在工程侧：聊天这个交互形态天生没有记忆、没有契约、没有验收，而这三样正是软件工程积累了五十年的存货。下一节从最便宜的那根柱子装起。 症状 缺的柱子 典型代价 AI 不懂规矩 项目记忆 隐性规则被绕过，静默改错 聊天记录当文档 spec 契约 意图稀释，账单翻倍 看起来对就合入 测试门禁 假绿灯，线上事故 一把梭无边界 边界与成本 会话雪球、并行互踩 二、第一根柱子：项目记忆，AGENTS.

Agent 拆开就四层，账单能差 30 倍：架构拆解与我的配置

xiaoshuai1024 included in AI 开发
同一个模型，关在聊天框里是台收音机：你放一句，它回一句，你不按播放键它就永远沉默。装进 Agent 里是条流水线：原料丢进去，成品吐出来，中间自己干，不用你守着。这两年所有人都在聊 Agent，聊的其实是这条流水线怎么搭。 但流水线有流水线的代价。很多 Agent 不是死在不能用，是死在月底账单：你以为开了台机器，结果机器空转也在烧电。每次调用都是一次全新握手，握手就计费；任务越复杂，提示词越写越长，token 烧得越猛。我在 AI 编程账单拆解 里晒过自己一条 952 万 token 的真实会话：同一个问题，配置不同，开销能差 30 倍。差距不在模型，在架构。 这篇文章把 Agent 拆成四层讲：大脑（怎么拆任务）、能源（怎么调模型、怎么省钱）、手脚（怎么连外部工具）、手册（怎么把流程固化成稳定能力）。四层各管一摊：大脑决定能力上限，能源决定运行成本，手脚决定能力边界，手册决定稳定下限。框架参考了一条高赞架构课的讲法，配置和账单部分换成我自己的实战数据。四层都拆完，你看任何 AI 产品都能一眼看穿它在哪层偷了工。 四层配置速查：先拿走，再读原理 层 管什么 可直接照做的配置 大脑 任务拆解质量 动手前先复述目标的开场验收（第一节） 能源 账单与稳定 模型路由分档表 + 缓存座次原则（第二节） 手脚 能力边界 MCP 三步接线与三条安全纪律（第三节） 手册 稳定下限 Skill 模块骨架与入库判据（第四节） 每层配置都在对应章节里，出问题先拿文末的四层排查速查表对症状查层，再回头读对应层的原理。 第一层：大脑，从你问一句它答一句到自己干到完 先把「Agent 为什么显得能干」这个神奇感拆掉。聊天框模式是响应式：输入什么，吐出什么，全程被动。Agent 模式换了个活法：给一个大目标，它自己拆步骤，自己调工具，干完一步看一眼结果，不行就调整再来，直到办成。 拿一个通用例子看它内部怎么转。目标「调研竞品，写份报告」，它会自己拆成三步：先当探索者去抓资料，再当分析师清洗信息、剔除对不上的部分，最后才当写作者成稿。每一步都在「按自己对任务的理解」做取舍：理解对，步步精准；理解偏，它会以最高效率把错误执行到底。这个执行循环是 Agent 全部能力的来源，也是全部风险的来源，后面第三层第四层都在给它修护栏。 这个循环有个正式名字：ReAct，思考、行动、观察三拍一轮。思考是模型对自己说「下一步该干嘛」，行动是调用工具，观察是读工具返回的结果，三拍完了带着新信息进下一轮。名字不重要，重要的是这个结构解释了 Agent 和聊天机器人的全部行为差异：聊天模型收到输入直接给输出，一锤子买卖；Agent 在思考与观察之间来回穿行，每一轮都带着上一轮的战果修正路线。你后面调试 Agent 时的全部日志分析，看的就是这三拍的轮转记录。 大脑层装没装好，有个简单验收：把任务丢给它，看它动手前说不说人话。合格的大脑会复述目标、列出打算分几步、每步用什么工具，然后等你点头或直接开跑；不合格的大脑拿到任务直接闷头写，写完你再发现方向整个歪了。复述这一步省下的返工，比任何模型升级都划算，这也是为什么说规划质量一半在模板：模板就是逼它开口讲人话的那道工序。 支撑这个循环的是三个部件。大模型是 CPU，负责想；规划是主频，决定任务拆得细不细；记忆是内存，存着上下文和干活的中间状态；工具调用是外设接口，让它读得到文件、跑得动命令、查得了数据库。只配 CPU 不配外设，主频再高也只能跑分，这是很多人搭 Agent 的第一个坑：模型买到顶配，工具一个没接，全靠模型用嘴干活。 三个部件落到工程上是三份配置。规划落在提示词里的任务拆解模板：先复述目标、再列步骤、每步标注打算用什么工具，模板写没写、写得细不细，直接决定规划质量。记忆分两条路，短期记忆靠上下文窗口，装当前任务的来龙去脉；长期记忆要外置，写文件、写数据库，会话结束也不丢。工具调用落在函数签名：每个工具的名字、参数、返回值定义得越规整，模型选工具的准确率越高，含糊的签名是调错工具的第一来源。 CPU 有个出厂设置必须知道：它的内存条每次通电自动清零。这次会话里你们聊得再透，下一次调用，它连你上周定的规矩都不记得。别怪它高冷，API 的无状态设计就是这样，下一层展开。 第二层：能源，API 是通用货币，汇率还分档 大脑要思考，思考要耗电，电就是 API。理解这一层，先认一条：API 是 AI 世界的通用货币，而且汇率分档。同一个请求，走大模型是商务舱，走小模型是地铁：都能到，票价差一个数量级。
