循环Transformer会让GPT-6 Astra藏起思维链吗？把这场架构争议拆开看

 included in 大模型
这台模型为什么在实际任务上体感提升有限，可以看我之前写的能力分层分析；本文只聊架构争议本身。 GPT-6 Astra 发布前的两天，The Information 援引内部消息扔出一颗雷：Astra 用了一种叫 recurrent depth（循环深度）的设计，也就是 looped transformer（循环 Transformer），而它「会让模型的部分乃至全部推理过程变得不可见」。模型上线后争议越滚越大，逼得 OpenAI 首席科学家 Jakub Pachocki 亲自出面，说他想避免「一场由混乱的报道引发的、奔向不可监控性的竞赛」，并强调当前前沿模型的计算图深度与 GPT-4 的差距仍在两倍以内。 这句话信息量不小，但被各家转述得语焉不详。Sebastian Raschka（《Build a Large Language Model (From Scratch)》的作者）随后写了一篇长文，把技术细节摊开讲了一遍。这篇是我读完他的原文和相关论文后的复述与整理。结论先给出来：循环 Transformer 大概率不是思维链变短的元凶，更合理的解释是模型变强了，不需要那么长的草稿纸。 循环 Transformer 到底是什么 循环 Transformer 的定义可以这样给：让中间表示两遍或多遍地通过同一批 Transformer 块（常规架构只过一遍），每一遍复用同一套权重。 拿今年 7 月发布的开放权重模型 Nanbeige4.2-3B 做例子最直观。它的架构看起来就是个常规 Transformer：输入经过 token 化和嵌入之后，穿过 22 个 Transformer 块，每块有自己的权重（块内部是什么，可以看QKV 矩阵级拆解，这篇不展开）。区别在于多了一条绕回栈开头的路径：第一遍走完后，隐藏状态被送回这同样的 22 个块再来一遍。 把计算过程展开看，相当于 44 次块应用。但和真正拥有 44 个独立块的模型不同，第 23 次块应用用的是块 1 的权重，第 24 次用的是块 2 的权重，依此类推。有效深度从 22 提到 44，参数量却不用翻倍，这就是全部诀窍。 这个思路不新。2018 年的 Universal Transformer 论文就在做类似的事，只不过它反复应用的是单个 Transformer 块，没有用一整个栈。

看完我的 AGENTS.md，你会看到我和一个爱删片的 agent 斗智斗勇的这半年

xiaoshuai1024 included in AI 开发
本仓的每一条定规都是强制性的。违反任何一条都会遭受毁灭性打击：轻则返工一晚上，重则像我一样，一夜之间丢掉 8 支已经发布、正在产生播放量的视频。不存在任何例外与豁免：出于好意的违反也是违反，为了进度的违反也是违反，「我觉得这样更好」的违反尤其是违反。 我的仓库是一个 Hugo 博客加一条完整的自媒体生产线：选题、写作、视频生成、四平台发布、数据回流，全部由 agent 会话驱动。所以我的 agent 手里的权限比一般写代码的 agent 大得多，它会真的去平台上发东西、删东西、改定时。权限越大，规矩越硬，这就是这份 AGENTS.md 的来历。 网上流传的那份名作，作者在和不说人话且 over-engineering 的模型搏斗。我这边战况不同：我的 agent 会把文章写成周报，会在发布时漏掉合规声明，会在合成任务里快乐地烧掉两个半小时，最辉煌的一战，它把「清理临时文件」理解成了「清理已发布资产」。 好消息是，每打输一仗，我就立一条法。半年下来，这份 AGENTS.md 已经厚到需要给自己立精简法了。下面按「事故 → 规矩」的顺序讲，战损最重的在前。 最重的一条：不许删任何已发布的东西 2026-09-15，例行盘点时我发现 8 支高播放视频（最高一支 30,955 播放）没了。平台成片、本地成片、场景 deck 全灭，只有口播稿幸存，原因特别讽刺：口播稿在另一个目录，清理命令没扫到它。它活下来靠的是目录结构，靠的是运气。 恢复方案是重制补档，按播放量序每天补一支，排期被打乱了半个多月。那可是挂在四个平台上、每天还在涨播放的资产，不是缓存。 事故之后立的规矩，现在钉在发布红线第 10 条： 任何会话不得删除/撤稿已发布视频及关联台账。清理类操作（删文件/删稿/清目录）先列清单向用户逐项确认；涉及高播放资产的删除即使获准，也必须先归档成片、deck、口播稿三件套，再执行。 注意这条规矩的立法技术：它压根没打算教 agent「判断什么该删」。判断已经被证明不可靠了，出事的那个会话在按下删除时，大概率也有一套自洽的理由。所以规矩直接绕过判断，把「清理」锁死成两步人肉流程，先列清单，逐项确认。慢就慢点，烦就烦点，总比再丢 8 支强。 这是我整份 AGENTS.md 的核心立法思想：凡是一次事故证明 agent 会判断错的地方，就不再给它判断的机会。 语言：写作层的死规矩 我的 agent 每天产出一篇文章和一支视频口播稿。AI 写中文技术内容有个通病，我管它叫「工作汇报体」：每段都像在念周报，工整，空洞，没有一个真人在说话。所以语言这一节规矩密度最高，挑几条感受一下。 禁词表是无例外的。「兜底」「铁证」这类词，放在技术语境里读着完全合理，拿数据库约束给业务兜底，多正经的表述。但 2026-08 的一次全站清理让我定规：一律不出现，技术语境也无例外。原因很实际：这些词已经成了 AI 文本的高频指纹，读者扫到第一反应就是「AI 写的」，信任一贴标签，后面写什么都打折。禁词表收在 de-ai-smell skill 里，配机检命令 make check-ai-smell，发布前必跑。命中要人工裁决，反讽语境和真实业务术语是合法的，脚本只定位，不改稿，改稿的锅我自己背。 段落不超过 4 行。 看着像排版洁癖，实际是注意力管理。手机上超过 4 行的段落，第二眼读者就开始跳读了。agent 天然爱写长段落，它一口气生成，没有换气的生理需求，只好用硬约束逼它呼吸。 语气权威自信，禁小白摸索口吻。 agent 特别爱写「我尝试了一下，似乎可以」「可能是因为什么吧」。这些词在探索时是诚实的，放进成稿就是灾难。你写的是教程，不是探索日记，探索的部分请留在你自己的思考里。

照榜单装了 12 个开源 Claude Code 插件，实测一个月我删了一半

 included in AI编程
Claude Code 的插件和 skill 榜单网上已经不少了，我之前也整理过一版。但榜单有个共同问题：只管推荐，不管售后。装的时候每个都写着「必装」，装完之后哪些真在干活、哪些在吃灰，没人告诉你。 这次我把话说完：照榜单装了 12 个开源插件，用一个月真实任务逐个实测，删了一半，留下 6 个。留下来的每个都附 GitHub 实拍、实测体验和照抄能用的安装命令；删掉的 6 个，也讲清楚为什么删，这部分可能比推荐更值钱。 先看结果 淘汰标准就一条：这一个月里，它有没有被我真实触发过。不是「我觉得它有用」，是有据可查的使用记录。插件和 npm 依赖一个道理：装 800 个包，入口就那几个，区别只是白白多出上下文开销和选择干扰。 留下的 6 个 1. Superpowers · 留 仓库：github.com/obra/superpowers 它是什么：一整套 agentic skills 框架 + 软件开发方法论。brainstorm、设计、TDD、代码审查、调试、执行计划，每个环节一个 skill，从想法到交付全链路覆盖。 实测体验：装完后第一个月我只用到了它的 brainstorming 和 executing-plans，第二个月开始 debugging、grill-me 也被自然带起来了：它们挂在开发流程的固定环节上，写到「设计完就该 TDD」的节点就会触发。这是它能留下的关键：它的工作流和写代码的流程天然重合，不用你记着去用。 安装（Claude Code）： /plugin marketplace add obra/superpowers-marketplace /plugin install superpowers@superpowers-marketplace2. ECC · 留 仓库：github.com/affaan-m/ECC 它是什么：agent 性能优化系统，打包了 skills、instincts（直觉规则）、memory（记忆）、security（安全）、research-first development 五个维度，管的是 agent「怎么跑任务」本身。 实测体验：它的 memory 和 research-first 两个模块在长任务上肉眼可见地稳：agent 动手前先调研、跨会话记得上下文，长任务稳不稳就看这两件事。选 minimal profile 装，full 版会把一堆你用不到的模块也塞进来，那正是我要在别人机器上删的东西。

你的 skill 配置就是攻击面：ECC 的 268 条安全规则拆解

 included in AI 开发
今年 8 月拆 ECC 的时候，我在那篇总览里提过一句它的安全扫描器 AgentShield：102 条静态规则，npx ecc-agentshield scan 一行命令扫 agent 配置。当时它是配角，一句带过。 为这篇重读源码时，README 已经对不上了：头部写着 268 条规则，拉到底部的规则汇总表还停在 102 条；CHANGELOG 显示 2026-09-10 一天连发两个版本，测试从 1841 个涨到 2444 个。一份 README 自己都追不上自家规则表的膨胀速度。 这件事本身就是本文的主题。AgentShield 已经拆成独立仓库（affaan-m/agentshield，npm 包 ecc-agentshield），它扫的对象不是你写的代码，是 .claude/、.codex/、mcp.json 这些「给 agent 看的」配置。多数人的直觉里这些文件是自己写的，可信；换一个角度看：agent 是一个能执行 shell 命令、能联网、能读文件的程序，它的行为说明书却没有经过任何安全评审。 我拿它跑了三次实测，结果先摆在这： 扫描目标 结果 官方自带的漏洞示例目录 F 级 0 分，199 条 finding，其中 40 条 critical ECC 仓库本尊（25.7 万星） F 级 19 分，2532 条 finding——85% 是文档示例，这个数字后面有大用 我自己的博客仓库 B 级 80 分，12 条 finding，两条 critical 是「CLAUDE.md 没写指令边界防御」 第三条值得停一下。我的仓库没有密钥泄露，没有危险 hook，scanner 给的两条 critical 全指向同一个缺口：你的提示词没写防御条款。这个工具对「安全」的定义比一般人想的宽——提示词本身也算安全配置。为什么，往下看。

Claude Code 的 skill 能自己进化？25 万星 ECC 源码拆出答案

 included in AI 开发
能。Claude Code 的 skill 确实可以自己进化——不用你写一行 SKILL.md，它从你的日常会话里观察、提炼、攒成本能，再定期把本能聚成新 skill。跑通这件事的项目叫 ECC，GitHub 上 25.7 万星，agent harness 赛道目前最大的开源项目。 这套进化机制的核心代码在 instinct-cli.py 里，第 1158 行藏着一句怨念很深的注释：trigger 句子平均只有 7 个词，用 Jaccard 相似度算聚类，明显相关的两条最高也只能到 0.33，「nothing ever groups」——什么都聚不起来。为了这句注释，作者把整个聚类算法换成了 overlap coefficient。 这是 ECC 的 Instincts 子系统。翻完它的源码，我最大的感受是它的诚实：每一层都在直面同一个物理事实——大语言模型没有记忆，你感觉到的「记性」，全部是外挂工程拼出来的。 这篇文章把这个外挂拆开看。先讲清楚为什么记忆必须外挂，再顺着数据流拆四层：观察、本能、注入、进化。ECC 给每一层交出的工程答案，比大多数「AI 记忆」创业产品的宣传页都有信息量。 一、先纠正一个错觉：模型的「记忆」是三种不同的东西 很多人聊 AI 记忆时把它们混成一团。认知科学把人类记忆分成三类，这个框架搬过来正好用： 认知科学分类 日常对应 AI 编程代理里的对应物 工作记忆 脑子里「正在想」的内容 上下文窗口（context window） 情景记忆 「上周三发生过什么」 会话日志、transcript 文件 程序记忆 骑自行车这种「肌肉记忆」 系统提示词、skills、规则文件 关键在第一行。LLM 是无状态的：每次推理，模型只看得到当前上下文窗口里的 token，上一次会话发生的一切对它来说不存在。你在 Claude Code 里教过它一百次「这个项目提交信息用 conventional commits」，新开一个会话，它照样给你写 update stuff。不是它不听话，是那个信息物理上不在它的输入里。 所以「让 AI 有记性」这个需求，翻译成工程语言就是：怎么把情景记忆（历史会话）提炼成程序记忆（可注入的行为规则），然后在恰当的时机塞回工作记忆（上下文窗口）。 ECC 的做法是四步：hooks 观察你的每次操作 → 后台代理从观察里提炼「本能」（instinct）→ 每次开新会话时把最相关的本能注入上下文 → 定期把攒多的本能聚合成 skills、commands、agents。整个 Instincts 子系统就跑在这条数据流上。
