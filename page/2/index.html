Cloudflare 开源 AI 安检员：450 行技能，7245 个真洞

 included in AI 开发
我先把 security-audit-skill 的仓库拉下来数了一遍：15 份 Markdown，加 4 份校验脚本和 1 份 JSON Schema，一共 20 个文件，官方博客说它的起点约 450 行。就这么大的一个技能，官方博客给出的内部战绩是：累计报出 20799 个候选漏洞，一路独立验证筛下来，7245 个是可行动的真洞，扫的是 Cloudflare 内部 145 个仓库。 450 行的技能，七千多个真洞。这个落差是我写这篇的原因。 你可能和我一样，早就察觉到一个别扭的现状：AI 写代码的速度越来越快，Claude Code 一个会话能产出几千行，但「查这些代码」这件事，还停留在人肉 review 加几十年前的扫描器。写代码的范式换了，查代码的范式没换。2026-09-21 这天，这个仓库单日涨了 2428 星。对建仓以来日均 195 星的增速，这是 12 倍，市场显然也在等这个答案。 这篇文章分六块把它讲透：它是什么，六个阶段怎么跑，靠哪三条纪律防止「自己骗自己」，结论为什么只分三档，怎么一条命令装上，以及它防不住什么。总览图先放这里，后面逐段展开。 一、它是什么：450 行的种子，七千个洞的出身 security-audit-skill 是 Cloudflare 官方仓库，MIT 协议，2026-06-18 建仓。它出自 Cloudflare 本家：自家漏洞发现系统（vulnerability discovery harness）的种子版本直接开源，官方博客《Build your own vulnerability harness》把来龙去脉交待得很清楚。 账本是这样的。那个约 450 行的技能，在 Cloudflare 内部被长成一整套系统：一个负责发现漏洞的流水线（VDH），加一个负责验证漏洞的系统（VVS），两边用不同的模型互相校验，覆盖了内部 145 个仓库。 运行结果累计报出 20,799 个候选，独立验证筛到约 12,057 个，跨系统合并去重时折叠掉 5,442 个重复、回收 1,154 个打错目标的发现，落定 7,245 个可行动的真漏洞。随着反馈循环转起来，初次验证的拒绝率从 40% 压到 11%，高完整性发现的占比从 35% 提到 58%。

模型没换，账单差20倍：三家AI编码工具价目表拆解

 included in AI 编程
先看一份我自己机器上的真实记录：一个 Codex 会话，五十四次调用，输入九百五十二万 token，输出只有六万六千，输入是输出的一百四十四倍。这份账单放到 DeepSeek、Anthropic、OpenAI 三家的现行价目表上结账，同一个 token 量，应付金额从四毛二到八块五，差出二十倍。模型一个都没换，换的只是价目表。 大多数人比价的方式是看「每百万 token 多少钱」。这篇给你一套更细的算法：账单是四个因子相乘，模型单价只是其中之一。价格数据截至 2026-09-20，口径在各节标明。 账单解剖：钱花在四个因子上 AI 编码的账单和人力成本逻辑不同：人力的大头在能力，token 的大头在重复。那份九百五十二万 token 的会话里，第一轮输入两万，最后一轮滚到二十二万，涨了十一倍，没有任何东西踩刹车。你付的钱，绝大多数没变成模型写的代码，变成了它每轮重读的聊天记录。 账单的结构，是四个因子相乘：任务 token 总量、壳的首包税、模型单价、缓存折扣。任务总量由活儿决定，短期动不了；首包税由壳决定，每轮原样重发的系统提示和工具说明书；模型单价看价目表；缓存折扣看你的使用纪律。四个因子里有两个半在你手里，后文的算法全围绕它们展开。 三张价目表，三种定价哲学 DeepSeek 的表结构最特殊，我直接从官方文档页抓的现行价（api-docs.deepseek.com，2026-09-20 20:45:00 抓取）：主力 deepseek-flash，输入命中缓存每百万零点零零三到零点零零六美元，未命中零点一五到零点三美元，输出零点六到一点二美元。每组两个数是峰谷两个价，谷时为峰时的一半。命中与未命中的价差五十倍，是三家最陡的缓存斜率。旗舰 deepseek-v4-pro 全线上浮约四点四倍，未命中价也只相当于 Claude Opus 5 的四分之一左右。 Anthropic 的表，按官方公告口径（2026-06-30 生效）：Claude Sonnet 5 每百万输入两美元、输出十美元，发布期价格已转永久；Opus 5 五美元和二十五美元；顶配 Fable 5 十美元和五十美元。缓存读长期按输入价一折计费，缓存写一点二五倍。牌价最贵，但一折缓存读配高命中率，实付没有牌面那么吓人。 OpenAI 的表，按官方定价页口径（2026-07-30 生效）：GPT-5.6 Sol 四美元和二十美元，缓存输入零点四美元；Terra 两美元和十二美元；Luna 零点二美元和一点二美元。坦白说明：OpenAI 定价页对我的网络环境返回 403，这组数字来自官方发布公告与多个独立来源交叉印证，引用请以官方页实时为准。 三张表摆在一起，是三种定价哲学：DeepSeek 把缓存和时段做成显式杠杆，奖励会安排任务的人；Anthropic 把缓存做成隐性折扣，奖励上下文管理得好的人；OpenAI 居中，胜在 Codex 生态顺手。你的使用习惯落在哪种奖励区间，比哪家单价低重要得多。 同一份 token 单，三家结账 现在把那份真实的 Codex 会话放到三张表上。口径交代清楚：九百五十二万输入、六万六千输出，命中率按九成计，这是对照自家实验里瘦指令目录的实测值取的整。 价目表 计算 应付 OpenAI GPT-5.6 Sol 857 万×$0.

26 万星 ECC 没引擎，23 万星 DSH 是真内核：两份源码读完的选装结论

 included in AI 编程
ECC 拿了 26 万星，读到源码级别才发现：里面没有一行引擎代码，本体是两千五百多个 Markdown 文件加六百多个脚本。DSH 只有 23 万星，反而是个带内核、带四端、带论文的完整框架。两个 GitHub 最热的 agent 框架，我把两份源码都读到了文件级，结论先放在这里：它们不在一个维度上，比不出谁强，只能分开装。 这篇给你三样能带走的东西：一张 ECC 和 DSH 的机制速查表（可截图收藏）、一套「谁该叠装、谁该换装」的选装结论、三条对应你自己现状的判断。所有数字核对于 2026-09-20 20:30:00（UTC+8），来源是 GitHub API 与两份仓库源码，性能类数字单独标口径。 星数接近，起点完全不同 先把档案摆在一起。DSH 是 DeepSeek 官方出品，2026-08-13 创建，TypeScript 编写，五周多一点冲到 23 万星。ECC 是个人开发者仓库，2026-01-18 创建，JavaScript 编写，八个月攒到 26.3 万星，当前版本 v2.2.2，最近一次提交 2026-09-19，更新极勤。 星数打平，星速差了六倍以上。这本身就是信息：2026 年下半年的 agent 赛道，背靠大厂发布渠道的框架，增长曲线和社区项目不在一个量级。两家官方描述的第一句也早就分了岔：DSH 写着 Everything is a Plugin，一切皆插件；ECC 写着 agent harness 性能优化系统。一个说自己是什么，一个说自己能优化什么。 DSH：一切皆插件的内核 DSH 构建在 Cordis 框架上，架构主张就一条：内核不认识任何具体能力。所有能力以插件形态外挂，连主循环都没有特权——循环本身也是一个插件。内核越薄，能外挂的东西越多，这个机制的源码细节我单独写过一篇插件系统走读。 产品形态随之确定：apps 目录下 cli、web、desktop、desktop-host 四个端跑同一套内核；插件装完十二秒生效；会话设计成类似 git 的结构，改炸了能回滚，细节见会话即 git 那篇。代价是初期生态要自己种，官方用插件市场和 dsh-plugin 话题标签聚拢第三方。README 里明确写着开发者预览期将有破坏性变更。大厂敢这么写，赌的是生态速度，五周 23 万星说明赌注暂时是赢的。

字节把 Trae 一分为二：写代码的归 Code，干活的归 TraeWork

 included in AI 开发
先看两条数据。抖音上「trae」关键词按点赞排序，半年内最高的两条视频：一条 2.5 万赞，英雄哪里出来的《TRAE SOLO 新版本发布，AI 跑通产品研发全流程》，265 秒，演示的是在 IDE 里用 AI 从零写出一个 3D 跑酷游戏；另一条 1.7 万赞，极物君的 AI 营地的《Trae Work 保姆级教程》，465 秒，演示的是让 AI 整理一家咖啡店的报表、发票和数据仪表盘。前一条的观众是程序员，后一条的观众是想让电脑替自己干活的普通人。 两条视频，两个没有交集的受众群体，恰好就是字节这步棋要分开的人群。Trae 官方文档最近挂出一行更新，标题只有一句：TraeWork is available。配合定价页和两条爆款视频的逐字稿，可以确认：SOLO 时代「不止编程」的那条线，已经从 IDE 里独立出来，成了单独的产品。 先把结论放在这：**写代码的 Agent 和干活的 Agent，从此是两个物种，选型逻辑不能混用。**这刀为什么这么切、你怎么选，往下看。 这篇拆四块：TraeWork 到底是什么、字节为什么把这刀切在这里、它和 Claude Code 这类编程 Agent 为什么不是一类工具、免费额度背后打的是什么主意。 TraeWork 是什么：一个能动手的聊天窗 先把产品说清楚。TraeWork 打开之后长得像豆包或者 DeepSeek 的聊天界面：中间一个输入框，可以打字也可以语音。区别在能力清单：聊天窗只能给你答案，TraeWork 能直接操作你的电脑。极物君在视频里演示的能力有四样：读取文件、移动文件、修改文件内容、创建新文件。这四样叠起来，就是「整理文件夹、把乱七八糟的表格提取成一份 Excel、做一个经营仪表盘、写日报」这类活的全集。 界面左侧有一个侧边栏，放的是豆包没有的两样东西：技能和自动化工作流。技能是预设好的任务模板，自动化工作流是可以重复触发的固定流程。这两样是把用过的活攒下来、下次一键重跑的容器，面向的是要反复做的固定任务，不是一次性问答。 复杂任务有一条单独的路径：Plan 模式。直接执行模式下，TraeWork 拿到任务就动手；Plan 模式下它先停下来，产出一份执行清单，把不确定的地方变成问题向你确认，你答完它才继续。极物君让他基于一份咖啡店销售汇总表做可视化仪表盘，用的就是 Plan 模式：它中途停下来问了两个数据口径的问题，确认之后才开工，最后交付了一个可交互的网页仪表盘，还附了一段「建议关注」的阅读提示。 这个设计值得单独说一句，因为它暴露了字节对这类产品的定位。写代码的 Agent 最大的风险是把代码改坏，所以要 diff 审查、要沙箱；干活的 Agent 最大的风险是理解错任务白干一场，所以它要先弄清任务再动手。同样是 Agent，风险模型不一样，交互设计就发展成了两个样子。 这刀为什么切在这里：从 SOLO 到分家 字节的这条产品线，过去二十个月的演化路径值得摊开看，每一步都在为最后的分家做铺垫。 2025 年 1 月，Trae 国际版发布，基于 VSCode 内核，卖点是在 IDE 里免费用 GPT-4o 和 Claude；3 月国内版跟进，配豆包模型，可切 DeepSeek。这个阶段的 Trae 是「免费 AI IDE」，打的是 Cursor 的价格锚点。

拆完 WorkBuddy 的 1GB 客户端,看懂了腾讯做 AI 办公的打法

 included in AI 工具
WorkBuddy 是腾讯 2026 年 3 月发布的 AI 办公工作台,上线四个月就坐上了国内 AI 办公智能体桌面端月活第一的位置:第三方榜单给它的数字是 1115 万,第二名百度搭子是 674 万。围绕这个第一,争议同样热闹:有港股报道说它月活 2000 万,知乎上有文章专门质疑这个数字的统计口径,36氪则泼了盆冷水:离腾讯想要的十亿级超级应用,还差 70 倍。 吵数据的人很多,拆产品的人很少。质疑派没拆过客户端,捧场派也拿不出机制层面的证据,争论停留在表态层面。 我把国内版 WorkBuddy 5.5.6 的 macOS 客户端完整拆了一遍:安装包、进程结构、打包代码、依赖清单,能看的地方都看了。这篇文章把拆到的东西按机制摆出来,最后回答标题里那个问题——这个第一,含金量到底怎么算。 先给一个判断框架:看懂执行型 AI,先看它的工具箱 大多数人第一次用 WorkBuddy 都有个错觉:这不就是个聊天窗口吗,和网页版大模型有什么区别? 区别在于:网页版大模型只能「说」,WorkBuddy 能「做」。你说「帮我把这个季度的数据整理成周报」,它真的会去打开文件、读内容、算数字、写文档、存到你指定的位置。这一类产品现在叫执行型 AI,或者叫 AI Agent(智能体):它和大模型聊天的部分只是入口,真正值钱的是后面那条执行链。 判断一个执行型 AI 靠不靠谱,我有个简单框架,三步: 第一步看工具箱:它能实际操作什么?是只能读写文件,还是能跨应用、能上网、能跑命令?工具箱的深度决定了它能替你干的活的上限。 第二步看连接方式:它和微信、飞书、钉钉这些办公软件是怎么对接的?接口是谁做的,权限怎么给,这条链路决定了它是在你的工作流里干活,还是只能在你眼前表演。 第三步看数据去了哪:你的文件、聊天记录、任务内容,哪些留在本机,哪些上了云?这决定了你敢把多少真实工作交给它。 下面按这三步逐层拆。结论的方向是:WorkBuddy 的工具箱和连接方式,做得比大多数人以为的认真;但它的第一,同样离不开一条别人拿不到的连接。 第一层解剖:1GB 的客户端里装了什么 动手拆之前,先交代版本和环境,所有证据都基于以下事实,你可以自己复现: 国内版:官网 workbuddy.cn,dmg 安装包 509MB,版本 5.5.6(build 38337834),应用装完后占 1.0GB 磁盘 国际版:官网 workbuddy.ai,5.5.2,dmg 490MB,com.workbuddy.workbuddy-ai——和国内版(com.tencent.workbuddy.mac)是两个完全独立的应用,连版本号都不同步 macOS 最低要求 11.0,Apple Silicon 优先 第一眼就值得说的数字:1.0GB。作为对比,我之前拆过 Claude Code 的 307MB 二进制,当时觉得已经够重了,WorkBuddy 直接是这个体积的三倍多。多出来的体积是什么?往下看。 启动后开进程列表,能看到一条很有信息量的东西:除了正常的界面进程,WorkBuddy 还跑了一个常驻守护进程,命令行是 daemon-app-server-entry.

你的 Claude 不一定需要 Claude Code：成功率只差 1%，账单差 2 倍

 included in AI 开发
先看一组我自己量出来的数。agent-autopsy 是一个专门抓包整理各家 coding agent 提示词的开源仓库，作者把 Claude Code、Codex、antigravity 这些壳运行起来，从实际发出的请求里截获系统提示词和工具定义，按模型分档存档。我把里面 Claude Code（Fable 5.1）那份下载下来量了一遍：系统提示词全文 10.4KB，六个章节；工具定义 37 个，按「单次请求实际发送一份」的口径合计 154KB，其中纯描述性文字 9.1 万字符，占六成。最大的一件是 Artifact 工具，光使用说明就 2.4 万字符，一个工具的说明书，是整个系统提示词的 4.7 倍。 也就是说，Claude Code 每次接活，模型要先读完将近 4 万 token 的「入职材料」才碰得到你的代码。这份材料不便宜：按 token 计价，它是每次请求都要重复支付的首包成本。 它买到智商了吗？2026-09-16，UC Berkeley Sky Computing Lab 和 LMArena 团队发了一项测量，名字起得很直白：HarnessTax（harness 税）。结论是：同一个模型，换个 harness，成功率只动 1 个百分点上下，账单差 2 到 5 倍。 这篇拆三件事：这笔税怎么测出来的、钱花在了哪里、什么情况下交得值。最后回到开头那份 4 万 token 的入职材料，它该不该瘦，答案在测量里。 先把账本摊开：HarnessTax 测了什么 harness 这个词，中文圈常译成「壳」或「执行框架」，指包裹在模型外面的那层工程：系统提示词、工具定义、权限控制、上下文管理、执行循环。Claude Code 是壳，Codex CLI 是壳，Pi 也是壳。模型本身只有一个，壳可以有无数个。 要回答「壳值多少钱」，得把壳和模型的组合拆开量。HarnessTax 的做法是控制变量：7 个模型 × 3 个 harness，组成 21 组配对，跑同一批任务。基准选了两个：SWE-bench Lite 每次跑 30 题、每题重复 3 次；Terminal-Bench 2.
