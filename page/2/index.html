你的 skill 配置就是攻击面：ECC 的 268 条安全规则拆解

 included in AI 开发
今年 8 月拆 ECC 的时候，我在那篇总览里提过一句它的安全扫描器 AgentShield：102 条静态规则，npx ecc-agentshield scan 一行命令扫 agent 配置。当时它是配角，一句带过。 为这篇重读源码时，README 已经对不上了：头部写着 268 条规则，拉到底部的规则汇总表还停在 102 条；CHANGELOG 显示 2026-09-10 一天连发两个版本，测试从 1841 个涨到 2444 个。一份 README 自己都追不上自家规则表的膨胀速度。 这件事本身就是本文的主题。AgentShield 已经拆成独立仓库（affaan-m/agentshield，npm 包 ecc-agentshield），它扫的对象不是你写的代码，是 .claude/、.codex/、mcp.json 这些「给 agent 看的」配置。多数人的直觉里这些文件是自己写的，可信；换一个角度看：agent 是一个能执行 shell 命令、能联网、能读文件的程序，它的行为说明书却没有经过任何安全评审。 我拿它跑了三次实测，结果先摆在这： 扫描目标 结果 官方自带的漏洞示例目录 F 级 0 分，199 条 finding，其中 40 条 critical ECC 仓库本尊（25.7 万星） F 级 19 分，2532 条 finding——85% 是文档示例，这个数字后面有大用 我自己的博客仓库 B 级 80 分，12 条 finding，两条 critical 是「CLAUDE.md 没写指令边界防御」 第三条值得停一下。我的仓库没有密钥泄露，没有危险 hook，scanner 给的两条 critical 全指向同一个缺口：你的提示词没写防御条款。这个工具对「安全」的定义比一般人想的宽——提示词本身也算安全配置。为什么，往下看。

Claude Code 的 skill 能自己进化？25 万星 ECC 源码拆出答案

 included in AI 开发
能。Claude Code 的 skill 确实可以自己进化——不用你写一行 SKILL.md，它从你的日常会话里观察、提炼、攒成本能，再定期把本能聚成新 skill。跑通这件事的项目叫 ECC，GitHub 上 25.7 万星，agent harness 赛道目前最大的开源项目。 这套进化机制的核心代码在 instinct-cli.py 里，第 1158 行藏着一句怨念很深的注释：trigger 句子平均只有 7 个词，用 Jaccard 相似度算聚类，明显相关的两条最高也只能到 0.33，「nothing ever groups」——什么都聚不起来。为了这句注释，作者把整个聚类算法换成了 overlap coefficient。 这是 ECC 的 Instincts 子系统。翻完它的源码，我最大的感受是它的诚实：每一层都在直面同一个物理事实——大语言模型没有记忆，你感觉到的「记性」，全部是外挂工程拼出来的。 这篇文章把这个外挂拆开看。先讲清楚为什么记忆必须外挂，再顺着数据流拆四层：观察、本能、注入、进化。ECC 给每一层交出的工程答案，比大多数「AI 记忆」创业产品的宣传页都有信息量。 一、先纠正一个错觉：模型的「记忆」是三种不同的东西 很多人聊 AI 记忆时把它们混成一团。认知科学把人类记忆分成三类，这个框架搬过来正好用： 认知科学分类 日常对应 AI 编程代理里的对应物 工作记忆 脑子里「正在想」的内容 上下文窗口（context window） 情景记忆 「上周三发生过什么」 会话日志、transcript 文件 程序记忆 骑自行车这种「肌肉记忆」 系统提示词、skills、规则文件 关键在第一行。LLM 是无状态的：每次推理，模型只看得到当前上下文窗口里的 token，上一次会话发生的一切对它来说不存在。你在 Claude Code 里教过它一百次「这个项目提交信息用 conventional commits」，新开一个会话，它照样给你写 update stuff。不是它不听话，是那个信息物理上不在它的输入里。 所以「让 AI 有记性」这个需求，翻译成工程语言就是：怎么把情景记忆（历史会话）提炼成程序记忆（可注入的行为规则），然后在恰当的时机塞回工作记忆（上下文窗口）。 ECC 的做法是四步：hooks 观察你的每次操作 → 后台代理从观察里提炼「本能」（instinct）→ 每次开新会话时把最相关的本能注入上下文 → 定期把攒多的本能聚合成 skills、commands、agents。整个 Instincts 子系统就跑在这条数据流上。

装完 Claude Code 先别急着聊：这 5 条提示词，决定你做出来的是玩具还是产品

 included in AI 开发
同一个需求，我听过两种结局。一句「给这个接口加个缓存」扔给 Claude Code，拿回来一套带配置层、适配器、多级策略的缓存体系，账单翻倍，这是许愿式问法。后来同一个需求换了个问法，第一轮就被四个问题问没了：这个接口写多读少，缓存攒不住热度，需求当场作废，半小时对话省掉几天的实现加无止境的维护。两次都是同一支 Claude Code，模型没换，提示词的文采也没变好。 差的不是第一句，是第一句之后还有什么。前一种问法，第一秒之后就没人管了，AI 自己决定方向、自己宣布完成；后一种问法，后面跟着一套东西接管全程。vibe coding 做出来的是玩具还是产品，分界线就画在这里。 我有个粗暴的判据：把你的会话记录翻到中间任意一轮，如果那一轮没有任何验收动作，产出大概率是玩具。中间轮次暴露的正是没人看着的时候 AI 在干什么。这篇把一次交付拆成五个阶段，每个阶段配一张提示词卡，卡和卡之间由人和门禁接力。单条提示词的深拆我写过三个提示词的事，工程资产的全景在五根工程柱子，这篇讲它们中间缺的那层：一次会话里，提示词怎么按阶段轮换。 一、玩具的特征：全程只有许愿一个动作 先看玩具是怎么造出来的。 一次交付实际是条流水线：理解需求、定方案、执行、验收、把教训攒下来。许愿式提示词只在第一站出现，一句「帮我优化一下性能」「参考某某产品做个类似的」，然后人就退场了。后面四站全部由 AI 自理，它按最隆重的方式做你没说的决定，按自己的标准宣布完成，教训哪也不去。翻车复盘我在裸聊四种姿势里摆过：不懂规矩、拿聊天记录当需求文档、看起来对就合入、一把梭没边界，四种姿势对应流水线上四个没人值守的工位。 很多人这时候的反应是换更长的提示词，把角色、要求、格式全塞进第一条。方向偏了。第一条提示词再长，管的还是第一秒；玩具感不是第一秒产生的，是第二秒到收工之间没有交接班产生的。生产级的做法不是打磨一句一步到位的话术，是给流水线的五个工位各派一个监工，每个监工就是一张卡。 所以这 5 张卡不长，也不用收藏——它们不是用来拜的，是用来换的。 二、开工卡：把许愿换成开工单 第一张卡在会话开头打出去。 这个需求先不动手。第一步，把相关代码读完，用你的话复述现状； 第二步，列出准备改哪些文件、每步干什么、明确不做什么； 第三步，列出需要我拍板的问题。我确认后再动手。它把「帮我把这事办了」改成「先告诉我你打算怎么办」。一字之差，身份变了：我从许愿的变成验收的。开头那个加缓存的需求就是被第三步救掉的：四问一出（缓存粒度、失效策略、穿透处理、单机还是多实例），「加个缓存」从愿望变成带边界的技术决策，而且第一轮就发现这题不用做。完整的故事在计划怎么把需求问掉里。 这张卡的单条深拆版本我写过，这里补一个用了一年的细节：确认计划时不要回「可以」，至少划掉一项。计划里总有做多了的或者顺序不对的地方，你划掉一项再放行，它收到的信号是这个老板真的看计划，之后每一轮的计划质量都会往上走。次次秒批，不出三次计划就开始水。 三、契约卡：把口述升格成 WHEN/THEN 计划确认了，需求还停在聊天记录里。第二张卡在动手前打，把口述意图变成可执行的契约： 把这份需求写成 spec：每个行为一条 WHEN/THEN，边界条件单独列， 涉及钱、权限、数据删除的场景必须覆盖失败路径。 信息不够的地方标 [待确认] 列出来问我，不许猜。聊天话术的每个词都留了解释空间，AI 会选一个解释继续干，选错的成本由账单支付。WHEN/THEN 是我把口述升格成契约的格式。实现之前它是指令，实现之后它是试卷，同一份文本用两次。拿我们踩过的佣金事故说：部分退款改造绕过了佣金结算，月底对账才炸。如果先有契约卡，这两个 WHEN 在写 spec 时就得回答： WHEN 部分退款金额大于已支付金额 THEN 拒绝请求，返回 REFUND_EXCEEDS_PAID THEN 不触发佣金重算，不写退款流水「不许猜」那半句和开工卡的第三步是一对：一个在计划层问掉歧义，一个在契约层堵死歧义。什么时候值得上这张卡，判据三条：改动跨文件、有外部副作用、需要决策留痕，命中一条就写 spec；单文件小修直接聊，流程开销超过动作本身就不划算。spec 流水线的完整用法我固化在 OpenSpec 六步里，中等改动走完全程约小半天，换来返工轮次明显下降。 四、止损卡：给 AI 体面的停机权 执行阶段最容易忽略的一张卡。它不指挥 AI 干什么，只规定它什么时候必须停： 执行期间三条纪律： 1. 确认不了的事实，停下来问我，「无法确认」是合法结论，别编； 2. 同一个错误失败两次，停止重试，把报错原文贴出来； 3. 删除或改写超过 50 行的代码，先单独列出清单等我确认。第一条是被账单教出来的。AI 没有心虚的概念，被逼着给答案时它一定给一个：编出来的配置项、猜出来的 API、虚构的日志，语气还特别自信。给它停机权比逼它硬编便宜得多，这条在我们仓库已经写进 AGENTS.

年薪 75 万美金的 FDE 没人科班：我拆完 1000 份 JD，说点实话

 included in AI 开发
两个数字放在一起看，很有意思。 第一个来自财联社：国内招聘平台上，FDE 的招聘需求涨了 42 倍，头部大厂给到年薪上百万。第二个来自数据团队 Bloomberry 2026 年 1 月的报告：他们拆了 1000 多份 FDE 招聘 JD，2025 年上半年的岗位数是 2024 年同期的 12.65 倍，平均总包 173,816 美金，基础模型实验室的 FDE 平均 25 万美金一年。 FDE，Forward Deployed Engineer，前置部署工程师。顺便纠个错：财联社把它译成「前端部署工程师」，不少国内的转述文章跟着抄错了。Forward 在这里是「向前推进到前线」的 forward，跟前端没有关系。硅谷给这个岗位起了个外号：the hottest job in AI that nobody was trained for，AI 圈最火、但没人受过科班训练的岗位。 高薪、暴涨、零科班，三件事同时成立，通常说明这个岗位正在被重新定义，定义权暂时握在第一批从业者和招聘方手里，市场上的信息是混乱的。你打开招聘软件搜 FDE，会看到一半岗位在要 Python 和 Agent 开发经验，另一半在要「客户沟通」和「方案讲解」，它们看起来根本不像同一个工种。 所以这篇文章不聊概念，聊数据。我把 Bloomberry 的 1000 份 JD 拆解、Anthropic 官方招聘页的 JD 原文、Levels.fyi 和猎聘的薪资档位放在一起，回答三个问题：这个岗位到底在干什么，门槛具体卡在哪，以及什么样的开发者应该转、什么样的千万别碰。 一、说人话：带着模型住进客户公司的工程师 FDE 这个词是 Palantir 造的。2003 年这家公司成立时的核心打法，就是把自己最强的工程师派到客户现场：情报机构、金融公司的办公室里，贴着客户的真实数据和真实流程做系统。工程师从大后方（总部）被推到最前线（客户现场），forward 说的就是这个位移。 类比一下：资深的家电维修老师傅，一部分坐店等机器送上门，另一部分直接背着工具箱去客户家里，看现场的使用环境、看接线、当场改方案。FDE 就是上门的那批。模型公司在总部把模型练好，但模型在客户那里跑不起来、跑起来不好用、好用了没人敢信，这些问题没有一个能靠远程支持解决。 为什么 2025、2026 年这个岗位突然爆炸？因为 AI 公司们撞上了同一堵墙。
